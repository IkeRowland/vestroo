# Story 2.1: Routes Collection Testing Guide

## Overview
This guide explains how to test the Routes collection functionality in PayloadCMS admin panel.

## Prerequisites

1. **Development Server Running**
   ```bash
   npm run dev
   ```
   The server should start on `http://localhost:3000` (or your configured port).

2. **Environment Variables Configured**
   Ensure your `.env.local` file contains:
   - `DATABASE_URL` - Supabase PostgreSQL connection string
   - `PAYLOAD_SECRET` - Secret key for PayloadCMS (can be any secure random string)
   - `NEXT_PUBLIC_SUPABASE_URL` - Your Supabase project URL
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` - Your Supabase anon key

3. **Admin User Created**
   You need to have an admin user in PayloadCMS. If you don't have one yet, you have several options:
   
   **Option A: Create via PayloadCMS Admin (First Time Setup)**
   - When you first access `/admin`, PayloadCMS may prompt you to create the first admin user
   - Follow the on-screen instructions to create your admin account
   
   **Option B: Create via PayloadCMS Local API (Script)**
   ```typescript
   // Create a script: scripts/create-admin.ts
   import { getPayload } from 'payload'
   import config from '../payload.config'
   
   const createAdmin = async () => {
     const payload = await getPayload({ config })
     await payload.create({
       collection: 'users',
       data: {
         email: 'admin@example.com',
         password: 'your-secure-password',
         role: 'admin',
       },
     })
     console.log('Admin user created!')
     process.exit(0)
   }
   
   createAdmin()
   ```
   Run with: `npx tsx scripts/create-admin.ts`
   
   **Option C: Manual Database Insert (Advanced)**
   - Connect to Supabase database
   - Insert a user record with `role: 'admin'` in the `users` table
   - Ensure password is properly hashed (PayloadCMS uses bcrypt)

## Accessing the Admin Panel

### Important: Direct URL Access Required

**The root URL (`http://localhost:3000/`) redirects to `/book/search`.** 

To access the PayloadCMS admin panel, you **must navigate directly** to:
```
http://localhost:3000/admin
```

**Do NOT** navigate to the root URL and expect to find a link to admin - go directly to `/admin`.

## Testing Checklist

### 1. Test Access Control with Non-Admin Users

**Objective:** Verify that non-admin users cannot access the Routes collection.

**Steps:**
1. Log out of PayloadCMS admin (if logged in)
2. Try to access `http://localhost:3000/admin`
3. Try to access `http://localhost:3000/admin/collections/routes` directly
4. **Expected Result:** 
   - Non-admin users should be denied access
   - You should see an authentication/authorization error or be redirected to login
   - Routes collection should not be visible in the admin panel

**To Test Admin Access:**
1. Log in with an admin user (user with `role: 'admin'`)
2. Navigate to `http://localhost:3000/admin`
3. **Expected Result:** 
   - Admin panel loads successfully
   - Routes collection appears in the sidebar under "Content" group
   - You can access the Routes collection

### 2. Verify Routes Collection Appears in PayloadCMS Admin Panel

**Objective:** Confirm the Routes collection is visible and accessible to admin users.

**Steps:**
1. Start the development server: `npm run dev`
2. Navigate directly to: `http://localhost:3000/admin`
3. Log in with an admin user
4. Look for "Routes" in the sidebar (should be under "Content" group)
5. Click on "Routes" to open the collection

**Expected Result:**
- Routes collection appears in the sidebar
- Clicking on it opens the Routes list view
- List view shows columns: Origin Name, Destination Name, Base Price, Active
- Search functionality works for origin_name, destination_name, and slug
- Pagination controls are visible (default 25 items per page)

### 3. Test Database Migration and Table Creation

**Objective:** Verify that PayloadCMS creates the routes table in Supabase.

**Steps:**
1. Ensure `DATABASE_URL` is correctly configured in `.env.local`
2. Start the development server: `npm run dev`
3. Navigate to `http://localhost:3000/admin` (this triggers PayloadCMS initialization)
4. Check your Supabase dashboard:
   - Go to Table Editor
   - Look for a table named `routes` (or `payload_routes` depending on PayloadCMS configuration)

**Expected Result:**
- Table is created automatically when PayloadCMS starts
- Table structure matches the Routes collection fields:
  - `id` (primary key)
  - `origin_name` (text)
  - `destination_name` (text)
  - `base_price` (numeric)
  - `is_active` (boolean)
  - `slug` (text, unique)
  - `seo_content` (JSONB for RichText)
  - `created_at`, `updated_at` (timestamps)

**Alternative Verification:**
- You can also verify by creating a route in the admin panel - if the table doesn't exist, PayloadCMS will create it automatically.

### 4. Verify Slug Generation and Updates

**Objective:** Test that slugs are auto-generated correctly and update when origin/destination changes.

**Test Case 1: Create New Route with Slug Generation**
1. Navigate to `http://localhost:3000/admin/collections/routes`
2. Click "Create New" button
3. Fill in:
   - Origin Name: `OR Tambo Airport`
   - Destination Name: `Sandton City`
   - Base Price: `250`
   - Active: ✓ (checked)
4. **Do NOT** fill in the Slug field (it should be read-only)
5. Click "Save"
6. **Expected Result:**
   - Slug is automatically generated as: `or-tambo-airport-to-sandton-city`
   - Slug field shows the generated value (read-only)
   - Route is saved successfully

**Test Case 2: Slug Updates on Origin/Destination Change**
1. Edit the route created in Test Case 1
2. Change Origin Name to: `Cape Town Airport`
3. Change Destination Name to: `V&A Waterfront`
4. Click "Save"
5. **Expected Result:**
   - Slug automatically updates to: `cape-town-airport-to-va-waterfront`
   - Old slug is replaced with new slug

**Test Case 3: Slug Uniqueness Handling**
1. Create a new route:
   - Origin: `Test Origin`
   - Destination: `Test Destination`
   - This will generate slug: `test-origin-to-test-destination`
2. Try to create another route with the same origin and destination
3. **Expected Result:**
   - System prevents duplicate origin/destination pairs
   - Error message: "A route with origin 'Test Origin' and destination 'Test Destination' already exists."
4. If you somehow create routes with different origins/destinations that generate the same slug, the system should append `-1`, `-2`, etc. to ensure uniqueness

**Test Case 4: Special Characters in Slug**
1. Create a route with:
   - Origin: `São Paulo Airport`
   - Destination: `Downtown (Main St.)`
2. **Expected Result:**
   - Slug should be: `sao-paulo-airport-to-downtown-main-st`
   - Special characters removed, spaces converted to hyphens
   - All lowercase

### 5. Test Validation (Duplicate Prevention, Price Validation)

**Test Case 1: Duplicate Route Prevention**
1. Create a route:
   - Origin: `Airport A`
   - Destination: `City B`
   - Base Price: `100`
2. Try to create another route with:
   - Origin: `Airport A`
   - Destination: `City B`
   - Base Price: `200` (different price)
3. **Expected Result:**
   - Save fails with error: "A route with origin 'Airport A' and destination 'City B' already exists."
   - Route is not created
   - Error message is user-friendly and clear

**Test Case 2: Negative Price Validation**
1. Create a new route
2. Enter Base Price: `-50`
3. Try to save
4. **Expected Result:**
   - Validation error: "Base price must be a positive number"
   - Route is not saved
   - Error message displayed in the form

**Test Case 3: Zero Price (Edge Case)**
1. Create a new route
2. Enter Base Price: `0`
3. Try to save
4. **Expected Result:**
   - Should be allowed (0 is a valid number, though not practical)
   - Or validation might require > 0 (check actual implementation)

**Test Case 4: Missing Required Fields**
1. Create a new route
2. Leave Origin Name empty
3. Leave Destination Name empty
4. Try to save
5. **Expected Result:**
   - Validation errors for required fields
   - Route is not saved
   - Required field indicators visible

**Test Case 5: Filtering Active/Inactive Routes**
1. Create multiple routes with different `is_active` values:
   - Route 1: Active = true
   - Route 2: Active = false
   - Route 3: Active = true
2. In the Routes list view, use the filter to show only active routes
3. **Expected Result:**
   - Only routes with `is_active = true` are displayed
4. Filter to show only inactive routes
5. **Expected Result:**
   - Only routes with `is_active = false` are displayed

## Troubleshooting

### Issue: Cannot Access /admin - Always Redirected to /book/search

**Solution:**
- Navigate **directly** to `http://localhost:3000/admin` (not the root URL)
- The root URL (`/`) intentionally redirects to `/book/search` for the booking flow
- Bookmark `/admin` for easy access during testing

### Issue: Routes Collection Not Visible

**Possible Causes:**
1. **Not logged in as admin user**
   - Solution: Log in with a user that has `role: 'admin'`

2. **PayloadCMS not initialized**
   - Solution: Restart the dev server and navigate to `/admin`

3. **Routes collection not registered**
   - Solution: Verify `payload.config.ts` imports and includes the Routes collection

### Issue: Database Connection Errors

**Solution:**
- Verify `DATABASE_URL` in `.env.local` is correct
- Check Supabase project is active
- Ensure connection string format is correct for Supabase
- Check Supabase connection pooling settings

### Issue: Slug Not Auto-Generating

**Solution:**
- Verify the `beforeValidate` hook is properly implemented
- Check browser console for JavaScript errors
- Verify PayloadCMS version is 3.0+
- Check that origin_name and destination_name are provided

## Quick Test Script

For rapid testing, you can use this sequence:

1. **Start server:** `npm run dev`
2. **Access admin:** Navigate to `http://localhost:3000/admin`
3. **Login:** Use admin credentials
4. **Create test route:**
   - Origin: `Test Origin 1`
   - Destination: `Test Destination 1`
   - Price: `100`
   - Active: ✓
5. **Verify slug:** Should be `test-origin-1-to-test-destination-1`
6. **Edit route:** Change origin to `Test Origin 2`
7. **Verify slug updated:** Should be `test-origin-2-to-test-destination-1`
8. **Try duplicate:** Create another route with same origin/destination → Should fail
9. **Try negative price:** Enter `-10` → Should fail validation
10. **Filter test:** Toggle `is_active` and verify filtering works

## Notes

- All tests should be performed in a development environment
- Database changes are persistent - you may want to clean up test data after testing
- PayloadCMS admin panel provides real-time validation feedback
- Check browser console for any JavaScript errors during testing
