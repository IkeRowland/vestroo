## Story

- As **a developer building `/account/*`**, I need a **`data-account-theme`** **wrapper** and **`--account-*` CSS variables** with **Tailwind** **`account.*`** classes, so **AccountShell** and pages can use **product-scoped** surfaces **without** reusing **ops** class names or **leaking** theme to **other** app layouts.

- As **a design-system reader**, I need **`docs/ops-design-system-parity.md` § 18.1** with a **short Storybook-style** snippet (`bg-account-canvas`, `text-account-foreground`, `border-account-border`, optional semantic), so **FE.18.1** is **traceable** alongside **§ 17.1** ops patterns.

## Acceptance Criteria (ACs)

1. **`globals.css`:** Under **`[data-account-theme="light"]`**, define **at least** the following **custom properties** (HSL / length values per **`visual-redesign-tokens.md` §1.4**; brand semantics **match** light **`[data-ops-theme="light"]`** HSL for **`--ops-accent`**, **`--ops-success`**, **`--ops-warning`**, **`--ops-danger`**, **`--ops-info`** and **include paired `*-foreground` HSLs where ops uses them in §1.2** for end-to-end tailwind parity): **`--account-canvas`**, **`--account-surface`**, **`--account-surface-hover`**, **`--account-border`**, **`--account-foreground`**, **`--account-muted`**, **`--account-topbar`**, **`--account-sidebar-width`** (**`14rem`**), **`--account-sidebar-collapsed-width`** (**`4.5rem`**), **`--account-accent`**, **`--account-success`**, **`--account-warning`**, **`--account-danger`**, **`--account-info`**, and **foreground** counterparts **as required by the ops pairing pattern**. **No** `[data-account-theme="dark"]` **required in 18.1** unless product revises this AC.
2. **`tailwind.config.ts`:** Add **`account`** (or equivalent **`colors.account`**) with utilities such as **`bg-account-canvas`**, **`text-account-foreground`**, **`border-account-border`**, **`w-account-sidebar`**, **`w-account-sidebar-collapsed`**, **`bg-account-accent`**, **`text-account-success`**, etc., **parallel** to the **`ops.*`** shape where applicable. **No** new runtime chart library.
3. **`src/app/(account)/account/(portal)/layout.tsx`:** Root element (or a single **immediate** **wrapper** around the existing **skip link** + **header** + **main** tree) sets **`data-account-theme="light"`** (and **className** / structure adjusted **only** as needed so **descendants** resolve **account** tokens; **lean client** **NFR.18.2** / **NFR.18.3** — keep **Server Component** default; **no** new **`'use client'`** **solely** for theme in **18.1** unless **Task 0** proves **required**).
4. **`:root` and marketing / booking** token blocks: **Unchanged** (byte-level intent: **no** accidental diffs in non-account sections).
5. **Tests:** New **`src/features/account/account-layout-tokens.test.ts`** (+ optional **`src/features/account/account-layout-tokens.ts`**) **mirrors** **`ops-layout-tokens.test.ts`**: assert **each** **contracted** `--account-*` **name** appears in **`[data-account-theme='light']`** block in **`globals.css`**.
6. **Documentation:** **`docs/ops-design-system-parity.md`** includes **§ 18.1** (title along the lines of **“FE.18.1 / Account theme tokens (light)”** or **“Epic 18 — 18.1: Account `data-account-theme`”**) with a **Storybook-style** code block (HTML or JSX with Tailwind classes) showing **canvas** + **foreground** + **border** and **at least one** **semantic** **`account.*`** utility — consistent with **Story 17.1** **§ 17.1** approach. **Note** in the subsection that **broader § 18** is completed in **Story 18.13** per **epic**.
7. **NFR.18.4 (spot):** **Progress Notes** document how **`data-account-theme`** is **scoped** to the **portal** layout (and that **`/ops/*`** **layouts** do **not** set it). **CI:** **`npm run lint`** and **`npm run test`** stay green.
8. **(Optional / verification)** **NFR.18.2:** No new **dependency** for theming; **stack** = existing **CSS + Tailwind** only.
