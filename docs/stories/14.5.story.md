## Story

- As a **customer**, I need a **direct “Pay now”** link at **`/q/[token]/pay`** that skips the accept screen but **commits the same way as accept**, so that **I can pay in one click** — **US-C3**, **Q14** (**[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C**).
- As a **customer with an expired quote link**, I need a **dedicated expired page** with trip context and a **clear path to start a new booking**, so that **I am not dropped on a generic error** — **US-C4**, **Q17**.

## Acceptance Criteria (ACs)

### US-C3 — Pay route + PayFast handoff (Theme C) + Q14

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C — US-C3** lines ~129–133; **Q14**; **§8** paths.)_

1. **Route (path + group):** Implement a **server** route whose path is **`/q/[token]/pay`**, **`[token]`** opaque per **14.2**. Place it under the **same** App Router group as **14.3** **`/q/[token]/accept`** and **14.4** **`/q/[token]/reject`** (**`(public-ops)`** or **`(quote)`** — match **14.3**; document in **Dev Technical Guidance** / **Progress Notes**).

2. **Token verification (14.2 contract):** Call **`verifyQuoteToken`** with **`expectedPurpose: 'pay'`**. For **`{ valid: false, reason: 'expired' }`**, follow **US-C4** ACs below (dedicated expired experience — **not** treated as generic invalid-only noise). For **`invalid_signature`**, **`malformed`**, and other non-expired failures, render **user-safe** server-rendered outcomes **analogous to 14.3** (friendly pages, not raw **500**).

3. **Load quote + booking guardrails:** After token **`valid: true`**, load **`booking_quotes`** by **`quoteId`** from payload; assert row belongs to **`bookingId`** from payload. **Only** if **`booking_quotes.status === 'sent'`** proceed to success flow. Otherwise mirror **14.3** outcomes for **already accepted**, **rejected**, **superseded**, **expired** (DB), etc.

4. **Success flow (Q14 — identical to accept):** When checks pass: transition quote **`sent → accepted`**, booking **`quote_sent → awaiting_payment`**, then invoke the **same** PayFast checkout path **14.3** uses (**`processPayment`** / signed checkout — **no** regression to return/cancel URLs). Respond so the customer reaches PayFast **without** an intermediate “accepted but not paying” screen.

5. **Audit / marker for direct pay:** Persist a **single** canonical record that the customer used the **pay shortcut** — **`client_type_source='direct_pay_skip'`** (epic wording) **or** equivalent one-off marker **on the quote** only if **`bookings`** / **`booking_metadata`** is the wrong layer. **Implementer:** survey schema (e.g. existing **`booking_metadata.client_type_source`** vs **`ops_audit_log`** action patterns); if no suitable column/payload exists, **one** migration is allowed **with AC justification** in the PR.

6. **Idempotency:** **Already accepted** / payment already in progress paths **mirror 14.3** — friendly messaging, **no** second PayFast session without guards that prevent duplicate charges.

7. **Webhook:** **No** changes to **`src/app/api/payfast/webhook/route.ts`** unless a bug is found (**[`docs/epic-14.md`](../epic-14.md)** **§8**).

8. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 2** (**14.5**), **§4 Theme C (US-C3)**, **Q14**, **§4 Theme G 14.5**, **§8** paths.

### US-C4 — Expired-token page (Theme C) + Q17

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C — US-C4** lines ~135–140; **Q17**; **§6**; **§7** expiry bullet.)_

1. **Dedicated expired page:** When **`verifyQuoteToken`** returns **`{ valid: false, reason: 'expired' }`** (signature valid, time window expired — per **14.2**), render a **dedicated** expired experience — **not** a generic **404**/**500**. Acceptable patterns: **(1)** dedicated route **`/q/expired`** with query params **only** for non-PII trip fields, **or** **(2)** a **shared** server-rendered component used by **`/q/[token]/pay`** (and optionally **`/q/[token]/accept`** / **`reject`** for consistency) without requiring a separate pathname.

2. **Trip summary (safe fields):** The expired view shows a **trip summary**: **origin**, **destination**, **trip date** (and **passenger count** if available from the same safe sources). **No** payment amounts, card data, or PayFast identifiers on this page unless product explicitly requires (default: **no payment info**).

3. **Copy + CTA:** Explain that **quotes expire** (epic default **72h** — align copy with **`booking_quotes.expires_at`** / product messaging) and that **prices may move**. Primary CTA: **“Request a new quote”** (or equivalent) navigates to **`/book`** with prefill query params **`origin`**, **`destination`**, **`date`**, **`passengers`** (exact query keys **TBD** to match the booking funnel — reuse **14.3** prefill builder if present). **§6:** **No** customer PII (name, email, phone) in the query string.

4. **New booking behaviour (Q17 — no false claims):** The CTA **starts** the normal booking funnel with a pre-filled **`/book`** URL. The **new** **`VST-*`** booking row is created when the customer **completes** the booking form (standard funnel) — **do not** claim server-side **auto-insert** on button click unless the repo already implements that; prose must read **“starts a new booking”**, not silent regeneration (**Q17**).

5. **Fallback when payload/booking is untrusted:** If expired verification **cannot** safely yield trip fields (e.g. no payload, tampered edge case, or DB load blocked), render a **minimal** expired page (clear “expired” message + generic **“Start a new booking”** linking to **`/book`** without sensitive query params). Document the branch in **Progress Notes**.

6. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C (US-C4)**, **Q17**, **§6**, **§7**, **§8** (`/q/expired/page.tsx` or equivalent).
