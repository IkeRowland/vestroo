### Completion Notes List

**Before (`queue=paid` server query + client filter):**

- PostgREST: `bookings.status = 'paid'` AND `payment_status = 'paid'` AND `(booking_intent IS NULL OR booking_intent <> 'trip_request')`, ordered by `created_at` desc, limit 100.
- Client: exclude any `id` present in `booking_trips.booking_id`; then take first 50 of remainder for the panel.

**After (`queue=paid`):**

- PostgREST: `bookings.status = 'ready_to_assign'` (via shared **`OPS_BOOKINGS_READY_TO_ASSIGN_STATUS`**) AND same `booking_intent` OR filter; same order/limit; same client-side **no `booking_trips` row** filter and slice to 50.

**Pending queue alignment:** `queue=pending` query adds `.neq('status', ready_to_assign)` so rows in RTA do not appear on Pending (matches updated **`matchesPendingBucket`** in `fulfil-queue-buckets.ts`).

**Shared module (Task 3):** Exported **`OPS_BOOKINGS_READY_TO_ASSIGN_STATUS`** from `src/lib/ops-bookings-queue-query.ts`; used by **`/ops/bookings`** RTA count query and **`/ops/fulfil`** paid + pending branches. No separate PostgREST filter-builder module (minimal constant-only shared surface).

**Row parity (Task 4 / AC2):** **Not identical** to the legacy set by design: legacy **`status='paid'` + `payment_status='paid'`** unlinked standard bookings **no longer** appear in **`queue=paid`** unless they are migrated to **`ready_to_assign`** (per Epic 14.1 / US-E2). Vitest **`fulfil-queue-buckets`** asserts **`matchesPaidBucket`** / **`classifyFulfilBookingBucket`** for **`ready_to_assign`** vs legacy paid. **Bookings chip count** (all `ready_to_assign`) can exceed **fulfil** list rows because fulfil **still** excludes **`trip_request`** intent and requires **no** `booking_trips` link — fulfil is a **subset** of the chip’s status-only predicate.
