## Story

- As **Vestroo (the system)**, I need a **daily** **invoice-due reminder** job that **reuses** Epic 13’s **existing cron** surface, so that **account-client** bookings in **`ready_to_invoice`** or **`invoiced`** receive **timely** **`invoice_due_reminder`** comms through the **`15C.2`** matrix **with** **configurable** **due-date windows**, **safe** **no-rule** behaviour, **transactional**-class treatment (**not** blocked by **marketing** opt-out per **epic §6**), and **idempotent** delivery **deduped** via **`ops_audit_log`**.

## Acceptance Criteria (ACs)

1. **Cron mechanism — extend Epic 13, not new scheduler:** The reminder logic is **invoked** by the **same** **daily** / **cron** **mechanism** already used for Epic 13’s **quote expiry** (or **documented** successor if renamed) — **survey** (`grep` **`cron`**, **`vercel.json`**, **`supabase/functions`**, **`/api/`** routes) and **record** the **chosen** integration point in **Dev Technical Guidance** + **Progress Notes**. **Do not** introduce a **second** vendor-specific scheduler **solely** for this feature without **PO** approval (**out of band** — default **reject**).

2. **Booking query — statuses, `due_date`, account scope:** Select **only** **`bookings`** (or **approved** view) where **`status IN ('ready_to_invoice','invoiced')`**, **`due_date` IS NOT NULL**, and the booking is **in scope** for **account invoicing** (per **Q20** / **`client_type`** or **`customer_account_id`** presence — **survey** schema and **document** the exact predicate). **Exclude** **walk-in** and any row **without** a **usable** **`due_date`** so the job **never** emits nonsense reminders.

3. **Configurable time windows — env defaults:** **Pre-due** window: bookings whose **`due_date`** is **exactly** **`INVOICE_REMINDER_DAYS_BEFORE`** calendar days **ahead** of **run date** (default **3**) **or** falls within the product-defined interpretation (e.g. “**on** the day that is N days before due” — **pick one**, **document**, **unit-test** edge cases). **Overdue** window: bookings whose **`due_date`** is **exactly** **`INVOICE_REMINDER_DAYS_OVERDUE`** calendar days **before** **run date** (default **1** meaning “**1 day overdue**” on the daily run — **define** unambiguously in DG). **Add** **`INVOICE_REMINDER_DAYS_BEFORE`** and **`INVOICE_REMINDER_DAYS_OVERDUE`** to **`.env.example`** with **one-line** comments.

4. **Dispatch — `invoice_due_reminder` via matrix (`15C.2`):** For each **matched** booking **after** dedupe checks, call the **existing** **comms dispatcher** used by **`15C.2`** with **`event_key = 'invoice_due_reminder'`** and **per-channel** behaviour unchanged from matrix semantics (**rules**, **templates**, **service-role** reads). **Respect** **`comms_no_rule_matched`** / **`comms_no_active_template`** (or **equivalent**) **no-op** + **`ops_audit_log`** at **debug** level per **`15.20`**.

5. **Payload for templates:** The **context** passed into template rendering / variable substitution **includes** at minimum **`booking_id`**, **`due_date`**, and **amount** fields **required** by **`comms_templates`** for **`invoice_due_reminder`** (plus any **existing** shared vars the dispatcher already supplies — **survey** **`15C.2`**). **Document** variable names in **Dev Technical Guidance**.

6. **Idempotency / dedupe — `ops_audit_log` preferred:** Before sending for a **`(booking_id, reminder_phase)`** tuple (e.g. **`pre_due`** vs **`overdue`** — **define** in code/constants), **query** or **insert-guard** using **`ops_audit_log`** so that **if** a **successful** **`invoice_due_reminder`** dispatch **audit** row **already exists** for **that** booking **and** **phase** on **the same local calendar day** as the cron run (**or** stricter: **any** prior send for that phase while still in same status window — **pick the stricter epic reading**: “**sent yesterday** → **not** **today**” implies **per-day** dedupe at minimum), **skip** the send. **Prefer** **`ops_audit_log`** with a **stable** **`action`** string (const-exported) over a **new** table unless justified.

7. **Privileges — service role or `SECURITY DEFINER`:** The job runs **without** a **user** JWT — use **`createServiceRoleClient()`** from the **cron** entrypoint **and/or** a **`SECURITY DEFINER`** SQL function **called** by **`pg_cron`** — **match** the **Epic 13** pattern. **Do not** weaken **portal** RLS; **no** broad **`authenticated`** **SELECT** on **`comms_*`** registry tables.

8. **Transactional class — epic §6:** **`invoice_due_reminder`** **must** be treated as **`transactional`** for **preference** / **suppression** logic (**if** any **send-time** check reads **`comms_preferences`**): it **must** **not** be skipped because **`marketing`** is off. **Align** with **`15.24`** **`getCommsEventCommsCategory`** (or successor) — if mapping **missing**, **add** **`invoice_due_reminder` → transactional** in the **same** module.

9. **Seeds / matrix coverage:** If **`invoice_due_reminder`** lacks **active** **`comms_dispatch_rules`** / **`comms_templates`** in **seeds**, **add** minimal **PR-reviewed** seed rows for **email** (and **SMS** only if **15C.1**/**15B.4** makes SMS **non-stub** for matrix — otherwise **document** **email-only v1** per **Out of scope**).

10. **Observability:** Each **run** logs a **summary** (**counts**: candidates, sent, skipped-dedupe, no-rule) at **info**/**debug** appropriate to hosting — **no PII** in **structured** logs beyond **booking id** if already standard. **Failures** do **not** **partially** **double-send** without **idempotency** keys where the **provider** supports them (**reuse** **`15C.2`** **Resend** patterns where applicable).

11. **Traceability:** **Maps to** **[`docs/epic-15.md`](../epic-15.md)** **US-B4**, **Theme E `15C.7`**, **§8** (scheduled job bullet); **defers** **`15C.8`** **E2E**/**compliance** checklist.

### Cron integration (AC1 / AC7)

- **Chosen entry:** **`GET` / `POST` `src/app/api/cron/daily-maintenance/route.ts`** — **single** HTTP surface for hosted schedulers (Vercel Cron, Supabase `pg_net` + Edge, external `curl`, etc.).
- **Sequence:** (1) `Authorization: Bearer ${CRON_SECRET}` gate; (2) `createServiceRoleClient()`; (3) `rpc('expire_sent_booking_quotes_past_due_v1')` (**Epic 13 / 13.11** SQL, same as migration runbook); (4) `runInvoiceDueReminderJob({ serviceSupabase })`.
- **Replacing `pg_cron` SQL-only:** operators who today run **`select public.expire_sent_booking_quotes_past_due_v1()`** from **`pg_cron`** should **unschedule** that job and **call this route once daily** instead (one scheduler, quote expiry + reminders). Alternative: keep `pg_cron` for SQL only **and** add a second schedule for HTTP — **not** recommended (two triggers).

### Booking scope & “due_date” (AC2)

- **There is no `bookings.due_date` column** in this repo; **due** is derived like **`/ops/invoicing`**: trip completion (from embedded **`booking_trips` → `trips`**) + **`credit_terms_days`** (from **`account_snapshot`** / **`customer_accounts`** via **`creditTermsDaysForInvoicingRow`**), then civil calendar add in **`INVOICE_REMINDER_TIME_ZONE`** (default **`Africa/Johannesburg`**) — see **`dueDateYmdForInvoiceReminder`** in **`src/lib/invoice-due-reminder-windows.ts`**.
- **Account invoicing (Q20) predicate:** **`client_type = 'account_client'` AND `customer_account_id IS NOT NULL`**. Walk-ins excluded by **`client_type`**; account rows without a linked account id are excluded.
- **Statuses:** **`status IN ('ready_to_invoice','invoiced')`**. Rows with no computable due (no completed trip anchor) increment **`noDueDate`** and are skipped.

### Env windows (AC3)

- **`INVOICE_REMINDER_DAYS_BEFORE`** (default **3**): **pre_due** when **`dueYmd === runYmd + N`** civil days in the job TZ.
- **`INVOICE_REMINDER_DAYS_OVERDUE`** (default **1**): **overdue** when **`dueYmd === runYmd − N`** civil days ( **`N = 1`** ⇒ due was **yesterday** in that TZ on the daily run).
- **`INVOICE_REMINDER_TIME_ZONE`:** optional; default **`Africa/Johannesburg`**.

### Template variables (AC5)

- **`sendCommsMatrixEmailDispatches`** accepts optional **`templateVariableMap`** — keys substituted as **`{{key}}`** in DB template **subject** / **body_html** alongside **`{{booking_ref}}`**.
- **Names for `invoice_due_reminder`:** **`booking_id`**, **`due_date`** (`YYYY-MM-DD`), **`amount`** (ZAR formatted, e.g. **`en-ZA`** currency), plus existing **`booking_ref`**.

### Dedupe & audits (AC4 / AC6 / AC10)

- **Phases:** **`pre_due`** | **`overdue`** (`InvoiceDueReminderPhase` in **`src/lib/invoice-due-reminder-constants.ts`**).
- **Sent:** **`appendOpsAuditLog`**, **`action = invoice_due_reminder_sent`**, **`payload`:** `{ booking_id, phase, run_date, event_key, due_date }` (`run_date` is **`YYYY-MM-DD`** in job TZ).
- **Dedupe probe:** existing row with **`action = invoice_due_reminder_sent`** and same **`payload->>booking_id`**, **`phase`**, **`run_date`** → skip send; optional **`invoice_due_reminder_skipped_duplicate`** when **`OPS_AUTOMATION_AUDIT_ACTOR_ID`** is set.
- **No-rule / no-template:** **`auditCommsMatrixPreSendBlocked`** (**15.20**) per booking with **`event_key: invoice_due_reminder`** in payload.
- **Sends require `OPS_AUTOMATION_AUDIT_ACTOR_ID`:** if unset after matrix gate, dispatch is **skipped** (error count) so **AC6** audits + dedupe cannot silently break.

### Transactional (AC8)

- **`src/lib/comms/comms-event-category.ts`** already maps **`invoice_due_reminder` → transactional`**; no code change required in **15.24** module for this story.
