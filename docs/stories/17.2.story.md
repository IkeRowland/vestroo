## Story

- As **ops staff**, I need a **top bar** with **inline search**, **settings**, **notifications**, and **profile** that matches modern SaaS chrome, so I can work faster without leaving the shell.

- As **the product**, we need **search suggestions** loaded via **server action** (no client PII index), so **privacy and authz posture** stay intact (**NFR.17.6**).

## Acceptance Criteria (ACs)

1. **Search (replace link):** Top bar shows an **inline `<input>`** (or `Input` primitive), placeholder **`Search bookings, clients, vehicles…`** (exact punctuation per epic).
2. **Focus → Popover:** On **focus**, open Radix **`Popover`** listing **recent searches** and **quick-jump** suggestions (booking ref, client name, vehicle reg). Data fetched via **server action** only — **no** client-side index of PII.
3. **Submit:** **Enter** navigates to **`/ops/search?q={encoded query}`** (existing route).
4. **Responsive:** **`breakpoint < sm`**: search collapses to **icon-only** control; **sub-`md`**: opening search uses a **Sheet** (epic wording) — full mobile search UX lives in sheet when inline bar does not fit.
5. **Settings:** **Settings** icon links to **`/ops/settings`** (visual + hit target per Wheelzie reference cluster).
6. **Notifications:** **`OpsNotificationsBell`** is re-styled with a **Wheelzie-style red dot badge** for unread; accessible name **`{count} unread notifications`** (pattern per epic — interpolate count).
7. **Profile chip:** Shows **avatar** (photo or **initials** fallback), **display name**, **role** label; opens Radix **`DropdownMenu`** with **Sign out**, **Profile**, **Settings** (order may match existing patterns — document in parity § 17.2).
8. **Breadcrumbs:** Moved **below** the top bar onto a secondary **`h-8` (32px)** strip so the utilities row stays clean. **Mobile:** strip shows **current page title** + **`<` back** control when a **parent** breadcrumb exists (navigation back semantics — document expected behaviour in § 17.2).
9. **Keyboard:** **`/`** focuses the search input when safe (see **Reconciliation**); profile **`DropdownMenu`** is **Tab**-reachable and **arrow-key** operable per Radix (**NFR.17.5**).
10. **Dependencies:** No new runtime dependency except **`@radix-ui/react-dropdown-menu`** as epic-approved; **`@radix-ui/react-popover`** / **`@radix-ui/react-dialog`** (sheet) allowed if **Task 0** confirms gaps — record **§ 17 Dependency inventory** bundle note when multiple primitives land (**NFR.17.2**).
11. **Tests:** **`OpsTopBar`** snapshot or focused component tests **updated or introduced** (Vitest); use **`@testing-library/react`** if adopted after Task 0 survey.
12. **Copy (NFR.17.8):** All new user-visible strings live in a **single export per surface** — e.g. **`ops-top-bar-copy.ts`** colocated with feature or under **`src/features/ops/copy/`** — not inline literals in JSX (future i18n).
13. **Architecture (NFR.17.3):** Prefer **Server Components** for shell framing; **Popover**, **Sheet**, **DropdownMenu**, and search input handlers remain **client** where interaction requires **`'use client'`**.
14. **Authz (NFR.17.6):** No changes to **`requireOpsStaffPage`**, RLS, or role mapping — presentation only.
15. **Documentation:** Add or extend **`docs/ops-design-system-parity.md`** with **§ 17.2** — props/interaction summary, **a11y** / keyboard notes, Radix dependency row (**NFR.17.1**).
16. **Quality:** **`npm run lint`** and **`npm run test`** remain green after implementation.
