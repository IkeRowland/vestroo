## Story

- As **ops staff**, I need a **“New Bookings”** (or equivalent) **card** on the ops home, so that **I can navigate to triage quickly** and see **how many bookings need attention** before I open the list (**US-B2**).

## Acceptance Criteria (ACs)

### US-B2 — Ops home card (Theme B)

1. **Deep-link:** The card’s primary navigation targets **`/ops/bookings`** per epic **US-B2**, using **sensible defaults** aligned with **US-B1**: **no pre-applied restrictive filters** — prefer **`href="/ops/bookings"`** (bare path). Do **not** append query params that **filter out** rows (status, intent, payment, client type). Optional **analytics-only** params are permitted if they do **not** affect server list predicates; otherwise omit. This **must not** contradict **US-B1** default-unfiltered list behaviour.

2. **Live count (needs-attention set):** The card displays a **count** of rows in **`bookings`** where **`status IN ('submitted','triaged','quote_sent','awaiting_payment')`** (epic “needs attention” set). The count is **RLS-respecting** (same session / Supabase client patterns as other ops staff reads). **Refresh model:** recalculated on **each navigation** to the ops home (e.g. **Server Component** refetch / route load) — **not** a **realtime** subscription (**12.4**).

3. **Empty vs non-empty UI:** When count **= 0**, show a **neutral** empty state (calm copy, no alarm styling). When count **> 0**, make the card **visually distinct** (e.g. **badge** and/or **accent colour**) per epic **US-B2**, consistent with ops dashboard visual language.

### Cross-cutting — Accessibility (**E2**-adjacent patterns)

4. **a11y:** Card behaves like other **ops dashboard** cards: primary control is **keyboard-operable** (**Tab** / **Enter**); exposed **accessible name** (and description if needed) reflects purpose (e.g. “New Bookings” + count or “No bookings need attention”) — match patterns used by sibling KPI/navigation cards on the same surface.

### Cross-cutting — Loading & errors (**E2**)

5. **Loading / error:** While the count query is in flight, show a **loading** state consistent with **`OpsDashboardView`** / ops home KPIs. On **failure**, show an **error** or **unavailable** state with **retry** or **navigation still available** to **`/ops/bookings`** per team **E2** conventions — **no** silent empty count that implies zero rows when the query did not succeed.

### Route existence (coordination with **12.3**)

6. **No dead 404:** Following **§8** / **Phase 2** ordering, **`GET /ops/bookings`** must **resolve** (full **12.3** page **or** documented **minimal stub** until **12.3** merges). The home card **must not** link staff to a **404**.
