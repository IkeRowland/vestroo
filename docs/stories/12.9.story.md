## Acceptance Criteria (ACs)

### Playwright (`tests/` — align with Theme B–E and **§7**)

1. **§7 Ops UX — submit → visible ≤ 3 s:** From the **public** booking flow, after a successful submit, the new booking appears on **`/ops/bookings`** within **3 seconds**, using either **realtime** (**12.4**) or an **explicit refresh** consistent with **[`docs/ops-data-freshness.md`](../ops-data-freshness.md)** (assert the chosen strategy in the test comment so reviewers know it is intentional).

2. **12.3 / Theme B — default + chips smoke:** **`/ops/bookings`** loads with **no restrictive pre-filters** (unfiltered default); **filter chips** smoke toggles at least one dimension each from **status**, **payment**, **intent**, **client type** (multi-select behaviour as implemented) without breaking list render.

3. **12.2 / Theme B — ops home card:** If **stable `data-testid` / role / text** selectors exist for the **“New Bookings”** (or equivalent) home card, assert navigation to **`/ops/bookings`** with **non-restrictive** defaults; if selectors are not yet stable, document a **Task** to add them and **`test.skip`** with rationale until fixed.

4. **12.5 / Theme D — Q6 domain match:** With **seeded** **`customer_accounts.authorized_email_domains`** (and **active** account) in **local seed** / **staging** test env, entering a **test email** whose domain matches triggers the **suggest-and-confirm** UI; explicit confirm yields **`account_client`** path metadata as exposed in UI or network (per implementation). Document required **env vars** / seed fixtures in **Dev Technical Guidance** (no secrets in repo).

5. **12.6 / Theme D — identify-client:** Using a **staff** Playwright fixture (storage state or login helper), run an **unpaid** booking **round-trip**: open **identify client**, link or unlink per **Q5** bounds, assert **disabled** state + tooltip when **`payment_status='paid'`** if a paid fixture exists; otherwise document **`test.skip`** for paid case with seed gap.

6. **12.7 / Theme E — Q4 PO required + §6 API bypass:** When the resolved account has **`default_po_required=true`**, **client-side** blocks submit without PO; add an **API / direct action** attempt (service or route used in tests — **discover**) that **bypasses** the form and assert **server-side rejection** or **`po_required_and_missing`** / equivalent error payload (epic **§6** mitigation).

7. **12.4 / Theme C (optional / quarantine):** Subscription teardown or **no duplicate channels** — implement if stable; if flaky under CI, **`test.skip`** or isolated file with **quarantine** policy documented in **Story Progress Notes**.

### `smoke_rls` (SQL — extends **12.1** / **12.8**)

8. **`npm run smoke:rls`** passes at **migration head** after extending **`supabase/smoke_rls.sql`** (or agreed harness) per team pattern (**transactional `ROLLBACK`** where fixtures are used).

9. **`booking_quotes` INSERT (test-only):** Add a **staff** or **service-role** path that **`INSERT`s** a minimal valid **`booking_quotes`** row (respecting **constraints** and **RLS**) tied to an existing **test booking**, and assert expected visibility / **`v_booking_current_quote`** if the view exists — **without** introducing a production writer (epic **§2** non-goals / **§6** risk row).

10. **RLS / append-only invariants:** Keep or extend assertions that **`booking_quotes`** has **no** effective **DELETE** policy (deny **DELETE** as staff and non-staff per **12.1** / epic **Theme A**).

### Definition of Done mapping (**§7**)

11. **§7 Quality:** Critical **Theme B–E** paths covered by **Playwright** and/or **`smoke_rls`** per above; **12.9** test jobs **green** in CI (document exact workflow commands in **Testing**).

12. **§7 Regression / `smoke_rls`:** Script updated and passing; includes **`booking_quotes`** insert validation and prior **12.8** member **INSERT** matrix still green.

13. **§7 Ops UX (evidence):** Playwright **AC1** provides the **“zero-invisible-booking property”** evidence chain required by epic **§7** (submit → list ≤ **3 s**).
