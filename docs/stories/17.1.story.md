## Story

- As **a developer maintaining `/ops/*`**, I need **semantic CSS variables** and **Tailwind utilities** for **accent**, **status**, **elevation**, **radii**, and **charts** under both **light** and **dark** ops themes, so **later stories** can compose UI **without arbitrary values** and stay aligned with **Vestroo brand** (**rust**, not reference-app coral).

- As **a design-system reader**, I need **§ 17.1** in **`ops-design-system-parity.md`** with a **Storybook-style** snippet showing **`rounded-ops-card`**, **`shadow-ops-1`**, **`bg-ops-accent-soft`**, and **status/chart** color usage, so implementers know the **canonical patterns**.

## Acceptance Criteria (ACs)

1. **`globals.css`:** Under **`[data-ops-theme="light"]`** and **`[data-ops-theme="dark"]`**, define **all** of: **`--ops-accent`**, **`--ops-accent-foreground`**, **`--ops-accent-soft`**; **`--ops-success`** / **`--ops-success-foreground`**; **`--ops-warning`** / **`--ops-warning-foreground`**; **`--ops-danger`** / **`--ops-danger-foreground`**; **`--ops-info`** / **`--ops-info-foreground`**; **`--ops-elevation-1`**, **`--ops-elevation-2`**; **`--ops-radius-card`**, **`--ops-radius-pill`**; **`--ops-chart-1`** … **`--ops-chart-6`**. Values **reconcile** with **[`docs/design/visual-redesign-tokens.md`](../design/visual-redesign-tokens.md)** (including dark §1.3 and chart §1.5). **Accent** equals **vest.rust** HSL **`9 58% 48%`** in light; **not** Wheelzie coral.
2. **`tailwind.config.ts`:** Extend **`theme.extend`** so utilities exist for consumers — at minimum **colors** (**`ops-accent`**, **`ops-accent-foreground`**, **`ops-accent-soft`**, **`ops-success`**, **`ops-warning`**, **`ops-danger`**, **`ops-info`**, each with **`-foreground`** where applicable), **chart** keys **`ops-chart-1`** … **`ops-chart-6`**, **`borderRadius`** (**`ops-card`**, **`ops-pill`**), **`boxShadow`** (**`ops-1`**, **`ops-2`**). Naming aligns with epic examples (**`bg-ops-accent`**, **`text-ops-success`**, **`rounded-ops-card`**, **`shadow-ops-1`**).
3. **`:root` marketing / booking tokens:** **Unchanged** from pre-story state (no accidental edits to marketing palette blocks).
4. **Tests:** **`src/features/ops/ops-layout-tokens.test.ts`** extended so a maintainer cannot delete a new var **silently** — asserts **presence of each new token name** (per **Reconciliation** test strategy).
5. **Documentation:** **`docs/ops-design-system-parity.md`** gains a **§ 17.1** subsection with a **Storybook-style** usage example (markdown code block: JSX or HTML + Tailwind classes) demonstrating **card radius**, **elevation shadow**, **accent soft** surface, and at least one **status** + one **chart** token reference.
6. **Quality:** **`npm run lint`** and **`npm run test`** remain green after changes.
7. **NFR.17.4:** Spot-check in browser (or Storybook if present): toggling **`data-ops-theme`** **light/dark** shows no broken contrast for **accent** and **status** swatches documented in § 17.1 (developer verification note in **Progress Notes**).
