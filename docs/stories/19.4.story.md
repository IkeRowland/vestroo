## Story

- As **a traveler on mobile**, I want a **single native datetime control** so I can pick **when** the pickup happens **without juggling two fields** (**FE.19.4**).

- As **a desktop traveler**, I want a **popover** with a **clear calendar grid** and **15-minute** time choices so picking date and time feels **fast** and **consistent** with ops calendar **patterns** (**FE.17.9** spirit — **no** new calendar library).

- As **ops / product**, I need pickups scheduled **at least one hour ahead**, with a **clear inline error** on **Next** — **no** pop-up noise (**FE.19.4**, **NFR.19.6**).

## Acceptance Criteria (ACs)

1. **Combined UX on slide 1:** **`TripRequestRideDetailsSlide`** replaces the **separate** date + time inputs with **one** combined flow: **mobile-first** — **`datetime-local`**; **desktop** — **`Popover`** + **date grid** + **time** control (**15-minute** steps). **No** new calendar **npm** dependency (**epic** lines **98–99**).
2. **Today / Tomorrow chips:** Where helpful, **quick chips** above the picker set **`rideDate`/`rideTime`** (or **Task 0** mapping) for **today** / **next Johannesburg calendar day** consistent with **19.2** rules (**epic** line **100**).
3. **60-minute lead time:** **`rideDateTimeIsInPast`** / **`rideDateTimeFutureCheck`** (or **successors** with the **same** call sites) enforce pickup **≥ 60 minutes** after **`now`** when validating complete date+time on **slide 1 Next** (**epic** lines **101**, **105**).
4. **Inline error only:** On violation, show *“Pickup must be at least 1 hour from now”* **inline** near the control — **no** **`toast`**, **no** **modal** (**epic** line **101**).
5. **Contract preserved:** **`RideDetailsFormValues`**, **`validateRideDetailsStep`**, **`validatedTripSlide1Schema` / `tripRequestSubmitPayloadSchema`** remain the **authoritative** shapes — combined UI **writes** **`rideDate`** (`YYYY-MM-DD`) and **`rideTime`** (`HH:mm`) unless **Task 0** records an approved structural change (**NFR.19.6** / **epic** line **243**).
6. **Touch targets:** Mobile interactive targets for the combined control (and any steppers/chips **introduced here**) meet **≥ 44×44** CSS px (**epic** line **106**, **NFR.19.2**).
7. **Tests:** Extend **`ride-details-validate.test.ts`** for **60-minute** boundary cases; add **RTL**/unit coverage for **popover**/chip behaviour as appropriate; **`npm run test`** green for **`trip-request-submit-schema.test.ts`** and related suites.
