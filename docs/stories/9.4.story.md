## Story

- As a **product, ops, compliance, and engineering** stakeholder with **go** at **[`#sh-9-1`](../epic-9.md#sh-9-1)** and **SH.9.2–SH.9.3** baseline tables and ADRs in place
- I want reference **BusTracking** and **DriverBusSchedule** **capabilities** — vehicle position relative to a **published pattern**, chauffeur tied to a **scheduled run** — mapped to **Vestroo Realtime** (Epic 7 / **VST-9**) with explicit **privacy** and **client** policies
- so that **authorised** ops, field, and (where product allows) customer surfaces receive **timely**, **role-appropriate** live updates **without** porting capstone **socket.io** or transit **product** framing, and **without** leaking precise location across **privacy tiers**

3. **Traceability mapping (docs):** Deliverable **MUST** state how reference **BusTracking**-style concerns (live position, progress vs **pattern** / **waypoint** sequence, ETA-style fields) map to **Vestroo** tables (**`vehicle_trackings`**, **`trips`**, **`service_runs`**, **`chauffeur_assignments`**, and related **ADR 0002** entities) and to **existing** or **new** **`postgres_changes`** subscriptions — reference **class / module names** appear **only** as traceability keys in **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** (**§ RT.7.1**) and/or this story’s **Dev Technical Guidance**, **not** as user-facing product names.

4. **Driver schedule / run binding:** Deliverable **MUST** state how reference **DriverBusSchedule**-style “chauffeur ↔ scheduled run / task” semantics map to **Vestroo** **`chauffeur_assignments`**, **`service_runs`**, and **`chauffeur_schedules`** (where used), including whether **Realtime** is **required** or **polling / refresh** suffices for a given surface — aligned with **RT.7.5** and matrix **`DriverScheduleModule`** / **`DriverBusScheduleModule`** rows (**no** default mass-transit timetable narrative).

5. **Channels:** Any **new** Realtime topic (table publication, filter, or **`realtime.ts`** builder) **MUST** be listed with **purpose**, **event shape** (insert/update/delete), and **which roles** may subscribe — **extend** **[`docs/realtime-and-notifications.md`](../realtime-and-notifications.md)** *Channels and roles* in the **same** delivery.

6. **RLS:** Tables or views exposed to **anon** / **authenticated** **Realtime** **MUST** have **RLS** policies consistent with **ops vs chauffeur vs customer** visibility; **service role** remains **server-only**; **no** broad **anon** read of tracking or roster fields.

7. **Rate limits and cadence:** Server-side location / run update paths **MUST** respect or extend documented throttles (**[`docs/realtime-and-notifications.md`](../realtime-and-notifications.md)** § *Update intervals and rate limits*; **`vehicle-tracking-throttle`**, **`publishChauffeurLocationAction`**, field publisher interval); any **new** publish path **MUST** document **server cap** + **client interval** + **ops debounce** pattern.

8. **Privacy tiers:** **Staff**, **corporate / future customer**, and **VIP** handling **MUST** align with the **Privacy matrix** in **[`docs/realtime-and-notifications.md`](../realtime-and-notifications.md)** (coordinate rounding, ETA wording, **no** higher precision to a lower tier than policy allows). If **customer** **`vehicle_trackings`** Realtime remains **disabled**, **explicitly** document **why** and what **approved** alternative (e.g. **trips**-only status, rounded ETA elsewhere) applies to **patterned** runs.

9. **Epic 7 / matrix alignment:** **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** **§ RT.7.1** / **§ RT.7.4** / **§ RT.7.5** **MUST** be updated in the **same** change set if shipped behaviour or **honest** deferral changes — keep **BusTracking** / **DriverBusSchedule** rows **traceability-accurate** (**SH.9.6** remains the **full** deferred-mapping story).

10. **Tests / verification:** Automated or **documented** staging checks proving **role-appropriate** subscription results (e.g. chauffeur A does **not** receive chauffeur B’s rows; customer does **not** receive disallowed precision); **reference** **[`docs/staging-and-promotion.md`](../staging-and-promotion.md)** Realtime checklist where applicable.
