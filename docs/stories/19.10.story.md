## Reconciliation (mandatory)

| Issue | Resolution |
|-------|------------|
| **Slide index vs internal step** | **`TripRequestBookingShell`** uses **`funnelStep`**: **0** = trip (**analytics `slide_index` 1**), **1** = vehicle (**2**), **2** = passenger + submit (**3**). **`submitState === 'success'`** + confirmation UI = **`slide_index` 4** (only after successful submit — matches epic). Map consistently in all slide events. |
| **`time_to_submit_ms`** | Measure from a single client anchor when the funnel becomes **interactive** (e.g. **`bootstrap.status === 'ready'`** after valid prefill) to **`submitTripRequest`** resolving **success** — document the anchor in **Progress Notes**. Do **not** include timestamps that recover wall-clock identity beyond coarse performance metrics. |
| **`booking_funnel_submit_error`** | Never send raw **`submitMessage`** or server strings if they may contain PII or ops detail — use a **small closed set** of categories (e.g. `validation_client`, `validation_server`, `network`, `unknown`) derived from **`submitTripRequest`** result shape / HTTP class; redact/fallback to `unknown` when unsure. |
| **`booking_funnel_submit_success`** | **`bookingReference`** from **`result.bookingReference`** (**non-PII** business id) + **`variant`** + **`time_to_submit_ms`** only — **no** passenger or trip address fields. |
| **Feature flag / variant** | Epic examples: `v_legacy_slides` vs `v_booking_slides_v2` — **lock final strings** in **Task 0** with PO. Reuse **env-driven** flags (**`NEXT_PUBLIC_*`** when client must read) with the same truthy convention as **[`src/lib/ops-dispatch-board-nav-env.ts`](../../src/lib/ops-dispatch-board-nav-env.ts)** (`1` \| `true` \| `yes` \| `on`) unless an existing named flag already gates this funnel (survey in **Task 0**). |
| **Analytics transport** | **`package.json`** has **no** PostHog / Segment / GTM dependency today — introduce a **thin** `trackBookingFunnelEvent` (or equivalent) that can noop in dev, log in debug, and forward to the chosen provider **without** leaking PII; **PO approval** before adding a new vendor dependency if required. |

## Story

- As **product / growth**, I need **standardised funnel events** with **variant** and **timing**, so we can measure ROI and run experiments safely.
- As **compliance**, I need **telemetry minimisation** (no email, phone, names, or addresses in analytics payloads), aligned with **POPIA-oriented** practice (**VST-12**).

## Acceptance Criteria (ACs)

1. **`booking_funnel_view`:** Fires when the trip-request funnel is shown in a **measurable** ready state (embedded **`BookingSearchForm`** path and **`/book/trip-request`**), including **`variant`** (string from flag resolution). **No PII** properties.
2. **Optional per-slide (recommended):** **`booking_funnel_slide_view`** when the traveller lands on each **`slide_index`** **1–4** (**4** only after submit success — confirmation). **`booking_funnel_slide_complete`** when **Next** succeeds from slides **1–2** or **Submit** succeeds from slide **3** (slide **4** completion may be omitted or defined as a separate product decision — document in **Progress Notes**). Payloads: **`slide_index`**, **`variant`**, and non-identifying metadata only (e.g. coarse **`embedded`** boolean if agreed — **not** place ids).
3. **`booking_funnel_submit_success`:** On **`submitTripRequest`** success — **`booking_ref`** (or epic-aligned property name **`booking_reference`**) = server booking reference, **`variant`**, **`time_to_submit_ms`**. **No** other trip/passenger fields.
4. **`booking_funnel_submit_error`:** On **`submitTripRequest`** failure — **`variant`**, **`error_category`** (closed enum / redacted), **no** raw error text if it could contain PII.
5. **Feature flag:** Controlled rollout via **documented** env (and **`.env.example`** comment) following existing patterns; default behaviour safe for production (e.g. single production variant until flag flipped).
6. **Tests:** Unit tests for **category mapping** + **payload guards** (assert keys absent: email, phone, name, address fragments); funnel integration tests **mock** the tracker and assert calls on **Next**, **Submit** success/failure; **`npm run test` / `npm run lint`** green.

## Story Progress Notes

- **Variant / flag:** **`NEXT_PUBLIC_BOOKING_FUNNEL_VARIANT`** (default **`v_booking_slides_v2`**); analytics forwarding **`NEXT_PUBLIC_BOOKING_FUNNEL_ANALYTICS_ENABLED`** (`1`/`true`/`yes`/`on`, same convention as **`ops-dispatch-board-nav-env`**). Default **off** — safe for production until explicitly enabled.
- **Transport:** No new npm analytics dependency — **`window.__VESTROO_TRACK_BOOKING_FUNNEL__({ name, properties })`** optional hook when enabled; tests use **`__setBookingFunnelAnalyticsSinkForTests`**. Dev-only console when **`NEXT_PUBLIC_BOOKING_FUNNEL_ANALYTICS_DEBUG=1`**.
- **`time_to_submit_ms` anchor:** **`performance.now()`** stored once when **`bootstrap.status === 'ready'`** (same tick as first **`booking_funnel_view`**); success uses **`Math.round(performance.now() - anchor)`** (falls back to **0** if anchor missing).
- **Slide mapping:** **`funnelStep`** 0/1/2 → **`slide_index`** 1/2/3; **`submitState === 'success'`** → **`slide_index` 4** for **`booking_funnel_slide_view`**. **`booking_funnel_slide_complete`:** slides **1–2** on successful **Next**; slide **3** on successful **Submit**; **no** **`slide_complete` for slide 4** (per epic “may be omitted”).
- **Submit error:** **`bookingFunnelSubmitErrorCategoryFromMessage`** — closed set **`validation_client` | `validation_server` | `network` | `purchase_order` | `unknown`**; never emits raw server strings.
- **PII guard:** **`assertBookingFunnelPayloadHasNoForbiddenKeys`** (non-production) rejects payload keys matching a denylist substring set.
- **19.11:** No edits to **`TripRequestFunnelProgress.tsx`** in this pass — only **`TripRequestBookingShell.tsx`** + new lib + tests.
- **Commands:** `npx vitest run src/lib/__tests__/booking-funnel-analytics.test.ts src/features/booking/components/__tests__/TripRequestBookingShell.funnel-analytics.test.tsx`; `npx vitest run …TripRequestBookingShell.org-inline.test.tsx` (regression). No Supabase migrations.
