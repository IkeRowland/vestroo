## Story

- As an **account customer** receiving the **invoice** communication, I need **bank name, account holder, full account number, branch code**, and a **clear EFT reference** (the **invoice number**), so I can pay by EFT and ops can match the payment — per **Q31** / **US-N5**.

- As **engineering**, I need a **single server-side** path that merges **`ops_settings.bank_account`** with the **invoice-number** reference (not the N4 booking-reference line), passes structured props into the **target** template, and keeps **unmasked** digits out of any **`'use client'`** bundle.

- As **QA**, I need a **unit test** on the **template render** (or **pure HTML builder** under test) proving bank fields and **invoice-number** reference appear from **mocked** `ops_settings`-shaped data.

## Acceptance Criteria (ACs)

1. **Send-path + template survey (blocking):** Before implementation, document which **file(s)** and **action(s)** constitute the “**account invoice email**” in this repo (candidates: **mark invoiced** hook, **invoice due reminder** job, new sender — see **Reconciliation**). The delivered work **must** target the **actual** path(s) responsible for the customer-facing invoice email, not a dead template.
2. **Bank block (HTML):** The customer-visible **HTML** (or comms **fallback HTML**) includes **bank name**, **account holder**, **account number (full, unmasked)**, **branch code** from **`ops_settings.bank_account`**, matching **16.11** / **N1** JSON keys.
3. **Payment reference (invoice number):** The displayed EFT reference uses the **invoice identifier**, defaulting to the string customers use on the bank (epic: e.g. `INV-2026-0042`); **not** the **N4** `reference_format` / `{booking_ref}` line unless product explicitly redefines “invoice number” to match booking ref (unlikely). If **`external_invoice_ref`** (or a future `invoice_number` column) is the source, wire that value into substitution; if **`ops_settings.bank_account.invoice_reference_format`** is **not** added in this story, use **direct** invoice string or a **minimal** `formatPaymentReference` with a **`{invoice_number}`** (or agreed) token for a future field.
4. **Post-N2 CTA / link hygiene:** No **PayFast** checkout, and **no** primary customer CTA to **`/q/.../pay`** (N2) in this email path; **Q33** accept URL is **walk-in**-scoped — **do not** inject **pay** links **unless** a separate product decision ties account invoices to quote tokens (default: **omit**).
5. **Plaintext:** If the send pipeline supports **`text/plain`**, include the same **bank + reference** facts in readable form; if **HTML-only**, document the gap and align with the **16.15** follow-up pattern.
6. **Server-side only:** Bank JSON is merged **only** in **server** modules (e.g. **`'use server'`** actions, service-role helpers), **not** in public routes or **client** components.
7. **Error handling — configurable:** If bank settings are **missing/incomplete**, align failure semantics with **16.15** (hard-fail vs ops-visible warning) as appropriate for **invoice** comms; **record** the decision in **Progress Notes**.
8. **Tests:** Add or extend tests (e.g. under **`src/lib/email/templates/__tests__/`** or a **new** colocated `__tests__` for the **extracted** bank helper) to assert **rendered** output includes mocked bank fields and **invoice-number** reference, and that **no** masked `***` **account_number** from **`getBankAccountForReader`** is used in the **customer** HTML fixture.

## Story Progress Notes

### Send-path survey (AC1)

- **Primary customer-facing “invoice” email path in-repo:** **`runInvoiceDueReminderJob`** (`src/lib/invoice-due-reminder-job.ts`) → **`sendCommsMatrixEmailDispatches`** with **`eventKey: 'invoice_due_reminder'`** (cron: `src/app/api/cron/daily-maintenance/route.ts`). This is the **account_client** + **`customer_account_id`** scheduled reminder for bookings in **`ready_to_invoice`** / **`invoiced`** with a derived due date — it is the real matrix-backed HTML path that repeatedly reaches account customers for invoice workflow.
- **`markInvoicedAction`** (`src/actions/opsInvoicingHooks.ts`) transitions **`ready_to_invoice` → `invoiced`** and persists **`external_invoice_ref`** but **does not send email**. Documented for PO: if product wants an **immediate** “invoice issued” email at mark-invoiced time, that would be a **new** comms event + sender (out of this story’s implemented path).

### Implementation summary

- **DRY:** Added **`src/lib/email/ops-bank-account-settings.ts`** — **`loadOpsBankAccount`**, **`formatPaymentReference`**, **`resolveAccountInvoiceEftReference`**. **`src/lib/email/walk-in-quote-bank-context.ts`** now delegates to **`loadOpsBankAccount`**; **`formatBankReference`** uses **`formatPaymentReference`** (N4 call sites unchanged).
- **Invoice EFT HTML fragment:** **`src/lib/email/account-invoice-eft-html.ts`** — **`renderAccountInvoiceEftAppendHtml`** (full unmasked account number; not **`getBankAccountForReader`**).
- **Matrix dispatch:** **`src/lib/comms/dispatch-email.ts`** — optional **`appendBeforeComplianceFooterHtml`** merged after template/fallback substitution, **before** compliance footer (16.16 EFT block).
- **Wiring:** **`invoice-due-reminder-job`** loads bank once per run (lazy on first successful send candidate), **`break invoiceReminderOuter`** on **`loadOpsBankAccount`** failure (**hard-fail** for that cron run — aligns with 16.15 philosophy). Appends EFT block + passes **`templateVariableMap.invoice_number`** (resolved reference string). Fallback HTML includes **`{{invoice_number}}`** for substitution when DB template body is empty.

### Reference source & empty handling (AC3)

- **Source:** **`bookings.external_invoice_ref`** when non-empty (staff **Mark invoiced**), else **fail-soft** fallback to trimmed **`bookings.payment_reference`**, else display **`—`** in reference fields.
- **Optional JSON (no migration):** If **`ops_settings.bank_account.invoice_reference_format`** is present, **`formatPaymentReference`** substitutes **`{invoice_number}`** and **`{booking_ref}`** (human **`bookingRefLabel`** used for **`booking_ref`**). If absent, the **direct** resolved string is used.

### Plaintext (AC5)

- **`sendEmail`** (`src/lib/email/send.ts`) remains **HTML-only** — same **16.15** pipeline gap; no **`text`** part for matrix dispatch. **`buildWalkInQuotePlaintext`** pattern remains the precedent; invoice reminder has no separate plaintext builder in this story.

### Bank failure semantics (AC7)

- **Misconfigured / incomplete bank:** First **`loadOpsBankAccount`** failure aborts **all** further invoice-due reminder sends in that job run (`errors += 1`, labeled **`break`**). Matches **hard-fail** intent for EFT customer comms when ops settings are unusable.

### CTA / N2 (AC4)

- No PayFast, no **`/q/.../pay`** added; invoice reminder path unchanged for pay links.
