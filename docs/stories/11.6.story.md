## Story

- As **ops staff**
- I need **Fleet CRUD** for vehicles used in booking and assignment (**create**, **edit**, **archive** per business rules) with **clear validation**
- so that the **live catalogue** and dispatch tooling reflect the actual fleet — **US-F1**

- As **ops staff**
- I need to **assign drivers** (profiles with the chauffeur/driver role or the project’s existing assignment model) to **trips/bookings** per existing domain rules
- so that assignments are **visible** on ops trip/booking views and **conflicts** (double-booking, overlapping time windows) are **handled or surfaced** — **US-F2**

- As a **customer** using the trip-request funnel
- I need **“Choose your ride”** to show options from the **real** **`vehicles`** / catalogue data (not placeholder inventory)
- so that my selection flows through to **quote/checkout** within the existing **`TripRequestBookingShell`** and booking pipeline — **US-F3**

## Acceptance Criteria (ACs)

### US-F1 — Fleet CRUD; validation; RLS for fleet tables (Theme F)

1. **CRUD surface:** Staff **MUST** be able to **create**, **update**, and **archive** (or equivalent lifecycle) **fleet rows** used by booking/assignment — **[`docs/epic-11.md`](../epic-11.md)** Theme F (**US-F1**). Exact UX (dedicated form vs modal) is agreed in **Tasks**; normative data targets **MUST** align with verified schema usage: **`public.vehicles`**, **`public.vehicle_categories`**, **`public.vehicle_pricings`** (see **`supabase/migrations/20260402131358_vin_shuttle_vehicles_and_pricing.sql`** and follow-on migrations; **verify** column sets in **`src/app/(ops)/ops/vehicles/page.tsx`** and types before shipping).

2. **Business rules:** Create/edit/archive rules **MUST** match **documented** business rules (required fields, allowed transitions, referential constraints); validation errors **MUST** be **clear** and **field-level** where appropriate — **US-F1** AC.

3. **RLS for mutations:** Row Level Security **MUST** allow **only** **authorized** roles to **mutate** fleet-related tables (`vehicles`, `vehicle_categories`, `vehicle_pricings` as applicable). Unauthorized roles **MUST** fail safely (no silent bypass). Updates **MUST** ship via **`supabase/migrations/`** and **`supabase/smoke_rls.sql`** (or intentional script updates with PR rationale) per **11.1** norms — **US-F1** AC.

4. **Theme B on ops fleet UI:** The **`/ops/vehicles`** (and any new fleet sub-routes) **MUST** use **`OpsFetchErrorIsland`**, **`OpsDataFreshnessBar`**, and loading patterns consistent with **[`docs/stories/11.2.story.md`](11.2.story.md)** — **US-F1** / Theme B alignment (see existing usage in **`src/app/(ops)/ops/vehicles/page.tsx`**).

### US-F2 — Assign drivers; visibility; conflicts (Theme F)

5. **Assignment actions:** Staff **MUST** be able to assign a **driver/chauffeur** to **bookings/trips** through **existing or extended** server actions (e.g. **`assignBookingToRun`** / related paths in **`src/actions/opsDispatch.ts`**) and UI surfaces such as **`src/features/ops/components/AssignBookingPanel.tsx`** on **`src/app/(ops)/ops/fulfil/page.tsx`** and trip tooling on **`src/app/(ops)/ops/trips/page.tsx`** with **`src/features/ops/components/TripOpsForms.tsx`** — **US-F2** AC (exact wiring per **Tasks** after schema/domain check).

6. **Visibility:** After assignment, the **assigned driver** (or profile link) **MUST** be **visible** on the **ops trip and/or booking views** staff use for dispatch (list rows, detail panels, or agreed drill-down) — **US-F2** AC.

7. **Conflicts:** Overlapping assignments for the **same driver** or **same vehicle** in the **same time window** **MUST** be **prevented** where the data model allows a definitive check, **or** **surfaced** with an actionable message (correlation id per **11.2** where applicable). Reuse or extend **`findVehicleWindowConflicts`** from **`src/lib/ops-time-windows.ts`** (already used in **`src/actions/opsDispatch.ts`** and **`src/app/(ops)/ops/vehicles/page.tsx`**) where trip windows are involved — **US-F2** AC.

8. **Logging:** Assignment mutations **MUST** emit **structured** logs per [`docs/ops-server-action-logging.md`](../ops-server-action-logging.md) (action name, outcome, safe ids) — **US-F2** / Theme B reinforcement.

### US-F3 — Public “Choose your ride”; real data; pipeline (Theme F)

9. **Real catalogue:** The trip-request **vehicle slide** (**`src/features/booking/components/trip-request/TripRequestVehicleSlide.tsx`**) **MUST** present options derived from **real** **`vehicles`** / catalogue data (via **`getTripRequestVehicleOffers`** in **`src/actions/getTripRequestVehicleOffers.ts`**, **`fetchActiveVehicleTypes`** in **`src/lib/pricing-data.ts`**, or a **documented** join/replace agreed in **Tasks**) — **US-F3** AC. **MUST NOT** ship static demo inventory as production data unless **explicitly** labeled **fixture** and **non-prod-only** — **US-F3** AC.

10. **End-to-end selection:** Selected **`TripOfferVehicle`** (**`src/features/booking/components/trip-request/trip-offer-vehicle.ts`**) **MUST** flow through **`src/features/booking/components/TripRequestBookingShell.tsx`** into **quote/checkout** without breaking existing **`TripRequestBookingShell`** constraints — **US-F3** AC.

11. **Freshness / errors (public):** Loading and failure states for vehicle offers **MUST** be **user-visible** (no infinite spinners without feedback); errors **MUST NOT** leak secrets — align with project booking UX norms — **US-F3** AC.

### Cross-cutting

12. **Schema verification:** Before implementation lock, **MUST** confirm **actual** Supabase table/column usage for fleet and offers (grep **`supabase/migrations/`**, **`src/lib/pricing-data.ts`**, booking actions) so **US-F3** does not assume columns that only exist on **`vehicle_pricings`** vs **`vehicles`**.

13. **Data freshness matrix:** Update **[`docs/ops-data-freshness.md`](../ops-data-freshness.md)** for **`/ops/vehicles`** (and any new fleet routes) if the **realtime / refresh** story changes; public trip-request row **may** be updated if offer loading strategy changes materially — **cross-cutting** documentation.
