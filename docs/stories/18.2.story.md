## Story

- As **an organisation admin or booker**, I need a **persistent sidebar and top bar** on the account portal, so navigation and key actions feel like a cohesive product (similar to ops console ergonomics).

- As **the product**, we need **account chrome** that respects **`data-account-theme`** and **does not change** **who can see what data** (**NFR.18.1**), so the redesign stays **presentation-only** on existing routes.

## Acceptance Criteria (ACs)

1. **`AccountShell`:** New client component (e.g. under **`src/features/account/components/`**) composes **sidebar + main column + top bar**, analogous to **`OpsShellClient`**: **`md+`** **collapsible** sidebar width using **`w-account-sidebar` / `w-account-sidebar-collapsed`** (from **18.1**); **`< md`** sidebar in **drawer** with **backdrop**, **`Escape`** closes, **Tab** cycles focus **inside** drawer (**focus trap**), **focus restored** to trigger on close (same semantics as **`OpsShellClient`**).
2. **`AccountSidebar`:** Light **`account.*`** tokens only; **grouped** navigation with labels **Activity**, **Billing**, **Organisation**, **Help**; items per **FE.18.2**: **Dashboard** → **`/account`**, **Bookings** → **`/account/bookings`**, **Trips** → resolution per **Reconciliation**, **Invoices** → **`/account/invoices`** (hidden if not admin-capable), **Members** → **`/account/members`** (hidden if not admin-capable), **Preferences** → **`/account/preferences`**, **Help** → **`/account/help`**; **Profile** link lives in **top bar menu**, not necessarily duplicated in sidebar (epic: profile via **dropdown** — **Task 0** may add sidebar entry if product prefers). **Active** route styling uses **account** tokens (e.g. rail or **`bg-account-surface-hover`** pattern — document in **§ 18.2**).
3. **`AccountTopBar`:** **`bg-account-topbar`** (or equivalent), **border** **`account-border`**; **search** placeholder exact: **`Search bookings, invoices…`** (ellipsis **…**); **notifications** bell with **accessible name** including **count** when **`> 0`** (pattern aligned with **`OpsTopBar`** / **17.2**); **profile chip** shows **avatar** (image or initials), **display name**, **role** label; **`DropdownMenu`**: **Profile** → **`/account/profile`**, **Switch organisation** (only when **`multi_account`** — embed **`AccountSwitcher`** or submenu), **Sign out** (existing sign-out flow — **Task 0** finds **`logout`** / **`signOut`** pattern used elsewhere in account portal).
4. **Layout integration:** **`src/app/(account)/account/(portal)/layout.tsx`** wraps authenticated portal content with **`AccountShell`** (pass **session** props needed for chip, switcher, nav visibility, notification count). **Retain** **`data-account-theme="light"`** on outer portal wrapper per **18.1**; **skip link** + **`#account-main`** **main** landmark preserved or improved (**WCAG**).
5. **No shell on auth surfaces:** **`/account/login`**, **`/account/invite/*`**, **`/account/unauthorized`** (if present) remain **outside** this layout tree — **no** regression (**FE.18.10**).
6. **Theme isolation (**NFR.18.4**):** No **`data-account-theme`** or account shell components mounted on **`/ops/*`** or marketing/booking layouts.
7. **Server-first (**NFR.18.3**):** **`layout.tsx`** stays a **Server Component** by default; only **shell / sidebar / top bar / drawer** client boundaries marked **`'use client'`** where interaction requires it.
8. **Authz (**NFR.18.1**):** No changes to **`requireAccountMemberPage`**, RLS, or role checks beyond **hiding** links that already match server-side gates; page data on **`/account/invoices`** etc. unchanged.
9. **Accessibility (**NFR.18.5**):** Focus order logical; **drawer** and **menus** keyboard-operable; **visible focus rings** using **`ring-account`** (or tokenised **`focus-visible`**); **landmark** roles (**`nav`**, **`main`**, optional **`banner`**) documented in **§ 18.2**.
10. **Copy discipline:** New user-visible strings for shell surfaces live in **`src/features/account/copy/`** (e.g. **`account-sidebar-copy.ts`**, **`account-top-bar-copy.ts`**, or one **`account-shell-copy.ts`** export object) — **single export per surface**; epic **no new translation system** — pattern only.
11. **Tests:** **Vitest** + **`@testing-library/react`** (as repo uses): **`AccountShell`** / **`AccountSidebar`** / **`AccountTopBar`** focused tests — e.g. **group headings**, **Escape** closes mobile drawer (where mockable), **profile menu** labels, **placeholder** text; extend if **`/account/search`** stub added.
12. **Documentation:** **`docs/ops-design-system-parity.md`** — new **§ 18.2** describing **`AccountShell`**, **`AccountSidebar`**, **`AccountTopBar`**, mobile drawer a11y, dependency note if new **`@radix-ui/*`** packages added (**NFR.18.2**); state that **full § 18** index is **Story 18.13**.
13. **Quality:** **`npm run lint`** and **`npm run test`** remain green.
