# Story 6.3: Nest REST → Server Actions / Route Handlers mapping

## Status: Done

**Dependencies:** **[Story 6.1](6.1.story.md)** — **Done** — **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** (**FE.5.10** / **BE.6.1**) lists all **24** domain **`app.module`** modules with **status**, **Supabase**, and high-level **Server Actions / Route Handlers** examples; **BE.6.3** adds **HTTP-level** traceability from **reference Nest controllers** to **Vestroo** surfaces **without** replacing the matrix. **[Story 6.2](6.2.story.md)** — **Done** — **migration** + **RLS** depth in the **same** matrix; **6.3** does **not** add migration cites or a second capability matrix. **[`docs/epic-6.md`](../epic-6.md)** — **BE.6.3** (authoritative epic text). **[`docs/epic-9.md`](../epic-9.md)** — **SH.9.1** / **SH.9.6** — **Bus**\* / **Ticket** / **DriverBusSchedule** and related reference-only domains MUST appear as **deferred** / **N/A** with an **Epic 9** pointer in the mapping tables, consistent with the matrix. **[`docs/front-end-api-interaction.md`](../front-end-api-interaction.md)** — canonical **Vestroo pattern** for **Server Actions**, **Route Handlers**, and **Decision: new Server Action vs new route.ts**; the **BE.6.3** artifact MUST **link back** here and MUST **not** duplicate the full action/route reference tables.

**Relationship to BE.6.1 / BE.6.2 / FE.5.9:** **BE.6.3** is a **dedicated** “**Nest `@Controller` → Vestroo entry point**” living artifact. The **[module matrix](../capstone-backend-module-matrix.md)** remains the **single** **domain ↔ capability** table; **6.3** answers “**which Nest route prefix became which Server Action / `route.ts` / deferred?**” **[`docs/capstone-reference-stack-integration.md`](../capstone-reference-stack-integration.md)** (**FE.5.9**) documents **axios / JWT-in-browser** anti-patterns vs Vestroo; **6.3** MUST **cross-link** it in **rationale** or **Related** so engineers see **both** integration posture and **per-controller** mapping.

**Explicit out of scope:** **CORE.6.4** end-to-end **search → quote → booking → checkout** flow deep-dive (separate epic story); **BE.6.5** full **Auth / Keytoken / OTP** reference-vs-Vestroo artifact (**6.3** may include **one** matrix row or footnote pointing to **BE.6.5**, not the full doc); **BE.6.6** **OpenAPI** / Swagger parity; **implementing** new **Server Actions** or **Route Handlers** except a **minimal** doc-only cross-link fix if a broken relative path is discovered during link check.

**Constraining NFRs:**

- **NFR.3.1:** **RLS** and **server-only secrets** are **authoritative**; the mapping and rationale MUST **not** imply **client-trusted** auth for **data access** (e.g. no suggestion that first-party UI should call **internal REST** with **bearer tokens in the browser** as the default).
- **NFR.4.1:** This story is **documentation-first**; **TypeScript** server code is **reference-only** when citing existing **`src/actions/*.ts`** and **`src/app/api/**/route.ts`** paths.

## Story

- As the **engineering team** maintaining **reference → Vestroo** parity documentation
- I want a **single, discoverable** document that maps **each reference Nest controller (or aligned route group)** to **Server Action** (default for trusted App Router UI), **Route Handler** (webhooks, third-party callbacks, non-Next callers), or **deferred** / **N/A**, with **explicit rationale** for **not** defaulting to **axios-style REST** from **first-party** UI
- So that **secrets**, **service role**, and **Supabase client** usage stay aligned with **[`docs/environment-vars.md`](../environment-vars.md)** and **server-only** discipline while **Epic 6** traceability stays obvious next to the **module matrix**

## Acceptance Criteria (ACs)

1. **New canonical artifact (no duplicate pattern encyclopedia):** Add **`docs/capstone-nest-rest-to-vestroo-mapping.md`** (this filename is the **required** path unless **Deviation Analysis** in **Progress Notes** records an agreed rename). The doc MUST begin with a short **scope** statement: **Vestroo interaction patterns** (when to use Server Actions vs Route Handlers) remain in **[`docs/front-end-api-interaction.md`](../front-end-api-interaction.md)** — this file is the **Nest controller / route-prefix → Vestroo surface** map. Include **grouped or single master table(s)** covering **every** reference domain aligned to **`docs/capstone-reference/backend/src/app.module.ts`** modules (**same spirit as** **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** — **24** domain rows). Each table row MUST include at minimum: **reference surface** (controller path under **`docs/capstone-reference/backend/src/modules/*/*.controller.ts`** and/or **`@Controller('prefix')`** derived from source), **Nest route group / domain module name**, **Vestroo pattern** (**Server Action** | **Route Handler** | **deferred** | **N/A**), **Vestroo surface** (concrete **`src/actions/<file>.ts`** action names and/or **`src/app/api/.../route.ts`** paths, or **`deferred`** / **`N/A`** with reason), **notes** (e.g. **CORE.6.4** pointer for booking flow detail, **BE.6.5** pointer for auth/token depth). **Bus**\* / **Ticket** / **DriverBusSchedule** (and other **Epic 9** deferred domains) MUST be **deferred** or **N/A** with a pointer to **[`docs/epic-9.md`](../epic-9.md)** — not described as mandatory Vestroo HTTP ports. **Inventory rule:** **`grep` / list** all **`docs/capstone-reference/backend/src/modules/**/*.controller.ts`** (~**23** files today); any **`app.module`** domain **without** a dedicated `*.controller.ts` (e.g. **`KeytokenModule`**) MUST still appear as **≥1** row (module-level **REST surface** / **service-only** / **N/A**) so **no** epic-listed module is silent.

2. **Explicit rationale subsection:** The artifact MUST include a titled subsection (e.g. **Why first-party UI does not default to axios → internal Nest-style REST**) explaining that **App Router** **first-party** callers should use **Server Actions** + **Supabase** server clients (**`src/lib/supabase/server.ts`**, **`createServiceRoleClient`** / **`createUserServerClient`** per task) so that **secrets** stay **server-only**, **RLS** remains enforced for user-scoped paths, and **typed** **Zod**-validated mutations stay **colocated** with UI — versus **browser** **axios** to an **internal** REST API, which tends to imply **token-in-client**, **wider** attack surface, and **duplicated** authz logic. MUST **cross-link** **[`docs/capstone-reference-stack-integration.md`](../capstone-reference-stack-integration.md)** (**FE.5.9**) for **axios / JWT anti-patterns**.

3. **Secrets and service role subsection:** The artifact MUST include a titled subsection that **does not** restate the full env catalog but **points** to **[`docs/environment-vars.md`](../environment-vars.md)** for **service role**, **`NEXT_PUBLIC_*`** rules, **PayFast**, **Google** keys, etc., and states **`server-only`** discipline: **no** secret material in **`NEXT_PUBLIC_`** vars; **service role** only inside **server** bundles (Server Actions, Route Handlers, server components). Align **when** **`createServiceRoleClient`** vs **user JWT** / **RLS-scoped** clients apply with **[`docs/front-end-api-interaction.md`](../front-end-api-interaction.md)** and, for **ops/field** gates, **[`docs/ops-console.md`](../ops-console.md)** (and **[`docs/field-tools.md`](../field-tools.md)** if chauffeur paths are mapped).

4. **`docs/index.md` Epics bullet:** **[`docs/index.md`](../index.md)** MUST gain a bullet under **Epics** (or the same **Documentation Index** subsection used for Epic 6 links) that links **`docs/capstone-nest-rest-to-vestroo-mapping.md`** and names **BE.6.3** / **Story 6.3** in the description (pattern consistent with neighbouring bullets, e.g. *Capstone Nest REST → Vestroo mapping (BE.6.3)* — controller/route-prefix → Server Actions / Route Handlers; links **front-end-api-interaction**).

5. **Matrix cross-link (one sentence, no second matrix):** **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** MUST be updated with **exactly one** sentence + link in the **intro** blurb or **Related** / **integration** area pointing to **`capstone-nest-rest-to-vestroo-mapping.md`** as the **BE.6.3** **Nest REST → Vestroo** mapping — **without** adding a second domain capability table.

6. **Phased delivery:** The artifact MAY ship in **phases** (e.g. **P1** — booking, checkout, pricing, search, trip, auth-adjacent; **P2** — remainder) if **each** phase’s table rows are **complete** for the controllers in scope and **backlog** rows are explicitly marked **deferred** with owner (**CORE.6.4**, **BE.6.5**, **Epic 9**, etc.). **Merge** criteria: **AC4** and **AC5** apply to the **final** merge that completes the story (or each phase updates index/matrix if product wants incremental discoverability — record choice in **Progress Notes**).
