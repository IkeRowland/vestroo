## Story

- As **an org admin or booker**, I want the **`/account`** dashboard to show **at-a-glance** KPIs, **my next trips**, and (when permitted) **invoice activity**, so I immediately see value without digging through pages.

- As **Vestroo**, we need the dashboard to use **shared SaaS primitives** (**`KpiCard`**, **`StatusPill`**, **`EmptyState`**, **`LoadingRegion`**) under **`theme="account"`**, so **ops** and **account** stay visually related without **theme leakage** (**NFR.18.4**).

## Acceptance Criteria (ACs)

1. **Welcome strip:** Renders **org name**, **role** pill, **signed-in email**, and **muted** **"Last sign-in: …"** per **Reconciliation**; removes legacy **plain quick-link** grid as the primary above-the-fold navigation (**scorecards** replace that affordance).
2. **Scorecards grid:** Responsive **2-up `sm`**, **4-up `lg`**; each deep-links to the URLs in **Story provenance** (trips this month, upcoming trips, open invoices, active members).
3. **`KpiCard` usage:** Each scorecard uses **`KpiCard`** with **`theme="account"`** (alias **`AccountKpiCard`** wrapper is optional if it improves readability) — **no sparklines** on these four cards.
4. **Loading:** While server sections resolve, KPI and rail regions show skeletons consistent with **`LoadingRegion`** / **`OpsLoadingRegion`** semantics (**Story 18.3**).
5. **Authorisation:** **Open invoices**, **Active members** scorecards and **Recent invoices** block are **absent** (not zero-masked) for **bookers**; no numeric or label leakage from admin-only APIs (**NFR.18.1**).
6. **Upcoming trips rail:** Mobile **horizontal scroll**; from **`md`**, **2-column** grid; cards show route **pickup → drop-off**, **date/time**, vehicle class **image or silhouette**, **`StatusPill`**, **View details** CTA; statuses cover at least **Pending quote**, **Confirmed**, **Driver assigned** (map from existing domain enums — adjust labels in **`account-dashboard-copy.ts`** only if needed).
7. **Empty rail:** Uses shared **`EmptyState`** (`theme="account"`) with illustration + **Book your next trip** → **`/book/search`**.
8. **Recent invoices (admin):** Exactly **5** rows (or fewer if fewer exist), columns **Reference**, **Date**, **Amount**, **Status** pill, **Download** / **Pay** actions wired to **existing** invoice behaviours; **View all →** to **`/account/invoices`**.
9. **Server-first:** Dashboard **`page.tsx`** remains **server-component–oriented**; data fetched on server; **no** new chart libraries (**NFR.18.2**).
10. **Performance:** On **cached** repeat load (document test method), dashboard **server HTML** path targets epic **&lt;200ms**; note relation to **NFR.18.6** in **Progress Notes** if metrics differ by environment.
11. **Accessibility:** Headings hierarchy, **keyboard** scroll for horizontal rail where applicable, **focus-visible** on CTAs, sufficient contrast on muted last-sign-in line (**NFR.18.5**).
12. **Copy:** All user-visible dashboard strings live in **`src/features/account/copy/account-dashboard-copy.ts`** (new), imported by **`AccountDashboard`** (and small presentational children if split).
13. **Tests:** **Vitest** for **role-gated** sections (e.g. booker vs admin snapshots or logic tests) and any **non-trivial** URL / formatter helpers; **`npm run test`** green.
14. **Lint:** **`npm run lint`** green; no broad **`eslint-disable`**.
15. **Documentation:** **`docs/ops-design-system-parity.md`** — new **`§ 18.4`** (**Story 18.4 / FE.18.3**): section diagram, primitive references, Wheelzie **#10**/**#6** QA note; states **Story 18.13** completes full § **18**.
16. **Epic alignment:** PR description cites **FE.18.3** and **Story 18.4**; **does not** claim **FE.18.4** / **Story 18.5** scope.
