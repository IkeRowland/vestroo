## Story

- As **account workflow ops staff**, I need **`/ops/accounts`** to show **only** **`account_client`** bookings with **stage tabs**, **live debounced counts**, and **the right primary action per stage**, so I do not mentally filter walk-in rows or use the wrong walk-in CTA set.

- As **ops staff**, I need **per-row guardrail context** from **`can_dispatch_account_booking()`** when dispatch is not **`ok`**, so credit / contract / PO issues are visible before I waste time on **Assign** / **Confirm dispatch**.

- As **ops staff**, I need the same **header / freshness / error** + **Realtime** patterns as **`/ops/walk-in`** and **`/ops/bookings`**, and **mobile** **`<select>`** for stages below **768px**, so the account queue feels consistent and usable on a phone in the yard.

## Acceptance Criteria (ACs)

1. **Account filter:** **`/ops/accounts`** loads a server-rendered queue where every listed **`bookings`** row satisfies **`client_type = 'account_client'`** (no walk-in rows).
2. **Stage tabs + counts:** Tabs: **New**, **Triaged**, **Availability checked**, **Assigned**, **In progress**, **Completed**, **Invoiced**, **Paid**. Each tab shows a **count** of matching rows. Counts **update** after **Realtime `bookings` INSERT/UPDATE** using **debounced refresh** per **Epic 11 E2** — reuse **`OpsBookingsRealtimeBridge`** ( **~2s** debounce, **`OpsErrorState`** on subscription fault) matching **`/ops/walk-in`** / **`/ops/bookings`**.
3. **CTAs per stage (account):**
   - **New** → **Triage** (reuse the same **account** / **shared** triage path used for account rows on **`/ops/bookings`**, or introduce account-specific triage if already separated — **Task 0**).
   - **Triaged** → **Check availability** — navigates to **`/ops/accounts/[bookingId]/availability`** **only if** that route **200**; else **disabled** + **tooltip** per **Reconciliation** (no **404** primary path).
   - **Availability checked** → **Assign trip** — reuses **fulfil / assign** navigation (**e.g.** **`opsFulfilAssignBookingHref`** or account-specific href — **Task 0**); if **B3** **`availability_check_required`** applies on server, surface errors per **Reconciliation**.
   - **Assigned** → **Confirm dispatch** — triggers / completes the **Epic 13** trip **confirmation** email path (**Task 0** action name); respect **`can_dispatch_account_booking`** (disable + chip when not dispatchable).
   - **In progress** → **view only** (no primary mutation CTA; secondary links allowed).
   - **Completed** → **Hand off to invoicing** — drives **`ready_to_invoice`** (or equivalent) per Epic 13 / **`opsInvoicing`** — **Task 0** for exact action.
   - **Invoiced** → **Mark EFT received** — **`MarkPaymentReceivedDialog`** → **`markBookingPaymentReceived`** with **Q32** / **[`16.14`](./16.14.story.md)** fields.
   - **Paid** → **terminal** (view-only; no **Mark EFT** CTA).
4. **Dispatch / credit chip:** For **account** rows where **`can_dispatch_account_booking` ≠ ok** (or equivalent loader flag), show a **per-row chip** (badges) with **reason code**; **tooltip** or inline detail uses **reason-code copy** + structured fields (**credit limits**, **dates**, **counts**) consistent with existing **`reason-code-copy.ts`**. When **ok**, no blocking chip.
5. **Shell components:** **`OpsPageHeader`**, **`OpsDataFreshnessBar`** ( **`fetchedAtIso`** from loader ), and **`OpsErrorState`** (or **`OpsFetchErrorIsland`**) for failed initial load + Realtime subscription faults — same family as **16.20**.
6. **Mobile:** Below **768px** width, stage **tabs** collapse to a **`<select>`** (or Radix **Select**) controlling the same **`stage`** URL state as desktop tabs (parity with **US-A1**).
7. **Quality gates:** **`npm run lint`** and **`npm run test`** remain green.
