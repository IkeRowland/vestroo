## Story

- As **Vestroo**, I need a **real, env-configured SMS layer** (replacing **`src/services/sms-stub.ts`**) with **transactional** sends, **retries/idempotency** appropriate for outages, and a **clear global toggle**, so that **riders** can receive **operational** SMS (including a **short tracking link** when a trip goes **`en_route`** and **`rider_phone`** is set) without blocking or rolling back **trip** state on send failure.

## Acceptance Criteria (ACs)

1. **Service module — replace stub:** Add **`src/services/sms.ts`** (or small **`src/services/sms/`** package with a single public entry) that **replaces** **`src/services/sms-stub.ts`** as the import path for app code. **Deprecate or remove** the stub file once call sites are migrated (no duplicate public APIs for the same behaviour). Existing stub contract reference: **`notifyBookingCreatedSmsStub`** in **`src/actions/createBooking`**, **`src/actions/processPayment`** — tests mock **`@/services/sms`** in **`createBooking.test.ts`**, **`createBooking-po-required.test.ts`**, **`processPayment.test.ts`**.

2. **Single transactional API — not 15C:** Export **one** primary function (e.g. **`sendTransactionalSms`**) with a **small, explicit input type** (at minimum: E.164 or validated destination, **body text**, optional **idempotency key**). **Do not** implement **15C** matrix tables, per-event template rows, or ops-editable rules in this story. Internal provider adapters may live in sibling files (e.g. `twilio.ts`, `messagebird.ts`) as long as the app imports **one** facade.

3. **Provider selection — env-based:** Support **at least one** real provider in code (e.g. **Twilio** or **MessageBird**) with configuration via **env vars**; document an **SA-focused** or regional provider as **TBD** in **Progress Notes** and **`.env.example`** (placeholders, not secrets). Today’s commented placeholders: **`SMS_PROVIDER_API_KEY`**, **`SMS_PROVIDER_FROM_NUMBER`** (extend/rename as needed; document the final names).

4. **Global enable / safe defaults:** If **`SMS_ENABLED`** (or an existing/aligned flag) is **false** or unset, **no live HTTP** to a provider; behaviour must be **explicit** (e.g. structured log or metric: `sms_skipped`) — analogous in spirit to Resend test-key skip in **`src/lib/email/send.ts`**. **AC:** document the flag in **`.env.example`** and **Progress Notes**.

5. **US-C1 `en_route` SMS (default path (a)):** When a trip transitions to **`en_route`**, if **`bookings.rider_phone`** (or the agreed normalised column from **15B.1**) is set, **send** an SMS with a **short** absolute URL to **`/track/[token]`** using the same HMAC pattern as **15B.2** ( **`src/lib/tracking-tokens.ts`**, `purpose: 'rider_track'`, `exp` per **Q21** / prior stories). **Preferred hook site:** after successful status update in **`src/actions/fieldChauffeur.ts`** in **`updateChauffeurTripStatusAction`** when **`nextStatus === 'en_route'`** (chauffeur `assigned → en_route` is the first transition to `en_route` in **`src/lib/chauffeur-trip-transitions.ts`** / ops vocabulary). **Failure** of the SMS call **must not** roll back the **trip** row update, **revalidate**, or **audit** success (epic **§6**). **Idempotency:** if the same transition could be retried by a client, use an **idempotency key** (e.g. `en_route_sms:{tripId}`) so duplicate SMS is **unlikely** within provider retention windows.
   - **Fallback (b) — if (a) is time-boxed:** In **Progress Notes** and this story’s **Tasks**, record **“provider + stub callers upgraded only”** and add a **follow-up story id** (e.g. *15.9.x / epic note*) for **`en_route`** wiring; **not** the default.

6. **Outage & retry — time-boxed:** Implement **retry** in the same **spirit** as Epic **13** email (e.g. bounded **2–3** attempts with backoff; **idempotency** key to reduce double-send). **AC:** If all attempts fail, **log** a non-fatal error with **correlation** (trip id, not raw phone in plain text in shared logs if avoidable) and **do not** throw past the **Server Action** boundary in a way that would undo the trip. **Outbox/queue** is **optional** for this story — if deferred, state so in **Tasks** and **Progress Notes**; prefer **minimal retry + idempotency** over full queue in **15B.4** scope.

7. **POPIA / data minimisation (minimal):** Transactional SMS only; no marketing copy; include only what is **necessary** for the message (e.g. short link + minimal context). **Do not** log **full** message body with **PII** at **info** level; avoid logging full phone numbers in production (mask or hash where logs are aggregated).

8. **Observability:** **Structured** logging and/or **metrics** hooks: send success, send failure, skipped (disabled), retry count. Align prefix/style with email **`[vestroo:...]`** pattern if practical.

9. **Cost & cap (documentation):** In **Tasks** (or **Progress Notes** for the PO), document **where** the team will record **per-message cost**, **monthly cap**, and **how** to disable SMS via **`SMS_ENABLED`** (or comms channel flag when **15C** exists) — per epic **§6** *SMS costs*.

10. **Tests:** Update mocks from **`@/services/sms-stub`** to the **new** module; add **unit** tests for the SMS facade: disabled flag → no provider call; idempotency key pass-through; optional provider adapter tests with **mocked** HTTP. **Grep** maintenance: ensure **`createBooking` / `processPayment`** tests stay green.

11. **Configuration docs:** **`.env.example`** lists all **SMS_** / provider vars. **Progress Notes** document **which** provider was **implemented first**, **TBD** SA alternates, and any **regional** number/sender requirements.

12. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15B.4`**, **§5** SMS first-time integration, **US-C1** (rider phone + `en_route`); **not** **15C** matrix implementation.
