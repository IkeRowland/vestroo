# Story 5.3: Component patterns for CRUD and data-heavy ops views

## Status: Done

**Dependencies:** **[Story 5.1](5.1.story.md)** — **Done** (`OpsShellClient`, `OpsSidebar`, `OpsTopBar`, `ops-nav-config`, shell landmarks). **[Story 5.2](5.2.story.md)** — **Done** (ADR **`docs/adr/0001-ops-field-ui-stack-tailwind-radix.md`**, parity **`docs/ops-design-system-parity.md`**, ops tokens, primitives: **`OpsPageHeader`**, **`OpsFilterRow`**, **`OpsTableShell`**, **`OpsActionGroup`**, **`ops-primitives.ts`**, layout tokens + **`ops-layout-tokens.test.ts`**).

This story **implements behavioural convergence** on top of FE.5.2 primitives: **loading / empty / error** regions, **async feedback** (inline vs toast), **destructive confirmations**, **form** consistency, and **accessible** table/list semantics. It **does not** re-litigate the ADR, duplicate the full parity spec, or deliver **FE.5.4+** mapping artifacts, **new backend domains**, **Ant Design**, or **pixel** capstone match.

## Story

- As a **dispatcher or ops staff member**
- I want **list, filter, and edit flows** in **`/ops/*`** to behave **predictably** (clear loading and empty states, recoverable errors, safe destructive actions, readable tables, consistent forms)
- so that **internal work is faster, safer, and easier to learn** — and so **new ops features** reuse the **same patterns** (**NFR.5.1**, **NFR.5.2**) with **Vestroo domain language** in UI copy (**NFR.5.4**)

## Epic traceability (source)

**From `docs/epic-5.md` — FE.5.3:** Ops screens with **lists, filters, and edit flows** MUST converge on **consistent Tailwind-based patterns** per FE.5.2: **loading and empty states**, **error surfaces**, **confirm destructive actions**, and **accessible table/list semantics**. New or refactored ops features MUST reuse **shared ops primitives** (not one-off styled blocks). Reference code under **`docs/capstone-reference/frontend-admin`** and **`frontend-manager`** MAY be cited as **interaction references only**, not for copy or naming that conflicts with **Epic 4 / VST** vocabulary (**NFR.5.4**).

**Constraining NFRs:**

- **NFR.5.1:** No duplicate one-off table/form chrome; extend **existing** primitives and shared **`src/components/ui/*`**.
- **NFR.5.2:** Prefer **RSC** for pages; **lazy-load** heavy client-only tables/widgets when introduced.
- **NFR.5.4:** User-visible strings on touched surfaces use **VST / Epic 4** terminology (e.g. corporate shuttle, trips, bookings, runs) — not capstone **demo** or legacy transit labels.

**Explicit out of scope:**

- **FE.5.4+** mapping matrices and backlog artifacts.
- **New** backend domains or schema work.
- **Ant Design**; **pixel-perfect** capstone theme match.

## Acceptance Criteria (ACs)

1. **Shared loading / empty / error patterns:** Provide **reusable** UI for **data regions** (list or table areas): at minimum **documented composition** plus **implemented** shared building blocks (e.g. thin **`OpsListState`** / **`OpsDataRegion`** / slot props on **`OpsTableShell`** — dev choice) so refactored pages **do not** hand-roll unrelated **`text-red-300` / `text-zinc-500`** blocks for the same three states. **Loading** MUST be distinguishable from **empty** (skeleton, spinner, or explicit “Loading…” region with **`aria-busy`** where client-driven). **Empty** MUST include **short guidance** (what is empty, optional next action). **Error** MUST be **recoverable in intent** (message + optional retry or refresh hint for client paths; server errors stay clear and scoped).

2. **Async operation feedback (inline vs toast):** **`package.json` has no `sonner`.** Default: use **`Alert`** from **`src/components/ui/alert.tsx`** and **inline** field/server-action errors on forms. **Document** in **`docs/ops-design-system-parity.md`** (Feedback section) the rule: **toast parity** requires an explicit story that adds **`sonner`** (or equivalent) with **bundle note** — **not** silently assumed in FE.5.3. Refactored **client** flows that perform async mutations MUST surface **failure** inline or via **`Alert`** in a **consistent** placement (e.g. top of form or above action group).

3. **Destructive action confirmation:** Introduce a **standard destructive confirm** using **`AlertDialog`** pattern under **`src/components/ui/`** (today **missing** — add via **`@radix-ui/react-alert-dialog`** + shadcn-style wrapper, matching existing **`button` / `alert`** conventions). At least **one** user-triggered **destructive or irreversible** action on a **refactored** ops page MUST use this pattern (e.g. status change, cancel, delete-like operation — **dev picks** a real control that exists today). **Keyboard** and **focus return** MUST behave per Radix **AlertDialog** defaults.

4. **Form patterns:** On **refactored** pages that include **forms**, use **`Form`**, **`FormField`**, **`Label`**, **`Input`**, **`Select`**, **`Button`** from **`src/components/ui/*`** where applicable; show **validation messages** consistently; **disable submit** (and show pending state) while **`isPending`** / action in flight. Align at least **one** existing client panel (e.g. **`AssignBookingPanel`**, **`TripOpsForms`**, **`CloseProtectionOpsForms`**, or **`OpsInvoicingHooksPanel`**) as part of the refactor set **if** that page is chosen.

5. **Table and list accessibility:** For **tabular** data, use **real** **`<table>`** semantics via **`OpsTableShell`** (already renders **`<table>`**); every table instance MUST pass a meaningful **`caption`** (typically **sr-only**) describing the dataset. For **non-table lists** used as primary data views, document **when** to use **`role="list"`** / **`role="listitem"`** or native **`<ul>`** — and apply on at least one refactored **list-heavy** page. **Sortable columns:** if this story adds **clickable column headers**, document **keyboard** (`Enter`/`Space`) and **`aria-sort`** (or defer sort implementation but **document** the contract in parity or component JSDoc). If sort is **not** implemented, parity doc MUST state **“sort deferred”** and require **non-interactive** header styling to avoid false affordance.

6. **Refactor quota — representative `/ops/*` pages:** Refactor **at least 2–3** distinct **`/ops/*`** routes to use **`OpsPageHeader`**, **`OpsFilterRow`** (where filters exist or a single filter row improves scan), **`OpsTableShell`** / agreed list wrapper, **`OpsActionGroup`**, and the **new** loading/empty/error/destructive/form patterns above. **Minimum coverage:** (a) **one list-heavy** page (multiple rows or sections of rows), (b) **one form / edit-heavy** page (client mutations). **Dev picks** routes; **suggested first targets** (all currently mix raw headings and ad hoc error UI): **`/ops/fulfil`** (queue + **`AssignBookingPanel`**), **`/ops/compliance`** (incidents + expiring documents), **`/ops/trips`** (**`TripOpsForms`** per trip). **`/ops/vehicles`** is already a primitive consumer — may be **touched lightly** only to adopt **new** state/confirm patterns, or left stable if other pages give enough coverage.

7. **NFR.5.4 — copy audit on touched pages:** Replace or avoid **capstone-demo** wording on **refactored** pages; align labels and empty/error copy with **VST / Epic 4** language (see **`docs/ops-console.md`**, **`docs/compliance-and-safety.md`** for compliance terms). **Do not** import reference **route labels** as product copy.

8. **NFR.5.1 / NFR.5.2 enforcement:** No **parallel** table/list wrappers duplicating **`OpsTableShell`**; new **client-only** heavy widgets MUST use **`next/dynamic`** with a documented **loading** fallback. Page **`default export`** remains **async Server Component** unless an existing pattern already uses a client page wrapper.

9. **Documentation updates:** Extend **`docs/ops-design-system-parity.md`** with an **FE.5.3 / Story 5.3** subsection: state machine summary (loading/empty/error), destructive confirm, form submit rules, a11y table/list notes. Update **`docs/ops-console.md`** to mention **new** UI helpers and **AlertDialog** location. Capstone citations: **only** as **interaction examples** with paths under **`docs/capstone-reference/frontend-admin`** and **`docs/capstone-reference/frontend-manager`** (e.g. list density, modal confirm rhythm) — **no** copy-paste of reference strings.

10. **Testing:** Add **Vitest** coverage for any **new pure helpers** (e.g. state copy builders, sort label helpers) following **`src/features/ops/ops-layout-tokens.test.ts`** and **`ops-nav-config.test.ts`** style. Optionally add or extend **Playwright** smoke for **one** refactored route (happy path + one error or empty state) if the repo already uses Playwright for ops (**`npm run test:e2e`**). **No** requirement for visual regression tooling.
