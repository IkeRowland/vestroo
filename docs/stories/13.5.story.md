## Story

- As **ops staff**, I need the **booking detail** view to show the **current quote** (version, totals, line items, send metadata, expiry, status) using **`current_quote_id`** with a safe fallback to **`v_booking_current_quote`**, so that **I do not re-send or act on stale information** (**US-B2**, **[`docs/epic-13.md`](../epic-13.md)** **§3 Phase 2**).
- As **ops staff**, I need **"Re-send quote"** when the quote is **`sent`** or **`accepted`**, so that a **new version** is issued, the **prior** row is **`superseded`** with **`superseded_by_quote_id`** populated, and the customer-facing send path stays consistent with **13.4** actions (**US-B2**).

## Acceptance Criteria (ACs)

### US-B2 — Booking detail current quote + re-send (Theme B)

1. **Current quote resolution:** Ops booking detail loads the **current** quote by **`bookings.current_quote_id`** when set; if **null**, falls back to the row returned by **`v_booking_current_quote`** for that **`booking_id`** — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-B2** (first **AC**). Document edge cases (e.g. only **draft** exists — view may return no row; UI shows empty / “No quote sent yet” state).

2. **Displayed fields:** When a current quote row exists, the UI shows **version**, **total** (**`total_zar`**), **line items** in a **mini-table** (labels, qty, unit/total as per **`BookingQuoteLineItem`**), **`sent_at`**, **`sent_to_email`**, **`expires_at`**, and **`status`** — **US-B2** (second **AC**).

3. **Re-send with supersede:** **"Re-send quote"** is offered only when the **resolved** current quote **`status IN ('sent','accepted')`**. Submitting the action creates a **new** **`booking_quotes`** version (via **`createBookingQuote`** or equivalent), transitions the **prior** current quote to **`status='superseded'`**, sets **`superseded_by_quote_id`** to the **new** quote’s **`id`** (and **`superseded_at`** if applicable), then sends the **new** quote (**`sendBookingQuote`** or dedicated RPC wrapping the same contract) so **`bookings.current_quote_id`** matches the new **sent** row — **US-B2** (third **AC**). Operation must be **staff-gated** and **failure-safe** (clear ops error on partial failure; no orphan **`superseded`** without a successor if transaction rolls back).

4. **Shared line-item type:** Line items on create (**13.4**) and in the **render module** for this story use the same **`BookingQuoteLineItem`** type (import from shared module such as **`src/types/booking-quote.ts`**) — **US-B2** (fourth **AC**).

### Cross-cutting

5. **Traceability:** Maps to **[`docs/epic-13.md`](../epic-13.md)** **§3** Phase **2**, **§4 Theme F** row **13.5** (**3 pts**, Theme **B**, Depends: **13.4**), and **§4 Theme B — US-B2** (~113–118).

6. **Primary code touchpoints:** **`src/app/(ops)/ops/bookings/`** (booking detail route/layout), new or extended component **`QuoteDetailPanel`** (name per epic **§8** — adjust filename to match repo conventions if needed), server action(s) under **`src/actions/`** for **re-send / supersede**; reuse **`src/actions/bookingQuoteOps.ts`** (**13.4**) where possible. **Migration:** only if triggers/RPCs are required for **atomic supersede + send**; otherwise document **app-layer transaction** strategy.

7. **Nice-to-have (optional):** **"Quote expired"** badge when resolved quote **`status='expired'`** — only if low effort; else note **13.11** / **US-E1** for coordinated UI.

### Implementation notes

- **Line items for re-send:** Product may require **pre-filled** line items from the current quote for editing, or **copy-as-is** — default to **copy current `line_items` + `total_zar`** unless PM specifies an edit flow (multi-quote negotiation is out of scope per **[`docs/epic-13.md`](../epic-13.md)** **§2**).
- **Order of operations:** Mark **superseded** only after the **new** quote **`id`** exists to satisfy **`superseded_by_quote_id`** FK to **`booking_quotes(id)`**.
- **Concurrency:** Two simultaneous re-sends should not corrupt **version** — rely on **`UNIQUE(booking_id, version)`** and retry logic as in **13.4**.
