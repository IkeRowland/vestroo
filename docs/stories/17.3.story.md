## Story

- As **ops staff**, I need the **sidebar** grouped with **clear section labels**, **optional counts** where relevant, and a **visible active rail**, so I can scan and navigate the console faster.

- As **the product**, we need an **optional promo region** behind a **feature flag** with **configurable** content, so we can highlight **release notes** or **training** without shipping fixed marketing copy in code.

## Acceptance Criteria (ACs)

1. **Named groups:** Nav items render under **named groups** whose labels use **`text-[11px] tracking-wide text-ops-muted`**, **uppercase** presentation (replace current **`text-[10px]`** / **`tracking-wider`** on group headers where inconsistent — align to epic). Group definitions remain in **`src/features/ops/ops-nav-config.ts`**; filtering uses **`filterOpsNavGroups`** and item-level **`visibleRoles`** as today.
2. **Group taxonomy:** Final **`group.title`** values and group **merge/split** decisions follow **Reconciliation** and are reflected in **`OPS_NAV_GROUPS`** (and **§ 17.3**).
3. **Count badge:** Items may show an optional **badge** when **`badgeCount`** is provided by the consumer; style: **rounded-full**, **`bg-ops-accent text-ops-accent-foreground`**, **`min-w-5 h-5 px-1.5`**, **`text-[11px] font-semibold`**. Badge is **not rendered** when count is **`0`** or **`null`** / **undefined**.
4. **Active item:** Active nav link has **left rail accent**: **`before:absolute before:inset-y-1 before:left-0 before:w-0.5 before:bg-ops-accent`** (parent **`relative`** as required) **and** retains **`bg-ops-surface-active`** (plus existing text/active rules).
5. **`OpsSidebarPromoSlot`:** Optional region **below** the scrollable nav list, **above** any bottom sidebar chrome documented in **§ 17.3**; **defaults to `null`**. When feature flag **`ops_sidebar_promo_enabled`** is **off**, slot renders **nothing** (no layout shift beyond optional reserved min-height **only if** parity doc specifies — default **no** reserved empty space).
6. **Promo content:** Promo **copy** and **image** (if any) are **configurable** per **Reconciliation** (no single hard-coded Wheelzie-style card in JSX).
7. **Feature flag:** Introduce **`ops_sidebar_promo_enabled`** consistent with existing ops **`NEXT_PUBLIC_*`** truthy parsing (reference **`isOpsDispatchBoardNavEnabled`** in **`src/lib/ops-dispatch-board-nav-env.ts`**). **Production default:** **false** / off; **staging default:** **true** / on — document in **`.env.example`** (and **`.env.test.example`** if applicable) with short comment.
8. **Copy (NFR.17.8):** New user-visible strings for sidebar chrome (group labels if moved to copy module, promo fallbacks, aria labels for badges) live in a **single export per surface** — e.g. **`src/features/ops/copy/ops-sidebar-copy.ts`** — not scattered literals.
9. **Architecture (NFR.17.3):** Prefer **Server Components** for shell; **`OpsSidebar`** stays **`'use client'`** only where needed (pathname, collapse, promo hydration if any).
10. **Theme (NFR.17.4):** Group labels, badges, active rail, and promo **work in light and dark** **`data-ops-theme`** without theme-branching beyond token utilities.
11. **Authz (NFR.17.6):** No changes to **`requireOpsStaffPage`**, RLS, or role mapping — **presentation and optional counts only**; counts MUST NOT leak data the user cannot already access via the linked route (consumer responsibility — note in § 17.3).
12. **Tests:** Update **existing** sidebar-related tests (**`ops-nav-config.test.ts`**, dispatch gate integration if affected); **add** tests that assert **group titles render** (post-taxonomy) and **badge visibility** (visible for positive count, absent for 0/null). Add **`OpsSidebar`** component tests (RTL/snapshot/focus) if missing after Task 0.
13. **Documentation:** Add **`docs/ops-design-system-parity.md`** **§ 17.3** — group label spec, badge spec, active rail spec, promo slot + flag, collapsed-badge behaviour, placement vs shell footer (**NFR.17.1**).
14. **Quality:** **`npm run lint`** and **`npm run test`** remain green after implementation.
