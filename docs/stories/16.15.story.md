## Story

- As a **walk-in customer** receiving the quote email, I need **clear bank details** and a **payment reference** so I can EFT the quoted amount, and a single obvious **accept** link to confirm the quote on **`/q/[token]/accept`**, consistent with **Q33**.

- As **engineering**, I need **one server-side** place that merges **`ops_settings.bank_account`** with the booking reference pattern and passes structured props into the **existing** email template module, keeping **bank digits out of any client bundle** used by ops UI.

- As **QA**, I need a **unit test** on the template render proving bank fields and reference appear from **mocked** settings-shaped props (and that **accept** URL segment is preserved).

### Reference substitution rules (AC3)

- `formatBankReference(template, bookingRef)` substitutes **every** occurrence of the literal token `{booking_ref}` in `template`, **case-sensitively** (epic Q31 — `reference_format` is staff-curated copy, not user input). Booking ref is `String.prototype.trim()`-normalised before substitution. When `template` is `null`, `undefined`, empty, or whitespace, the helper falls back to **`VST-{booking_ref}`** (matching the seed default introduced by Story 16.11 / N1). When the template lacks `{booking_ref}` it is returned verbatim (static reference allowed).

### Bank-failure handling decision

- **Hard fail.** Sending a walk-in quote email without bank details would defeat US-N4: customer would receive an EFT-first email with blank instructions and no way to pay. The action therefore returns `VALIDATION` (or `DATABASE` for Supabase errors) with a reason-coded failure (`BANK_ACCOUNT_NOT_CONFIGURED` / `BANK_ACCOUNT_INCOMPLETE` / `BANK_ACCOUNT_MALFORMED` / `BANK_ACCOUNT_DATABASE`) and a staff-readable message (e.g. *“Bank account settings are incomplete (missing: account_number, branch_code). Ask an admin to update ops_settings.bank_account.”*). The send pipeline is short-circuited **before** the matrix gate, RPC, status update, or email dispatch — no half-state.
