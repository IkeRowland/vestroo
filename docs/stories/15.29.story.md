## Story

- As an **algorithm owner** / **ops lead**, I need **every successful assign** to write a **clear, comparable** record in **`ops_audit_log`**: when the path was **suggestion-prefilled** and **server-validated** against the **current** top suggestions for that **booking**, **`action = 'assignment_from_suggestion'`** with **rank**, **score**, and **vehicle** in **payload**; when the path was **free-pick** (no **validated** **`fromSuggestion`**), **`action = 'assignment_free_pick'`** — so **`15D.4`** and ad-hoc **SQL** can **segment** paths **without** trusting **raw** client **scores** for security.

## Acceptance Criteria (ACs)

1. **API contract — `fromSuggestion`:** Extend **`assignBookingToRun`** ( **`src/actions/opsDispatch.ts`** and any **shared** types) so callers may pass optional **`fromSuggestion: { vehicleId, score, rank?: 1 | 2 | 3 }`**. **Document** in code or **Progress Notes** whether **`rank` / `score` from the client** are **hints only**; **server** is the **source of truth** for **bound** **rank** and **score** in **`ops_audit_log`** per **AC3–AC4** (unless product explicitly **documents** a **fraud-accepted** path — **prefer** **AC3**).

2. **UI / state handoff (15D.2):** The **Fulfil** assign path **MUST** pass **into** the assign call (or a **form field** the action reads) sufficient context so the **server** can know the dispatcher **clicked a suggestion** for the **selected** **vehicle** — at minimum **vehicleId**; **15.28** should also **surface** **rank** and **score** in state (extend **`15D.2`** if not already present). If **`15.28` Done** work **lacks** any of **`vehicleId` / score / rank** in the submit payload, **treat as gap**: **AC** is **met** by **completing** the missing wiring in the **same PR** or an **immediately** stacked PR — **call out** in **Progress Notes**.

3. **Server trust — bind to top-3 (preferred):** On assign, if **`fromSuggestion` is present** (or an equivalent “user claims suggestion path” flag), the **server MUST** re-run **`suggestVehiclesForBooking(bookingId)`** (or a **private** **shared** helper with the **same** **logic**) **in the same request** (or a **tight** internal sub-call), find the **row** in the **top-3** whose **`vehicleId` matches the submitted** assign **target** (`vehicleId` for the run/assignment — **define** the exact field in **Progress Notes** to match **ops** data model), and **bind** **`rank`** and **`score` from that row** for audit. If the **submitted** vehicle is **not** in the top-3 results, **treat** as **invalid** **`fromSuggestion`:** **do not** log **`assignment_from_suggestion`**; fall through to **AC5** (free-pick) **or** a **documented** **validation error** that **blocks** assign (choose **one**; **prefer** **degrade to free-pick** to avoid stranding work — **document** the choice). **MUST** still validate the **submitted** vehicle is the **intended** assign **target** (e.g. matches **form** / **RPC** args) — **no** log line that claims **suggestion** for a **different** vehicle.

4. **Documented alternative (non-preferred):** If **re-fetch** is **infeasible** (must be **justified** in **Progress Notes**), document **fraud** / **mismatch** risk and **still** require **`vehicleId`** to match the assign **target**; log **client-provided** **score** / **rank** only with **explicit** **caveat** in **payload** (e.g. `source: 'client'`) — **this path** is **lower** than **re-fetch** in the **hierarchy of acceptance**; **PI** / **PO** may reject in review if **re-fetch** is **possible** in the codebase.

5. **Free-pick `action`:** If assign **succeeds** and **AC3** did **not** produce a **validated** suggestion bind (no **`fromSuggestion`**, **invalid** **top-3** match, or **explicit** “free-pick” path), write **`action = 'assignment_free_pick'`** in **`ops_audit_log`**.

6. **Suggestion `action`:** If assign **succeeds** and **AC3** **validates** the **suggestion** path, write **`action = 'assignment_from_suggestion'`** and include **`score`**, **`rank` (#1 / #2 / #3)**, and **`vehicleId`** (or canonical **`vehicle_id`**) in **`payload`**, plus any **minimal** metadata needed for **`15D.4`** (e.g. **booking** **id** already on row — follow **`appendOpsAuditLog`** conventions) — **SQL-ready** shape, **not** a **report** **UI**.

7. **Success only:** **Audit** rows for **`assignment_*`** are written only **after** assign **succeeds** (same **transaction** or **immediately** after **confirmed** **success** with **idempotency** considered—**survey** how **`opsDispatch.ts`** does **other** post-success **hooks**; **no** “optimistic” audit on failure).

8. **Epic 11 alignment:** All **`ops_audit_log` inserts** go through the **established** **`appendOpsAuditLog`**, include **`actor_id`**, and pass **any** **required** **enums** / **payload** schema the repo uses; **no** new **bypass** of **staff** **policies**.

9. **Feature flag (optional, consistent):** If dispatch **suggestions** are **off** ( **`DISPATCH_SUGGESTIONS_ENABLED`** or successor from **`15D.2`** ), **`fromSuggestion` must** be **ignored** / **rejected** at the **edge**; **only** **`assignment_free_pick`** (or **no** `fromSuggestion` path) is possible — **document** **interaction** with the flag in **Progress Notes** so **re-enable** is safe.

10. **Traceability:** **Story** file, **DoD**, and **Progress Notes** reference **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15D.3`**, **Theme D US-D3 (1)–(3)**, **Q25**, **§5** / **§8** (**15D** rows) as applicable; **cross-link** **`15D.2`** and **`15D.4`** for handoff to **report** work.
