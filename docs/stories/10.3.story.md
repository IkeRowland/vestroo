## Story

- As a **traveler** on **Slide 2** of the public **trip request** flow
- I want to **choose exactly one** vehicle from the **offered** options, seeing **image**, **classification**, and **helpful attributes** (for example **passenger** and **luggage** capacity per product rules) **without** any **rand price**, **quote**, or **total**
- so that my request reflects **vehicle preference only**, **operations** can price **out of band**, and the experience stays **one page**, **calm**, and aligned with **[FE.10.3](../epic-10.md)** and **[FE.10.5](../epic-10.md)** (**no payment at booking**)

## Acceptance Criteria (ACs)

### Vehicle selection — normative (FE.10.3)

1. **Exactly one selection:** The traveler **MUST** **select exactly one** vehicle from the **offered list** for the request (for example **radio-group** semantics or a single **controlled** choice id). **Zero** or **more than one** simultaneous selection **MUST NOT** satisfy **Next** / forward validation for Slide 2 — **[FE.10.3](../epic-10.md)**.

2. **Vehicle image:** Each **offered** option **MUST** display a **vehicle image** (photo or approved placeholder when missing — **document** placeholder rules in **Dev Technical Guidance** or PR). Images **MUST** have **non-empty** **accessible** naming where appropriate (**decorative** vs **informative** — **AC15**) — **[FE.10.3](../epic-10.md)**.

3. **Classification:** Each option **MUST** display **classification** (for example **class** or **category** label) sourced from the **product/data model** — **[FE.10.3](../epic-10.md)**.

4. **Attributes:** Each option **MUST** display **attributes** relevant to choice (for example **passenger capacity**, **luggage** — exact fields **per** product/schema). If the backend provides **additional** non-price facts, the UI **MAY** show them when they **do not** imply pricing — **[FE.10.3](../epic-10.md)**; **[Design Goals](../epic-10.md)** (**imagery and facts**, not price).

### No-price — UI guardrails

5. **No rand pricing or quotes in UI:** Slide 2 **MUST NOT** **calculate**, **display**, or **imply** **rand** (**ZAR**) **pricing**, **quotes**, **estimates**, or **totals** (including **strikethrough** “was” prices, **per km** hints tied to money, or **“from R…”** copy) — **[FE.10.3](../epic-10.md)**; **[Non-Goals](../epic-10.md#non-goals)**.

6. **No payment or checkout affordances:** Slide 2 **MUST NOT** embed **PayFast**, **card** UI, **basket**, or **pay** CTAs — **[Non-Goals](../epic-10.md#non-goals)**.

### No-price — API and data-layer contract

7. **Documented contract:** **Dev Technical Guidance** (or adjacent **`*.md`** only if the repo already uses that pattern for API notes — **prefer** story + PR description) **MUST** document the **no-price** contract: **TypeScript** types (or equivalent) for **vehicle options** **MUST** **exclude** monetary fields (**price**, **amount**, **total**, **quote**, **fare**, **estimate**, **ZAR**, **cents**, **PayFast** ids, etc.) **or** **explicitly** map **server** DTOs through a **sanitizing** layer that **strips** price-like keys before UI consumption. The doc **MUST** list **forbidden** fields and the **single** **boundary** (fetch adapter, **zod** parse, etc.) where **sanitization** happens.

8. **Runtime safety if server sends price:** If the **API response** includes **unexpected** price-like fields, the client **MUST** **not** render them on Slide 2. The implementation **MUST** either **strip** at the boundary (**AC7**) or **fail closed** (for example **error state** + **no** price leakage) per **AC12** — **never** pass raw **unknown** monetary props into cards.

### Async list behaviour

9. **Loading state:** While the **offered list** is **loading** (if **async**), Slide 2 **MUST** show an **accessible** loading pattern (for example **skeleton** cards and/or **`aria-busy`** / **live region** consistent with **FE.10.1** shell patterns). **MUST NOT** show **placeholder prices** during load — **AC5**.

10. **Empty state:** If **zero** vehicles are returned (valid **empty** offer), Slide 2 **MUST** show a **clear** empty message and **block** **Next** until product rules define otherwise (**default:** user **cannot** proceed without a selection — document **product** decision in PR if **allow skip** is ever required).

11. **Error state:** On **fetch** or **parse** failure, Slide 2 **MUST** show a **recoverable** error UI (**retry** where applicable) **without** exposing **stack traces** or **internal** URLs. **MUST NOT** display **pricing** in error copy — **AC5**.

### Alignment with FE.10.1 (shell) and FE.10.2 (Slide 1)

12. **One page, no step routes:** Implementing Slide 2 **MUST NOT** add **distinct application routes** for this step. The traveler **MUST** remain on the **same primary URL** as **Stories 10.1–10.2** — **[FE.10.1](../epic-10.md)**; **[`docs/stories/10.1.story.md`](10.1.story.md)**.

13. **Inside the unified form:** Slide 2 content **MUST** live **inside** the **existing** **FE.10.1** **form section** (same **`<form>`** / unified semantics as **10.1**), not a nested separate form — **[FE.10.1](../epic-10.md)**.

14. **Replace Slide 2 placeholder only:** **10.3** **MUST** replace the **Slide 2** **stub** with **vehicle selection** UI while **leaving Slide 3** as **placeholder** until **FE.10.4** — **do not** implement passenger fields here.

15. **Slide 1 integration:** Vehicle list **MAY** depend on Slide 1 **client state** (for example **pickup/drop-off/datetime/passengers**) for **fetching** offers; wiring **MUST NOT** **rewrite** Slide 1 **fields** except for **explicit** **bugfixes** listed in **Tasks** — **[`docs/stories/10.2.story.md`](10.2.story.md)**.

### Accessibility

16. **Keyboard and focus:** Each vehicle option **MUST** be **operable** with **keyboard** (Tab / arrow keys as appropriate to the **radio**/**roving tabindex** pattern). **Visible focus** **MUST** meet project conventions. When entering Slide 2, focus **MUST** behave consistently with **FE.10.1** (**AC8** in **10.1**) — **no** silent step change.

17. **Selected state:** The **current** selection **MUST** be **programmatically** exposed (**`aria-checked`**, **`aria-selected`**, or **native** **`<input type="radio">`** in **fieldset**) and **visually** distinct. Screen readers **MUST** be able to **infer** **which** vehicle is selected when moving through the list.

### Mobile and layout

18. **Mobile-first cards:** Vehicle options **MUST** **reflow** on **narrow** viewports: **no** required horizontal scroll for **primary** card content; touch targets **SHOULD** meet project **minimum** sizes — **[Design Goals](../epic-10.md)** (**Responsiveness**).

### Images and non-functional guardrails

19. **Image performance (CLS):** Vehicle images **SHOULD** use **`next/image`** (or equivalent) with **explicit** **dimensions**, **aspect-ratio** wrapper, or **stable** **skeleton** sizing so **CLS** stays **low** when images load. **Lazy loading** **SHOULD** apply below the fold or for **offscreen** cards per **Next**/browser defaults — **NFR.1.1**.

20. **Security / SEO posture (NFR.3.1, NFR.3.2):** **MUST NOT** weaken **HTTPS** for API or assets. **SHOULD** avoid **new** route-level SEO changes beyond **10.1** — **Constraining NFRs** above.
