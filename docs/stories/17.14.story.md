## Story

- As **ops staff**, I need a **week-at-a-glance** calendar on **`/ops/calendar`** with **time-of-day** context, **today** and **now** visible, and an **event detail rail** (**vehicle**, **client**, **driver**, **notes**), so I can **scan and open** scheduled work without leaving the ops console — using **Vestroo shuttle** vocabulary (**NFR.17.7**).

- As **the codebase**, we need a reusable **`OpsCalendarWeek`** primitive (**FE.17.9**) and **`/ops/calendar`** wired to **`OpsSplitView`**, **deep-linkable** week + selection, **keyboard**-accessible, **token**-themed, and **documented** for **17.15** to extend — **without** **`OpsCalendarMonth`** or **`/ops/roster`** in this PR.

## Acceptance Criteria (ACs)

1. **`OpsCalendarWeek` primitive:** New component(s) under **`src/features/ops/components/`** (or documented path) implementing **7 columns** (week days), **hour rows** default **06:00–24:00**, **props** for configurable **startHour** / **endHour** (document edge cases, e.g. crossing midnight — **Task 0**).

2. **`events` contract:** Public type **`{ id, startsAt, endsAt, title, subtitle, tone, href? }[]`**; events **positioned** in the grid with **stacking** for overlaps (**Task 0** defines min-height / overflow behaviour).

3. **Interaction:** **Click** event → opens **`OpsDetailRail`** when **`href`** is absent, or **navigates** to **`event.href`** when present (**FE.17.9**).

4. **Today + now:** **Today** column visually distinct; **current time** horizontal indicator on **today** only (updates on client per **Task 0** — **no** SSR hydration mismatch policy documented).

5. **`/ops/calendar` route:** Refactor **`src/app/(ops)/ops/calendar/page.tsx`** to use **`OpsPageHeader`** (title/description/copy module) consistent with **`/ops/trips`**, **`/ops/vehicles`**, etc.; **`OpsDataFreshnessBar`** preserved or rationalized in layout.

6. **Data mapping:** **Server** load **trips** (or **Task 0**-agreed query) with joins **only** as allowed by existing **RLS**; map rows → **`events`** (**Reconciliation**); replace **day-column-only** UI; **`.limit(120)`** — **Task 0** documents trade-off vs week window (narrow query by week range preferred if indexes support — **no** authz change).

7. **`OpsSplitView` + `OpsDetailRail`:** **Calendar** main region + **detail** rail per **17.9**; **`< lg`** drawer + **`xl+`** sticky rail; **Esc** / **focus return** aligned with **17.9** / **17.13**.

8. **Deep linking:** URL reflects **week anchor** and **selected event** (**`?id=`** or agreed param); refresh and shared links restore **week + selection**; invalid **`id`** behaviour documented (**Reconciliation**).

9. **Optional list/agenda toggle:** If shipped in **17.14**, **minimal** **list** view of the **same week’s** events (**no** **`OpsCalendarMonth`**); **no layout shift** toggling **week ↔ list** (**Reconciliation**). If **deferred**, parity doc states **follow-up**.

10. **Keyboard (FE.17.9):** **Arrow** navigation within grid/event list; **Enter** opens selection; **Esc** closes rail; **axe**-clean on calendar surface (**NFR.17.5**).

11. **Accessibility:** **Icon-only** controls have **`aria-label`**; grid / events expose **roles/labels** appropriate to pattern (**Task 0** vs **grid** vs **listbox** model).

12. **Theme (NFR.17.4):** **`data-ops-theme` light/dark** — no theme-branching beyond tokens.

13. **Copy module (NFR.17.8):** **`src/features/ops/copy/…`** (e.g. **`ops-calendar-copy.ts`**) — **single export surface** for page title, descriptions, empty states, aria labels, toggle labels.

14. **Parity doc (NFR.17.1):** **`docs/ops-design-system-parity.md`** **§ 17.14** — **`OpsCalendarWeek`** props table, **`events`** type, URL params, **tone** mapping, **no `react-big-calendar`**, **RSC/client** split, keyboard spec.

15. **Tests:** **Vitest** / **RTL** — URL week helpers if extracted; **event** mapping unit tests; smoke for **rail** open/close where feasible.

16. **`npm run lint`** and **`npm run test`** green.

17. **Tablet / QA:** **`docs/ops-console.md`** (**FE.5.7**) or **Task 0** substitute; record in **Progress Notes**.

18. **Story maintenance:** On completion, dev agent updates **Status**, **Tasks**, **Progress Notes**, **DoD report**, per **[`.cursor/rules/story-completion-dev-agent.mdc`](../../.cursor/rules/story-completion-dev-agent.mdc)**.
