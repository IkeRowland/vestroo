### US-F1 (narrow) — Golden path regression + webhook idempotency (Phase 5 / §7 **partial**)

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 5**; **§4 Theme F — US-F1** **AC1** (first sentence only for **14.10**), **AC4**; **§7** **Golden path** (partial) + **Quality**; **§8**.)_

1. **Golden path (automated, walk-in, quote-first):** **One** automated test (prefer **Playwright** under **`tests/e2e/`** — **survey**; repo currently includes e.g. **`tests/e2e/epic13-theme-c-resend-failure.spec.ts`**) that exercises at minimum:
   - **Non-trivial** walk-in **submit** (e.g. **`trip_request` \| `hourly_hire` \| `experience_package`** per **Q13** / **14.7**) → booking row shows **`status='submitted'`** on **`/ops/bookings`** (or equivalent **ops** list assertion via **E2E** **API** / **DB** as existing harness does).
   - **Ops** **Send quote** (UI or harness action) → **`booking_quotes`** row with **`status='sent'`** and **`expires_at`** consistent with the **72h** / **Q2** **contract** (assert **shape**, not full **11** matrix).
   - Customer follows **primary** path documented in this story’s **Tasks** — **accept** link (recommended) to **`/q/.../accept`** → **PayFast** **mocked** (no real payment) → **simulate** **PayFast ITN** with **`payment_status` → `paid`** (or product-equivalent **COMPLETE** payload per **`docs/integrations-and-payments.md`** — **survey**).
   - Booking reaches **`bookings.status='ready_to_assign'`** (trigger **Q19** / **14.1**).
   - Booking is **visible** in **"Ready to assign"** **preset** **or** **`/ops/fulfil?queue=paid`** (pick **one** **primary** assert + **document**; optional **secondary** assert if **stable**).
   - **Ops** **assign** → **`trips`** row **created** (or product-equivalent “trip exists” assertion used elsewhere in E2E).

2. **Webhook idempotency (US-F1 AC4):** **Automated** test (**second** **`it`** in the **same** spec **or** **API-level** test) that posts a **duplicate** **`COMPLETE`**-equivalent ITN payload for an **already-paid** walk-in booking (same idempotency key / PayFast event semantics as production **handler**) and asserts:
   - **No** second **`trips`** row / **no** duplicate **trip** side effect for that replay.
   - **`bookings.status`** remains **`ready_to_assign`** (or another **acceptable** **terminal** for this state — **no** oscillation, **no** duplicate **ready_to_assign** side effects); behaviour must match existing idempotency in **`src/app/api/payfast/webhook/route.ts`**.

3. **Implementation constraints:** **PayFast** and **ITN** simulation align with **existing** E2E infrastructure (**service role**, **`/api/e2e/*`**, **cookies**, **mocks** — **TBD** **survey**). **Resend** may be **mocked** to satisfy **§7** “mocked PayFast” emphasis and reduce flake.

4. **Code touch for webhook:** **No** changes to **`src/app/api/payfast/webhook/route.ts`** **except** to fix a **proven** **bug** (failing test with clear repro). Otherwise **read-only** verification.

5. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 5 (14.10)**, **US-F1** slices **AC1** (first sentence) + **AC4**, **§7** (**partial** + **Quality**), **Theme G 14.10**, **§8**.
