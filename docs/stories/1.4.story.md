# Story 1.4: Booking Confirmation

## Status: Done

## Story

- As a **traveler**
- I want to **receive an automatic confirmation email after successfully completing my booking and payment**
- so that **I have a record of my booking details and can reference it for my upcoming trip**

## Acceptance Criteria (ACs)

1. **AC1:** The system MUST automatically send a confirmation email to the customer's email address immediately upon successful payment confirmation via the PayFast webhook.

2. **AC2:** The confirmation email MUST include all essential booking details:
   - Booking reference number/ID
   - Customer name
   - Route information (origin, destination)
   - Pickup date and time
   - Passenger count
   - Flight number (if provided)
   - Total amount paid
   - Payment reference/transaction ID

3. **AC3:** The confirmation email MUST be professionally formatted and branded consistent with the Vestroo platform design (modern, friendly, corporate, professional, trustworthy).

4. **AC4:** The email sending MUST be integrated into the PayFast webhook handler, triggered when booking status is updated from 'pending' to 'paid'.

5. **AC5:** The system MUST handle email sending failures gracefully:
   - Log errors for monitoring/debugging
   - Do not block the booking status update if email fails
   - Implement retry logic for transient email service failures

6. **AC6:** The email service integration MUST use server-side only configuration (API keys, credentials never exposed to client).

7. **AC7:** The system MUST validate that the booking has 'paid' status and contains valid customer email before attempting to send the confirmation email.

8. **AC8:** The confirmation email MUST include clear instructions for the customer, such as:
   - Contact information for support
   - What to expect on the day of travel
   - Instructions to save/print the confirmation

## Dev Technical Guidance

### Story Context & Dependencies

This story implements the **automatic booking confirmation email** feature. It builds directly on:

- **Story 1.3**: PayFast payment integration and webhook handler (provides the trigger point for email sending)
- **Story 1.2**: Customer details collection (provides customer email address)
- **Story 1.1**: Booking search and quote (provides booking route and trip details)

The PayFast webhook handler (`src/app/api/payfast/webhook/route.ts`) created in Story 1.3 currently:
- Receives payment confirmation from PayFast
- Verifies webhook signature
- Updates booking status from 'pending' to 'paid' in Supabase

This story adds email sending functionality to be triggered immediately after the booking status update is successful.

### Key Technical Requirements

1. **Email Service Selection:**
   - **Recommended: Resend** - Modern email API designed for Next.js/React, excellent developer experience, good Vercel integration
   - **Alternative: SendGrid** - Mature email service, widely used, good free tier
   - **Alternative: Nodemailer with SMTP** - More control, requires SMTP server configuration
   - Choose based on project needs; Resend is recommended for simplicity and Next.js integration

2. **Email Service Implementation (`src/services/email.ts`):**
   - Create reusable email service module following the architecture pattern mentioned in `docs/architecture.md#Core-Service-Layer`
   - Service should expose: `sendBookingConfirmation(bookingData: BookingEmailData): Promise<void>`
   - Handle all email service-specific logic (API calls, error handling, retries)

3. **Email Template Design:**
   - Create HTML email template with inline CSS (email client compatibility)
   - Include plain text fallback version
   - Match Vestroo branding (professional, trustworthy, corporate)
   - Mobile-responsive design
   - Include all booking details clearly formatted

4. **Webhook Integration:**
   - Modify `src/app/api/payfast/webhook/route.ts` to call email service after booking update
   - Email sending should be non-blocking (don't fail webhook if email fails)
   - Log email sending attempts and results

### Data Model Requirements

Reference: `docs/data-models.md#Booking`

The Booking entity includes:
- `id: string` - Booking reference/ID
- `user_id: string` - Customer user ID (relation)
- `route_id: string` - Route ID (relation)
- `status: 'pending' | 'paid' | 'confirmed' | 'completed' | 'cancelled'`
- `passenger_count: number`
- `pickup_datetime: Date`
- `flight_number?: string`
- `total_amount: number`
- `payment_reference: string`
- `transaction_id: string`

For email sending, you'll need to:
- Fetch booking record from Supabase
- Fetch related route details (origin_name, destination_name) from PayloadCMS or Supabase
- Fetch customer details (name, email, phone) - stored in booking record or via user_id relation

### Webhook Handler Updates

Reference: `docs/stories/1.3.story.md#Webhook-Handler-Implementation`

Update the webhook handler to:

1. After successfully updating booking status to 'paid':
   - Fetch complete booking details from Supabase (including customer email)
   - Fetch route details (if not already in booking record)
   - Call `sendBookingConfirmation()` with booking data
   - Log email sending result (but don't fail webhook if email fails)

2. Error handling:
   - Wrap email sending in try-catch
   - Log errors but continue webhook execution
   - Return 200 to PayFast even if email fails (booking is already updated)

Example integration:

```typescript
// In webhook handler, after booking status update:
try {
  const bookingData = await fetchBookingData(bookingId);
  if (bookingData.status === 'paid' && bookingData.customerEmail) {
    await sendBookingConfirmation(bookingData);
    console.log(`Confirmation email sent for booking ${bookingId}`);
  }
} catch (error) {
  console.error(`Failed to send confirmation email for booking ${bookingId}:`, error);
  // Don't throw - email failure shouldn't fail webhook
}
```

### Email Service Recommendations

**Resend (Recommended for Next.js/Vercel):**
- Modern, developer-friendly API
- Excellent Next.js integration
- Good free tier (3,000 emails/month)
- Simple React email template support
- Good documentation

**SendGrid:**
- Mature, widely-used service
- Generous free tier (100 emails/day)
- Good deliverability
- More configuration options

**Nodemailer with SMTP:**
- Full control over email sending
- Requires SMTP server (AWS SES, Google SMTP, etc.)
- More setup complexity

### Error Handling Patterns

1. **Email Service Failures:**
   - Log error with booking ID and error details
   - Don't throw error (non-blocking)
   - Consider retry logic for transient failures

2. **Invalid/Missing Data:**
   - Validate booking has 'paid' status before sending
   - Validate customer email exists and is valid format
   - Skip email if required data is missing (log warning)

3. **Retry Logic:**
   - Implement retry for network errors, rate limits
   - Use exponential backoff (e.g., 1s, 2s, 4s delays)
   - Max 3 retry attempts recommended

### Integration Flow

1. PayFast processes payment → Sends webhook to `/api/payfast/webhook`
2. Webhook handler verifies signature → Updates booking status to 'paid'
3. **After successful status update:**
   - Fetch complete booking data from Supabase
   - Validate booking status is 'paid' and email exists
   - Call `sendBookingConfirmation()` with booking data
   - Log email sending result
4. Customer receives confirmation email
5. Webhook handler returns 200 to PayFast
