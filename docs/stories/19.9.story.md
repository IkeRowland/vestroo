## Story

- As **a traveller** booking with a **corporate account that requires a PO**, I see the **purchase order** field **directly under my email** (and org association notice), so the flow reads as one contact/billing column **before** phone (**FE.19.9**).
- As **a traveller** who **dismisses** org association (**guest**), I **do not** see the PO field unless the product rules say otherwise (**association** required).
- As **a traveller** whose submit fails because the **server** rejects a missing/invalid PO, I get **clear feedback** and the **PO field is scrolled into view and focused** **within slide 3**, without a blocking overlay (**NFR.19.2**).

## Acceptance Criteria (ACs)

1. **Placement:** When PO is required (**`tripInvoicingContext?.defaultPoRequired`** with accepted **`account_client`** association per **Reconciliation**), the PO **`Input`** + helper copy render **inline below email**, **after** the **FE.19.8** inline org notice in the **slide 3** column — **not** only below the phone block.
2. **Copy / client validation:** Reuse **`accountRequiresPurchaseOrderMessage(tripInvoicingContext.accountDisplayName)`** for helper text; keep **`tripPoOk`** / **`canSubmitTrip`** behaviour equivalent to **pre-19.9** (still blocks submit when PO empty and required).
3. **Server parity:** **`submitTripRequest`** success/failure rules for PO **`unchanged`**; **no** edits to **`assertPurchaseOrderForAccountBookingInsert`** or **`tripRequestSubmitPayloadSchema`** PO fields **unless** fixing a proven defect (**NFR.19.6**).
4. **PO submit error UX:** On **`submitTripRequest`** failure with a **PO-related** message, **do not** open a modal; **`scrollIntoView`** (sensible block alignment) + **`focus()`** on the PO input **`id="trip-purchase-order-ref"`**; keep **`role="alert"`** / **`aria-live`** error summary as today or improve without breaking **NFR.19.2**.
5. **Accessibility:** Focus order remains logical: name → email → org notice → PO (when shown) → phone row → footer actions; **no** focus trap; visible labels on PO **`*`** required state preserved.
6. **Tests:** Extend **`TripRequestBookingShell`** / **`TripRequestPassengerSlide`** tests (or add **`TripRequestBookingShell` PO-inline** suite): PO appears **below email** when **`defaultPoRequired`**; **guest** path hides PO; mocked **submit** returning PO error triggers **focus** target (or ref callback) — **`npm run test` / `npm run lint`** green for touched files.
