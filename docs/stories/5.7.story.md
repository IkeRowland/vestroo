# Story 5.7: Responsive polish for internal routes

## Status: Done

**Dependencies:** **[Stories 5.1–5.6](5.6.story.md)** — **Done** (per user / project). **Story 5.1** delivers **`OpsShellClient`**, **`OpsSidebar`**, **`OpsTopBar`** and **`requireOpsStaffPage`**-gated **`src/app/(ops)/ops/layout.tsx`**. **Story 5.2** supplies **Tailwind ops tokens** (`data-ops-theme`, **`w-ops-sidebar`**, semantic colours) — see **[ADR 0001](../adr/0001-ops-field-ui-stack-tailwind-radix.md)** and **[`docs/ops-design-system-parity.md`](../ops-design-system-parity.md)**. **Story 5.6** delivered **field** sticky/safe-area/touch-target work — this story **extends** tablet verification for **`/field/*`** without re-scoping native driver modality.

**Explicit out of scope:** **`(marketing)`** and **`(app)`** booking routes — **unchanged** unless investigation proves a defect originates from **shared** primitives used only by internal consoles (unlikely; do **not** broaden scope preemptively). **FE.5.8** — **full** WCAG baseline (skip-link polish beyond existing ops skip link, axe CI, full contrast audit) is **not** owned here; **cross-reference** **[`docs/epic-5.md`](../epic-5.md) — FE.5.8** only. This story may apply **minimal** **`focus-visible` / overflow** fixes if they **unblock** tablet usability and stay **CSS-first** — it does **not** replace FE.5.8.

**Constraining NFRs:**

- **NFR.5.3:** Layout/shell changes MUST **not** weaken **`requireOpsStaffPage()`** (**`src/lib/ops-auth.ts`**) or **`requireChauffeurPage()`** (**`src/lib/field-auth.ts`**); no client-only bypass of staff/chauffeur gates.
- **NFR.5.2:** Prefer **CSS/layout** (`min-w-0`, `overflow-*`, flex/grid, existing **`OpsTableShell`**) over new client bundles; avoid heavy new client JS for responsive behaviour.

## Story

- As a **dispatcher, ops admin, or chauffeur using a tablet or narrow laptop**
- I want **`/ops/*` and authenticated `/field/*`** to remain **usable without horizontal clipping of primary chrome and actions**, with **predictable scroll regions** and **overlays that fit the viewport**
- so that **internal consoles work on common tablet widths** while **marketing and booking** stay governed by their own epics, and **security gates** stay **server-first**

## Epic traceability (source)

**From `docs/epic-5.md` — FE.5.7:** **`/ops/*` and authenticated `/field/*`** MUST be usable on **tablet widths** without horizontal clipping of **primary actions**: **sidebar collapse** behaviour, **scroll regions**, and **modals/drawers** MUST be verified at **agreed breakpoints**. **Marketing and booking** flows remain governed by existing epics; this story targets **internal** consoles.

## Acceptance Criteria (ACs)

1. **Agreed breakpoints (documented in-repo):** Record Vestroo’s **verification widths** and Tailwind alignment in the **verification subsections** (see **AC7**):
   - **Phone / narrow:** **under 768px** — Tailwind **default** (below **`md:`**). Ops: **drawer sidebar** + top bar **menu** control; field: **mobile-first** layout from Story 5.6.
   - **Tablet / small laptop:** **768px–1024px** — align checks with **`md:`** (768px) and **`lg:`** (1024px) as used in **`src/features/ops/components/OpsSidebar.tsx`**, **`OpsTopBar.tsx`**, **`OpsShellClient.tsx`**, and **`src/app/(field)/field/layout.tsx`** (`sm:` / `md:`). **Do not** introduce a custom breakpoint scale inconsistent with **`tailwind.config.ts`** without ADR note (not expected).

2. **`/ops/*` — shell and main column:** At **768px, 820px (common tablet), 1024px**, and **390px** (phone):
   - **Sidebar:** **Below `md`:** off-canvas drawer + backdrop; **`md` and up:** sticky column with **expand/collapse rail** (`collapsed` vs full width per **`w-ops-sidebar` / `w-ops-sidebar-collapsed`**). No **primary nav** labels permanently clipped when expanded; collapsed mode shows **icons + `aria-label` / `title`** as today.
   - **Main column:** The **flex main stack** (**`OpsShellClient`**) MUST **not** cause **page-level horizontal scroll** due to shell chrome alone (`min-w-0` on flex children where needed). **Primary** top-bar actions (**search** affordance, **sign out**, **notifications** placeholder) remain **reachable** without horizontal panning (wrapping or shrink rules acceptable).
   - **Scroll regions:** Long **sidebar** nav scrolls inside the nav panel (**`overflow-y-auto`** on `#ops-sidebar-nav`); long **page** content scrolls in **`#ops-main`** without trapping focus incorrectly. If a route needs **inner** horizontal scroll for **tabular** data, it MUST use **`OpsTableShell`** (or equivalent documented pattern) so **wide tables** do not blow out the **entire** viewport width.

3. **`/ops/*` — dialogs and future overlays:** Audit **Radix `AlertDialog`** usage on ops flows (**e.g.** **`src/features/ops/components/TripOpsForms.tsx`**, **`ComplianceDsrPanel.tsx`** via **`@/components/ui/alert-dialog`**). At **390px** and **768px** widths, **`AlertDialogContent`** MUST remain **visible and dismissible** (no off-screen **primary** buttons; **`max-w-lg` + `w-full`** must leave **usable margins** — adjust **padding / `max-h` / `overflow-y-auto` on content** only if required). **Sheet / Dialog:** If **no** Sheet exists on ops pages at implementation time, **document “none yet”** in verification notes and ensure **AlertDialog** cases above pass; any **new** Sheet/Dialog added before this story closes MUST meet the same viewport rules.

4. **`/field/*` — tablet trip actions:** On **768px** and **1024px** (and **820px**), **trip detail** primary flows (**Confirm assignment**, **Mark completed**, **maps** links, **Call customer** when shown) MUST **not** clip horizontally when **`FieldTripDetailActions`** uses **`stickyFooter`** (Story 5.6): sticky region **`max-w-3xl`** aligned with **`main`** in **`src/app/(field)/field/layout.tsx`**, **`overflow-y-auto`** in footer, **`env(safe-area-inset-bottom)`** preserved. **List page** **`/field`** MUST keep **touch targets** and **wrapping** consistent with **`min-h-11`** patterns.

5. **Regression guard — auth and route groups:** After changes, **`requireOpsStaffPage()`** still runs from **`src/app/(ops)/ops/layout.tsx`** for protected ops routes; **`requireChauffeurPage()`** from **`src/app/(field)/field/layout.tsx`** for protected field routes. **No** new **client-only** “layout” that renders privileged UI without the existing server gates.

6. **Deviation handling — wide content:** Ops pages with **intrinsically wide** content (e.g. **kanban** **`/ops/board`**, **calendar** **`/ops/calendar`**, multi-column filters) MAY scroll **horizontally inside a deliberate region** (board columns, table **`OpsTableShell`**) as long as **shell chrome** and **primary page actions** (section headers, **OpsActionGroup** primary buttons where present) **do not** require horizontal scroll to **discover** or **activate**. Document any page-specific **exceptions** in **Deviation Analysis** (story) and a **one-line** note in **AC7** docs.

7. **Verification documentation:** Add a **short manual checklist** (target widths, **pass/fail** criteria, **no** full visual regression suite) to:
   - **[`docs/ops-console.md`](../ops-console.md)** — **`/ops/*`** shell, sidebar, top bar, main scroll, **AlertDialog** spot-checks; and
   - **[`docs/field-tools.md`](../field-tools.md)** — **`/field/*`** tablet checks for list + trip detail **sticky** actions.

   Each subsection MUST list **at least** widths **390, 768, 820, 1024** (CSS pixels) and **Pass** definition: *no horizontal overflow required to use **primary** chrome/actions* (per AC2/AC4), **Fail** if **primary** control is off-screen or **unreachable** without zoom. **Optional:** one cross-link sentence from **[`docs/ops-design-system-parity.md`](../ops-design-system-parity.md)** to these checklists if parity doc is the canonical index for FE.5.2 — **not required** to duplicate full tables there.
