## Story

- As a **customer who received a walk-in quote**, I need an **“Accept & pay”** landing page at **`/q/[token]/accept`** that verifies my token and redirects me to **PayFast**, so that **I can commit to the quote without creating an account** — **Q14**, **US-C1** (**[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C**).
- As **ops/product**, we need **accept** to be **safe for superseded quotes** and **idempotent for already-accepted / paid** paths, so that **we do not double-charge** and **stale tokens fail closed** — **§6**, **US-C1** AC5–6.

## Acceptance Criteria (ACs)

### US-C1 — Accept route + PayFast handoff (Theme C) + Q14

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C — US-C1** lines ~111–118; **Q14**; **§6** superseded risk; **§8** paths.)_

1. **Route (final path fixed in this story):** Implement a **server** route whose path is **`/q/[token]/accept`**, where **`[token]`** is a **dynamic segment** — **opaque string** (the signed token from **14.6+** email links). Place the route under **`src/app/(public-ops)/`** **or** **`src/app/(quote)/`** per epic **§1** / **§8** (group choice documented in **Dev Technical Guidance** / **Progress Notes**).

2. **Token verification (14.2 contract):** On request, call **`verifyQuoteToken`** with **`expectedPurpose: 'accept'`** (per **14.2**). Handle **`{ valid: false, reason }`** for **`'expired'` | `'invalid_signature'` | `'malformed'`** with **distinct, user-safe** server-rendered outcomes **TBD** where epic requires nuance: invalid signature vs expired vs wrong purpose — each maps to a **friendly** error page (not a raw 500). **Invalid/expired** path must include **Q17** “Request a new quote” CTA (**US-C1** AC4; **[`docs/epic-14.md`](../epic-14.md)** Q17 ~lines 48–49 — deep-link pattern: trip inputs only, **no PII**). If full pre-fill needs a booking fetch and token verification fails **before** DB load, **minimal** CTA may deep-link to **`/book`**; if verification succeeds enough to load **`booking_id`**, **best-effort** query pre-fill per Q17 (**document chosen behaviour** in **Progress Notes**).

3. **Load quote + booking guardrails:** After token **`valid: true`**, load **`booking_quotes`** by **`quoteId`** from payload; assert row belongs to **`bookingId`** from payload. **Only** if **`booking_quotes.status === 'sent'`** proceed to success flow. Otherwise render **appropriate UX**: already **accepted** / **rejected** / **superseded** / **expired** (DB state vs token expiry — both may exist) per **US-C1** and **§6** (superseded → not actionable as `sent`).

4. **Success flow (Q14 — atomic / ordered):** When checks pass, perform transitions and PayFast handoff so there is **no** customer-visible “accepted but not paying” state: transition quote **`sent → accepted`**, booking **`quote_sent → awaiting_payment`**, then call existing **`processPayment`** (server action) to obtain the PayFast checkout URL and respond with **302** redirect to that URL. **Order/atomicity:** Implement **DB updates + payment URL generation** in the correct order; use a **single transaction** or **documented ordering** that prevents inconsistent reads (e.g. accepted without awaiting redirect) — **TBD** in implementation with project DB helpers.

5. **PayFast integration:** **`processPayment`** must continue to use the existing **`return_url`** and **`cancel_url`**; customer must still land on existing **`/confirmation`** and **`/book/payment?error=cancelled`** flows **unchanged** (**US-C1** AC3). **No** edits to **`src/lib/payfast.ts`** unless required to fix a discovered defect — default **reuse only**.

6. **Already accepted / paid (idempotency):** If the quote is **already accepted** or payment already progressed such that a **second checkout** must not run, render a friendly **“already accepted — check your email”** (or equivalent) page (**US-C1** AC5). **Do not** call **`processPayment`** again without a **guard** that prevents duplicate charges / duplicate payment sessions (**spell expectation** in code comments or story notes).

7. **SSR / a11y:** Pages are **server-rendered**; **no** required client JS beyond **project-standard** analytics if any (**US-C1** AC6).

8. **Webhook:** **No** changes to **`src/app/api/payfast/webhook/route.ts`** unless a bug is found (**[`docs/epic-14.md`](../epic-14.md)** **§8**).

9. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 2** (**14.3**), **§4 Theme C (US-C1)**, **Q14**, **§4 Theme G 14.3**, **§6** superseded risk, **§7** golden-path partial, **§8** paths.
