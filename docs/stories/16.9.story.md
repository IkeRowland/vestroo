1. **Migration file:** New migration named **`YYYYMMDDHHMMSS_ops16_availability_check_columns.sql`** (timestamp chosen at implementation time; suffix **exactly** **`ops16_availability_check_columns`**) containing SQL **equivalent** to **[`docs/epic-16.md`](../epic-16.md)** **US-B1** snippet (~208–224):
   - **`alter table public.bookings`** with **`add column if not exists`** for:
     - **`availability_checked_at timestamptz null`**
     - **`availability_checked_by uuid null references public.profiles(id) on delete set null`**
     - **`availability_check jsonb null`**
   - **`comment on column`** for all three columns — text **matches epic intent** (staff completion time, staff profile id, JSON snapshot including override semantics **as described in epic**).
   - **`create index if not exists idx_bookings_availability_checked`** on **`(availability_checked_at)`** **`where availability_checked_at is not null`**.
2. **RLS inheritance:** **Do not** add a new **`create policy`** on **`bookings`** for this story. Document in **Progress Notes** that **`bookings_update`** (Epic 12 / VST-14 lineage, Epic 14.1 comment) already governs staff **`UPDATE`**; new columns are **not** excluded by policy text and therefore **inherit** staff write access where **`public.is_staff(auth.uid())`** holds.
3. **Field-role verification:** Confirm (read **`pg_policies`** + policy definitions in migrations; optional **smoke** behaviour) that an **`authenticated`** session representing a **chauffeur / field driver** (**not** `is_staff`) **cannot** successfully **`UPDATE`** **`availability_checked_at`** / **`availability_checked_by`** / **`availability_check`** on a row they might **SELECT** via **`bookings_select_chauffeur_linked`** (expect **no row updated** or **`42501`** per Postgres behaviour — assert the **intended denial** in **smoke_rls** or document the **exact** outcome in **Progress Notes** with migration citation).
4. **`smoke_rls.sql`:** Add a dedicated block (numbered comment consistent with file style, e.g. **“Epic 16 / Story 16.9 — Theme B / US-B1”**) that **replaces** the epic’s placeholder (~228–236) with **executable** checks, including at minimum:
   - Columns exist on **`public.bookings`** (**`information_schema.columns`** or **`pg_attribute`**).
   - Index **`idx_bookings_availability_checked`** exists (**`pg_indexes`** / **`pg_class`** pattern consistent with nearby blocks).
   - **`COMMENT ON COLUMN`** present for all three columns (**`pg_description`** joined to **`pg_attribute`**, or equivalent used elsewhere in **`smoke_rls.sql`**).
   - **Staff positive control:** **`UPDATE`** on a fixture booking as **`is_staff`** identity (reuse patterns from **§14** / staff fixtures) sets the three columns and passes **`WITH CHECK`**.
   - **Driver negative control:** under chauffeur JWT / **`set_config('request.jwt.claim.sub', …)`** + **`set local role authenticated`**, an **`UPDATE`** that only touches availability columns **does not** persist (or raises **`42501`**) — match assertion style to how other blocks express success/failure.
   - **Optional / if low-cost:** assert a **customer** session cannot read another customer’s **`availability_check`** blob (portal isolation pattern already in file — only if a **minimal** extension fits without broadening scope).
