## Acceptance Criteria (ACs)

### US-E2 — E2E + smoke (Theme E) — **13.12 slice (full US-E2 + §7 testing)**

_(Epic **[`docs/epic-13.md`](../epic-13.md)** **§4 Theme E — US-E2** — lines ~164–170; **§7 Definition of Done** testing bullets.)_

1. **Happy path (Theme A + B + C + D):** Playwright: **account** booking with **healthy** account data → **dispatch without prepayment** succeeds → **`booking_quotes`** row exists / **`bookings.current_quote_id`** consistent with implemented UI → email path exercised with **Resend mocked** → **`rendered_html`** is **non-null** after send (or equivalent contract asserted against DB/API used by tests) → **`rendered_html`** assertion: **does not** contain the literal substring **`{{`** → after **trip completed**, booking reaches **invoicing queue** contract (**`ready_to_invoice`** or UI list equivalent used in **13.10**).

2. **Reason-code blocks (Theme A):** Playwright: for **each** reason code required by **`can_dispatch_account_booking()`** / ops copy module, a **seeded** scenario renders the **correct block** (human copy or stable **`data-testid`** contract per project norm). **Minimum explicit scenarios:** **`account_suspended`**; **`credit_limit_exceeded`** showing **outstanding**, **this booking**, and **limit** numbers as per **Q11** / **13.2**; **PO-required** booking **without** **`purchase_order_ref`** (**`po_required_and_missing`**). **Non-overridable** codes must **not** expose override affordances.

3. **Admin override (Theme A, Q12):** Playwright: **`credit_limit_exceeded`** — user with **`dispatcher`** role: block visible, **no** override button (or control); user with **`admin`** role: override visible, submit blocked until **reason** meets **min length**, success re-runs dispatch path → assert **`ops_audit_log`** row with **`action='dispatch_override'`** and payload including **`original_reason_code`**, **`override_reason`**, **`booking_id`**, **`overridden_by_profile_id`** (exact column shapes per implementation).

4. **Resend failure + retry queue (Theme C, Q9):** Playwright: **Resend** client **mocked**; simulate **HTTP 500** (or SDK-equivalent failure) on send so **trip/quote are not rolled back** → assert **retry queue** surfaces the booking/quote row per **13.8** UI (or stable empty-state inverse assertion documented in **Progress Notes** if UI is sub-route).

5. **Smoke RLS:** Update **`supabase/smoke_rls.sql`** so smoke coverage includes **`ready_to_invoice`**, **`invoiced`**, and **`paid_invoice`**: **staff** can perform allowed writes; **customer** policies allow read **where applicable** (mirror existing smoke patterns for **`bookings.status`** transitions).

6. **§7 DoD — breadth:** Test suite layout documented under **`tests/e2e/`** (or repo-standard path): one or more specs may split by theme, but **traceability** to **Theme A–D** and **US-E2** is obvious from file names / describe blocks.

7. **Types & CI:** **`npm run build`** and **Playwright** (**`npm run test:e2e`** on your runner or local machine) remain **green**; no flaky timing — use **`expect.poll`** / network idle patterns consistent with existing **`tests/e2e/`** specs.

8. **Traceability:** Maps to **[`docs/epic-13.md`](../epic-13.md)** **§3** Phase **5**, **§4 Theme F** **13.12**, **§4 Theme E — US-E2**, **§6** template-typo risk, **§7 DoD** testing bullets, **§8** tests + smoke paths.

9. **Primary touchpoints (paths-only):** `tests/e2e/*.spec.ts` (new or extended); shared Playwright **fixtures** / **seed** helpers if the repo already uses them; **`supabase/smoke_rls.sql`**; optional **`.env.test`** / test seed SQL documented in **Progress Notes** only if required.
