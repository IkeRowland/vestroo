## Story

- As **ops staff**, I need a **dedicated retry panel** listing **booking quotes** that need a **trip confirmation email** resent or completed after a **send failure**, so that **transient SMTP/API issues** do not silently drop customer comms (**US-C2**, **Q9**).
- As **ops staff**, I need a **“Retry now”** action that calls **`retrySendBookingQuoteEmail(quoteId)`** and is **safe to click twice**, so that **I don’t double-email** customers (**US-C2** third **AC**, **13.4** **`idempotency_key`**).
- As **ops staff**, after **three** failed retries on a quote, I need a clear **warning** and **“Mark failed, will contact manually”** so the row **leaves the queue** and **finance/ops** have an **audit trail** of manual follow-up (**US-C2** fourth **AC**).

## Acceptance Criteria (ACs)

### US-C2 — Email retry queue & manual exit (Theme C)

1. **Failure handling (no rollback + audit):** On Resend failure (timeout, **5xx**, rate-limit), **trip and quote rows are NOT rolled back**; **`booking_quotes`** remains consistent with **Q9** / **13.7** (typically **`status='sent'`** after dispatch send). Failure is recorded in **`ops_audit_log`** with **`action='email_send_failed'`** and **`payload`** including **`quote_id`**, **`error_message`**, **`attempt_count`** — **may already exist from [`docs/stories/13.7.story.md`](../stories/13.7.story.md)**. **13.8** must define the **retry candidate** query to match **[`docs/epic-13.md`](../epic-13.md)** **§4 US-C2** second **AC**: quotes with **`status='sent'`** where **`rendered_html IS NULL`** **OR** an **`email_send_failed`** entry is **more recent** than any **`email_sent`** entry (per **`ops_audit_log`** timestamps / ordering). If **`email_sent`** rows are **missing** from the live path after **13.7**, **gap-fill** with **`email_sent`** append on successful send **or** an explicitly documented alternative ordering rule (**Dev Technical Guidance** + **Progress Notes**).

2. **Ops panel route:** New ops UI at **`/ops/bookings`** **or** a sub-route **`/ops/bookings/comms-retry`** lists **retry candidates** (paginated or scrollable per existing ops patterns) — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-C2** second **AC**; **§8** **`EmailRetryQueue`**.

3. **Retry action + idempotency:** Each row exposes **“Retry now”** invoking **`retrySendBookingQuoteEmail(quoteId)`** (server action or equivalent **ops**-safe module). The action is **idempotent** via **`booking_quotes.idempotency_key`** (and/or existing **Resend** idempotency — document) so **duplicate invocations** do not double-send — **US-C2** third **AC**, **13.4**.

4. **Three-strike + manual exit:** After **3** failed **retry** attempts (define whether this counts only **post–initial-send** retries or includes the **first** failed **`sendBookingQuote`** attempt — pick one rule, document in **Progress Notes**), the row shows a **warning** badge and offers **“Mark failed, will contact manually”**, which **removes** the quote from the **retry queue** and **appends** an **`ops_audit_log`** row (e.g. action name consistent with repo conventions such as **`email_retry_abandoned`** or **`comms_manual_followup`** — **must** be **approved** in implementation notes / migration if new enum-like action strings are restricted) — **US-C2** fourth **AC**.

### Completion Notes List

- **AC1 / ordering:** Implemented **`email_sent`** gap-fill on successful **`sendEmail`** in **`sendBookingQuote`** (`mode: 'sent'` or **`skipped_test_mode`**), payload `{ quote_id, mode }`, so **`email_send_failed` vs `email_sent`** ordering is defined. - **`attempt_count`:** Derived **only from audit rows** before each new failure: count of **`email_send_failed`** for that quote with **`created_at` > latest `email_sent`** (or all failures if no **`email_sent`**), then **`+ 1`** for the payload of the new row (initial send + retries stay consistent).
- **AC2 / UI:** Route **`/ops/bookings/comms-retry`**, component **`src/features/ops/components/EmailRetryQueue.tsx`**, sidebar link **Comms retry** (`ops-nav-config`).
- **AC3 / idempotency:** Initial send uses Resend idempotency key **`trip-confirmation-send:`** + **`booking_quotes.idempotency_key`** (fallback quote id). Retry uses **`trip-confirmation-retry:{quoteId}:{latestFailureIso}`** with sentinel **`no-email-send-failed`** when the queue row has no failure timestamp (missing-html-only wave). **`retrySendBookingQuoteEmail`** short-circuits with **`idempotent: true`** when the quote is absent from the RPC list (stale UI / already recovered).
- **AC4 / strikes:** **`failure_strike_count`** in the RPC equals audit failures since last **`email_sent`** (includes the first **`sendBookingQuote`** email failure when no **`email_sent`** yet). UI shows warning + **Mark failed** at **`>= 3`**. Manual exit appends **`email_retry_abandoned`** (audit-first; no **`booking_quotes`** column).
- **AC5 / Q9:** No RPC or status rollback on retry failure or abandon; quote stays **`sent`**.
