## Story

- As **a developer shipping `/account/*` and `/ops/*`**, I need **one home** for SaaS-grade **presentation primitives** (KPI cards, charts, pills, pagination, split view, detail rail, empty/loading/error states), so **Wheelzie-inspired** UI stays **consistent** without **copy-paste** between consoles.

- As **the design system**, we need **`theme` / composition**-driven tokens (**`ops`** vs **`account`**) and **chart** colours via **`currentColor`**, so **NFR.18.4** theme isolation stays intact and **a11y** patterns remain **centralised** (**NFR.18.5**).

## Acceptance Criteria (ACs)

1. **Inventory (**Task 0**):** Document in **Progress Notes** (or story appendix) a table mapping each epic-listed primitive to **current** **`src/features/ops/components/`** source files (e.g. **`OpsKpiCard.tsx`**, **`OpsSparkline.tsx`**, **`OpsBarChart.tsx`**, **`OpsDonutChart.tsx`**, **`OpsAreaChart.tsx`**, **`OpsStatusPill.tsx`**, **`OpsAvatarCell.tsx`**, **`OpsPagination.tsx`**, **`OpsSplitView.tsx`**, **`OpsDetailRail.tsx`**, **`OpsEmptyState.tsx`**, **`OpsLoadingRegion.tsx`**, **`OpsErrorState.tsx`**) and **test** co-locations — **no** behaviour rewrite; **move / rewire** only.
2. **Shared location:** Implement shared modules under **`src/components/saas/`** **or** **`src/components/ui/`** per **FE.18.13** epic rule; **Task 0** locks the path and **barrel** export strategy (**`index.ts`**).
3. **Theming:** Shared **`KpiCard`**, **`StatusPill`**, **`EmptyState`**, **`LoadingRegion`**, **`ErrorState`**, **`Pagination`**, **`SplitView`**, **`DetailRail`**, **`AvatarCell`** accept **`theme="ops" \| "account"`** and/or **`variant`** per **Reconciliation**, composing **`ops.*`** vs **`account.*`** Tailwind classes **without** importing account components into ops routes incorrectly (**NFR.18.4**).
4. **Charts:** **`Sparkline`**, **`BarChart`**, **`DonutChart`**, **`AreaChart`** use **SVG** + **`currentColor`** (and existing tone tokens where applicable); **no new** charting **npm** dependencies (**NFR.18.2**).
5. **`/ops/*` import stability:** Either **update** imports to shared paths **or** provide **`Ops*`** thin re-exports from **`src/features/ops/components/`** so **existing** deep links to ops feature modules **do not** mass-break CI (**Reconciliation** — **phased** OK).
6. **`/account/*`:** No **required** consumption of every primitive in this story **if** time-boxed; **where** used, components **must** use **`theme="account"`** (or equivalent) and **only** under **`data-account-theme`** subtree.
7. **No auth / data / RLS changes:** **NFR.18.1** — primitives remain **dumb UI**; **no** changes to **Supabase**, **server actions**, or **session** models.
8. **Server-first posture:** **No** new **`'use client'`** boundaries **unless** required for **existing** interactive behaviour (e.g. split view drag); **do not** move server-only parents to client solely for this extraction (**NFR.18.3**).
9. **Accessibility:** Preserve **roles**, **labels**, **focus** behaviour, and **keyboard** paths from **Epic 17** implementations; **add** tests if gaps found during move (**NFR.18.5**).
10. **Tests:** **Vitest** — move or re-point tests with components; **no** dropped coverage for moved **`Ops*`** units; **`npm run test`** green.
11. **Lint:** **`npm run lint`** green; **no** **`eslint-disable`** churn unless pre-existing.
12. **Documentation:** **`docs/ops-design-system-parity.md`** — new **`§ 18.3`** (**Story 18.3 / FE.18.13**): primitive list, **file paths**, **`theme` / `variant`** contract, **cross-links** to **§ 17.x** ops originals; **explicit note** that **Story 18.13** finishes **full § 18** + **`ui-ux-specification.md`** updates.
13. **Duplication:** After migration, **grep** confirms **no** second copy of the same **SVG/path math** or **KPI card layout** left under **`features/ops`** except **thin wrappers** (document exceptions in **Progress Notes**).
14. **Epic alignment:** PR description references **FE.18.13** and **Story 18.3**; **does not** claim **Story 18.13** (doc finalisation) scope.
