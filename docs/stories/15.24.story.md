## Story

- As **Vestroo** (and as an **email recipient** subject to **POPIA** / best-effort **CAN-SPAM** alignment), I need **outbound non-transactional HTML emails** that go through the **comms matrix / established email pipeline** to include a **compliant footer** (sender identity, contact, address) and **working** **manage preferences** / **unsubscribe** links that use the **same** **URL and query** contract as **[`15.23`](15.23.story.md)**, and I need **transactional** **operational** email to **never** be framed as “marketing opt-out” or be **skippable** because someone turned off **non-transactional** categories — with **List-Unsubscribe** **headers** on applicable **non-transactional** sends when **Resend** (or configured provider) allows.

## Acceptance Criteria (ACs)

1. **Survey and mapping — `CommsEventKey` vs category:** A **documented** mapping (table in **Dev Technical Guidance** + code comments or shared const module) classifies each **`CommsEventKey`** (and any **template-only** / **pre-matrix** path included in **scope**, e.g. `sendEmail` call sites) as **`transactional`**, **`informational`**, or **`marketing`** for the purpose of **footer inclusion** and **link** behaviour. **Keys** for preference toggles **must** match **`comms_preferences`** in **[`15.23`](15.23.story.md)** (`informational`, `marketing`, `transactional`). If the product needs a **new** column (e.g. on **`comms_templates`**) or **metadata** block for **category**, add it in **migration** and **document** — **avoid** divergent ad-hoc strings in templates only.

2. **Non-transactional HTML — POPIA / CAN-SPAM–style footer:** For every **outbound** **HTML** **email** in **scope** that is classified **`informational`** or **`marketing`**, the **rendered** body **includes** a **footer** block (dedicated **section** or **append** after main content) containing at minimum: **legal / trading name** (or **DBA** as product agrees), **contact email** (e.g. **`SUPPORT_EMAIL`**
   or **dedicated** env), and **physical address** (postal or street per legal advice). **Values** come from **env** (e.g. **`NEXT_PUBLIC_*`**
   and/or **`COMPANY_*`**
   as appropriate — **server vs client** rules respected: **no secrets** in `NEXT_PUBLIC_*`). **Add** or **update** **`.env.example`** for **any** **new** variables **and** one-line **purpose** comments. **Do not** apply this **full** **marketing**/**informational** **footer** block to **transactional** **HTML** in a way that implies the recipient can “unsubscribe” from **required** comms; see **AC3**.

3. **Transactional HTML — no suppressible “unsubscribe from operations” (epic §6 + Q24):** Emails classified **`transactional`** (required **booking** / **payment** / **receipt**-class messages per mapping) **must not** offer **category** **unsubscribe** that **maps** to **`comms_preferences` marketing/informational** in a way that could be **read** as opting out of **legally/operationally** required notice. They **may** still include a **short** line with **company** identity and **contact** and a **factual** note that **operational** messages are **not** **preference-managed** the same way — **wording** **TBD** with **legal** copy. **`15C.2`** / matrix **dispatch** for these events **must** **bypass** **`informational`/`marketing` preference** checks (if such checks exist); if **check** is **not** yet in **`15.20`**, **implement** bypass **here** or **spike** and **file** a **one-line** follow-up **in Progress Notes** with **story** id — **epic** **DoD** requires **assertion** for **transactional** bypass (see **[`docs/epic-15.md`](../epic-15.md)** §6 row “transactional”).

4. **Preference links — absolute URL and `?category=`:** For **`informational`** and **`marketing`** **HTML** emails to recipients who **can** be associated with a **`customer_account_members`** row (i.e. **portal-eligible** **known** **member** **context** in the **send** pipeline), **“Manage email preferences”** and/or **“Unsubscribe from this type of message”** links use an **absolute** app URL to **`/account/preferences`** with **[`15.23` canonical query](15.23.story.md):** **`?category=<informational|marketing>`** (and **`transactional`** only if product insists for **clarity** — default **not** in **unsubscribe** CTA for **non-transactional**). **Unsubscribe** in **US-B3** terms is **satisfied** by **opening** the **preference centre** with the **relevant** section **pre-highlighted**; **writes** and **“next send respects the setting”** are **entirely** the **15.23** portal behaviour — **immediate** **persist** per **15.23** (e.g. **per-toggle** and/or **Save**).

5. **Unauthenticated user — login + returnUrl:** If the recipient is **not** **logged in**, the **link** to **`/account/preferences?...`** **must** result in **auth** **gating** that **redirects to login** with a **`returnUrl`**
   (or project-standard **redirect** param) **preserving** the full **`/account/preferences`** path **and** **`?category=...`**
   **query** so **after** login they land on the **highlighted** state. **AC** a **manual** or **E2E-capable** **description** of this path (or add a test if the repo pattern exists). Implement the **minimum** **routing** **glue** in the **account** auth flow if **returnUrl** to **`/account/preferences`**
   is not yet supported — do **not** require a full auth redesign.

6. **No `customer_account_members` (walk-in / guest):** For **walk-in** and **other** recipients with **no** **member** row, **do not** emit **member-specific** **preference** **URLs** that would **imply** a **portal** **account** **exists**. **Defensible** **default (pick in implementation, document in DG):** **footer** with **company** + **address** + **`mailto:`** and/or a **static** **marketing** **opt-out** or **contact** line pointing to a **public** page (e.g. **marketing** site **/contact** or **privacy** URL **from** **env**). If **epic** **Q20** **excludes** **walk-in** **portal**, this story **reinforces** that **by** not **faking** **signed-in** **experiences** for **non-members**.

7. **`List-Unsubscribe` (stretch with documentation):** For **`informational` / `marketing`**
   **HTML** **email** where **Resend** (or **configured** **provider** API) **allows** **custom** **headers**, set **`List-Unsubscribe`** (and **`List-Unsubscribe-Post`**
   **if** one-click is **supported** **without** **new** **token** **backend** — **otherwise** **omit** **one-click**). If the **provider** **does** **not** support **arbitrary** **headers** in **v1**, **document** **the** **limit** **in** **Progress Notes** and still **ship** **visible** **footer** **links** (AC2–4).

8. **Pipeline coverage:** **Minimum** path set to **audited** in **Tasks**: **`sendEmail`**-based **sends** consumed by the **comms** **matrix** ( **[`15.20`](15.20.story.md)**
   ) for **`quote_sent_account`**, **`quote_sent_walk_in`**, **`payment_received`**, and **any** **other** **active** **HTML** **CommsEventKey** rows in **seeds** that are **`informational` or `marketing`**; **include** any **non-matrix** **HTML** still used in **production** for the **same** **journey** **or** **split** a **Task** to **decommission** in favour of **template**-driven **HTML** (document).

9. **No regression — transactional** **dispatch** **bypasses** **suppression** **(cross-check `15.20`):** **Send** path(s) for **`transactional`**-classified **events** **do** **not** **skip** **sends** solely because **`marketing=false`**; **if** **preference** gating is **absent** today, **footer** + **mapping** **ACs** still **hold**, and **Progress Notes** state **where** **send-time** **enforcement** **will** **land** **if** not **in** this PR.

10. **Traceability:** **Maps to** **[`docs/epic-15.md`](../epic-15.md)** **US-B3** (unsubscribe / preference **links** from **email**, **compliance**), **Q24**, **Theme E `15C.6`**; **epic** **§6** **mitigation** on **transactional** **bypass**; defers **cron**/**E2E** to **`15C.7` / `15C.8`**.
