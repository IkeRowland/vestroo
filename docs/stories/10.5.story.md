## Status: Done

**Dependencies:** **[`docs/epic-10.md`](../epic-10.md)** — **FE.10.6** (Design alignment with **product UI references** — **layout**, **spacing**, **component patterns** informed by **screenshots/mockups** while meeting **FE.10.1–FE.10.5**); **Epic [Goals](../epic-10.md)** (**integration-boundary** documentation for **ops** follow-ups); **Related NFRs** (**NFR.1.1**, **NFR.3.1**); **Non-Goals** (no **PayFast** at booking, no **instant pricing** in funnel, **no automated** client-side **email** for quote/payment-link, **no separate routes** per slide, **no guaranteed** availability / **dynamic** inventory pricing). **Prerequisites — functional funnel assumed complete:** **[`docs/stories/10.1.story.md`](10.1.story.md)** (**FE.10.1** shell). **[`docs/stories/10.2.story.md`](10.2.story.md)** (**FE.10.2** Slide 1). **[`docs/stories/10.3.story.md`](10.3.story.md)** (**FE.10.3** Slide 2). **[`docs/stories/10.4.story.md`](10.4.story.md)** (**FE.10.4** Slide 3 + **FE.10.5** submit / persistence / request-received). **Story 10.5** is **polish**, **visual alignment**, **design QA**, and **boundary documentation** — **not** a re-scope of **FE.10.1–FE.10.5** behaviour except **narrow** **regression fixes** where alignment work would otherwise **break** agreed behaviour. **[`docs/epic-1.md`](../epic-1.md)** — optional **documentation** alignment per **Relationship to epic-1** / **Recommendation** in **[`docs/epic-10.md`](../epic-10.md#relationship-to-epic-1-dependency--conflict)** (see **optional** ACs below).

**Explicit out of scope:** **PayFast** (or other) **checkout** on booking submit. **Instant rand pricing**, quote **totals**, or **fare breakdown** in the funnel. **Automated** quote or **payment-link** **email** **from** the public booking UI (**client**). **Rebuilding** slides or adding **new routes** for steps (**FE.10.1** remains **one page**, **no step routes**). **Ops console** **product** features — **except** **documentation** of **integration boundaries** where listed in **Tasks** / **ACs**. **Guaranteed** vehicle availability or **dynamic** inventory **pricing**. **Implementing** **email quote** dispatch, **payment-link generation**, or **ops** **notification** pipelines (**follow-up** stories).

**Constraining NFRs:**

- **NFR.1.1 (Web performance — [`docs/epic-10.md`](../epic-10.md)):** Alignment work **SHOULD NOT** introduce **unnecessary layout shift** (**CLS**); **images** and **async** UI **SHOULD** keep **stable** **skeletons** / **dimensions** consistent with **Stories 10.1–10.4** improvements — **Related Non-Functional Requirements**.
- **NFR.3.1 (Security):** **All** **assets** and **submission** paths **MUST** remain **HTTPS/TLS**; **MUST NOT** introduce **http** or **mixed-content** **asset** URLs — **Related Non-Functional Requirements**.

## Story

- As a **traveler** completing the **public trip-request** funnel **and** as a **stakeholder** maintaining **docs** for **ops** hand-off
- I want the **on-page** **three-slide** experience to **visually align** with **approved** **product references** (**layout**, **spacing**, **patterns**) **without** changing the **functional** contract of **FE.10.1–FE.10.5**, and I want **clear** **documentation** of **where** the **client** stops and **ops** / **follow-up** integrations (**email quote**, **payment link**) **begin**
- so that the funnel feels **cohesive** with **marketing** and **design intent**, **performance** and **security** guardrails stay intact, and **future** **ops** stories have an **explicit** **boundary** **artifact** to build on

## Acceptance Criteria (ACs)

### Reference materials — FE.10.6

1. **Reference asset location:** Product-approved **screenshots** and/or **mockups** used as **normative comparison** for this story **MUST** live under a **single**, **documented** path in the repo (for example **`docs/design/booking-funnel/`** or **`docs/assets/booking-funnel-references/`** — **exact** folder **MUST** be chosen and **recorded** in **Dev Technical Guidance**). **MUST NOT** rely on **only** external links without a **checked-in** copy or **pinned** archive **unless** product **explicitly** waives (then **document** waiver in PR).

2. **Naming convention:** Each reference file **MUST** use a **predictable** name (for example **`slide-01-ride-details.png`**, **`slide-02-choose-ride.png`**, **`slide-03-passenger-details.png`**, plus **`chrome`** / **mobile** variants if provided). **README** (or **`INDEX.md`**) in the same folder **MUST** list **each** file with **one-line** **purpose** (which **slide** / **viewport**).

3. **Comparison process:** **Dev Technical Guidance** **MUST** describe **how** **designers** and **developers** **compare** implementation to references (**side-by-side checklist**, **Figma** link if applicable, **viewport** widths — **e.g.** **360**, **768**, **1280**). **MUST** state that **functional** **FE.10.1–FE.10.5** requirements **take precedence** if a **mock** conflicts (**FE.10.6** uses **SHOULD**-level alignment to references in **[epic](../epic-10.md)**).

### Slide / step chrome and structure

4. **Slide chrome alignment:** The **in-page** **slide** **structure** (**step** labels, **progress** / **stepper** if present, **slide titles**, **Next** / **Back**, **Submit** placement) **SHOULD** match the **reference** **patterns** within **existing** **shell** implementation (**[`docs/stories/10.1.story.md`](10.1.story.md)**) — **no** **new routes**; **MAY** adjust **copy**, **spacing**, **visual** **hierarchy** only. **MUST** remain **keyboard** and **screen-reader** **consistent** with **10.1** (**no** **regression** of **focus** / **announcement** patterns **without** **explicit** fix list in **Tasks**).

5. **Section hierarchy:** **Headings**, **grouping**, and **visual** **separation** between **Ride details**, **Choose your ride**, and **Passenger details** **SHOULD** align with references **where** they do not **conflict** with **accessible** **heading order** already established in **10.1–10.4**.

### Spacing, typography, and components (design system)

6. **Spacing and layout:** **Margins**, **padding**, **grid** alignment, and **vertical rhythm** **SHOULD** match references **using** **existing** **design tokens** / **Tailwind** / **component** **primitives** already used in the app — **avoid** **one-off** **magic numbers** **unless** **documented** with **reason** in PR (for example **exception** list in **Dev Technical Guidance**).

7. **Typography:** **Slide titles**, **field labels**, **helper text**, and **body** **SHOULD** use **existing** **type** **scale** and **font** **tokens**; **MAY** tune **weight** / **size** **within** **design-system** **constraints** to match references.

8. **Component patterns:** **Buttons**, **inputs**, **cards** (vehicle), **lists**, and **empty/loading/error** **patterns** **SHOULD** **reuse** **existing** **shared** **components** where available; **MAY** adjust **variants** / **composition** for **visual** parity with references — **MUST NOT** introduce **pricing**-specific **components** (**out of scope**).

### Mobile and performance

9. **Mobile polish:** At **narrow** viewports, **touch targets**, **stacking**, **readable** **line lengths**, and **non-destructive** **overflow** behaviour **SHOULD** match **mobile** references **or** **improve** on **10.1–10.4** **without** **breaking** **FE.10.1** **single-page** **semantics**.

10. **CLS / layout stability (NFR.1.1):** Visual tweaks **MUST NOT** materially **increase** **CLS** vs **baseline** **Stories 10.1–10.4**; **images** and **dynamic** blocks **SHOULD** keep **reserved** **space** / **skeletons** as already implemented — **if** **regression**, **fix** or **revert** **per** **Tasks**.

### No pricing UI — guardrail

11. **No pricing introduction:** This story **MUST NOT** add **rand** / **ZAR** / **quote** / **total** / **PayFast** **UI** or **copy** that **implies** **checkout** or **instant** **fare** — **[FE.10.3](../epic-10.md)**, **[FE.10.5](../epic-10.md)**, **[Non-Goals](../epic-10.md#non-goals)**. **Visual** alignment **MUST** preserve the **no-price** **contract** from **10.3** / **`docs/trip-request-vehicle-offers.md`** where applicable.
