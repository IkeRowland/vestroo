## Story

- As **a traveler on mobile**, I want **large `+` / `-`** controls so I can set party size **without typing**, within **1–20** (**FE.19.5**, **NFR.19.2**).

- As **a keyboard user**, I can still **adjust the value** with meaningful **`aria-valuenow`** and **clear min/max disabled state** (**FE.19.5**).

- As **a traveler comparing vehicles**, I see when my **party exceeds** a class’s **capacity** — **dimmed** card + **short** hint — **without** losing a **valid** choice I already made if I **fix** passenger count on slide 1 (**FE.19.5**).

## Acceptance Criteria (ACs)

1. **Slide 1 stepper:** **`TripRequestRideDetailsSlide`** replaces the **number** `<Input>` with a **stepper**: primary **`−`** / **`+`** around the **current** count; **min 1**, **max 20** (**epic** lines **112–114**).
2. **Schema unchanged:** **`RideDetailsFormValues.passengers`**, **`validateRideDetailsStep`** (range **1–20**), and **`validatedTripSlide1Schema`** / **`tripRequestSubmitPayloadSchema`** remain authoritative — **no** relaxed or tightened numeric rules (**NFR.19.6** / **epic** line **243**).
3. **Accessibility:** Stepper exposes **`aria-valuenow`** (and associated **roles**/labels per pattern); at **min (1)** the **decrease** control uses **`aria-disabled="true"`**; at **max (20)** the **increase** control uses **`aria-disabled="true"`** — **not** only `disabled` without semantics, unless equivalent (**epic** lines **115**, **120–121**).
4. **Touch targets:** **`−`** / **`+`** (and any hit areas that activate them) meet **≥ 44×44** CSS px on **mobile** (**epic** line **119**, **NFR.19.2**).
5. **Slide 2 capacity warning:** On **`TripRequestVehicleSlide`**, when **`validatedSlide1.passengers` > `vehicle.passengerCapacity`**, that **vehicle** card is **visually dimmed** (e.g. reduced opacity / muted border) and shows **soft** supporting text such as *“Capacity: {n} — pick a larger class”* — **warning only**, **no** auto-deselect (**epic** lines **116–117**).
6. **Selection retention:** If the user **selected** a vehicle then **returns** to slide 1 and **reduces** passengers so the party **fits**, **do not** clear that selection **only** due to passenger reduction — align with **Task 0** and **`goNextFromTrip`** reset logic (**epic** line **116**).
7. **Re-validation on Next:** **`Next`** from slide 1 still runs **`validateRideDetailsStep`**; passenger changes continue to surface **`errors.passengers`** as today (**epic** line **116**).
8. **Tests:** Extend **Vitest** / RTL for stepper **a11y** attributes, **min/max** behaviour, and slide-2 **dim + copy** when capacity exceeded; **`npm run test`** green for **`ride-details-validate`**, **`trip-request-submit-schema`**, and affected suites.
