## Acceptance Criteria (ACs)

1. **Migrations (parity SQL):** New or updated **parity** work lands as **forward-only, reviewable** SQL under **`supabase/migrations/`** per **[`docs/local-development.md`](../local-development.md)** (**timestamp-ordered** filenames, **append-only** history) and **[`CONTRIBUTING.md`](../../CONTRIBUTING.md)** (migrations **with** or **before** dependent app changes). Use **defensive / repeatable** patterns where appropriate (**`IF NOT EXISTS`**, idempotent policy names, safe guards) so reviewers can reason about **re-apply** and **promotion** risk. **RLS** MUST be **`ENABLE ROW LEVEL SECURITY`** on **new** tables that hold **tenant- or role-sensitive** data, with policies matching intended **SELECT / INSERT / UPDATE / DELETE** paths. If a deliberate **exception** is required (e.g. read-wide catalog), document it in the **PR** and matrix with a **security review** pointer (see **[`docs/staging-and-promotion.md`](../staging-and-promotion.md)** — **RLS on promotion**).

2. **VST-5 / data-models / Epic 4 vocabulary:** Table, column, and domain language for **new or altered** objects MUST align with **[`docs/data-models.md`](../data-models.md)** and **[`docs/epic-4.md`](../epic-4.md)** (**VST-5** naming — e.g. **chauffeur** / **dispatcher**, **service_**\* over transit-demo labels). **Do not** rename or weaken **established** **VST-5** vocabulary **without** product + engineering agreement; if required, add a short **Deviation Analysis** subsection (matrix or linked ADR) stating **why** and **migration** that implements it.

3. **Matrix migration citations:** **[`docs/capstone-backend-module-matrix.md`](../capstone-backend-module-matrix.md)** — for **each** row in the **authoritative domain module** master table with status **implemented** or **partial** where the **Supabase** column is **non-empty** and **not** purely **none** / **N/A** placeholders, **Notes** (or a dedicated table column) MUST cite **at least one concrete** **`supabase/migrations/<filename>.sql`** that **created** or **last materially altered** the referenced **tables**, **RLS policies**, or **views**. Prefer **comma-separated** filenames when multiple migrations own one surface. **Remove or shrink** the **[`## Migration citation gaps (BE.6.2 — Story 6.2)`](../capstone-backend-module-matrix.md)** backlog as rows are satisfied; rows that are **not applicable** / **deferred** for **[`docs/epic-9.md`](../epic-9.md)** need **no** migration cite beyond **N/A** / rationale already in the row. **FE.5.11 / BE.6.7** subsection: add migration cites **only** where that subsection references **concrete** `public.*` surfaces (not **TBD**-only rows).

4. **RLS review record:** For **every** table/policy **touched** by this story’s migrations or matrix updates, **RLS posture** (**who** can **SELECT / INSERT / UPDATE / DELETE** — by role / JWT claim / ownership) is recorded **consistently**: either in the matrix **RLS summary** column for the matching domain row, a short **appendix** subsection in the same matrix file, or both — **without** contradicting **[`docs/data-models.md`](../data-models.md)**. **NFR.3.1:** summaries MUST reflect **server + RLS** truth, not **client-only** checks.

5. **Phased delivery:** Work MAY ship as **mergeable slices** (e.g. one **domain** or **table family** per PR) provided **each** slice **updates the matrix** migration cites and RLS summaries for the rows it touches. If a **big-bang** is unavoidable, document **Deviation Analysis** (why slices are unsafe) in **Story Progress Notes** before merge.

6. **Generated types:** If **schema** changes land in **`supabase/migrations/`**, the developer MUST run **`npm run db:types`** against a **linked** project (see **[`docs/local-development.md`](../local-development.md)** — **Supabase types**); output is **`src/types/supabase.generated.ts`** per **[`package.json`](../../package.json)** — align consuming code / hand-maintained type barrels per team practice — record completion in **Progress Notes**. If **no** schema change in a slice, **note** “N/A for this PR.”
