# Story 10.4: Slide 3 — Passenger details (global phone), submit, persistence & request received (FE.10.4 + FE.10.5)

## Status: Done

**Dependencies:** **[`docs/epic-10.md`](../epic-10.md)** — **FE.10.4** (Slide 3 — Add Passenger Details; **global phone**); **FE.10.5** (Submission behaviour — **no instant quote**, **no PayFast** at booking, **recorded trip or booking request** for **ops**); **Related NFRs** (**NFR.1.1**, **NFR.3.1**, **NFR.3.2**); **Non-Goals** (no PayFast at booking, no instant pricing in funnel, **no separate routes per slide**, **no automated** quote/payment-link **email from** the public booking UI). **Prerequisites:** **[`docs/stories/10.1.story.md`](10.1.story.md)** — **FE.10.1** shell (**single page**, **three slides**, **one form section**, **Next** / **Back**, **no step routes**). **[`docs/stories/10.2.story.md`](10.2.story.md)** — **FE.10.2** Slide 1 ride details (**pickup**, **drop-off**, **date/time**, **passengers**, **instructions**, **conditional flight number**). **[`docs/stories/10.3.story.md`](10.3.story.md)** — **FE.10.3** Slide 2 vehicle selection (**exactly one** vehicle, **no-price** UI contract). This story **implements Slide 3** **and** **end-to-end submit**, **request-received** UX, and **backend persistence** per **[Suggested child stories — item 4](../epic-10.md#suggested-child-stories-implementation-sprints)**, inside the **same** **one-page** funnel — **do not** add **per-step routes** or **duplicate** the shell. **[`docs/epic-1.md`](../epic-1.md)** — Epic 10 **supersedes or amends** **FE.1.1–FE.1.4** for the **public** funnel; see **Relationship to epic-1** in **[`docs/epic-10.md`](../epic-10.md#relationship-to-epic-1-dependency--conflict)**.

**Explicit out of scope:** **PayFast** (or any **checkout**) **on** booking **submit** for this flow. **Instant rand** quote step, **fare breakdown**, or **rand totals** **in** the funnel (including **after** submit as a **gating** “quote review” step). **Automated** quote email or **payment-link** email **sent from** the public booking UI (**Non-Goals**). **Ops console** features **beyond** what is **necessary** to **persist** the request and support **request-received** / minimal **ops** visibility **if** required by the chosen persistence design. **Re-implementing** Slides **1–2** except **narrow** bugfixes **explicitly** listed in **Tasks** (default: **defer** to **10.2** / **10.3** follow-up). **Guaranteed** vehicle availability or **dynamic inventory pricing**. **Auto** payment-link generation and **email from ops** as **productized** integrations — **follow-up** stories unless epic expands.

**Constraining NFRs:**

- **NFR.1.1 (Web performance — [`docs/epic-10.md`](../epic-10.md)):** Slide 3 **SHOULD** avoid **unnecessary layout shift**; **country list** + search **SHOULD NOT** block first interaction (**lazy** load, **code-split**, or **virtualized** list as needed — **Related Non-Functional Requirements**).
- **NFR.3.1 (Security):** **All submission and personal data** (**PII**) **MUST** use **HTTPS/TLS** in deployed environments; **MUST NOT** introduce **http** or **mixed-content** for submit endpoints.
- **NFR.3.2 (SEO):** **SHOULD** preserve existing **ISR** / **App Router** conventions for the **host** booking route — **no new** **step** routes (**FE.10.1**).

## Story

- As a **traveler** on **Slide 3** of the public **trip request** flow
- I want to enter **my name**, **email**, and a **globally valid** **phone** using a **searchable country** control that sets the **international dial prefix**, then **submit** so my **full trip context** (rides **1–3**) is **saved** for **operations**
- so that I get a clear **request received** outcome **without** being forced through **instant pricing**, **quote totals**, or **PayFast**, and **ops** can follow up **out of band** per **[FE.10.4](../epic-10.md)**, **[FE.10.5](../epic-10.md)**, and **[Non-Goals](../epic-10.md#non-goals)**

## Acceptance Criteria (ACs)

### Passenger and contact fields — normative (FE.10.4)

1. **First Name:** The traveler **MUST** provide **First Name**; it **MUST** be **required** before **Submit** succeeds. Leading/trailing whitespace **SHOULD** be **trimmed** server-side (or at a single validation boundary consistent with the app) — **[FE.10.4](../epic-10.md)**.

2. **Last Name:** The traveler **MUST** provide **Last Name**; it **MUST** be **required** before **Submit** succeeds — **[FE.10.4](../epic-10.md)**.

3. **Email Address:** The traveler **MUST** provide **Email Address**; it **MUST** be **required** and pass **reasonable** **email format** validation (project-standard **Zod** or equivalent) before **Submit** succeeds — **[FE.10.4](../epic-10.md)**.

### Country and phone — global (FE.10.4)

4. **Country dropdown — completeness:** The UI **MUST** offer a **dropdown** (or **combobox**) covering **all countries** (ISO-3166–aligned country list or equivalent **complete** set — **document** source in **Dev Technical Guidance** / PR). **MUST NOT** present **only** South Africa or a **ZA-only** subset as the selectable set — **[FE.10.4](../epic-10.md)**.

5. **Country search:** The country control **MUST** support **search** (type-to-filter, **combobox**, or equivalent) so travelers can find countries without excessive scrolling — **[FE.10.4](../epic-10.md)**; **[Design Goals](../epic-10.md)** (**accessible country search**).

6. **Dial prefix behaviour:** When the traveler **selects** a **country**, the UI **MUST** set the **international dial code** as the **phone prefix** (for example **+27**, **+1**) and **MUST** make the **prefix** **visible** and **stable** relative to the selected country (implementation **MAY** store **country** + **national number** separately **or** a single **E.164** string — **document** the **canonical** persisted shape at the **server boundary**) — **[FE.10.4](../epic-10.md)**.

7. **Phone number — international, not ZA-only:** The traveler **MUST** enter a **Phone Number** that, **together with** the **country dial prefix**, forms a number that is **internationally dialable**. The implementation **MUST NOT** **restrict** input to **South Africa–only** formats, **MUST NOT** apply **ZA-only** input masking as the **only** path, and **MUST NOT** assume a fixed **10-digit SA** pattern — **[FE.10.4](../epic-10.md)**.

8. **Phone validation:** **Client** and **server** **MUST** validate the **phone** using a **strategy** appropriate for **international** numbers (for example **libphonenumber**-based validation, or **documented** rules that reject obvious garbage without hard-coding **ZA**). **MUST NOT** validate as **South Africa–only** — **[FE.10.4](../epic-10.md)**.

### Alignment with FE.10.1 (shell) and Slides 1–2

9. **One page, no step routes:** Slide 3 and **submit** **MUST NOT** introduce **distinct application routes** for this step. The traveler **MUST** remain on the **same primary URL** as **Stories 10.1–10.3** — **[FE.10.1](../epic-10.md)**; **[`docs/stories/10.1.story.md`](10.1.story.md)**.

10. **Inside the unified form:** Slide 3 fields **MUST** live **inside** the **existing** **FE.10.1** **form section** (same **`<form>`** / unified semantics as **10.1**), not a **nested** separate form — **[FE.10.1](../epic-10.md)**.

11. **Replace Slide 3 placeholder:** **10.4** **MUST** replace the **Slide 3** **placeholder** in the shell with **passenger** UI and **wired** **Submit** per this story — **[Suggested child stories — item 4](../epic-10.md#suggested-child-stories-implementation-sprints)**.

12. **Prior slides unchanged:** Implementation **MUST NOT** **rewrite** Slide **1** or **2** **fields** or **validation** except for **narrow** bugfixes **explicitly** listed in **Tasks** — **[`docs/stories/10.2.story.md`](10.2.story.md)**, **[`docs/stories/10.3.story.md`](10.3.story.md)**.

### Submission, persistence, and request received (FE.10.5 + sprint item 4)

13. **Submit affordance:** On the **last slide**, the traveler **MUST** have a **primary** **Submit** (or equivalent) that **submits** the **unified** trip-request **form** (not a **dead** / **disabled** stub once validation and persistence are implemented) — **[FE.10.5](../epic-10.md)**; shell currently documents stub behaviour in code — replace per **AC11**.

14. **Persisted record:** **Successful** submit **MUST** create or update a **durable** **server-side** record (**recorded trip** or **booking request** — exact **table** / **status** names are **implementation details**) that **operations** can use, **aligned to existing architecture** (**Next.js Server Actions** and **Supabase** patterns described in **[`docs/front-end-api-interaction.md`](../front-end-api-interaction.md)** and peers). Engineers **MUST** discover the **correct** boundary (**Server Action**, **route handler**, **RPC**) and **schema** by inspecting the repo — **do not** invent **table** names in this story unless **verified** in code or migrations.

15. **Payload shape — Slides 1–3:** The **persisted** payload **MUST** include **validated** data from **Slide 1** (ride details), **Slide 2** (selected **vehicle** identity consistent with **FE.10.3** / **no-price** types), and **Slide 3** (passenger **name**, **email**, **country**, **phone** / **E.164** or equivalent). **Exact** field mapping **MUST** follow **existing** **booking** or **trip** patterns after codebase review (**e.g.** comparison with **`createBooking`** / **`bookings`** insert shape in `src/actions/` — **whether** to **extend** or **add** a **trip-request-specific** path is **an implementation decision** documented in PR).

16. **Success UX — request received:** After **successful** persistence, the UI **MUST** present a **request received** outcome (clear **confirmation of submission**, **not** “payment successful” / **not** PayFast confirmation). Copy **SHOULD** set expectation that **ops** will follow up — **[FE.10.5](../epic-10.md)**; **[Relationship to epic-1](../epic-10.md#relationship-to-epic-1-dependency--conflict)**.

17. **No payment confirmation framing:** Success state **MUST NOT** present **paid**, **captured**, or **checkout complete** language **unless** tied to a **real** payment event (**out of scope** here) — **[Non-Goals](../epic-10.md#non-goals)**.

### FE.10.5 guardrails — no pricing, no PayFast on submit path

18. **No instant quote / rand pricing as gating:** **Submit** **MUST NOT** navigate to or present **quote options**, **instant rand pricing**, **fare breakdown**, or **totals** as a **required** step — **[FE.10.5](../epic-10.md)**; **[Non-Goals](../epic-10.md#non-goals)**.

19. **No PayFast at submit:** The submit path **MUST NOT** integrate **PayFast** (or equivalent **hosted checkout** / **payment redirect**) **at this stage** — **[FE.10.5](../epic-10.md)**; **[Non-Goals](../epic-10.md#non-goals)**.

20. **No client-automated ops email:** **MUST NOT** trigger **automated** quote or **payment-link** **email** **from** the public booking UI — **[Non-Goals](../epic-10.md#non-goals)** (**follow-up** integrations).

### Errors, loading, and safety

21. **Submit loading state:** While submit is **in flight**, the UI **MUST** show a **clear** **loading** / **disabled** pattern and **MUST** **prevent** **accidental double submit** — **FE.10.5** alignment.

22. **Error handling:** On **failure** (network, validation, server), the UI **MUST** show a **recoverable**, **user-safe** message **without** **stack traces**, raw **SQL**, **internal** keys, or **opaque** IDs **unless** product-approved for support — **[Design Goals](../epic-10.md)** (trust).

23. **HTTPS / PII (NFR.3.1):** Submit **MUST** occur over **HTTPS** in deployed environments; **MUST NOT** add **http** submit URLs — **Constraining NFRs** above.

### Accessibility and mobile

24. **Country control accessibility:** The **searchable** country control **MUST** be **keyboard** operable, with **visible focus**, and **MUST** expose **selected** country + dial prefix to **assistive tech** (for example **combobox** / **listbox** patterns, **`aria-expanded`**, **`aria-controls`** as appropriate) — **[Design Goals](../epic-10.md)**.

25. **Announce success/failure:** **Success** and **non-inline** **errors** **SHOULD** use **`aria-live`** or **focus management** consistent with **FE.10.1** shell patterns — **[`docs/stories/10.1.story.md`](10.1.story.md)**.

26. **Mobile-first Slide 3:** Passenger fields and country search **MUST** **reflow** on **narrow** viewports; touch targets **SHOULD** meet project minimums — **[Design Goals](../epic-10.md)** (**Responsiveness**).
