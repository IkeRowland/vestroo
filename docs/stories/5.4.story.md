# Story 5.4: Capstone admin feature mapping onto Vestroo ops backlog

## Status: Done

**Dependencies:** **[Story 5.1](5.1.story.md)** — **Done** (ops shell, `requireOpsStaffPage`, `ops-nav-config`, landmarks). **[Story 5.2](5.2.story.md)** — **Done** (ADR, **`docs/ops-design-system-parity.md`**, ops primitives, tokens). **[Story 5.3](5.3.story.md)** — **Done** (CRUD/data-region patterns, **`AlertDialog`**, refactored exemplar routes). This story **does not** implement product UI; it delivers a **traceability / backlog mapping** artifact for **capstone admin** only.

**Explicit out of scope:** **FE.5.5** (capstone **manager** feature mapping onto **`/ops/*` and `/field/*`**) — do **not** duplicate manager dashboard routes or analytics widgets here; **Story 5.5** may follow as the dedicated manager mapping.

## Story

- As a **product or engineering lead**
- I want a **single mapping artifact** from capstone **`frontend-admin`** screens and navigation (**`docs/capstone-reference/frontend-admin`**, especially **`src/app/_components/common/Sidebar.tsx`** and **`src/app/(page)/`**) to **Vestroo `/ops/*` routes**, **Supabase** capabilities (tables, Storage, RLS at high level), and **story IDs** (**VST-*** and/or **5.x** where applicable)
- so that **feature drift stays visible**, **prioritisation** is clear for **pricing**, **vehicle categories**, **map/geo authoring**, and **calculator**-style tools when absent, and engineers **do not** copy reference **auth**, **JWT-in-`localStorage`**, or **Firebase** patterns blindly (**NFR.5.3**, **NFR.5.4**)

## Epic traceability (source)

**From `docs/epic-5.md` — FE.5.4:** The product MUST maintain a **mapping artifact** (table or section in an existing planning doc) from capstone **admin** capabilities to **`/ops/*` routes**, **Supabase capabilities**, and **story IDs** (e.g. **VST-***). The artifact MUST include at least these **reference screens** from `frontend-admin` (see **`Sidebar.tsx`** and **`src/app/(page)/`**): **user management** (home **`/`**); **vehicle categories** (`/category`); **vehicles** (`/vehicles`, detail **`[id]`**); **staff profile** (`/profile`); **road and service-area authoring** (`/router`, including Leaflet map + routing/editing patterns—express in **corporate shuttle** terms such as **corridors**, **zones**, and **approved pickup/drop-off points**; **do not** carry over reference labels or IA tied to fixed public-transit networks); **cash flow / pricing** (`/money`—config and price rows); **price calculator** (`/cal`); **trip management** (`/trip`). It MUST also map **media uploads**: reference uses **Firebase Storage** for vehicle images (`utils/firebase`)—document the **Vestroo equivalent** (e.g. **Supabase Storage**) and any **UX gap**. **Forgot-password** and **login** flows in the reference admin MUST map to **`/ops/login`** (and equivalents) for parity of **recovery and session** expectations, **without** adopting **JWT-in-localStorage** as the security model. Each row MUST state **implemented**, **partial**, or **not started** and the **Vestroo-preferred term** where it differs from the reference. **Outcomes:** no silent feature drift; clear prioritisation for **pricing**, **categories**, **map/geo authoring**, and **calculator** tools if absent.

**Constraining NFRs:**

- **NFR.5.4:** Mapping and any embedded UI examples use **Epic 4 / VST** vocabulary (corporate shuttle, service routes, service points, trips, bookings, fleet)—not capstone **demo** or legacy **public-transit** product naming when describing Vestroo targets.
- **NFR.5.3:** The artifact MUST **not** imply that **client-stored JWTs**, **axios-to-Nest** as the default for first-party ops UI, or **Firebase** auth/storage are Vestroo patterns; it MUST point to **`requireOpsStaffPage`**, **Supabase session cookies**, **Server Actions**, and **Supabase Storage** as the intended model (aligned with **`docs/ops-console.md`**, **`docs/epic-6.md` BE.6.5**, **FE.5.9**).

## Acceptance Criteria (ACs)

1. **Artifact location and default filename:** Add a **new** primary document **`docs/capstone-admin-to-ops-mapping.md`** (default). The doc MUST be self-contained for **admin** scope; **do not** merge into **`docs/ops-console.md`** for this story (ops-console remains the **operational runbook**; the mapping links **to** it). The doc MUST start with **purpose**, **scope** (admin only), **sources** (paths under **`docs/capstone-reference/frontend-admin`**), and **last updated** date.

2. **Master mapping table — required columns:** Include a **single primary table** (allow appendix tables only if they avoid duplicating the main row set). Every **data row** MUST include at minimum these **columns**:
   - **Reference screen / capstone route** (e.g. `/`, `/category`, …).
   - **Capstone implementation pointer** (e.g. **`src/app/page.tsx`**, **`src/app/(page)/vehicles/[id]/page.tsx`**).
   - **Vestroo target** — primary **`/ops/*` route(s)** and/or explicit **“no dedicated ops route yet”** / **server-only** / **deferred** wording.
   - **Status** — exactly one of **`implemented`**, **`partial`**, **`not started`** per row (definitions footnoted: e.g. **implemented** = staffed UI + data path exists; **partial** = data or fragmented UI without full parity; **not started** = no intentional staffed surface).
   - **Vestroo-preferred term / naming** (**NFR.5.4**) — where the reference name differs (e.g. route vs **service route**, **service point** vs stop).
   - **Supabase / platform** — **tables** or **views** (by name), **Storage** buckets/patterns if relevant, **RLS** note at **high level** (e.g. staff via **`is_staff`**, admin-only actions)—no policy SQL dumps.
   - **Story / epic traceability** — **VST-*** IDs and/or **Epic 5** story refs (**5.1–5.3**, **5.4**) and **Epic 6** rows where backend ownership matters; cite **`docs/epic-4.md`**, **`docs/epic-6.md`** subsections where helpful.

3. **Minimum reference screens — one table row each (mandatory):** The primary table MUST include **at least one row** for each of:
   - **User management** — capstone home **`/`** (implemented in **`docs/capstone-reference/frontend-admin/src/app/page.tsx`** per Sidebar).
   - **Vehicle categories** — **`/category`** (list + **`/category/[id]`** as needed for traceability).
   - **Vehicles** — **`/vehicles`** and **detail `[id]`**.
   - **Staff profile** — **`/profile`**.
   - **Road / service-area authoring** — **`/router`** (Leaflet / editing patterns in reference). The row narrative MUST use **corporate shuttle** vocabulary (**corridors**, **zones**, **approved pickup/drop-off** / **service points**) and MUST **not** frame Vestroo as operating fixed **public-transit** networks (**NFR.5.4**, **Epic 9** posture for deferred **Bus**\* domains).
   - **Cash flow / pricing** — **`/money`**.
   - **Price calculator** — **`/cal`**.
   - **Trip management** — **`/trip`**.

4. **Media uploads row (mandatory):** Include at least **one** row (may be combined with **vehicles** or standalone) that states: reference **Firebase Storage** (e.g. vehicle images, **`utils/firebase`**) → **Vestroo equivalent** (**Supabase Storage** or **not yet wired**), plus a short **UX gap** note (e.g. no ops image upload vs read-only fleet).

5. **Auth & recovery row (mandatory):** Include **at least one** row covering capstone **`/login`** and **`/forgot-password`** (**`src/app/(page)/login/page.tsx`**, **`src/app/(page)/forgot-password/page.tsx`**) mapped to **`/ops/login`**, **`/ops/unauthorized`**, and **session recovery expectations** (Supabase Auth, **no** tokens in **`localStorage`** for staff console). The row MUST explicitly satisfy **NFR.5.3** / **NFR.5.4**: document **server-first** gates (**`requireOpsStaffPage`**) and **do not** present JWT-in-browser storage as an acceptable pattern for Vestroo ops.

6. **Prioritisation outcomes:** Close the document with a short **“Backlog / prioritisation”** subsection that calls out **pricing**, **vehicle categories**, **map/geo authoring**, and **calculator**-class gaps (if **not started** or **partial**) so roadmap readers see **what to schedule next** without reading the full table.

7. **Documentation index:** Add a bullet under **`docs/index.md`** (suggested: **Epic 5** area or **Additional Documentation**) linking **`docs/capstone-admin-to-ops-mapping.md`** with one-line description (**FE.5.4** admin mapping).

8. **Epic cross-link:** In **`docs/epic-5.md`**, add a **single** sentence or bullet under **FE.5.4** pointing to **`docs/capstone-admin-to-ops-mapping.md`** as the living artifact (avoid duplicating the full matrix in the epic body).

9. **Optional Sidebar extra — `/busstop`:** If included, **`/busstop`** MUST be marked **deferred / not applicable / Epic 9** (or **corporate shuttle equivalent** only with rationale)—**not** as a default Vestroo ops feature (**FE.5.10** / **Epic 9** alignment). This is **optional**; the **mandatory** rows are those in **AC3**.

10. **Verification method:** Author MUST **cross-check** Vestroo routes against the **App Router tree** under **`src/app/(ops)/ops/**`** (and public **`src/app/(public-ops)/`** for login/unauthorized if applicable) and **align** the **Status** column with what exists today; note **intentional gaps** explicitly.
