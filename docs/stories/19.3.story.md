## Story

- As **a traveler**, I want **familiar pickup/drop-off patterns** on **slide 1** — **recent** rows when I focus an **empty** field, **quick** chips for **common** hubs, and on **desktop** a **single** **origin/destination** block with **swap** — so I **complete addresses faster** without losing **validation** from **`validateRideDetailsStep`** (**FE.19.3**).

- As **privacy-conscious traveler**, I expect **recent** address hints to stay **in-session** unless I’m **signed in** and **opted in** (**NFR.19.4**).

- As **a11y-conscious traveler**, I need **swap** to expose an **`aria-label`** and motion that **respects** **WCAG** expectations (**NFR.19.2**).

## Acceptance Criteria (ACs)

1. **`AddressAutocomplete` retained:** **Pickup** and **drop-off** continue to use **`AddressAutocomplete`** with **Google Places** via existing **`loadGoogleMapsPlacesClient`** / **`@types/google.maps`** — **no** **new** npm dependency for maps (**epic** lines **82–83**, **Non-Goals** line **34**).
2. **Recent searches (focused + empty):** When a **pickup** or **drop-off** input is **focused** and its **controlled text value** is **empty**, show **recent** booking searches **from this tab session** (session storage); **no cross-session** persistence **unless** authenticated **and** opted-in per product (**epic** lines **83–84**, **NFR.19.4**).
3. **Featured chips:** Render **quick-select chips** for **common pickup locations** using data from **`loadFeaturedPickupLocations`** (implement if missing); chips are **not** personalised (**epic** line **84**).
4. **Mobile chips:** Featured chips **scroll horizontally** when they **overflow** the viewport (**epic** line **89**).
5. **Desktop grouping + swap:** At **desktop** breakpoint, present **pickup** + **drop-off** in one **“Origin & destination”** (or equivalent) **visual group** with a **swap** control that **exchanges** **pickup** and **drop-off** (**inputs + resolved `TripRequestLocation`s**) in **one** action (**epic** lines **85–86**).
6. **Swap a11y + motion:** Swap control has a concise **`aria-label`** (e.g. “Swap pickup and drop-off”); visual swap uses a **short** transition (~**200ms**) **unless** **`prefers-reduced-motion: reduce`** (**epic** lines **90–91**, **NFR.19.2**).
7. **Submit integrity:** **`validateRideDetailsStep`** and **`tripRequestSubmitPayloadSchema`** remain authoritative — **no** relaxed server rules (**NFR.19.6**); picking a chip or recent row must end in **valid** **`TripRequestLocation`**s when the user **Next**s.
8. **Tests:** Add or extend **Vitest** (and **RTL** where useful) for **swap** state, **session** recent list **dedupe/limit** behaviour, and **chip** select → **form** update; keep **`ride-details-validate.test.ts`** and **`trip-request-submit-schema.test.ts`** green.
