## Story

- As a **chauffeur** on **`/field/*`**, I need a small **informational** indicator when the **active trip** is under an account that has **live rider tracking** enabled (**`customer_accounts.live_rider_tracking === true`**), so that **I know when riders may be eligible to see live location** per account policy; I **must not** get a per-trip “turn off” control — objections are **ops / account config**, not runtime UI.

## Acceptance Criteria (ACs)

1. **Field trip detail — indicator visibility:** On **[`src/app/(field)/field/trips/[tripId]/page.tsx`](../../src/app/(field)/field/trips/[tripId]/page.tsx)** (after existing **`requireChauffeurPage`** / **`chauffeur_id`** ownership check), surface a compact, accessible **“Live tracking: ON”** label (or **PO-approved** product copy) **only** when the trip is linked to a **booking** with a non-null **`customer_account_id`** **and** the joined **`customer_accounts.live_rider_tracking`** is **`true`**. If **`customer_account_id`** is **null** (walk-in / no account) **or** the flag is **false** / account row missing → **no** indicator (no account-level live-tracking concept for walk-ins).

2. **Informational only — no chauffeur disable:** The control is **read-only** (no toggle, no “opt out” for this trip). Copy may briefly note that **account** settings control this; align with **[`docs/epic-15.md`](../epic-15.md)** **US-C4** second bullet.

3. **Account vs deploy env (single sentence):** Chauffeur awareness follows **`live_rider_tracking`** on the booking’s **account**; when the account flag is **`true`** but **`RIDER_LIVE_LOCATION_ENABLED`** is **false**, still show the primary **“Live tracking: ON”** indicator **and** a **muted secondary line**: **“Rider live map disabled in this deployment”** (exact wording **survey** in Tasks — avoids implying riders see a map when the global gate is off, without hiding account opt-in from the chauffeur).

4. **Data loading — RLS-safe path:** Extend the existing **`booking_trips` → `bookings`** load on the field trip page (or a small server helper colocated with field trip loading) to fetch **`customer_account_id`** and, when present, **`customer_accounts.live_rider_tracking`** (join or follow-up select under the **chauffeur** session). **Survey** current **`createUserServerClient`** RLS: if the chauffeur JWT cannot read **`customer_accounts`**, use a **narrow** pattern already used elsewhere (e.g. **service role** in a server-only helper **scoped** to trip + chauffeur ownership) — **document** the chosen approach in **Dev guidance** / **Progress Notes**; **do not** widen RLS globally without an explicit security story.

5. **Placement / cohesion:** Place the indicator near existing live-location affordances — **survey** **[`FieldLocationPublisher`](../../src/features/field/components/FieldLocationPublisher.tsx)** and **[`FieldTripDetailActions`](../../src/features/field/components/FieldTripDetailActions.tsx)** for least clutter (badge under trip header vs inline with publisher); respect mobile field layout (**`pb-[min(42vh,18rem)]`** sticky footer).

6. **Session / auth:** Reuse **[`src/lib/field-auth.ts`](../../src/lib/field-auth.ts)** **`requireChauffeurPage`** (or equivalent) — no new auth surface; indicator is **server-rendered** or passed as props from the same server component that already validates the trip.

7. **Tests:** Add **Vitest** for any **pure** helper (e.g. “should show primary indicator”, “should append env-off subcopy”) if logic is extracted; otherwise **minimal** component test or document **manual** verification in **Testing** — **no** Playwright requirement in this story (**15B.8** owns E2E breadth).

8. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15B.6`**, **US-C4**; **§6** chauffeur privacy awareness.
