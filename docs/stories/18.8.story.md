## Story

- As **an org member**, I want **`/account/preferences`** organised as **clear sections on separate cards** with **per-section Save**, so I can update notifications and related settings without a cluttered single form.

- As **an org admin**, I want **default billing entity** (and other org defaults where applicable) in the same hub, **gated to my role**, so org configuration stays coherent and safe (**NFR.18.1**).

- As **Vestroo**, we need preferences to match **account portal** chrome (**Wheelzie-inspired** density: white **card per section**, optional **sticky** footer row per card) and stay **server-first** with **accessible** forms (**NFR.18.3**, **NFR.18.5**).

## Acceptance Criteria (ACs)

1. **Layout:** **Vertical** stack of sections; **no tab** control for primary navigation between sections (**FE.18.7**).
2. **Visual:** Each section lives in a **distinct** light **`Card`** (or tokenised surface) on **`bg-account-canvas`**; spacing/typography consistent with **Story 18.2–18.4** account pages.
3. **Notifications:** **Informational** and **marketing** email toggles remain **functionally equivalent** to today; **`updateAccountCommsPreferencesAction`** payload/semantics **unchanged** (**Reconciliation**).
4. **Deep link:** **`/account/preferences?category=…`** continues to **scroll/highlight** the notifications area per **`parseAccountPrefsCategoryQuery`** (or successor helper) — **no** broken email footer / compliance links.
5. **Per-section Save:** **Notifications**, **Default cost centre** (if shipped), **Default billing entity** (if shipped), **Communication preferences** (if shipped) each expose a **Save** (or **Update**) control that persists **only** that section’s fields (independent dirty state **allowed** — **Task 0** defines UX for unchanged submits).
6. **Success/error:** Each section shows **inline `Alert`** for **success** and **failure** after save attempt; dismiss or replace on next action per UX consistency with other account forms — **no Sonner** (**NFR.18.2**).
7. **Default cost centre:** If **Task 0** confirms a persisted field + action path, ship **controlled input** + section Save; if **not** in schema, section **omitted** or **explicitly deferred** in **Progress Notes** (PO); **Task 0** lists which ACs remain **in scope** for the iteration.
8. **Default billing entity:** **Admin-only** section: **`<Select>`** (or **Combobox**) options bound to **org billing entities** list from server; **non-admins** do **not** see the section (**NFR.18.1**). If list loader is additive in this story, it remains **member-scoped** / **RLS-safe** as today’s portal queries.
9. **Communication preferences:** **Locale** control is **placeholder** (single fixed/disabled value acceptable); **timezone** shown **read-only** (derive from session/profile/org rule — **Task 0** picks source of truth).
10. **Sticky save (optional):** If **Task 0** opts in, section footer **sticks** within the card viewport on scroll (**Wheelzie** reference); if deferred, **Progress Notes** record deferral.
11. **Server-first:** **`preferences/page.tsx`** remains **RSC-oriented** for initial data; client boundaries **only** where needed for interactivity (**NFR.18.3**).
12. **Authorisation:** Admin-only sections match **`requireAccountPortalRoles`** (or current portal role helpers) — **no** weaker gates (**NFR.18.1**).
13. **Accessibility:** Section headings (`h2`/`h3` hierarchy), labels tied to inputs, **`Alert`** roles/live region behaviour where appropriate, keyboard **Save** — **NFR.18.5**.
14. **Vocabulary:** **B2B shuttle / organisation** language in **`account-preferences-copy.ts`** — **no** rental / Wheelzie **driver** wording.
15. **Copy / tests / lint / docs:** User-visible strings in **`account-preferences-copy.ts`**; **Vitest** for any new URL/query or small pure helpers if non-trivial; **`npm run lint`** / **`npm run test`** green; **`docs/ops-design-system-parity.md` § 18.8** (**Story 18.8 / FE.18.7**).
16. **PR hygiene:** PR cites **FE.18.7** and **Story 18.8** — **does not** claim **FE.18.8** / **Story 18.9** (profile).
