## Story

- As **an org admin**, I want **`/account/members`** to read like a **team roster** — searchable table, clear roles, last activity, and quick actions — so I can onboard and govern members without friction.

- As **Vestroo**, we need the members surface to use the **same SaaS primitives** as other account lists (**`AvatarCell`**, **`Pagination`**, **`EmptyState`**, **`LoadingRegion`**, **`theme="account"`**) while keeping **admin-only** enforcement and **existing** member actions (**NFR.18.1**).

## Acceptance Criteria (ACs)

1. **Admin-only:** **`requireAccountPortalRoles`** (admin set) unchanged; booker direct access **403** / same behaviour as today (**NFR.18.1**).
2. **Role display:** Member roles use **`portalRoleLabel`** (or equivalent shared helper) for **admin / booker** (and other roles if present in data) — **no** ad-hoc role strings in JSX.
3. **Default layout:** **Table** is the **default** view; density appropriate for **5–50** members (epic).
4. **Columns (table):** **Avatar** + **name** + **email** + **role pill** + **last active** + **actions** (menu or equivalent accessible pattern).
5. **Action menu:** **Resend invite**, **Change role**, **Deactivate** (or existing labels) wired to **existing** server actions — **no** new auth model (**epic acceptance**).
6. **Invite CTA:** Primary **"Invite member"** opens **existing** invite flow (modal recommended if it removes page clutter); behaviour matches current **`inviteAccountMemberAction`** gates (**admin-only** unchanged).
7. **Search:** Search input filters the roster **server-side** via **`searchParams`** (or agreed param name); empty query shows full page of results per **Pagination** rules.
8. **Pagination:** Use shared **`Pagination`** with **`theme="account"`** and the same **account-scoped** param names as other portal lists (**`acct_page` / `acct_per`** or existing members page convention — **Task 0** locks naming).
9. **Empty state:** When there are no members (or no search hits — **Task 0** decides copy), show **"Invite your team to book and track trips together."** (and CTA to invite where applicable).
10. **Loading / error:** Use **`LoadingRegion`** (or equivalent) for shell loading; load errors remain **non-leaky** and **accessible** (**NFR.18.5**).
11. **Optional card view:** If shipped, **toggle** + **`?view=card|table`** with **default `table`**; card rows show the same fields (**Reconciliation**). If deferred, **Progress Notes** record the deferral.
12. **Server-first:** **`members/page.tsx`** stays **RSC-oriented**; member rows from **`loadAccountMemberRows`** (or successor) on the server; **no** new client-only data tree (**NFR.18.3**).
13. **Performance / a11y:** Respect **NFR.18.6** for list path; semantic table (or list role for card layout), visible focus, keyboard operable menus (**NFR.18.5**).
14. **Vocabulary:** User-visible copy uses **members / bookers / admins / organisation** — **no** "drivers" or rental terms (**Wheelzie** is visual reference only).
15. **Copy / tests / lint / docs:** User-visible strings in **`account-members-copy.ts`**; **Vitest** for search param parsing / view toggle helpers if non-trivial; **`npm run lint`** / **`npm run test`** green; **`docs/ops-design-system-parity.md` § 18.7** (**Story 18.7 / FE.18.6**).
16. **PR hygiene:** PR cites **FE.18.6** and **Story 18.7** — **does not** claim **FE.18.7** / **Story 18.8** (preferences).
