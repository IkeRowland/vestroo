- **Gates:** Cannot send if the **booking** **`status`** is **`cancelled`** or **`expired`** — **validation error**, not silent no-op — **US-B1**.
- **Idempotent send:** Two invocations of **`sendBookingQuote`** for the same **`quoteId`** when the quote is already **`sent`** must not duplicate effects (**US-B1**; align with **`idempotency_key`** uniqueness and **at-most-once** semantics).

## Story

- As **ops staff**, I need **`createBookingQuote`** and **`sendBookingQuote`** server actions that **version** quotes, enforce **idempotency**, and **tie** the active quote to **`bookings.current_quote_id`**, so that **what was communicated** is captured before **full email wiring** (**US-B1**, **[`docs/epic-13.md`](../epic-13.md)** **§3 Phase 2**).

## Acceptance Criteria (ACs)

### US-B1 — Create & send quote (Theme B)

1. **`createBookingQuote(bookingId, lineItems, totalZar, expiresAt?)`:** Inserts a **`booking_quotes`** row with the **next `version`** for that **`booking_id`**, **`status='draft'`**, **`line_items`** serialized from **`BookingQuoteLineItem[]`**, **`total_zar`**, and **`idempotency_key = '{bookingId}:{version}'`** (stable string form) — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-B1** (first **AC**).

2. **`sendBookingQuote(quoteId)`:** Transitions the quote **`draft → sent`**; sets **`sent_at`**, **`sent_to_email`** (from account/booking context per existing data model), **`sent_by`** (staff **`profiles.id`**); may set **`rendered_html`** if available — in **13.4**, **`rendered_html`** may remain **null** until **13.7**; **atomically** updates **`bookings.current_quote_id`** to this quote’s **`id`** (same transaction as quote update) — **US-B1** (second **AC**).

3. **`expires_at` default:** If **`expiresAt`** is **not** supplied on create, set **`expires_at`** to **`now() + 14 days`** for **`account_client`** bookings — **Epic 12 Q2**, **US-B1** (third **AC**). If **`expiresAt`** **is** supplied, persist it. (Document behaviour for **`walk_in`** if the action is callable — e.g. different default per epic-12 notes — or restrict **`createBookingQuote`** to account bookings only if product-locked.)

4. **Concurrent create:** Concurrent **`createBookingQuote`** calls for the same **`booking_id`** are safe: **`UNIQUE(booking_id, version)`** prevents duplicates; implementation handles allocation so one wins and others retry or fail deterministically — **US-B1** (fourth **AC**).

5. **Idempotent send:** Calling **`sendBookingQuote`** twice with the same **`quoteId`** results in **at most one** logical send path (no duplicate **`sent_at`** mutation / no double **`current_quote_id`** churn); second call is **idempotent success** (no error storm) — aligns with **`idempotency_key UNIQUE`** intent — **US-B1** (fifth **AC**). In **13.4**, without Resend, **“one email”** means **no duplicate outbound side effects** once **`sent`**; stub/no-op does not fire twice.

6. **Booking gate:** If the booking is **`cancelled`** or **`expired`**, **`sendBookingQuote`** returns a **validation error** (structured ops error per project patterns) — **not** a silent no-op — **US-B1** (sixth **AC**).
