## Story

- As an **account admin**, I need an **invoice and quote archive** at **`/account/invoices`** with a **read-only view** of the **stored HTML** for each item, so that I can **resolve billing disputes** without contacting ops (per **US-A4**). **Bookers** must **not** access this archive or its viewer in Epic **15** scope (see ACs).

## Acceptance Criteria (ACs)

1. **List — route:** **`/account/invoices`** (replace the current **15A.2** stub) renders a **server-rendered** archive **for the active `customer_accounts` context** only, using patterns from **15.1** (active account + membership, Supabase user client, RLS as second line of defence).

2. **List — data union (survey DB, exact enums):** Rows include:
   - **(A)** All **`booking_quotes`** for **bookings** where **`bookings.customer_account_id = activeAccountId`** and **`booking_quotes.status IN ('sent','accepted','superseded','expired','rejected')`** (exact **`BookingQuoteStatusDb`** set — no **`draft`** in this list unless product explicitly adds it later).
   - **(B)** Plus **Epic 13 invoice-queue** coverage: **bookings** for the same account with **`bookings.status IN ('ready_to_invoice','invoiced','paid_invoice')`** (exact **`BookingPipelineStatusDb`** subset).
   - **Union / deduplication:** **Survey** whether **(A)** and **(B)** overlap (e.g. same booking appears in both). **AC:** Implement a **single coherent row set** without duplicate "same logical document" where avoidable. **Document the rule** in **Progress Notes** (e.g. prefer **`booking_quotes.id`** as the stable row key when a quote row exists; merge booking-level **invoiced / paid** context onto the matching quote row when both apply; for invoice-pipeline **bookings** with **no** matching quote in **(A)**, show a **booking-anchored** row with explicit handling for **View** — e.g. **latest** quote with **`rendered_html`**, or **empty** state with copy — **survey** and justify in Progress Notes).

3. **List — columns:** Each row shows (when present in schema): **booking reference** (align label/source with **15.3** list / **15.4** detail), **quote version**, **total**, **status** (quote and/or booking — clarify in UI without ambiguity), and **dates**: **sent**, **accepted**, **invoiced**, **paid** as applicable. **Survey** which timestamps live on **`booking_quotes`** vs **`bookings`** (e.g. finance hooks, Epic **13.9** / **13.10** fields) and map columns accordingly; use **"—"** for missing data.

4. **List — View link:** Each row that can be viewed includes a **"View"** (or equivalent) link to a **dedicated read-only** page that displays the **immutable** snapshot HTML from **`booking_quotes.rendered_html`** for the **authorised** quote (same content the customer received — **not** re-rendered from live templates). Rows without viewable HTML must **not** present a dead link — show disabled state or **"—"** (document in Progress Notes).

5. **Viewer — sanitised read-only HTML:** The view page **reuses** **`QuoteRenderedHTMLViewer`** (**DRY** — one portal component for stored quote HTML). If **`rendered_html`** is null/empty, show a clear empty state (no empty iframe). **Do not** introduce a second HTML-embedding pattern (iframe/`srcDoc` + sandbox alignment stays in **`QuoteRenderedHTMLViewer`**).

6. **Viewer — route and authorisation:** Add a **RESTful** route under **`src/app/(account)/account/(portal)/invoices/`** — e.g. **`[quoteId]/page.tsx`** (primary key from **`booking_quotes`**) or **`view/[id]/page.tsx`** — **survey** repo conventions; **must** load by **id** and verify **server-side** that the quote’s **booking** belongs to **`activeAccountId`** (same double-check pattern as **15.4** booking detail). On forbidden / wrong account: **`notFound()`** or **403** per project precedent (**survey** **15.4**), without leaking cross-account existence where applicable.

7. **Access control — admin only (US-A4):** The list and viewer use **`requireAccountPortalRoles`** with **admin only** (e.g. `new Set<CustomerAccountMemberRoleDb>(['admin'])` — **survey** [`src/lib/account-portal-auth.ts`](../../src/lib/account-portal-auth.ts)). **Booker** and **rider** must **not** see the archive: **redirect** or **forbidden** consistent with other portal role gates (today **`requireAccountPortalRoles`** redirects disallowed roles to **`/account`** — **document** if changing to a dedicated **403** page for clarity).

8. **Follow-up — 15A.2 dashboard (UX):** **Align** **[`src/features/account/components/AccountDashboard.tsx`](../../src/features/account/components/AccountDashboard.tsx)** (and any home quick-link source) so the **"Invoices"** card is **admin-only** — **hidden for bookers** (prefer **hide** over "link then forbidden" for consistency with **US-A4** for this slice). **Trace** the earlier **US-A1** admin+booker copy in **15.2**; **15A.7** / **US-A4** **overrides** archive visibility. Update **15.2** story **Progress Notes** or add a **Change log** line there **if** the team keeps historical accuracy on shipped stories (optional; minimum: document in **15.7** Progress Notes that dashboard was updated).

9. **RLS / security:** All queries use **active account** + **membership** invariants from **15.1**; **no** authorising purely from **client** params. Cite **15A.9** for **full** multi-account smoke — this story does **not** replace smoke coverage.

10. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-A4**; catalogue **15A.7**; does **not** implement **US-A1** home semantics beyond the **Invoices** quick-link follow-up in AC8.
