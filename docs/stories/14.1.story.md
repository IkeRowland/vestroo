## Story

- As a **maintainer**, I need **`ready_to_assign`** added to **`bookings_status_check`** and a **DB trigger** that sets **`status='ready_to_assign'`** when **`payment_status`** flips to **`'paid'`** AND **`client_type='walk_in'`**, so that **the transition is race-free and owned by one layer** — **Q19** (**US-A1**, **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme A**).
- As **ops security**, I need **smoke RLS assertions** for the new status value and **smoke trigger assertions** for walk-in vs account vs terminal cases, so that **no role accidentally writes `ready_to_assign` without authorization** and **the trigger cannot misfire on account bookings** (**US-A2**, **§6** risk row).

## Acceptance Criteria (ACs)

### US-A1 — Schema + trigger (Theme A)

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme A — US-A1** — lines ~82–89; **Q19**; **§3 Phase 1**; **§8** migrations.)_

1. **CHECK constraint:** Migration adds **`ready_to_assign`** to the **`bookings_status_check`** (or equivalent **`CHECK`** on **`bookings.status`**) **without** dropping existing allowed values — including transitional **`pending`** and all other values present before this migration (**trace:** **US-A1** first AC; **[`docs/epic-12.md`](../epic-12.md)** bookings status vocabulary).

2. **Trigger definition:** Create trigger **`bookings_walk_in_paid_to_ready_to_assign`** on **`UPDATE OF payment_status ON bookings`**. When **`NEW.payment_status = 'paid'`** AND **`OLD.payment_status IS DISTINCT FROM 'paid'`** (or equivalent **`OLD.payment_status <> 'paid'`** handling NULLs per project SQL style) AND **`NEW.client_type = 'walk_in'`**, set **`NEW.status := 'ready_to_assign'`** **inside the trigger** (same statement — **no** separate **`UPDATE bookings`** from the trigger). Name and column semantics must match **[`docs/epic-14.md`](../epic-14.md)** **US-A1** second AC.

3. **Account no-op:** For **`NEW.client_type <> 'walk_in'`** (in particular **`account_client`**), the trigger **does not** change **`status`** solely due to **`payment_status`** becoming **`paid`** (**trace:** **US-A1** third AC; Epic 13 **`ready_to_invoice`** path preserved).

4. **Terminal no-op:** If **`NEW.status`** is already **`cancelled`**, **`expired`**, or **`completed`**, the trigger **does not** set **`ready_to_assign`** when **`payment_status`** flips to **`paid`** (**trace:** **US-A1** fourth AC; **§6** “late webhook” / resurrection risk).

5. **Smoke / SQL assertions (trigger behaviour):** Extend **`supabase/smoke_rls.sql`** **or** add **`supabase/smoke_triggers.sql`** (repo choice — document in **Progress Notes**) so automated smoke covers at least:
   - **Walk-in** **`pending` → `paid`** (on **`payment_status`**) → **`status = 'ready_to_assign'`**;
   - **Account** **`pending` → `paid`** → **`status`** **unchanged** by the trigger;
   - **Walk-in** already **`cancelled`**, then **`payment_status`** becomes **`paid`** → **`status`** remains **`cancelled`**.  
   (**trace:** **US-A1** last AC; **§8** References.)

### US-A2 — Smoke RLS + migration documentation (Theme A)

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme A — US-A2** — lines ~91–96.)_

6. **RLS — non-staff:** Smoke asserts a **non-staff** role **cannot** **`UPDATE bookings.status`** to **`ready_to_assign`** (existing RLS enforced; assert via smoke JWT/session pattern consistent with **`supabase/smoke_rls.sql`**).

7. **RLS — staff:** Smoke asserts **staff** **can** **`UPDATE bookings.status`** to **`ready_to_assign`** (manual ops corrections).

8. **Trigger vs RLS:** Migration file **header comment** documents that the **trigger path is not subject to RLS** in the same way as client updates, and records the implementation choice (**`SECURITY DEFINER`** function vs table-level trigger) with a one-line rationale (**trace:** **US-A2** third AC; **Q19** implementation note).

9. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 1**, **§4 Theme A (US-A1, US-A2)**, **§4 Theme G 14.1**, **§5** matrix row 1, **§6** trigger risk, **§7 DoD** “Trigger correctness” (partial — full E2E later), **§8** paths.
