## Story

- As a **CI maintainer** (and **migration author**), I need a **lint** that flags **inline cross-table `EXISTS`** patterns in **`create policy`** bodies, a **PR check** when **`supabase/migrations/`** changes, a **`smoke_rls.sql`** **42P17** sweep over the **epic-defined** table set, a **strictness switch** and **advisory** rollout, and a **documented escape hatch** for **reviewed** exceptions, so new migrations **do not reintroduce** the **`service_runs` × `tickets`** class of **RLS recursion** and errors reference **ADR 0006** by a **stable** path.

## Acceptance Criteria (ACs)

1. **New script** at **`scripts/lint-rls-policies.mjs`**:
   - Parses files matching **`supabase/migrations/*.sql`**.
   - Finds **`create policy`** blocks (regex and/or a small SQL-oriented parser — implementation choice in tasks).
   - Within each block’s **`USING`** and **`WITH CHECK`** clauses (case-insensitive keywords), **flags** any use of **`from public.<another_table>`** (or equivalent **`public.`<identifier>`** after `from`) that is **not** a **function** invocation (i.e. a **direct** table reference typical of an inline **`EXISTS`** on another RLS-protected table).
   - **Excludes** same-table references (policy table **equals** referenced table) and **ignores** **helper** usage expressed as **function call** to **`public.<name>(...)`** (or bare **`<name>(...)`** if the implementation normalizes) per **ADR 0006**.
   - **Output** (stderr or stdout, machine-readable enough for PR logs): **file path**, **line number** (or best-effort), **policy name**, **offending fragment**, and a **link** to **[`docs/adr/0006-rls-cross-table-helpers.md`](../adr/0006-rls-cross-table-helpers.md)** (repo-relative or raw URL as team standardises — must match **ADR 0006**).
2. **GitHub Actions** workflow step runs the lint on **pull requests** that **touch** paths under **`supabase/migrations/`** (or the repo’s equivalent migration glob). On **violations** in **enforcing** mode: **exit code 1** with a clear line including: **`Cross-table RLS check via inline EXISTS — see ADR 0006. Use a SECURITY DEFINER helper instead.`** (or substantive paraphrase **plus** the same ADR link as AC1). **Survey:** as of story authoring, **`.github/workflows/`** may be **empty** — **add** a workflow file (or extend an existing one) as part of implementation; do not assume a pre-existing workflow name.
3. **Lint** runs **clean** (**RLS_LINT_STRICT=1**, no violations) against the **current** **`supabase/migrations/*.sql`** set after **Theme K1** and related recursion fixes on **`main`** (satisfies epic **US-O2** “existing migration set” check). If a **false positive** is unavoidable, use the **escape hatch** in AC5 and **document in PR** — not a silent skip.
4. **`supabase/smoke_rls.sql`** extended with the **42P17**-detection block from **[`docs/epic-16.md`](../epic-16.md)** **US-O2** (verbatim structure and **exact** `tablename in (...)` list):
   - **`profiles`**, **`bookings`**, **`booking_trips`**, **`trips`**, **`service_runs`**, **`tickets`**, **`chauffeur_assignments`**, **`customer_accounts`**, **`customer_account_members`**, **`booking_quotes`**, **`ops_audit_log`**, **`ops_alerts`**, **`ops_settings`**, **`vehicle_trackings`**, **`shared_itineraries`**, **`service_run_manifest_entries`**, **`vehicle_maintenance_records`**, **`vehicle_fuel_logs`**
   - The **`DO $$ … $$;`** pattern: loop tables, `execute format('select 1 from public.%I limit 1', tbl);`, **exception** **`when sqlstate '42P17'`** then **`raise exception 'RLS recursion detected on %', tbl;`**
   - Placed in a **new section** with a **header comment** pointing to **Epic 16 / US-O2** and **Theme O** (align **`[smoke_rls]`** error style with the rest of the file where applicable).
5. **Advisory then enforcing (week 1):** Implement **`RLS_LINT_STRICT`** as **`0` | `1`** (or unset default — **document** in **`CONTRIBUTING.md`** or **`docs/local-development.md`** RLS section):
   - **`RLS_LINT_STRICT=0`:** print **warnings** for violations but **exit 0** (advisory; suitable for a **first** merge window or branch policy).
   - **`RLS_LINT_STRICT=1`:** violations → **non-zero** exit (enforcing).
   - **CI:** for the **enforcing** switch-over, either set **`RLS_LINT_STRICT: "1"`** in the workflow without **`continue-on-error`**, or run one advisory week with **`RLS_LINT_STRICT=0`** and flip to **`1`**; **record the chosen cut-over** in **Progress Notes** / team channel / **Change log** as appropriate.
6. **Escape hatch:** The epic’s literal **`// rls-lint-ok: <reason>`** applies to **C-style** comments; **SQL migrations** use **`--`**. This story’s **canonical** form is: **a line comment immediately preceding the `create policy` (or the flagged clause)** — **`-- rls-lint-ok: <reason>`** — with **`<reason>`** non-empty. The **lint** must **suppress** the finding for that policy (or that line range — implementation detail in tasks) when the **reviewed exception** is justified; **code review** is the approval gate. **(Optional future:** support **`// rls-lint-ok`** in a different file type if the repo ever lints **non-`.sql`** — **out of scope** unless already present.)
7. **`package.json`:** add an **`npm run`** entry (e.g. **`lint:rls`**) that invokes **`node scripts/lint-rls-policies.mjs`**, and document in **Dev Guidance**; align **env** passthrough for **`RLS_LINT_STRICT`**.

### SQL vs epic escape-hatch string

- Migrations are **`.sql`**; the epic’s **`// rls-lint-ok:`** is interpreted in this story as the **SQL** form **`-- rls-lint-ok: <reason>`** on the line **above** the **`create policy`** (or directly above the **flagged** subclause, if the implementation uses a narrow span). Rationale: **`--`** is the portable SQL line comment; **`//` is not valid** in standard PostgreSQL **SQL** files.
- The **lint** is **file-based**; it does not need to match **`//`** in **`.sql`** files.

### Rollout (`RLS_LINT_STRICT`)

- **Advisory (e.g. week 1):** set **`RLS_LINT_STRICT=0`** in the **workflow** `env` (warnings only, **exit 0**).
- **Enforcing:** set **`RLS_LINT_STRICT=1`** (or default **strict** if unset, **only if** documented) and **fail** the check.
- **Alternative** allowed by epic: **`continue-on-error: true`** on the lint **step** during advisory only — **pick one** primary mechanism to avoid **double** “always green” confusions; the tasks above **prefer** **`RLS_LINT_STRICT=0`** over **`continue-on-error`** for clarity (warnings still visible, exit 0 by design).
