## Acceptance Criteria (ACs)

### US-D3 — Intent-based routing + **Q13** + feature flag

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme D — US-D3** lines ~160–166; **Q13** ~line 44; **§5** matrix **Booking form intent-based routing**; **§6** flag risk; **§8**.)_

1. **Branch on `booking_intent`:** Implementation touches the real checkout path(s) — **survey required:** primary PayFast flow is **`src/actions/processPayment.ts`** (creates booking + returns PayFast payload) and **`src/app/(app)/book/payment/page.tsx`** (calls **`processPayment`**, **`initializePayFastModal`**). **`src/actions/createBooking.ts`** duplicates insert logic (**`status: 'pending'`** today) and must stay **consistent** if any caller exists or for API parity (**survey** for non-test callers). Behaviour:
   - **`point_to_point`** → **preserve** existing flow: **PayFast** after booking insert (**unchanged**).
   - **`trip_request` \| `hourly_hire` \| `experience_package`** → when **`QUOTE_FIRST_FOR_NON_TRIVIAL_INTENTS`** is **ON** (default after ship): create booking with **`status='submitted'`**, show customer-friendly confirmation (**“Thanks — we’re preparing your quote…”** / ~**1 business hour** copy per epic), **do not** call PayFast / **do not** redirect to PayFast from this step.

2. **Feature flag:** Add **`QUOTE_FIRST_FOR_NON_TRIVIAL_INTENTS`** (server-readable env). When **OFF**, restore **legacy** behaviour for non-trivial intents: today’s code inserts **`status: 'pending'`** and proceeds to PayFast via **`processPayment`** where applicable; **`trip_request`** also appears on **`/ops/fulfil?queue=trip_request`** for the dedicated funnel (**[`docs/epic-14.md`](../epic-14.md)** **§6**). Implementer must **diff pre-change behaviour** per intent and entry funnel, and record the baseline vs flag states in **Story Progress Notes**.

3. **`trip_request` funnel parity (survey):** Dedicated funnel **`submitTripRequest`** (**`src/actions/submitTripRequest.ts`**) currently inserts **`trip_request`** with **`status: 'pending'`** and **no** PayFast. Confirm with product/tech whether **Q13** requires **`submitted`** here when the flag is **ON** for consistency with **`/ops/bookings`**; if yes, extend the same flag + status rules; if explicitly out of scope, document the decision in **Progress Notes** (avoid split-brain **`trip_request`** semantics).

4. **`point_to_point` regression guard:** No change to **`point_to_point`** success path (PayFast handoff, confirmation URLs, amounts) — **US-D3 AC2** / epic **§7**.

5. **`.env.example`:** Add **`QUOTE_FIRST_FOR_NON_TRIVIAL_INTENTS`** with comment: default **ON** after **14.7** ships; document accepted truthy values (**e.g.** `true` / `1` — align with a single server-side parser; project has mixed patterns **`=== '1'`** in some modules — **define one convention** in code + comment).

6. **`docs/environment-vars.md`:** If team policy is to document new server env vars when introduced (this repo already documents **`QUOTE_LINK_SIGNING_KEY`** here), add a **Server-only** table row for **`QUOTE_FIRST_FOR_NON_TRIVIAL_INTENTS`** (purpose, default, rollback). If the team defers doc-only work to **14.12**, state that explicitly in **Progress Notes** and leave a **Tasks** checkbox unchecked with justification.

7. **§6 mitigation — release + training:** Tasks include **(a)** a short **migration / release note** (intended behaviour change: non-trivial intents → **`submitted`**, no immediate PayFast when flag **ON**) and **(b)** **ops training** bullet: new submissions appear as **`submitted`** on **`/ops/bookings`**; use **Send quote** (**14.6**) to email the customer.

8. **Epic 12 dependency — `/ops/bookings`:** Verify **`submitted`** rows are visible to ops on **`/ops/bookings`** (default grid or intent/status filters). If not, file as **blocker** or add a **subtask** under Epic **12**/**14** boundary (minimal query/filter fix) — **survey** **`src/app/(ops)/ops/bookings/page.tsx`** and related query helpers.

9. **Migrations:** **Default none.** **`submitted`** is already allowed on **`bookings.status`** (**`bookings_status_check`** in existing migrations). Add a migration **only** if smoke/schema survey proves otherwise — unlikely; if added, use epic trace in filename/comment.

10. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 3** (**14.7**), **§4 Theme D (US-D3)**, **Q13**, **§5–§8**.
