## Story

- As a **developer**, I need a dedicated **`src/lib/email/`** module with a **typed Resend client** and **`sendEmail`** that returns **structured success/failure**, so that **13.7** can wire trip confirmations without inventing ad hoc SDK usage (**US-C1** first AC — partial; **Theme F 13.6**).
- As a **developer**, I need **test-mode detection** for non-production when the API key matches a **test pattern**, so that **local and staging runs do not dispatch real email** (**US-C1** fifth AC).
- As a **developer**, I need **`RESEND_FROM_EMAIL`** / **`RESEND_API_KEY`** documented in repo-safe env docs, so that **ops and engineers provision Resend consistently** (**US-C1** third AC — documentation slice for **13.6**).

## Acceptance Criteria (ACs)

### US-C1 — Resend trip confirmation email (Theme C) — **13.6 scope only**

1. **Module skeleton:** **`src/lib/email/`** exists and contains **`resend-client.ts`** (factory or singleton pattern acceptable; **typed** exports wrapping **`Resend`** from the **`resend`** package) and **`send.ts`** with **`sendEmail`** (inputs: at minimum **to**, **subject**, **html** or React render path stub, **from** resolved from env with safe defaulting rules documented — align with **`RESEND_FROM_EMAIL`**) — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-C1** first **AC** (file list: client + send + **`templates/`** subtree).

2. **Template placeholder only:** **`templates/`** includes a **minimal** **`account-trip-confirmation`** placeholder (filename may be **`account-trip-confirmation.tsx`** per epic **§8** or equivalent under **`templates/`**) so **13.7** can implement full fields — **not** required: driver, vehicle, line items, payment terms, cancellation copy, support contact (**US-C1** second **AC** → **defer to 13.7**).

3. **Env contract (no secrets in repo):** **`RESEND_FROM_EMAIL`** and **`RESEND_API_KEY`** are documented for engineers (purpose, server-only, never **`NEXT_PUBLIC_`**). Update **`docs/environment-vars.md`** if the file exists; otherwise extend **`.env.example`** and note in **Story Progress Notes** / epic **§7** alignment — **US-C1** third **AC** (documentation portion for **13.6**).

4. **`rendered_html` persistence:** **Out of scope for 13.6** — **`booking_quotes.rendered_html`** capture happens in **13.7** when **`sendBookingQuote`** invokes **`sendEmail`** (**US-C1** fourth **AC** → **defer to 13.7**).

5. **Test-mode guard:** When **`NODE_ENV !== 'production'`** and **`RESEND_API_KEY`** matches the project’s **test pattern** (define in implementation, e.g. prefix `re_test_` or documented placeholder from **`.env.example`** — must be **deterministic** and **documented**), **`sendEmail`** **does not** dispatch via Resend; it returns a **success-shaped or explicit “skipped”** result consistent with the structured API (document in **Dev Technical Guidance**) and **logs** at appropriate level — **US-C1** fifth **AC**.

6. **Structured failure:** On live-send path (non-test-mode), failures from Resend or configuration (e.g. missing **`RESEND_API_KEY`** in production) surface through **`sendEmail`** as **typed error info** (code/category + message), not only thrown exceptions — supports **13.7** / **13.8** audit and retry flows.

- **Server-only:** Email send must run only in server contexts (Server Actions, Route Handlers, server components’ data loaders) — **do not** import **`sendEmail`** into client bundles; avoid **`NEXT_PUBLIC_`** for secrets.
- **Test-mode result shape:** Prefer an explicit discriminant such as `{ ok: true, mode: 'sent' | 'skipped_test_mode' }` or `{ ok: false, error: { kind, message } }` — document chosen shape in **Progress Notes** for **13.7**.

- **13.4:** Leave **`sendBookingQuote`** behaviour unchanged unless a no-op import is needed to verify tree-shaking — coordinate in PR description only.
