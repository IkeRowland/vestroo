## Story

- As a **migration author**, I need a **`public.driver_assignments`** **view** over **`public.chauffeur_assignments`** with **`chauffeur_id` exposed as `driver_id`** (and a stable column projection), **`COMMENT ON VIEW`**, and **invoker-safe** semantics **documented and verified**, so **Epic 16** reporting and raw SQL can use a **driver**-named object **without** violating **Q34**.

- As **QA / platform**, I need **`smoke_rls.sql`** to assert a **staff** **`SELECT`** against **`public.driver_assignments`** succeeds under the same **RLS** expectations as reading the underlying assignments where staff policy applies — **no** new write path.

## Acceptance Criteria (ACs)

1. **Migration file:** New migration named **`YYYYMMDDHHMMSS_ops16_driver_assignments_view.sql`** (timestamp at implementation time; suffix **exactly** **`ops16_driver_assignments_view`**) that:
   - **`create or replace view public.driver_assignments`** with a **stable `SELECT`** from **`public.chauffeur_assignments`**: **`select ca.*, ca.chauffeur_id as driver_id`** (or an **explicit column list** that includes **`chauffeur_id as driver_id`**, preferred for stable diffs). **Must** expose **`driver_id`** as an alias of **`chauffeur_id`**. **Do not** remove or rename base columns on the **table** — view only.
   - **`comment on view public.driver_assignments`** stating: **read-only** façade over **`chauffeur_assignments`**; **writes** remain on the base table until **[`docs/epic-17.md`](../epic-17.md)**; cites **Q34** / **Phase 1** intent.
2. **RLS / PostgreSQL view security:** In the migration **comments** (and **Progress Notes**), document the choice of view options for the project’s PostgreSQL major version (survey **`select current_setting('server_version');`** on local / hosted Supabase):
   - **Default (PG ≥ 15):** prefer **`create view … with (security_invoker = true)`** so row visibility is evaluated with the **invoker’s** rights and **underlying `chauffeur_assignments` RLS** applies as for a direct table read.
   - If **`security_invoker`** is **not** available on the pinned version, document fallback behaviour (**view runs with invoker by default in recent Postgres** — still verify) and that **`security_barrier`** is **not** required for this simple passthrough view (it is for **different** threat models; cite Postgres docs / internal ADR if one exists).
   - **No new `CREATE POLICY` on the view** — RLS remains on **`public.chauffeur_assignments`**.
3. **Grants:** **`GRANT SELECT ON public.driver_assignments`** to the same roles that can **meaningfully** read **`public.chauffeur_assignments`** through PostgREST (typically **`authenticated`**, and **`service_role`** if other tables use it — **survey** existing grants on **`chauffeur_assignments`** / project baseline; match project convention).
4. **`smoke_rls.sql`:** Add a dedicated block (numbered comment consistent with file style, e.g. **“Epic 16 / Story 16.12 — Phase 1 `driver_assignments` view”**) that, under the **existing staff / dispatcher JWT fixture** pattern used elsewhere in the file:
   - Runs **`SELECT count(*) FROM public.driver_assignments`** (or **`SELECT 1 … LIMIT 1`**) and **asserts success** (no **`42501`** / unexpected auth failure) — align with **staff can read assignments** policy semantics.
   - **Does not** add a requirement for **writes** through the view.
5. **Optional hygiene:** If **Theme O / US-O2** recursion sweep is extended to cover **views**, consider adding **`driver_assignments`** to a **`pg_views`-driven** loop **only if** the maintainers want parity; **not** an AC unless O2 explicitly requires it — minimum is **AC4**.
6. **Types:** Update **`src/types/database.types.ts`** **if** repo convention commits hand-typed / generated shapes for new **`public`** views (match **16.9** / **16.10** / **16.11**); otherwise document **“types follow-up”** in **Progress Notes** — **not** a blocker for migration-only acceptance if convention says views are omitted.
