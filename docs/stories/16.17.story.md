## Story

- As a **walk-in customer** who opened the **accept** link from the quote email, I need to **confirm acceptance**, see **our bank details and EFT reference**, and a clear **"what happens next"** message, without being sent to a **payment gateway** — per **Q33** / **US-N6**.

- As **ops/compliance**, I need a **durable** **`quote_accepted_at`** timestamp and a **`customer_accepted_quote`** audit entry **once** per booking acceptance, and a **confirmation email** that matches the same bank+reference facts — per **Q31** / **Q32** narrative.

- As **engineering**, I need **idempotent** page loads: **refresh** after acceptance must **not** duplicate email or audit, and must show the same confirmation — per epic **~777–779**.

## Acceptance Criteria (ACs)

1. **Route:** Customer-facing page remains **`src/app/(quote)/q/[token]/accept/page.tsx`** (evolve in place, not deleted).
2. **Server validation:** **Server-side** flow validates the opaque **token**, resolves **booking** + **quote** (walk-in), rejects invalid / wrong-state / non-walk-in per existing **`runQuoteAcceptCheckout`** semantics unless product tightens error copy in this story.
3. **UI — confirmation:** Renders **heading** "Quote accepted" (or product-approved copy); **subheading** includes **reference** in **`VST-{booking_ref}`** form (or **N1**-aligned label already used in **N4** email); **bank block:** bank name, account holder, **full** account number, branch code, **EFT reference** line; **next steps** text per epic ~773: e.g. **"We'll confirm receipt within 1 business day. You'll receive a confirmation email shortly."** (exact string may match tone guide).
4. **First load (acceptance event):** When the customer **first** successfully accepts from **`quote_sent`** (and state machine allows it): set **`bookings.quote_accepted_at = now()`**; ensure booking is **`awaiting_payment`**; send **`walk-in-acceptance-confirmation`** email with the **same** bank + reference as the page; insert **`ops_audit_log`** with **`action = 'customer_accepted_quote'`** (and payload shape consistent with other customer-facing ops audits).
5. **Idempotency:** If **`quote_accepted_at` is already set** (reload / repeat open): **do not** update timestamp again, **do not** re-send email, **do not** write duplicate **audit**; render the same **Quote accepted** + bank + copy.
6. **No PayFast:** No **`processPayment`**, no PayFast redirect builder, no primary **pay** CTA to removed checkout — **prerequisite [16.13](./16.13.story.md)**; implementation completes **US-N6** (~780) replacement.
7. **Server-only bank details:** **Unmasked** bank fields assembled only in **server** modules (RSC, **`'use server'`** actions, or service client helpers) — not passed through public JSON APIs to anonymous clients beyond what the **HTML** already exposes on the page.
8. **Tests:** Automated tests assert **first** visit performs expected **writes** (or observable side effects / mocks) and **second** visit is a **no-op** for **email, audit, and timestamp** — unit tests for **quote-accept** flow and/or component-level tests with mocked server module as project patterns allow.
