## Story

- As **engineering / QA**, we need a **coherent Playwright** suite for **15B** rider tracking that exercises **public** **`/track/*`** (invalid, valid, and **optional** live-map paths) and **optionally** **field** awareness, with **`skip`/`test.skip`** when **`.env.test`** / DB / keys are not provisioned, so that **Q21** / **Q22**-aligned **privacy** behaviour and **regressions** are caught before ship — **complementing** **15.9** and **15.10**, not replacing them.

## Acceptance Criteria (ACs)

1. **Suite entrypoint (coherent 15B file):** Add **one** primary spec (or a **justified** split) under **`tests/e2e/`** — e.g. **`epic15-15b8-rider-tracking-privacy.spec.ts`**. Spec(s) use **`@playwright/test`**, follow existing **typed** helper patterns, and remain **serial**-safe with current **`playwright.config.ts`** ( **`workers: 1`** ). **Document** in **Progress Notes** if 15.7’s spec is **imported** vs **moved/merged** so the repo does not maintain two unrelated invalid-token suites.

2. **Invalid / expired token — no PII:** Assert that navigation to a **known-bad** token (e.g. malformed / **`verifyRiderTrackToken`** rejection **without** trip fetch — **survey** **[`src/lib/tracking-tokens.ts`](../../src/lib/tracking-tokens.ts)**) and **`/track/expired`** (if 15.7 route exists) show the **non-PII** surface. **Align** with **15.17**: **import** or **extract** shared **`assertInvalidTrackSurface`** (or a named denylist) from **[`tests/e2e/epic15-17-track-token-invalid-privacy.spec.ts`](../../tests/e2e/epic15-17-track-token-invalid-privacy.spec.ts)** (or a **`tests/e2e/helpers/rider-track-privacy.ts`**) so assertions **do not drift**. **AC:** no accidental leakage of **documented** high-risk PII substrings in HTML for these routes.

3. **Valid token — happy path (gated):** If feasible, assert **milestone** (or shell) content for a **valid** unexpired token. **Preferred:** a **test helper** that uses **Supabase service client** (or existing **`tests/e2e/helpers`**) + **`signRiderTrackToken`** to mint a token for a **seeded** or **fixture** trip in a **dev** / **E2E** database. **Alternative:** a **documented** static **fixture token** in non-prod seed data (same signing key as app). **Skip** with a **clear message** when **`QUOTE_LINK_SIGNING_KEY`**, Supabase, or **trip** seed data is unavailable — **no** false green in CI without env.

4. **Live map (double opt-in — skippable):** When both **`RIDER_LIVE_LOCATION_ENABLED`** (or **`isRiderLiveLocationEnvEnabled()`** from **[`src/features/rider-tracking/lib/rider-live-location-env.ts`](../../src/features/rider-tracking/lib/rider-live-location-env.ts)**) **and** the booking’s account has **`live_rider_tracking=true`**, the rider page may show the **live map** embed. **AC:** one **conditional** test (or `test.step`) that asserts **map** presence or **stable** map container when env + data allow. **Default CI:** `test.skip` or gate behind **`E2E_RIDER_LIVE_MAP=1`** (or equivalent) so unconfigured pipelines stay green. **Document** the gate in **`.env.test.example`** and **Progress Notes**.

5. **Field — optional chauffeur indicator (survey / defer):** **Survey** existing **field** E2E or login helpers (e.g. **field** auth patterns; compare **`ops-staff-login`**-style for staff vs field). If a **deterministic** path exists: add an **optional** spec block that logs in as a **chauffeur**, opens **`/field/trips/[tripId]`** for a trip whose booking has **`live_rider_tracking=true`**, and asserts **“Live tracking: ON”** (or shipped copy) per **15.16**. If field auth or seeding is **not** available in CI, use **`test.skip` + TODO** in the spec; **do not** block story merge on field E2E.

6. **SMS (15B.4) — no live SMS in E2E:** **Do not** require sending or receiving real SMS. If **15B.4** exposes a **test-only hook** (e.g. in-memory outbox, log line, or API used only in dev), a test may assert **stub** / **log** path only. Otherwise **document** “SMS E2E **N/A**” in **Progress Notes** and **omit** SMS assertions (no placeholder failures).

7. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15B.8`**, **§5** 15B privacy, **§6** live/SMS risk framing, **Q21** / **Q22** as exercised in the browser; complements **15.7** and **15.9/15.10** (different surfaces).
