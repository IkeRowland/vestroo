## Story

- As **an organisation member or invitee**, I want **sign-in** and **invitation acceptance** pages to **match the account portal visual language** (canvas, accent CTA, clear hierarchy), so I **trust** the surface and understand **how to get help** if sign-in fails.

- As **Vestroo**, we need **public** **`/account/login`** and **`/account/signup`** to stay **outside** **`AccountShell`** while still resolving **`account.*`** tokens (**FE.18.2**), **without** changing **Supabase** auth behaviour.

## Acceptance Criteria (ACs)

1. **Layout / theme:** **`src/app/(public-account)/layout.tsx`** (or **Task 0**–approved equivalent) wraps **`/account/login`**, **`/account/signup`**, and **`/account/unauthorized`** with **`data-account-theme="light"`**, **`min-h-screen`**, **`bg-account-canvas`**, **`text-account-foreground`** — **NFR.18.4** (theme confined to this subtree + existing portal layout; **never** on **`/ops/*`** or marketing root).
2. **Centered card:** **Login**, **valid invite**, **invalid invite**, and **`unauthorized`** pages use a **single-column** **max-width** card (**~`max-w-md`**) on the account canvas — **border** / **surface** use **`border-account-border`**, **`bg-card`** or **`bg-account-surface`** per **Task 0** alignment with portal **`Card`** feel.
3. **Brand mark:** **Vestroo** mark appears **above** the card title on **login** and **signup** (and **Task 0** decides **invalid invite** / **unauthorized** parity).
4. **Primary CTA:** Submit buttons on **login** and **invite** flows use **`bg-account-accent`** + matching **foreground** (**`text-account-accent-foreground`**) per design tokens — loading/disabled states preserved.
5. **Help link (pre-auth):** **"Need help signing in?"** (or **Task 0**–approved label) resolves to **`mailto:`** using **`resolveSupportEmailAddress()`**; visible support address behaviour matches **`SUPPORT_EMAIL`** override (**[`email-copy.ts`](../../src/lib/email/email-copy.ts)**). **Do not** link **only** to **`/account/help`** for **anonymous** users without a **Task 0** public-help decision (**Reconciliation**).
6. **`AccountLoginForm`:** Inherits new page chrome; **no** change to **`signInWithPassword`** contract; errors remain **`role="alert"`** — **NFR.18.5**.
7. **`AccountInviteSignupPanel`:** **Minor visual refresh** — clearer **hierarchy** for **organisation name**, **role**, **invited email**; **no** new server actions; **no** inviter-name field without token work (**Reconciliation**).
8. **`signup/page.tsx`:** **`InvalidInvite`** states share the **same** outer chrome as success path (**centered card**, mark, account tokens).
9. **Copy discipline:** New/changed user-visible strings for these routes live in a **single** module (e.g. **`src/features/account/copy/account-auth-surfaces-copy.ts`**) — **no** new i18n framework (**epic** non-goals).
10. **Back to site / secondary links:** Styled with **`text-account-muted`** + focus rings consistent with **account** focus token pattern (**`ring-account`**, **`ring-offset-account-canvas`** where used elsewhere).
11. **Server-first:** **`login/page.tsx`** and **`signup/page.tsx`** remain **async server** pages; **no** unnecessary **`'use client'`** on **`page.tsx`** files — **NFR.18.3**.
12. **Feedback:** **No Sonner** — **NFR.18.2**.
13. **Accessibility:** **Logical heading order** on each variant; **keyboard** focus order through mark → title → form → help → footer links — **NFR.18.5**.
14. **Performance:** **No** new heavy client dependencies; **brand mark** import only — **NFR.18.6**.
15. **Tests:** **`npm run test -- --run`** green; add **Vitest** only if **Task 0** introduces non-trivial pure helpers.
16. **Lint:** **`npm run lint`** green.
17. **Parity doc:** **`docs/ops-design-system-parity.md` § 18.11** documents **Story 18.11 / FE.18.10** (routes, theme scoping, help **mailto** rule); **Story 18.13** remains owner of full § **18** index polish.
18. **PR hygiene:** PR cites **FE.18.10** and **Story 18.11** — **does not** claim **FE.18.9** / **Story 18.10** (help).
