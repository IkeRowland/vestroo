## Story

- As **ops staff** (and **ops admin** where applicable), I need **`/ops/settings`** and its sub-pages to use a **clear sectioned layout**, consistent **ops chrome** (**`OpsPageHeader`**, **`OpsTableShell`** where tables exist), and **token**-driven borders/spacing (**`bg-ops-accent-soft`** focus/hover per **Design Goals**), so I can **find and adjust configuration** without visual clutter.

- As **the codebase**, we need **presentation + information architecture only** — **no** intentional change to authorization loaders, RLS, or server action contracts (**NFR.17.6**) unless **Task 0** records a justified pre-existing defect.

## Acceptance Criteria (ACs)

1. **`/ops/settings` index:** **`src/app/(ops)/ops/settings/page.tsx`** uses **`OpsPageHeader`** and a **Task 0**-locked **grouped** layout (cards, section headings, and/or secondary nav) linking to **`/ops/settings/bank-account`** and **`/ops/settings/service-runs`** — **Wheelzie-inspired** density; **no** new routes unless **PO** approves (**Reconciliation**).

2. **`/ops/settings/bank-account`:** **`src/app/(ops)/ops/settings/bank-account/page.tsx`** retains **`requireOpsAdminPage`**, **`OpsBankAccountSettingsForm`**, and **`OpsPageHeader`**; **form fields are grouped into sections** with consistent spacing, labels, and **token** borders — **admin gate unchanged**.

3. **`/ops/settings/service-runs`:** **`src/app/(ops)/ops/settings/service-runs/page.tsx`** retains **`requireOpsStaffPage`**, **`OpsServiceRunsSettingsForm`**, **`OpsPageHeader`**, and **`OpsTableShell`** (and existing patterns/runs queries); **tables** and **forms** match epic **row hover** / focus patterns (**`bg-ops-accent-soft`** where applicable).

4. **`OpsTableShell`:** Any **table** surfaces touched by this story use **`OpsTableShell`** (or **Task 0**-approved equivalent) with consistent header/body rhythm aligned with other Epic **17** surfaces.

5. **`OpsStatusPill` (optional):** If **17.7** applies, **Task 0** maps **user-visible status** columns (**e.g.** service pattern **`status`**) to **`OpsStatusPill`** tones — **no** raw colour-only badges for those columns (**NFR.17.5**).

6. **Chrome parity:** All three surfaces share **`OpsPageHeader`** usage and **ops** visual consistency (spacing, muted descriptions, action placement per **Design Goals**).

7. **Theme (NFR.17.4):** **`data-ops-theme` light/dark** — no theme branching beyond tokens on new or adjusted chrome.

8. **Accessibility (NFR.17.5):** **axe** clean on touched surfaces; **keyboard** operable controls; **`aria-label`** on icon-only controls; section headings form a sensible document outline.

9. **Copy modules (NFR.17.8):** Strings introduced or reorganized by this story live under **`src/features/ops/copy/…`** per **Task 0** rule (**per-page** vs namespaced **`ops-settings-copy.ts`**).

11. **Tests:** **Vitest** / **RTL** — smoke or helper tests **if** new layout helpers or copy barrels warrant them (**Task 0** scope).
