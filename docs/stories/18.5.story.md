## Story

- As **an org admin or booker**, I want **`/account/bookings`** to feel like a **professional trip register** — filters, a dense table, and a **side detail rail** — so I can find trips quickly and act without leaving the portal.

- As **Vestroo**, we need **one** bookings surface that composes **shared SaaS primitives** (**`SplitView`**, **`DetailRail`**, **`Pagination`**, **`StatusPill`**, **`AvatarCell`**) under **`theme="account"`**, keeping **ops** and **account** visually related (**NFR.18.4**).

## Acceptance Criteria (ACs)

1. **Primitives:** Bookings UI composes **`SplitView`** + **`DetailRail`** + table chrome using **`theme="account"`** where applicable; **no** duplicate split-view markup copied from **`/ops`** (**Story 18.3**).
2. **Filter row:** Date range (wired to **server** query — extend **`account-bookings-list-query`** as needed), **status** pill **multi-select** (maps to whitelist / DB statuses), **trip type** filter (point-to-point, hourly, tour, close protection — **domain-accurate**), **search** (existing or extended search fields — **server-side**).
3. **Table columns:** Booking ref, date+time, route (pickup → drop-off, **single-line ellipsis**), vehicle class, **`StatusPill`**, amount if quoted, **row action menu** (kebab or equivalent).
4. **Row interaction:** **Row click** (or explicit control with same outcome) opens **detail rail** without full navigation away from list; **keyboard** and **focus** move into rail per **NFR.18.5**.
5. **Detail rail — itinerary:** Pickup and drop-off addresses; **static map** snapshot via **server-built** Static Maps URL (**`<img>` or `next/image`** with allowed host config if needed) — **no** Maps JavaScript SDK.
6. **Detail rail — trip:** Date, time, passengers, special instructions; vehicle (**class**, **model** when assigned).
7. **Detail rail — driver:** When assigned, show **`AvatarCell`** + first name + **first letter of surname** + masking rules consistent with privacy norms elsewhere in portal.
8. **Detail rail — comms timeline:** Read-only vertical timeline (quote-sent, quote-accepted, payment-link-sent, etc.) from **real** data; graceful empty state.
9. **Detail rail — actions:** **Modify** links to **`/book/search?modify=<ref>`**; **Cancel** opens **`AlertDialog`** then existing cancel path; **Re-book** uses **`BookThisAgainButton`** with same **search href** construction as today where applicable.
10. **Detail rail — footer:** **Receipt PDF** (or equivalent) uses **existing** download / signed-URL behaviour — **no** new storage buckets.
11. **Capability gates:** **Modify** and **Cancel** visibility / disabled state match **existing** policy and role gates (**NFR.18.1**).
12. **Deep-link:** Loading **`/account/bookings?id=<ref>`** opens list with rail focused on that booking (when authorised); invalid / other-org id → **404** or safe empty consistent with portal patterns.
13. **Pagination:** Uses shared **`Pagination`** with **`theme="account"`** (or **`OpsPagination`** wrapper if that is the current shared export) — **not** bespoke unstyled page links.
14. **Server-first:** Primary **`page.tsx`** stays **RSC-oriented**; filters + pagination + **`id`** read from **`searchParams`** on server; avoid new client-only data trees (**NFR.18.3**).
15. **Performance / a11y:** Respect **NFR.18.6** for list path (document warm **TTFB** check in **Progress Notes**); table **semantic** markup, **visible focus**, **Esc** to close rail if pattern supports it, sufficient contrast (**NFR.18.5**).
16. **Copy:** User-visible bookings strings for this tranche live in **`src/features/account/copy/account-bookings-copy.ts`** — **B2B shuttle / chauffeur** wording only.
17. **Tests:** **Vitest** for **URL parsing** extensions, filter helpers, and **role-gated** action visibility where non-trivial; **`npm run test`** green.
18. **Lint & docs:** **`npm run lint`** green; **`docs/ops-design-system-parity.md`** — new **`§ 18.5`** (**Story 18.5 / FE.18.4**); PR cites **FE.18.4** and **Story 18.5** — **does not** claim **FE.18.5** / **Story 18.6**.
