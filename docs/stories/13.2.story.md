## Story

- As **fulfilment staff**, when **dispatch is refused** for an **account** booking, I need a **clear block panel** that names the **reason in plain language**, so that **I know whether to contact the booker, finance, or admin** (**US-A2**, **[`docs/epic-13.md`](../epic-13.md)** **§4**).
- As **fulfilment staff**, when the refusal is **`credit_limit_exceeded`**, I need to see **how much is already outstanding**, **what this booking adds**, and the **limit**, so that **I can judge the situation** before escalation (**Q11**, **Theme F 13.2**).

## Acceptance Criteria (ACs)

### US-A2 — Reason-code block panel (Theme A)

1. **Trigger:** When **`assignBookingToRun`** returns a failure whose **`OpsActionError`** variant is **`NOT_DISPATCHABLE_ACCOUNT`** (per **[`docs/stories/13.1.story.md`](../stories/13.1.story.md)**), the ops UI renders a **dedicated block panel** (not only a flat toast string) in the **Fulfil assign** step — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-A2** (third **AC**).

2. **Seven reason codes — human copy:** For each code below, the panel shows messaging **equivalent** to the epic’s copy (template placeholders filled from server/detail or fetched data):
   - **`account_on_hold`** → *"This account is currently on hold. Contact account admin before dispatch."*
   - **`account_suspended`** → *"This account is suspended. Dispatch is not permitted."*
   - **`contract_expired`** → *"The account's contract expired on {contract_ends_on}. Renew before dispatch."*
   - **`contract_not_yet_active`** → *"The account's contract starts on {contract_starts_on}. Dispatch is not permitted yet."*
   - **`po_required_and_missing`** → *"This account requires a purchase order reference. Add one to the booking before dispatch."*
   - **`credit_limit_exceeded`** → *"Outstanding R{outstanding} + this booking R{this_booking} exceeds credit limit R{credit_limit}."* (**Q11** — three numeric parts)
   - **`overdue_invoices`** → *"This account has {n} overdue invoice(s). Resolve before dispatch."*

3. **Copy module:** All strings for **AC2** (including templates / formatter helpers) live in **`src/features/ops/reason-code-copy.ts`** — **US-A2** second **AC**.

4. **No override in 13.2:** The panel **does not** include an override affordance; **13.3** owns **US-A3** / **Q12** — see **Explicit out of scope** above.

5. **Q11 data sourcing:** For **`credit_limit_exceeded`**, **`outstanding`**, **`this_booking`**, and **`credit_limit`** are populated from **`NOT_DISPATCHABLE_ACCOUNT`** detail fields **and/or** existing reads (booking amount, account snapshot) per project patterns — developer verifies consistency with **`can_dispatch_account_booking()`** and **13.1** payload; if gaps remain, **narrow follow-up** in **13.1** server layer is preferred over client-side guesswork.

6. **Traceability:** Implementation maps to **[`docs/epic-13.md`](../epic-13.md)** **§3** Phase **1**, **§4 Theme F** row **13.2** (**Reason-code block panel with human copy + current outstanding display (Q11)** | Theme **A** | **3 pts** | Depends: **13.1**), and **§4 Theme A — US-A2** (lines ~81–92).

7. **Primary code touchpoints:** **`src/features/ops/reason-code-copy.ts`** (new); **`src/features/ops/components/AssignBookingPanel.tsx`** (or extracted subcomponent colocated under **`src/features/ops/components/`**); entry route **`src/app/(ops)/ops/fulfil/`** — **[`docs/epic-13.md`](../epic-13.md)** **§8 References**.
