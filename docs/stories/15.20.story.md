## Story

- As **Vestroo engineering**, we need **Epic 13 trip confirmation**, **Epic 14 walk-in quote**, and **existing booking-payment confirmation** paths to **load active dispatch rules and templates** from **`comms_dispatch_rules`** / **`comms_templates`** (keyed by **`CommsEventKey`** + **`CommsChannel`**), so that **ops can change who gets what** via data (**15C.3** later) **without** a deploy, while **invalid or missing rules** fail safe (**no send**) and are **auditable**.

## Acceptance Criteria (ACs)

1. **Dispatch contract — query rules + templates:** Introduce a **server-only** module (e.g. under **`src/lib/comms/`** — exact path **TBD in implementation**, single import surface) that, given **`event_key: CommsEventKey`**, **`channel: CommsChannel`**, and **booking-scoped context** (ids, `client_type`, quote id, etc.), **loads** all **`comms_dispatch_rules`** rows where **`event_key`**, **`channel`**, and **`active`** match. For each rule, resolve **recipient** email/phone (and role) from **`recipient_role`** + **`recipient_filter`** using **documented** semantics (start with **`recipient_filter = '{}'`** = “default recipient for that role from booking context”; extend only if product requires). For **email** channel, load the **active** **`comms_templates`** row for the same **`(event_key, channel)`** and use **`subject`**, **`body_html`**, **`body_text`** (and **`sms_body`** for **sms**) **instead of** hard-coded subject/body **where** the matrix supplies them. **Rendering** may continue to use existing React/HTML template functions **only if** the DB body is empty and a **documented** fallback is required — **prefer** DB-driven bodies for events wired in this story once seeded (**Q23** seeds remain PR-reviewed).

2. **Event key mapping (explicit):** Each refactored path uses **`CommsEventKey`** from **`src/types/comms.ts`** (no raw string literals for these events). Minimum mapping for this story (**adjust in Progress Notes if product revises**):
   - **Account** trip confirmation / quote send (today’s **`bookingQuoteOps`** “send trip confirmation” path, **`retrySendBookingQuoteEmail`**) → **`quote_sent_account`**, channel **`email`**.
   - **Walk-in** quote email (**`sendWalkInQuote`**) → **`quote_sent_walk_in`**, channel **`email`**.
   - **PayFast** (or equivalent) **payment-complete** booking confirmation (**`sendBookingConfirmation`** in **`src/services/email.ts`**) → **`payment_received`**, channel **`email`** (or **`booking_submitted`** if product confirms that semantic — **pick one** and document in Progress Notes; default **`payment_received`** for **paid** transition).

3. **Per-channel, per-rule sends:** For each **active** rule returned for **`(event_key, channel)`**, perform **at most one** outbound send per **(rule id, channel)** unless idempotency keys already justify duplicates — **preserve** existing **Resend `Idempotency-Key`** patterns from **`bookingQuoteOps`**, **`sendWalkInQuote`**, and **`retrySendBookingQuoteEmail`**. **SMS** channel: if **no** live SMS integration exists for matrix sends, **stub** or **skip** with **`comms_no_rule_matched`**-equivalent logging **only** when **no** rule; if **rules** request **sms** but provider is stubbed, **document** behaviour in Progress Notes (**must not** throw uncaught).

4. **No active rule — no-op + audit:** If **no** **`comms_dispatch_rules`** row exists for **`(event_key, channel)`** with **`active = true`**, **do not** call **`sendEmail`** / SMS for that channel. Insert **`ops_audit_log`** with **`action = 'comms_no_rule_matched'`**, **`entity`** (e.g. **`comms_dispatch`** or **`booking`** — **choose one** and stay consistent), **`entity_id`** (booking or quote id when available), **`payload`** including **`event_key`**, **`channel`**, **`log_level: 'debug'`** (epic “debug level” — **no** dedicated DB column today), and minimal correlation ids. **Actor:** satisfy **`actor_id` NOT NULL** using the **same pattern** as other automated server writes (**service role** insert policy, dedicated system profile, or staff **`auth.uid()`** when the caller is staff-only — **survey** **`appendOpsAuditLog`** / migrations and **extend** policies **only** if justified).

5. **No active template — fail safe:** If rules exist but **no** active **`comms_templates`** row exists for **`(event_key, channel)`**, **do not** send with **invented** copy; treat as configuration error: **no-op** for outbound, log **`comms_no_rule_matched`** or a **distinct** action **`comms_no_active_template`** (either is acceptable if **documented**; **prefer** separate action for ops triage).

6. **Types and DB alignment:** All new queries use **`CommsEventKey`**, **`CommsChannel`**, and row types from **`src/types/comms.ts`** / **`database.types.ts`** (**`CommsTemplateRowDb`**, **`CommsDispatchRuleRowDb`**). Any new **`ops_audit_log`** **`action`** strings are **const-exported** or **documented** in **`src/lib/ops-audit.ts`** or adjacent module.

7. **RLS / client:** Registry reads use **`createServiceRoleClient()`** (or existing **service-role** Supabase helper used for cron/server-only reads) — **not** the **portal** user session. **Do not** weaken **15C.1** RLS; **no** **`authenticated`** broad **select** on **`comms_*`** for this story.

8. **Regression — existing tests:** Update **`bookingQuoteOps`**, **`sendWalkInQuote`**, **retry**, and **PayFast webhook** tests so mocks include **seeded** **`comms_*`** rows (or **mock** the new loader) and assert **matrix-driven** sends. **`npm run test`** and **`npm run lint`** remain green.

9. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-B1** (dispatch AC), **Q23** (bodies from PR-controlled storage), **Theme E `15C.2`**; prerequisite **[`15.19.story.md`](15.19.story.md)**.

## Story Progress Notes

- **Import surface:** `@/lib/comms` (`dispatch-email`, `matrix-queries`, `recipient-resolve`, `audit-actions`, `automation-audit-actor`).
- **Service role:** `createServiceRoleClient()` in **`src/lib/supabase/server.ts`** (alias of **`createServerClient`**) for **`comms_*`** reads; staff paths still use **`createUserServerClient`** for recipient resolution + staff **`ops_audit_log`** inserts.
- **Event keys:** `sendBookingQuote` → `quote_sent_walk_in` when `client_type === 'walk_in'`, else **`quote_sent_account`**; **`retrySendBookingQuoteEmail`** same; **`sendWalkInQuote`** → **`quote_sent_walk_in`**; **`sendBookingConfirmation`** / PayFast → **`payment_received`**.
- **Pre-RPC gate:** **`sendBookingQuote`** and **`sendWalkInQuote`** call **`loadCommsEmailMatrixGate`** before **`ops_send_booking_quote_v1`** so quotes are not marked sent without a configured matrix.
- **Retry:** If matrix missing, **`auditCommsMatrixPreSendBlocked`** + **`{ ok: true, idempotent: true }`** (no customer resend).
- **Templates:** DB **`subject`** with optional **`{{booking_ref}}`** replacement; **`body_html`** null → React/HTML fallback (`renderAccountTripConfirmationHtml`, walk-in template, **`renderBookingConfirmationEmail`**).
- **Recipients (`recipient_filter` `{}`):** `booker` / `customer` → **`resolveSentToEmailForBooking`**; **`rider`** → **`rider_email`**; **`ops`** / **`dispatcher`** / **`admin`** → **`SUPPORT_EMAIL`** when set; **`chauffeur`** not implemented (rule skipped).
- **Idempotency:** Same bases as before: `trip-confirmation-send:…`, `walk-in-quote-send:…`, retry `trip-confirmation-retry:…`, **`payment-received:{bookingId}`**; suffixed with **`:{dispatch_rule_id}`** per rule.
- **Audit actions:** **`src/lib/comms/audit-actions.ts`** — `comms_no_rule_matched`, `comms_no_active_template`; payload includes **`log_level: 'debug'`**; **`entity`** = **`booking`** (stable for triage). Variant **`no_resolvable_email_recipients`** uses **`comms_no_rule_matched`** with **`payload.variant`**.
- **Automation `actor_id`:** **`OPS_AUTOMATION_AUDIT_ACTOR_ID`** (optional UUID → **`profiles.id`**) for service-role audit rows when staff JWT absent; documented in **`.env.example`**. Service role bypasses RLS on insert — no new migration policy.
- **Seed migration:** **`supabase/migrations/20260426110500_epic15_15c2_comms_matrix_default_seed.sql`** — idempotent default active templates (subject only, **`body_html` null**) + **`customer`** email rules for the three events. Applied to hosted Supabase via MCP as **`epic15_15c2_comms_matrix_default_seed`** (version **`20260426110500`**).
- **Tests:** **`src/lib/comms/__tests__/dispatch-email.test.ts`**, updated **`bookingQuoteOps`**, **`retrySendBookingQuoteEmail`**, **`email`** service tests; **`npx vitest run`** on those files — green.
