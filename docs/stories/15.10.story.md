## Story

- As **engineering / QA**, we need **Playwright E2E** covering **portal golden paths** for **admin**, **booker**, and **rider**-appropriate journeys (as implemented in **15.2–15.8**), plus a **WCAG AA**-aligned **accessibility** outcome for **15A** customer surfaces, so that **regressions** in sign-in, navigation, role-gated UI, rebook prefill, and **basic inclusive UX** are caught before ship — complementing **15.9** RLS smoke, not duplicating it.

## Acceptance Criteria (ACs)

1. **E2E entrypoint:** Add one or more specs under **`tests/e2e/`** — default name **`epic15-15a10-portal-golden-paths.spec.ts`** (split into additional files **only** if serialisation, runtime, or readability require it; **justify** in Progress Notes). Spec(s) use **`@playwright/test`**, follow existing **typed** helper patterns, and **skip** with a **clear message** when required env (Supabase URL/keys, portal test users) is missing (same spirit as **`epic14-10` staffCreds** guard).

2. **Personas & env (minimum 2–3 roles):** **Survey** the app: if **rider** has no distinct portal journey beyond read-only bookings, a **single** “non-admin” path may cover **booker + rider** with **one** env pair — **document** the mapping. Prefer **explicit** env vars, e.g. **`E2E_PORTAL_ADMIN_EMAIL` / `E2E_PORTAL_ADMIN_PASSWORD`**, **`E2E_PORTAL_BOOKER_EMAIL` / `…_PASSWORD`**, and optionally **`E2E_PORTAL_RIDER_…`**, with **`.env.test.example`** / story notes updated (placeholders only). **Alternative:** one spec file with **`test.step`** and **`process.env` role** selection — must remain **serial**-safe given **`workers: 1`**.

3. **Golden path — sign-in → home:** For each **implemented** persona, **sign in** (Supabase **customer** auth — not ops staff) and assert landing on **`/account`** (or the **documented** post-login redirect) with **expected** home content from **15.2** (account name, role treatment, **quick links** as shipped).

4. **Golden path — admin:** From home: open **`/account/bookings`**, open **at least one** row → **`/account/bookings/[id]`** (detail from **15.4**). Open **`/account/members`** (**15.5**). Open **`/account/invoices`**, then **one** “View” / detail (**15.7** — e.g. **`/account/invoices/[quoteId]`** if that is the shipped route). **Assert** **HTTP/UI success** (no error boundary; key headings or **data-testid**s as stable hooks — **prefer** text or roles to reduce flake).

5. **Golden path — booker (non-admin):** **Bookings** list + **one** detail. **“New booking”** and/or **“Book this again”** (**15.8**): assert navigation to **`/book/search`** with **stable** prefill — **e.g. query params** and/or **sessionStorage** as implemented — and **assert** with **`expect.poll` / `waitForURL` / `waitForLoadState`** patterns that avoid **race** with hydration (**survey** existing E2E: **`/book/search?e2e_fixture=…`** in **[`docs/hardening-and-go-live.md`](../hardening-and-go-live.md)**; portal prefill may differ — **no flake** is mandatory).

6. **Role gates (forbidden surfaces):** **One** of: **(a)** **booker** session: **`/account/members`** and **`/account/invoices`** → **`notFound`**, **redirect to `/account`**, or **unauthorized** UI as **intentionally** shipped; **(b)** separate focused tests. Must match **15.5 / 15.7** product rules (**US-A3** admin-only members; **US-A4** admin-only invoices in epic scope).

7. **Account switcher (US-A1) — honest deferral:** If **dual membership** test data (same user, two `customer_account_members` rows) **exists** in the **non-prod** DB used for E2E: add a test that **changes** active account via the switcher and asserts **list scope** or **URL** updates. If **not** available in CI, document **deferred** AC: **`test.skip` in CI** (or `!!process.env.E2E_PORTAL_DUAL_ACCOUNT=1` gate) with a **TODO** in spec + **Progress Notes** — **no** false green.

8. **Negative / security (browser, complements 15.9):** **One** test: authenticated user **A** (or deep-link with session **A**) navigates to **`/account/bookings/{id}`** for a booking id **known to belong to another account** (seed or service client insert) → expect **`notFound(404)`**, **redirect away**, or **empty/error** consistent with app (**15.1 / 15.4** server gating) — **not** a second full RLS suite.

9. **Accessibility (WCAG AA, epic §7):** Deliver **at least one** of the following (state which in **Progress Notes** and **Tasks**):
   - **(a) Automated in Playwright:** add **`@axe-core/playwright`** (devDependency), run **`AxeBuilder`** (or project equivalent) on a **defined set** of portal pages **after** login (e.g. home, bookings list, one detail, members, invoices list) — **zero** serious violations, or file issues with **explicit waivers** in story notes; **or**
   - **(b) No new dep:** keep **`eslint-plugin-jsx-a11y`** on **touched** portal components from this slice **if** any a11y fixes are required; **plus** a **time-boxed** **manual** keyboard + screen-reader / **checklist** (focus order, form labels, heading hierarchy) with **exit criteria** and **signed completion** in **Progress Notes** (acceptable for **3 pts** only with clear scope **limits** to portal routes, not whole marketing site).

10. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **15A.10**, **Theme A** (US-A1–A5), **§7** a11y DoD for **15A**; complements **Q20** (account clients only in portal E2E).
