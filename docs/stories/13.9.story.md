## Story

- As **finance / ops**, I need **`ready_to_invoice`**, **`invoiced`**, and **`paid_invoice`** to be **valid** **`bookings.status`** values at the database layer, with a place to store an **external invoice reference** on the booking row, so that **13.10** can build the invoicing queue and mark-paid flows on a **stable schema** (**US-D1** first **AC**, **US-D2** first **AC**, **§8**).
- As **finance**, I need **completed account trips** to **automatically** move the linked booking toward billing by setting **`status='ready_to_invoice'`** when the trip completes, so that **work is billable without a separate batch job** in v1 (**US-D1** second **AC**, **Q10** queue contract — PDF still deferred).

### Completion Notes List

- **Migration:** `supabase/migrations/20260420200000_epic13_story139_bookings_invoicing_statuses_v1.sql` — drops/recreates **`bookings_status_check`** with **`ready_to_invoice`**, **`invoiced`**, **`paid_invoice`**; adds nullable **`bookings.external_invoice_ref`** (`IF NOT EXISTS` for idempotent column add).
- **`updateTripStatusAction`:** After a successful **`trips`** row update to **`completed`**, loads **`booking_trips`** for the trip, then each linked **`bookings`** row (`id`, **`client_type`**, **`status`**, **`status_history`**). Updates booking **only if** `shouldSetBookingReadyToInvoiceOnTripCompleted` is true (**`client_type === 'account_client'`** and status not blocked). **`bookings.status_history`** gets an append entry `{ at, from, to: 'ready_to_invoice', source: 'ops_trip_completed' }`. **Order:** trip row first, then booking(s); no single DB transaction (matches existing action pattern using `createUserServerClient()`).
- **Terminal / no-op rules (do not set `ready_to_invoice`):** **`cancelled`**, **`expired`**, **`invoiced`**, **`paid_invoice`**; also **no-op** if already **`ready_to_invoice`** (retries). Walk-in / anything other than **`account_client`** skips the booking update.
- **Types:** Extended hand-maintained **`src/types/database.types.ts`** with **`BookingPipelineStatusDb`**. Extended **`OPS_BOOKINGS_QUEUE_STATUS_ORDER`** in **`src/lib/ops-bookings-queue-query.ts`**. **`npm run db:types`** was **not** run — Supabase CLI (`supabase`) was **not available** on PATH in this environment; full codegen is **`npm run db:types`** → **`src/types/supabase.generated.ts`** when linked.
- **Helper / tests:** **`src/lib/ops-trip-complete-booking-invoice-hook.ts`** + **`src/lib/__tests__/ops-trip-complete-booking-invoice-hook.test.ts`** (Vitest).
- **Commands run:** `npm run test -- --run src/lib/__tests__/ops-trip-complete-booking-invoice-hook.test.ts` (**6** tests, pass); `npm run build` (pass; existing repo ESLint warnings only).

- **Partial failure:** If the booking update fails after the trip row is already **`completed`**, the action returns **`DATABASE`** while the trip remains completed; ops can retry (booking hook is idempotent when already **`ready_to_invoice`**). No DB-level transaction wraps trip + booking in v1.
