## Story

- As **walk-in ops staff**, I need **`/ops/walk-in`** to show **only** walk-in bookings with **stage tabs**, **live counts**, and **the right primary action per stage**, so I do not mentally filter **account** rows or hunt inside a shared dropdown.

- As **ops staff**, I need the same **header / freshness / error** patterns as other ops queues so the page feels consistent and surfaces **Realtime** faults clearly.

- As **ops staff on mobile**, I need tabs to collapse to a **select** under **768px** so the queue remains usable.

- As **ops staff**, I need the **dashboard New Bookings** tile to open the **walk-in** queue (filtered), while **finance/admin** can still use **`/ops/bookings`** for cross-cutting work (**Q20**).

## Acceptance Criteria (ACs)

1. **Walk-in filter:** **`/ops/walk-in`** loads a server-rendered queue where every listed **`bookings`** row satisfies **`client_type = 'walk_in'`** (no **`account_client`** rows).
2. **Stage tabs + counts:** Tabs match **US-A1** naming: **New** (`submitted`), **Triaged**, **Availability checked**, **Quote sent**, **Awaiting payment**, **Ready to assign**, **In progress**, **Completed**. Each tab shows a **count** of matching rows (consistent with the active filter). Counts **update** after **Realtime `bookings` INSERT/UPDATE** using **debounced refresh** per **Epic 11 E2** — reuse or extract the **`OpsBookingsRealtimeBridge`** pattern (**~2s** debounce, **`OpsErrorState`** on subscription fault) so behaviour matches **`/ops/bookings`**.
3. **CTAs per stage (walk-in):**
   - **New** → **Triage** (existing transition / action used on **`/ops/bookings`** — survey **`BookingsQueueTableRow`** / related actions).
   - **Triaged** → **Check availability** — navigates to **`/ops/walk-in/[bookingId]/availability`** **only if** that route returns **200**; otherwise **disabled** + **tooltip** per **Reconciliation** (no **404** primary path).
   - **Availability checked** → **Send quote** — calls **`sendWalkInQuote`** ( **[`16.15`](./16.15.story.md)** / **`src/actions/sendWalkInQuote.ts`** ); respects **ops_settings** / bank email prerequisites (**[`16.11`](./16.11.story.md)**).
   - **Quote sent** → **view only** (no primary mutation CTA — row detail / secondary links allowed).
   - **Awaiting payment** → **Mark EFT received** — **`MarkPaymentReceivedDialog`** wired to **`markBookingPaymentReceived`** with **`evidence_ref`**, **`amount_zar`**, **`received_at`** (+ variance) per **Q32** / **[`16.14`](./16.14.story.md)**.
   - **Ready to assign** → **Assign trip** — reuse existing fulfil / assign navigation pattern (**e.g.** **`opsFulfilAssignBookingHref`** from **`/ops/bookings`**).
   - **In progress** → **view only**.
   - **Completed** → **Archive** — only if **Reconciliation** / **Task 0** yields an implemented, authorised action; otherwise **PO** sign-off to **defer** with **hidden/disabled** state documented.
4. **Shell components:** Page uses **`OpsPageHeader`**, **`OpsDataFreshnessBar`** ( **`fetchedAtIso`** from loader ), and **`OpsErrorState`** (or **`OpsFetchErrorIsland`**) for **failed initial load** — consistent with **`/ops/bookings`** / **`/ops/fulfil`**.
5. **Dashboard drill-down:** **New Bookings** card on **`/ops/`** links to **`/ops/walk-in`** with query params that **restrict to walk-in** and align with **“new”** work (**stage** / statuses — match **US-A1** **New** tab intent); update **visible/aria** copy so it no longer claims the link only opens the **unfiltered** unified queue **if** that is no longer true.
6. **Mobile:** Below **768px** viewport width, stage **tabs** collapse to a **native select** (or Radix **`Select`**) controlling the same **`stage`** state as desktop tabs.
7. **Quality gates:** **`npm run lint`** and **`npm run test`** remain green.

### Stage → SQL predicate table

All predicates compose with `client_type = 'walk_in'` plus the optional `intent` token (`booking_intent IS NULL` / `IN (...)` / `OR` of both per `parseOpsBookingsQueueSearchParams`).

| Stage tab | URL `stage` | Server predicate (after `client_type='walk_in'`) | CTA in row | Notes |
|-----------|-------------|--------------------------------------------------|------------|-------|
| New | `new` | `status = 'submitted'` | **Triage** (`triageWalkInBookingAction`) | Default tab. |
| Triaged | `triaged` | `(status = 'triaged' AND availability_checked_at IS NULL) OR status = 'quote_rejected'` | **Check availability** (gated — disabled until B2) | `quote_rejected` folded back to triaged so re-quote work is visible without a separate tab. |

| Awaiting payment | `awaiting_payment` | `status = 'awaiting_payment'` | **Mark EFT received** (`MarkPaymentReceivedDialog` → `markBookingPaymentReceived`, Q32) | Uses 16.14 fields verbatim. |

### Realtime

Reused **`OpsBookingsRealtimeBridge`** **directly** — no extraction. Constant: `OPS_BOOKINGS_REALTIME_DEBOUNCE_MS = 2_000` (≈2s) per Epic 11 E2. The bridge subscribes to the `bookings` Postgres change stream and calls `router.refresh()` on the trailing edge of a debounce window, which causes both the row list (`walkInListQuery`) and the per-tab counts (`walkInCountQuery × 8`) to refetch in a single RSC render — no parallel client-side fetch fan-out, no N+1.
