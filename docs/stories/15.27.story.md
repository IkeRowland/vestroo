## Story

- As **engineering**, we need a **pure TypeScript library** that, given a **`bookingId`**, returns **ranked, scored vehicle suggestions** using the **locked** weighted formula from **Q26**, with **weights** as **exported constants** in a sibling config module, so that **dispatchers** (in **`15D.2`**) can later see **defensible, testable** recommendations **without** this story touching **Fulfil** UI or **assignment** audit trails.

## Acceptance Criteria (ACs)

1. **Module surface:** Add **`src/lib/dispatch-suggestions.ts`** exporting **`suggestVehiclesForBooking(bookingId: string): Promise<Suggestion[]>`** — **[`docs/epic-15.md`](../epic-15.md)** US-D2 shows **`Suggestion[]`** without **`Promise`**; use **`Promise`** here because booking resolution is **I/O**-backed in production. **Optional (preferred for testability):** also export a **pure** **`computeDispatchSuggestions(input): Suggestion[]`** (or similar) that takes a **preloaded** booking + candidates + trips snapshot so **Vitest** never needs async DB for **AC8**–**AC9**. **`Suggestion`** **minimum** shape: **`vehicleId`**, **`score`** (overall **0–100**), **`rank`** (1-based order in the returned array), **`rationale: string`** (single line, suitable for **`15D.2`**). **Optional** exported sub-score fields on **`Suggestion`** (or a nested **`signals`** object) for **debugging** and **tests** — developer choice, but **tests** must be able to assert **normalised** sub-scores where relevant.

2. **Config module:** Add **`src/lib/dispatch-suggestions-config.ts`** exporting **named constants** for weights **`0.4`**, **`0.2`**, **`0.2`**, **`0.2`** mapped to **capacity fit**, **schedule gap**, **chauffeur familiarity**, **cost tier alignment** respectively — **Q26**; **no** DB table or runtime admin table for weights in this story.

3. **Scoring formula:** Overall **`score`** = **`WEIGHT_CAPACITY * capacityFit + WEIGHT_SCHEDULE * scheduleGap + WEIGHT_CHAUFFEUR * chauffeurFamiliarity + WEIGHT_COST * costTierAlignment`** using the **exported** constants from **AC2**. Each **sub-score** is **normalised 0–100** before weighting; final **overall** **`score`** is **clamped or rounded** to a **0–100** number documented in code (e.g. **integer** for UI parity with **US-D1**).

4. **Eligibility rules:** Implementation **excludes** vehicles that are **not viable** for the booking window: **overlapping availability** (conflicting assigned trips / runs in the same window — **define** overlap using the same time semantics as existing **ops** assignment validation **or** document a **conservative** rule in **Progress Notes**) and **fully-booked** / **at-capacity** vehicles per **service run** capacity rules **if** that data is available from injected inputs; when capacity RPCs exist (**survey** `service_runs`, **`reserve_service_run_capacity`**, **`src/actions/service-run-capacity.ts`**), prefer **consistent** definitions with **assign** flow or document divergence.

5. **Ranking:** Returned array is sorted by **descending** **`score`**; **`rank`** matches array order (**1** = best). **Ties:** **deterministic** secondary sort (e.g. **`vehicleId`** lexicographic) — **document** in module comment.

6. **Thin data path:** When the universe of vehicles is sparse, the function returns **≥ 2** suggestions whenever **at least two** vehicles exist in the candidate pool after **hard** exclusions (**AC4**); if strict filters would yield **< 2**, **relax** filters in a **documented** order (e.g. widen time slack, ignore soft “nice to have” filters) rather than returning an **empty** list — **unless** the fleet has **< 2** eligible vehicles, in which case returning **all** eligible rows is acceptable.

7. **Unit tests — file location:** Add **`src/lib/__tests__/dispatch-suggestions.test.ts`**. **Repo survey (locked):** **`package.json`** **`"test": "vitest"`** — use **`vitest`** APIs consistent with **`src/lib/__tests__/*.test.ts`** siblings.

8. **Unit tests — scenarios (mandatory):** (**a**) **Obvious best-fit first** — fixture where one vehicle clearly wins on combined signals ranks **#1**. (**b**) **Overlapping availability excluded** — vehicle with conflicting trip in window **absent** from results. (**c**) **Fully-booked / at-capacity excluded** — vehicle with no remaining seats **absent** (use injected capacity state). (**d**) **Thin data** — fixture with minimal history returns **≥ 2** suggestions when **≥ 2** vehicles exist (**AC6**).

9. **Testability / no live DB requirement:** Core scoring and filtering logic is covered with **in-memory** fixtures via **injectable** deps (e.g. passed **`getBooking` / `listCandidateVehicles` / `listTripsForWindow`** mocks). If a **integration** test against Supabase is added later, it is **out of scope** for **`15D.1`** unless the story owner explicitly extends scope — **this** AC requires **CI-stable** **unit** coverage without **`.env`** for the algorithm tests.

10. **Documentation traceability:** Module **file header** (short comment): **Q25** advisory nature; **Q26** weight location; pointer that **full** tuning doc lands in **`15D.6`**. **Story / DoD** reference **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15D.1`**, **Theme D US-D2**, **§5** (**15D** row), **§8** (**15D** paths).
