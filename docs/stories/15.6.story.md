## Story

- As an **account admin**, when I **invite** a colleague, they receive a **transactional email** with a **secure accept link**, so that **they can sign up or sign in** and **join** the account **without ops**.
- As an **invitee**, I need a **clear landing** at the link in the email, so that **after** I authenticate with the **same email** as the invite, my **`profile_id`** is **linked** on **`customer_account_members`**, **`accepted_at`** is set, and I can use **`/account`**.

## Acceptance Criteria (ACs)

1. **Template (Epic 13 registry):** A new **account member invite** template is added under **`src/lib/email/templates/`**, exported through **`src/lib/email/templates/index.ts`** into **`emailTemplateRegistry`** (same pattern as **`account-trip-confirmation`** / **`walk-in-quote`**). **Variables** include at minimum: **organisation / account name**, **inviter display name** (or fallback), **invited role** label, **accept-invite absolute URL**, and **expiry** copy if the token is time-limited. Subject line is professional and identifies Vestroo + the account.

2. **Rendering + send API:** Callers can build **HTML** (and optional plain text if the project standard requires it — **survey** `sendEmail` usage) via a typed props type; **no** raw `{{var}}` leakage in output for required fields.

3. **Send on invite:** When an admin successfully completes **Invite member** (existing **`inviteAccountMemberAction`** or successor), the server **attempts** to send the invite email to the **pending row’s `email`** via **`sendEmail`** / Resend, using a **stable idempotency key** (e.g. derived from **`account_id` + normalized `email` + invite row version or `invited_at`** — **survey** to avoid double-send on double-submit). **If send fails:** the **pending row** remains (invite still valid); **log** structured failure (and optionally **`ops_audit_log`** or existing email-failure pattern — **survey** Epic 13). **Document** in **Progress Notes** whether retry is **ops-queue** aligned or **best-effort only** for **15A.6**.

4. **Resend invite:** **`/account/members`** exposes a **Resend** (or **“Send again”**) action for rows with **`accepted_at IS NULL`**, reusing the same template and a **fresh** token if tokens are single-use, with **server-side** admin + active-account checks identical to **15A.5**. **Rate-limit** resend per target email / per admin if **15A.5** throttle exists; otherwise note **deferred** with pointer to **epic-15 §6**.

5. **Signup / accept landing — routes:** New route(s) under **`src/app/(public-account)/account/`** (mirror **`login`** / **`unauthorized`**) e.g. **`signup`** (or **`invite`** + **`signup`** split — **survey** UX) so the stub in **`members/page.tsx`** becomes a **real** URL. The page explains the invite and routes the user through **Supabase auth** (**sign up** and/or **sign in** / magic link — **survey** repo conventions).

6. **Token validation:** The accept link carries a **token** (**signed JWT**, **HMAC** payload, or **opaque id** validated against **DB** — **survey**; prefer **short TTL** and **no** unnecessary secrets in logs). **Invalid**, **expired**, or **already-used** tokens show a **safe** error page (no cross-account data).

7. **Email binding:** On success path, the **authenticated user’s email** MUST **match** the **`customer_account_members.email`** for the invite (case-normalised compare — **survey** Supabase / `auth.users`). **Mismatch:** refuse to attach; show guidance to sign in with the invited address or contact admin.

8. **Attach membership:** After successful auth + validation, update the **same** pending row: set **`profile_id` = `auth.uid()`**, **`accepted_at` = now()** (preserve **`invited_at`**). **Idempotent:** repeating accept with same user is a no-op success. **RLS:** use existing **portal admin** patterns or a **controlled** server path (service role only if unavoidable — justify in **Progress Notes**).

9. **Security:** Token is **single-use** OR **short TTL** (explicit choice documented); **cannot** accept for wrong email (AC7); consider **constant-time** comparisons for hashed tokens; note **abuse** / **enumeration** mitigations (generic errors, align with **15A.5** invite-creation throttle where applicable).

10. **Remove 15A.5 stubs:** Replace **“Full invite email ships in 15A.6”** / **copy-paste-only** UX in **`AccountMembersManage`** (and related copy) with **sent** / **queued-failed** state, **last sent at** if tracked, and **Resend** control. Update **`inviteAccountMemberAction`** success message to reflect **email attempted**. **Optional minimal migration:** e.g. **`invite_token_hash`**, **`invite_expires_at`**, **`invite_email_last_sent_at`** — only if required by the chosen token strategy; keep **minimal**.

11. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-A3** (invite email + signup link); catalogue **15A.6**; boundaries with **15C** / **15A.7** / bookings stories respected.
