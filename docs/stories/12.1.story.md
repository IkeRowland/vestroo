## Acceptance Criteria (ACs)

### US-A1 — VST-14 migration & data integrity (Theme A)

1. **Migration file:** DDL ships as **`supabase/migrations/20260419120000_vst14_account_clients_and_quotes.sql`**, **or** a **successor** migration file **renamed in the PR with rationale** (pointer to architecture review / epic **§Canonical technical design**). The applied head **matches** the agreed DDL — **do not invent DDL in the story**; implement per epic + migration artefact.

2. **`booking_quotes.expires_at`:** Column **`expires_at`** present on **`booking_quotes`** per epic **US-A1** / **§Canonical technical design** (**Q2**).

3. **`can_dispatch_account_booking()`:** Returns structured **reason codes**: `account_{status}`, `contract_not_yet_active`, `contract_expired`, `po_required_and_missing`, `credit_limit_exceeded`, `overdue_invoices`; enforces **PO** rules per **Q4** (epic **US-A1**).

4. **`UNIQUE(booking_id)` on `booking_trips`:** **`booking_trips.booking_id`** is **unique** (MVP 1:1 per **Q1**); attempting to **insert** a **second** row with the same **`booking_id`** on a staging/branch DB **fails at the database** (not only application-layer) — epic **US-A1**.

5. **`bookings_status_check` + transitional `pending`:** **`bookings_status_check`** includes transitional **`pending`**; **existing** rows with **`status='pending'`** are **backfilled** to **`submitted`** (mitigation per **§6 Risks** — *“Existing application code writes `status='pending'` after the CHECK constraint lands”*); attempting to insert an **unlisted** status string **fails** — epic **US-A1**.

6. **`bookings_account_linkage_check`:** Rejects **`client_type='walk_in' AND customer_account_id IS NOT NULL`** and rejects **`client_type='account_client' AND customer_account_id IS NULL`** — epic **US-A1** / **§Canonical technical design**.

7. **`bookings.payment_status` CHECK:** **`bookings.payment_status`** constrained by **`CHECK`** per epic **US-A1** (line 92: *“`CHECK` constraints on `bookings.status` and `bookings.payment_status`”*).

8. **Types & build:** Types regenerated (**`npm run db:types`** or project-equivalent); **`next build`** passes; **no new type errors** in **`src/actions/`** or **`src/app/(ops)/`** — epic **US-A1**.

### US-A2 — Smoke RLS for VST-14 (Theme A)

9. **Documented roles/tables:** Smoke documents **roles** and **tables** added for VST-14: **`customer_accounts`**, **`customer_account_members`**, **`booking_quotes`** — epic **US-A2**.

10. **Assertions:** Cover: **staff** full access on all three; **member** SELECT on own-account row; **member** SELECT on own-account members; **booking-owner** SELECT on own quotes; **non-staff non-member** returns **zero** rows — epic **US-A2**.

11. **No DELETE on `booking_quotes`:** Assertion that **`booking_quotes`** has **no** DELETE policy — **DELETE** attempts (**staff** or non-staff) **fail** — epic **US-A2** / **§Canonical technical design**.

12. **Smoke at migration head:** CI/local smoke **passes** at **migration head**; result **documented** in **`supabase/smoke_rls.sql` comment header** — epic **US-A2**.

### Cross-cutting

13. **Epic 12 DoD (schema slice):** Per **[`docs/epic-12.md`](../epic-12.md)** **§7 Definition of Done** — VST-14 tables, **`UNIQUE(booking_id)`** on **`booking_trips`**, **`booking_quotes.expires_at`**, **`bookings.status`** and **`bookings.payment_status`** **`CHECK`**, **`bookings_account_linkage_check`**, **`can_dispatch_account_booking()`** with PO block and reason codes — **migrated** and traceable to this story.
