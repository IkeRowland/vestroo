## Story

- As **platform / engineering**
- I want a **discoverable** document that explains reference **Nest/Mongo** **Auth**, **Keytoken**, and **OTP** behaviour **vs** **Supabase Auth**, **SSR/cookie-oriented** sessions (**`createServerClient`** / **`@supabase/ssr`** as the team applies in **`src/lib/supabase/`**), and **Vestroo** staff/field gates (**`requireOpsStaffPage`**, **`requireChauffeurPage`**)
- So that engineers **do not** copy **JWT-in-`localStorage`** or **refresh-token-in-browser** patterns from the reference **without an ADR**, **OTP** expectations (**provider**, **rate-limit / abuse**) are **explicit**, and **Epic 6** / **FE.5.9** / **BE.6.3** stay **consistent**

MUST summarize **reference Nest OTP** (**Mongo** repository, **bcrypt**-hashed codes, **`POST otp/verify`**, coupling to **Keytoken** token return on success) and contrast with **Vestroo** (no dedicated OTP Server Actions / **`route.ts`** today per **6.3** row — update if implementation lands).
