## Story

- As an **account user**, I need a **full booking detail** at **`/account/bookings/[id]`** for my **active** organisation, including a **current quote** section with **line items**, **rendered quote HTML** when stored, and any **downloadable artefacts** the system already has, so that I can **verify what I booked and what I was quoted** without contacting ops (per **US-A2**).

## Acceptance Criteria (ACs)

1. **Replaces 15A.3 placeholder:** **`src/app/(account)/account/(portal)/bookings/[id]/page.tsx`** is no longer only thin placeholder copy. It renders a **server-side** **booking detail** for the **active** `customer_accounts` context, with **membership and account checks** consistent with **15.1** and **15.3** (same invariants: portal JWT, RLS, **no** client-supplied account id).

2. **Access control (double defense):** The page uses **`requireAccountMemberPage`**. The loaded **`bookings`** row must have **`customer_account_id === activeAccountId`** (or equivalent **verified** join) **on the server**; on mismatch or cross-account attempt, respond with **403** (or project-standard forbidden **not** leaking existence — **survey** 15.3 behaviour: `notFound()` vs 403) **and** rely on **RLS** as second line. **Do not** pass account id from the client for authorisation.

3. **Summary section (US-A2 alignment):** Show **summary fields** for the booking when present in schema, **aligned with the list page** and **15.3** column survey: e.g. **status**, **payment status** / **total**, **pickup** (and relevant window fields), **origin → destination** (or agreed labels), **booking intent** (`booking_intent`), **passenger count** (or structured passenger fields — **survey**), **vehicle category** or agreed substitute (e.g. trip **`service_type`** if portal cannot read `vehicles` — **document** gaps in **Progress Notes** as in 15.3). Use **"—"** for missing data; **do not** invent.

4. **Current quote — row selection:** Load the **active / latest relevant** `booking_quotes` row for this **booking** (rules **survey**: e.g. latest by **`version`** or **`created_at`**, prefer **`accepted`** or **`sent`** if product requires — **document** the rule in **Progress Notes**). Display **version**, **status**, and **totals** (currency fields **survey** `booking_quotes`).

5. **Current quote — line items:** Show **line items** in a **structured** table or list. Source is either **JSON** on the quote row (e.g. `line_items` / payload column — **survey**) or a **relational** line table — **survey** schema; **no** invented fields.

6. **Rendered HTML (`rendered_html`):** If the selected quote has **non-empty** `rendered_html` (or agreed column), show it in a **read-only** viewer. **Survey** how **ops** or **email preview** renders HTML; prefer **sanitised** embedding (e.g. iframe with trusted `srcDoc` + sanitiser) or **trusted server** render pattern. **If** a shared **`QuoteRenderedHTMLViewer`** (or similar) is added under **`src/features/account/components/`**, **note** **DRY** alignment with **15A.7** immutable archive viewer: **reuse** one component when **15A.7** ships, or document a **single** extraction task if duplication is unavoidable in this story.

7. **Downloadable artefacts:** **Survey** Epic **13** schema and existing code paths for **attachment URLs**, **PDF links**, "download quote" fields, or related storage. **Surface** any that exist for this booking/quote in the UI (links with clear labels). **If none** exist, **AC:** document **N/A** in **Progress Notes** and show **placeholder** copy in the UI for **future** artefact types (no new DB columns or buckets in this story).

8. **UI cohesion:** Reuse **account portal** layout from **15.1/15.2/15.3**; detail typography and spacing should match the list page **breadcrumb/back** to **`/account/bookings`**.

9. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-A2** row-click detail; catalogue **15A.4**; **US-A5** / **"Book this again"** → **15A.8** (explicitly **out of scope**).
