## Story

- As **an organisation member**, I want **the account portal** to be **usable on a phone** (navigation, lists, invoice actions, profile/settings), so I can **manage travel and billing** without horizontal frustration or lost primary actions.

- As **Vestroo**, we need **one coordinated responsive pass** across **all account routes** so behaviour matches **FE.5.7** mobile-first expectations and **NFR.18.5** / **NFR.18.6**.

## Acceptance Criteria (ACs)
1. **Sidebar:** At **viewport < md**, navigation uses **top-bar hamburger** → **left drawer**; opening sets focus **inside** the drawer; **Escape** closes and restores focus; backdrop dismisses — consistent with existing **[`AccountShell`](../../src/features/account/components/AccountShell.tsx)** behaviour or improved to meet **FE.18.12** / **NFR.18.5**.
2. **Focus trap:** Mobile nav drawer documents **focus containment** (Tab cycles within panel; **Shift+Tab** from first → last); no **focus leak** to **`#account-main`** while open — **NFR.18.5**.
3. **Tables → cards < md:** **`/account/bookings`**, **`/account/invoices`**, **`/account/members`** present **stacked card rows** (key fields per epic) **below md**; **at md+** retain **tabular** layout (existing **`Table`**). Horizontal-only scroll **without** card mode is **not sufficient** for **FE.18.12** on narrow phones.
4. **Table accessibility:** Card layout preserves **understandable order** (labels + values), **keyboard** activation for row→detail where applicable, and **visible** sort/filter controls (may collapse behind controls — **Task 0**).
5. **Detail rails < lg:** Booking and invoice **split views** use **full-width** (full-viewport) **right sheet** **below lg**, sliding from **right**; **≥ lg** keeps **inline** rail — **[`SplitView`](../../src/components/saas/SplitView.tsx)** / **`Sheet`** updated per **Reconciliation** (width class), **`theme="account"`** unchanged.
6. **Detail focus:** Closing mobile detail sheet returns focus to **list** anchor (**`listFocusReturnRef`** pattern preserved — [`SplitView`](../../src/components/saas/SplitView.tsx) **`onCloseAutoFocus`**).
7. **Sticky mobile CTA:** Where **`DetailRail`** exposes **primary payment** (e.g. **`footerPayNow`** on invoice rail), **< lg** shows **sticky bottom bar** (or equivalent) for **primary CTA** so **Pay** is reachable without excessive scroll — align copy with **[`accountInvoicesCopy`](../../src/features/account/copy/account-invoices-copy.ts)**.
8. **Public auth (~390px):** **`/account/login`**, **`/account/signup`**, **`/account/unauthorized`** — card remains **readable**, inputs **not clipped**, **no** horizontal overflow; touch targets **≥44px** where feasible — regression vs **Story 18.11**.
9. **Dashboard & static pages:** **`AccountDashboard`**, **preferences**, **profile**, **help** — no **unhandled** overflow; grids **stack** appropriately (**[`AccountDashboard.tsx`](../../src/features/account/components/AccountDashboard.tsx)** existing **`sm:`/`md:`** patterns reviewed).
10. **Server-first:** **No** new global client data layers; **`'use client'`** only for shell, sheets, and existing interactive islands — **NFR.18.3**.
11. **Lean client:** **No** new chart/calendar libraries — **NFR.18.2** / **NFR.18.6**.
12. **Theme isolation:** **`data-account-theme`** remains only on account layouts — **NFR.18.4**.
13. **Auth / RLS:** **No** changes to authorisation or session — **NFR.18.1**.
14. **Tests:** **`npm run test -- --run`** green; add **Vitest** only for **non-trivial** responsive helpers (e.g. breakpoint hook) if introduced.
15. **Lint:** **`npm run lint`** green.
16. **Parity doc:** **`docs/ops-design-system-parity.md`** **§ 18.12** (**`parity-18-12`**) documents breakpoints, shell drawer, table→cards, rail drawer, sticky CTA — **Story 18.13** still owns **full § 18** index polish.
17. **PR hygiene:** PR cites **FE.18.12** and **Story 18.12** — **not** **FE.18.13** / **Story 18.13** unless touching shared primitive scope intentionally.
