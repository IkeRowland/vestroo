## Story

- As **an organisation member**, I want **`/account/profile`** to edit **my** name and phone and manage **my** sign-in security, so my identity is accurate across the portal without confusing **organisation** settings (**`/account/preferences`**).

- As **an organisation member**, I want a **clear distinction** between **personal profile** and **org preferences**, so I do not change the wrong settings.

- As **Vestroo**, we need profile to match **account portal** chrome (**Story 18.2**), stay **server-first** (**NFR.18.3**), remain **accessible** (**NFR.18.5**), and respect **authz** on **`profiles`** and storage (**NFR.18.1**).

## Acceptance Criteria (ACs)

1. **Route:** **`/account/profile`** renders inside **`AccountShell`** with page title and description consistent with **Story 18.2–18.4** account pages (**tokenised** surfaces on **`bg-account-canvas`**).
2. **Scope clarity:** UI copy states that this page is **personal**; **does not** expose **organisation** notification/billing controls (**FE.18.8** vs **FE.18.7**).
3. **Personal info — names:** **First name** and **last name** are editable with **per-section** or single-form Save pattern (**Task 0**); persisted to **`profiles`** (or documented store) with **RLS-safe** updates (**NFR.18.1**).
4. **Personal info — email:** **Work email** displayed **read-only** (from session / profile — single source per **Task 0**).
5. **Personal info — phone:** **Phone** optional or required per **Task 0**; validated with **`libphonenumber-js`** (valid **E.164** or agreed format); inline error on invalid input.
6. **Avatar (optional):** When **`account_profile_avatar_upload_enabled`** (or **Task 0** flag) is **on**, user can upload/replace avatar via **Supabase Storage** with acceptable image types/size limits; when **off**, section **hidden** or shows **“not available”** per product choice — **document in Progress Notes**.
7. **Sign-in security — password:** User can **change password** using **Supabase Auth** (current password + new password + confirm); success/error via **inline `Alert`** (**NFR.18.2**).
8. **Sign-in security — MFA:** **MFA** subsection shows **placeholder** copy **"Coming soon"** (or **`account-profile-copy`** equivalent) — **no** fake MFA toggles.
9. **Active sessions:** Either **list sessions** via supported Supabase API **or** display **support-managed** note (no broken promises) — **Task 0** records which path shipped.
10. **Membership exit:** **Delete or transfer my membership** presents link(s) to **`/contact`** (or documented URL) and explains that ops/admin handles transfer — **no** silent data loss.
11. **Server-first:** **`profile/page.tsx`** remains **RSC-oriented** for initial session/profile load; client boundaries **only** where needed (**NFR.18.3**).
12. **Authorisation:** Only the **signed-in user’s** profile row is readable/updatable; **no** cross-member leakage (**NFR.18.1**).
13. **Accessibility:** Headings hierarchy, labels, **`Alert`** roles/live regions where appropriate, keyboard operability — **NFR.18.5**.
14. **Performance:** **No** heavy client-only dashboard on this page; avatar upload **chunk** acceptable only behind dynamic import if needed — **NFR.18.6** / **NFR.18.2**.
15. **Vocabulary:** **B2B shuttle / organisation** language in **`account-profile-copy.ts`** — **no** rental / Wheelzie **driver** wording.
16. **Copy / tests / lint / docs:** User-visible strings in **`account-profile-copy.ts`**; **Vitest** for pure helpers (phone parsing wrappers, flag guards) if non-trivial; **`npm run lint`** / **`npm run test`** green; **`docs/ops-design-system-parity.md` § 18.9** (**Story 18.9 / FE.18.8**).
17. **PR hygiene:** PR cites **FE.18.8** and **Story 18.9** — **does not** claim **FE.18.9** / **Story 18.10** (help).
