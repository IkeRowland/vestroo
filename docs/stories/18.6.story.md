## Story

- As **an org admin**, I want **`/account/invoices`** to read like a **payments workspace** — KPIs, a scannable table, and a **detail rail** — so I can pay or download without hunting through ops email threads.

- As **Vestroo**, we need the invoices surface to compose the **same SaaS primitives** as bookings (**`SplitView`**, **`DetailRail`**, **`Pagination`**, **`StatusPill`**, **`KpiCard` `theme="account"`**) while keeping **admin-only** enforcement and **existing** payment / PDF mechanics (**NFR.18.1**).

## Acceptance Criteria (ACs)

1. **Admin-only:** **`requireAccountPortalRoles`** (admin set) unchanged; booker direct access **403** / same behaviour as today (**NFR.18.1**).
2. **Primitives:** Invoices UI composes **`SplitView`** + **`DetailRail`** + table chrome with **`theme="account"`** where applicable; **no** duplicated split-view markup from **`/ops`** (**Story 18.3**).
3. **KPI strip:** Three metrics — **Paid (last 90d)**, **Awaiting payment**, **Overdue** — using **`KpiCard`** (or **`AccountKpiCard`** wrapper) with **`theme="account"`**; loading state uses shared **`LoadingRegion`** semantics where appropriate.
4. **Table columns:** Reference, Issue date, Due date, Amount, **`StatusPill`**, Action (**Pay** / **Download PDF** as applicable per row).
5. **Row interaction:** Row click (or equivalent accessible control) opens **detail rail** without leaving list context; **focus** moves into rail (**NFR.18.5**).
6. **Detail rail — header:** Invoice / quote **reference**, issue and due dates, amount summary (matches table semantics).
7. **Detail rail — line items:** List **booking refs**, descriptions, line amounts from **real** data (extend **`loadAccountInvoiceQuoteForViewer`** / archive query or add **`loadAccountInvoiceDetailForRail`** — **no** placeholder line items).
8. **Detail rail — payment timeline:** Read-only vertical **timeline** (sent, accepted, invoiced, paid, overdue markers as applicable) from **existing** timestamps / statuses; graceful **empty** when partial.
9. **Detail rail — PO:** When account requires PO, show **PO reference** block; omit or show “—” when not required / not set (consistent with org rules).
10. **Detail rail — footer:** **Pay now** and **Download** (or disabled equivalents) mirror table actions; **Pay now** uses **existing** PayFast / payment-link path only.
11. **Pay flow:** No change to integration contracts, env vars specific to PayFast, or payment creation semantics (**AC10** regression guard).
12. **PDF:** **Download** uses **existing** signed-URL pattern for **`pdf_storage_path`**; **no** new bucket policies.
13. **Deep-link:** **`/account/invoices?id=…`** opens list with rail focused on that invoice/quote when authorised; invalid id → **404** or safe empty per portal patterns.
14. **`?status=open`:** Dashboard and bookmarks using **`?status=open`** continue to filter **open** invoice work queue as today (**Reconciliation**).
15. **Pagination:** Shared **`Pagination`** with **`theme="account"`** and **`acct_page` / `acct_per`**.
16. **Server-first:** Primary **`page.tsx`** remains **RSC-oriented**; list + rail data from server loaders; avoid new client-only data trees (**NFR.18.3**).
17. **Performance / a11y:** Respect **NFR.18.6** for list path; semantic table, visible focus, **Esc** closes rail if pattern supports (**NFR.18.5**).
18. **Copy / tests / lint / docs:** User-visible strings in **`account-invoices-copy.ts`**; **Vitest** for URL parsing / KPI helpers where non-trivial; **`npm run lint`** / **`npm run test`** green; **`docs/ops-design-system-parity.md` § 18.6** (**Story 18.6 / FE.18.5**); PR cites **FE.18.5** and **Story 18.6** — **does not** claim **FE.18.6** / **Story 18.7**.
