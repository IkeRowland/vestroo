## Story

- As an **account booker** (and **admin** when the product treats them as able to start bookings—**survey** if rider should ever see the action), I need a **"Book this again"** control on **booking detail** so that I can **open the public booking journey with the same trip shape prefilled** (origin, destination, vehicle category, passengers), **date left empty**, **no price expectations**, **my account and email context applied**, and **default PO / billing ref behaviour** when the account requires it—so that **recurring corporate travel stays one click** (per **US-A5**).

## Acceptance Criteria (ACs)

1. **Surface — route:** On **`/account/bookings/[id]`** (see **15.4** path above), a **"Book this again"** (or product-aligned label) action appears for **eligible** portal roles. **Minimum:** **booker** and **admin**; **rider:** **do not** show the primary rebook CTA **unless** product explicitly requires it (**survey** `getActiveMembershipRole` usage on the detail page).

2. **Navigation target:** The action **deep-links** into the **existing public booking entry** (primary: **`/book/search`** — [`src/app/(app)/book/search/page.tsx`](../../src/app/(app)/book/search/page.tsx)) with a **defined query-string contract** to carry **non-sensitive trip hints** only (align with **Q17** spirit in [`src/lib/quote-accept-prefill.ts`](../../src/lib/quote-accept-prefill.ts): no unnecessary PII in the URL). **No** monetary amounts, **no** past quote id, **no** historic price.

3. **Prefill fields — trip:** The public flow receives enough state to prefill: **origin**, **destination**, **vehicle / service type** (consistent with list/detail `service_type` / vehicle category—**survey** mapping from [`extractTripServiceTypeForDetail`](../../src/lib/account-booking-detail.ts) to search + quote **vehicle** selection), **passenger count**, and **booking intent** if applicable. **Pick-up date / time** must be **left empty** (or cleared after parse)—**do not** copy `pickup_datetime` as an implied “same slot” (epic: date empty; avoids stale **§6** pricing psychology).

4. **Prefill — account & member context:** The journey **reuses the active account** for the new booking: **`client_type` = `account_client`**, **`customer_account_id`** = portal **active** account, **not** from an untrusted client param. **Member email** (and name if already standard in the flow) is prefilled for contact steps—**survey** session (`createUserServerClient` / `getUser`) vs store. **PO / default billing:** if **`customer_accounts.default_po_required`** (and related fields), prefill **purchase order / default billing reference** from account defaults (e.g. **`default_billing_entity_ref`** — **survey** [`CustomerAccountRowDb`](../../src/types/database.types.ts) and [`AccountInvoicingUiContext`](../../src/features/booking/components/BookingAccountDomainGate.tsx) / [`ContactDetailsForm`](../../src/features/booking/components/ContactDetailsForm.tsx) behaviour).

5. **Implementation bridge — `BookingSearchForm` + store:** Today [`buildBookSearchPrefillHrefFromBooking`](../../src/lib/quote-accept-prefill.ts) builds **`originHint`**, **`destinationHint`**, **`passengers`**, optional **`tripDate`**, **`intent`**. The **"Book this again"** path must **omit** **`tripDate`** (or ensure the consumer ignores it) and add **vehicle / service** hints as needed. **AC:** **Survey** whether [`BookingSearchForm`](../../src/features/booking/components/BookingSearchForm.tsx) and [`src/app/(app)/book/search/page.tsx`](../../src/app/(app)/book/search/page.tsx) already pass **`searchParams`** into the form and consume those hints; if **not**, extend the page/form (or a small client bootstrap) to **read** the agreed query keys and **hydrate** `useBookingStore` / address fields—**no** dead links that only set URL without UI effect. *(Repo check: `book/search` currently only awaits `{ tab }`; prefill **survey** is required.)*

6. **Security:** **RLS** + app-layer: only bookings **for** `client_type = 'account_client'` **and** `customer_account_id = session.activeAccountId` may generate a rebook handoff. **Not found** for wrong id/tenant, consistent with **15.4**. **Q20:** do **not** enable portal-style account selection via tampered query params; **server-side** session + cookie invariants from **15.1** win.

7. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-A5**; catalogue **15A.8**; completes the **15.4** deferral ("Book this again" was **out of scope** in **15.4**).

### Completion Notes List

- **Query params (trip, no PII / no price):** `originHint`, `destinationHint`, `passengers`, `intent` (booking intent), `serviceTypeHint` (first trip `service_type` text from `extractTripServiceTypeForDetail`), `omitTripDate=1`. **Never** `tripDate`, quote id, or amounts.
- **Account id:** **Not** in the URL. Short-lived httpOnly cookie `vestroo_book_again_account_id` (path `/`, 600s) set by server action `setBookAgainPortalHandoffCookieAction` after `requireAccountMemberPage`; `/book/search` RSC calls `loadBookAgainPortalBootstrap()` (membership + `customer_accounts` read with user client), passes bootstrap to `BookingSearchForm`; client hydrates store then `clearBookAgainPortalHandoffCookieAction` expires the cookie.
- **`clientTypeResolution`:** `portal_active_account_session` (new enum on `webClientTypeResolutionSchema`). **Submit:** `enrichTripRequestBookingWithClientType` / `enrichWebBookingWithClientType` call `resolvePortalVerifiedAccountClientInsert` (RLS membership + account row) — bypasses Q6 domain candidates when this source is used.
- **Rider / admin survey:** Detail page already uses `getActiveMembershipRole(session)`; **rebook CTA only for `booker` and `admin`**; **rider** does not see the button (product default: hide for rider).
- **service_type → vehicle:** URL carries opaque `serviceTypeHint`; store field `preferredVehicleTypeHint`; `pickVehicleIdFromServiceTypeHint` in `quote-accept-prefill.ts` matches UUID to vehicle `id` else case-insensitive name substring; used in **`TripRequestBookingShell`** after vehicle offers load and **`/book/quote`** when hourly/legacy vehicle options appear.
- **PO / billing:** Bootstrap includes `default_po_required` + `default_billing_entity_ref` from server; store `purchaseOrderRef` prefilled when PO required. **`loadActiveCustomerAccountForPortal`** extended with `default_po_required` for consistency (dashboard / future use).
- **Domain gate:** `ContactDetailsForm` and embedded **`TripRequestBookingShell`** disable **`BookingAccountDomainGate`** when `clientTypeSource === 'portal_active_account_session'` so the probe does not overwrite verified portal context.
- **Migrations:** None.
