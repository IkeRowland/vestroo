## Story

- As a **migration author**, I need **`public.ops_settings`** with bank-account seed data and **RLS** (staff read, admin update), **`bookings`** payment-receipt columns with documentation comments, and **`smoke_rls`** assertions for **SELECT** / **UPDATE** / negative **UPDATE**, so **N2–N6** and email/accept flows have a **stable store** for EFT configuration and receipt metadata per **Q31** / **Q32**.

- As a **developer**, I need **`getBankAccountForReader(reader: ProfileRole)`** so server code never exposes a full **`account_number`** to non-admin staff while still allowing **dispatchers** to support ops workflows with a **last-four** display pattern.

## Acceptance Criteria (ACs)

1. **Migration file:** New migration named **`YYYYMMDDHHMMSS_ops16_ops_settings_and_payment_columns.sql`** (timestamp at implementation time; suffix **exactly** **`ops16_ops_settings_and_payment_columns`**) containing SQL **equivalent** to **[`docs/epic-16.md`](../epic-16.md)** **US-N1** snippet (~637–688):
   - **`create table public.ops_settings`** with columns:
     - **`id uuid primary key default gen_random_uuid()`**
     - **`key text unique not null`**
     - **`value jsonb not null`**
     - **`updated_at timestamptz not null default now()`**
     - **`updated_by uuid references public.profiles(id) on delete set null`**
   - **Seed** **`insert into public.ops_settings (key, value)`** for **`key = 'bank_account'`** with JSON keys **`bank_name`**, **`account_holder`**, **`account_number`**, **`branch_code`**, **`reference_format`** (default **`VST-{booking_ref}`** in the seed **`value`**) — empty-string placeholders per epic.
   - **`alter table public.ops_settings enable row level security`**
   - **`create policy ops_settings_staff_select`** — **`for select`** **`to authenticated`** **`using (public.is_staff(auth.uid()))`**
   - **`create policy ops_settings_admin_update`** — **`for update`** **`to authenticated`** **`using` / `with check`** as in epic (**`exists (select 1 from public.profiles p where p.id = auth.uid() and p.role = 'admin')`** for both).
   - **`alter table public.bookings`** add **`payment_received_at timestamptz null`**, **`payment_evidence_ref text null`** with **`if not exists`** per epic.
   - **`comment on column public.bookings.payment_received_at`** and **`comment on column public.bookings.payment_evidence_ref`** exactly as epic (~685–688).
2. **Idempotency / safety:** Prefer **`if not exists`** / **`drop policy if exists` + `create policy`** (or equivalent safe re-run pattern used in sibling **`ops16_*`** migrations) for table, policies, and columns — without weakening the epic DDL semantics.
3. **`smoke_rls.sql`:** Add a dedicated block (numbered comment consistent with file style, e.g. **“Epic 16 / Story 16.11 — Theme N / US-N1”**) that asserts at minimum:
   - **Staff (`dispatcher` JWT fixture):** may **`SELECT`** **`ops_settings`** rows relevant to the test (e.g. **`key = 'bank_account'`**); **database RLS does not mask** — document that **masking is application-layer**; smoke may assert raw row visibility **or** assert **`SELECT`** succeeds and leave masking to **vitest** for **`getBankAccountForReader`** (align with epic wording: *“Staff (`dispatcher`) can SELECT but server-shaping masks `account_number`”* — i.e. **RLS allows read**; **helper** enforces mask for dispatcher-facing server code).
   - **Admin:** may **`UPDATE`** **`ops_settings`** (e.g. touch **`updated_at`** / a harmless **`value`** field in a test-scoped way) and satisfies **`WITH CHECK`**.
   - **Non-admin staff:** **`UPDATE`** **`ops_settings`** as **`dispatcher`** (or other **non-admin** staff role) is **rejected** (RLS / **`42501`** — match existing smoke negative-control style).
   - Add **`ops_settings`** to the **§O2** recursion-sweep table list in **`smoke_rls.sql`** **if** that list is maintained as an explicit inventory (epic ~860 already includes **`ops_settings`** — keep in sync when extending behavioural block).
4. **Server helper:** Implement **`getBankAccountForReader(reader: ProfileRole, value: …)`** (signature may take raw **`jsonb` / object`** parsed from **`ops_settings.value`** for **`key === 'bank_account'`** — story leaves exact parameter types to repo **`Json`** / typed interface conventions) such that:
   - **`reader === 'admin'`** — returns the **full** bank-account object (same keys as stored JSON).
   - **`reader === 'dispatcher'`** — returns a **copy** of the object with **`account_number`** replaced by a **masked** string showing **only the last four characters** of the original when length ≥ 4; otherwise a fully redacted placeholder (epic shorthand **`***last4`**).
   - **All other `ProfileRole` values** — returns **`null`** (treat as forbidden for ops bank display).
5. **Types:** Update **`src/types/database.types.ts`** per repo convention after the schema change (**regen** or **hand-maintained** — match **16.9** / **16.10**).
