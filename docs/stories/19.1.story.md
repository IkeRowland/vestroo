## Story

- As **engineering / design**, we need a **single-shell, four-slide** public trip-request experience (**Trip → Vehicle → Details → Done**) on **one URL**, with **visible progress**, **Back** that preserves session state, and **Next / Submit** validation scoped per slide, so travelers understand where they are and **FE.10.1** single-page semantics are preserved while meeting **[FE.19.1](../epic-19.md#fe191-four-slide-funnel-shell-progress-motion-no-extra-routes)**.

- As **a11y-conscious travelers**, we need **keyboard-accessible** progress and primary actions (**NFR.19.2**), focus management between slides, and **non-essential motion** disabled when **`prefers-reduced-motion: reduce`** is set, consistent with **[Epic 17](../epic-17.md)** / **[Epic 18](../epic-18.md)** quality bars.

- As **ops and data integrity**, we need the UI to continue mapping to **`tripRequestSubmitPayloadSchema`** and **`submitTripRequest`** without weakening server validation (**NFR.19.6**).

## Acceptance Criteria (ACs)

1. **Four slides, one shell, one URL:** The traveler completes **slide 1** (trip details), **slide 2** (vehicle, required), **slide 3** (passenger + contact + submit), **slide 4** (confirmation after **successful** submit) **without** navigating to **distinct application routes** between slides (reaffirms **[FE.10.1](../epic-10.md#fe101-single-page-slide-based-funnel-no-extra-routes-for-steps)**).
2. **Progress UI:** Shell shows **clear progress** matching epic intent (labels or dots: **Trip → Vehicle → Details → Done**); current step is visually and programmatically identifiable (**NFR.19.2** — appropriate **`aria-current`** / headings pattern **Task 0** selects).
3. **Back:** **Back** from slides **2–4** (where applicable) does **not** discard valid entered data in session state; behaviour matches **Task 0** spec when leaving the funnel entirely.
4. **Browser Back:** Product-chosen behaviour (confirm-leave **or** restore in-shell last step) is **documented** in implementation (**comment** near handler and/or **Progress Notes**).
5. **Next slide 1:** Runs **trip-step validation only** (equivalent to **`validateRideDetailsStep`** success before advancing).
6. **Next slide 2:** **Disabled or blocked** until **`selectedVehicleId`** is set (and existing vehicle-offer readiness / error handling remains sensible).
7. **Submit slide 3:** Runs **full** **`tripRequestSubmitPayloadSchema`** validation before calling **`submitTripRequest`**; server-side **`submitTripRequest`** and schema **remain authoritative** (**NFR.19.6** — no intentional relaxation of server rules).
8. **Slide 4:** Shown **only** after **successful** submit; includes **request received** / booking reference treatment consistent with existing success path unless **19.12** already owns richer copy (**19.1** may keep concise success if **Task 0** defers copy to **19.12**).
9. **Motion:** Slide transitions use motion **consistent** with design-system patterns used elsewhere post–Epic **17/18** (**Task 0** picks `framer-motion` vs CSS — today booking trip shell has **no** `framer-motion`; [`BookingWizardStepper`](../../src/features/booking/components/BookingWizardStepper.tsx) shows **framer-motion** usage elsewhere for reference).
10. **`prefers-reduced-motion`:** When **`(prefers-reduced-motion: reduce)`**, **non-essential** transition/animation is skipped (instant state change acceptable); essential feedback (focus, live regions) remains (**NFR.19.2**). In-repo reference for media-query handling: [`HeroSlider`](../../src/components/homepage/HeroSlider.tsx) (`matchMedia('(prefers-reduced-motion: reduce)')`).
11. **Keyboard / a11y:** Progress, **Back**, **Next**, and **Submit** are operable via keyboard; inline error surfaces respect **`aria-live`** patterns already used on success/error (**NFR.19.2**).
12. **Tests:** Update or add **Vitest** / RTL coverage for step gating and reduced-motion branch where feasible; keep **`tripRequestSubmitPayloadSchema`** tests passing (**[`trip-request-submit-schema.test.ts`](../../src/features/booking/components/trip-request/trip-request-submit-schema.test.ts)**).
