# Story 1.2: Checkout Process

## Status: Done

## Story

- As a **traveler**
- I want to **be guided through a simple, high-conversion, multi-step checkout process**
- so that **I can complete my booking efficiently and securely**

## Acceptance Criteria (ACs)

1. **AC1:** The system MUST provide a multi-step checkout flow with the following steps:
   - Step 1: Quote Review (display calculated quote options and allow vehicle selection)
   - Step 2: Contact Details (collect passenger information: name, email, phone, optional flight number)
   - Step 3: Payment (display final price summary and initiate payment processing)
   - Step 4: Confirmation (display booking confirmation with reference number)

2. **AC2:** The checkout process MUST include a visual progress indicator (stepper) showing the current step and completed steps.

3. **AC3:** The Quote Review step MUST:
   - Display the calculated quote from Story 1.1
   - Show available vehicle options (e.g., Sedan, Van) with pricing
   - Allow the user to select a vehicle option
   - Display trip summary (origin, destination, date, time, passenger count)
   - Provide a "Continue" button that navigates to Contact Details step

4. **AC4:** The Contact Details step MUST:
   - Collect required fields: Full Name, Email, Phone Number
   - Optionally collect Flight Number (if origin is an airport, as determined in Story 1.1)
   - Validate all inputs using Zod schema (client-side and server-side)
   - Display validation errors clearly
   - Store validated data in Zustand store
   - Provide "Back" and "Continue to Payment" buttons

5. **AC5:** The Payment step MUST:
   - Display a comprehensive booking summary (trip details, selected vehicle, passenger info, final price)
   - Show the final price clearly and prominently
   - Provide a "Pay Securely" button that initiates the payment flow
   - Note: Actual PayFast integration and payment processing will be implemented in Story 1.3

6. **AC6:** The Confirmation step MUST:
   - Display booking confirmation details (booking reference, trip summary, passenger details)
   - Show a success message
   - Provide options to view booking details or return to homepage
   - Note: Email confirmation will be implemented in Story 1.4

7. **AC7:** The checkout flow MUST implement route protection:
   - `/book/quote` requires valid origin/destination in store (redirect to `/book/search` if missing)
   - `/book/details` requires selected vehicle in store (redirect to `/book/quote` if missing)
   - `/book/payment` requires customer details in store (redirect to `/book/details` if missing)
   - `/confirmation` requires booking ID (will be provided after payment in Story 1.3)

8. **AC8:** All checkout steps MUST be mobile-first responsive and follow the design goals: modern, friendly, corporate, professional, trustworthy, and efficient.

9. **AC9:** The checkout flow MUST use smooth transitions between steps (using framer-motion) to enhance user experience.

10. **AC10:** All user inputs and selections MUST be persisted in the Zustand store (`useBookingStore`) to maintain state across navigation.

11. **AC11:** Error handling MUST be implemented for:
    - Invalid or missing required data (redirect to appropriate step)
    - Form validation errors (display inline)
    - Navigation errors (graceful fallback)

## Dev Technical Guidance

### Story Context & Dependencies

This story builds directly on **Story 1.1** which implemented the booking search and quote calculation. The checkout process uses the quote data stored in the Zustand store from Story 1.1. Key dependencies:

- **Story 1.1 Outputs:**
  - Zustand store (`useBookingStore`) with trip details (origin, destination, date, passengers, flightNumber)
  - Quote calculation result (quoteAmount, estimatedDuration, distance) stored in Zustand
  - `/book/search` page that populates the store and navigates to `/book/quote`

- **Upcoming Stories:**
  - **Story 1.3** will implement actual PayFast payment processing (the "Pay Securely" button will be functional)
  - **Story 1.4** will implement email confirmation (the confirmation page will trigger email sending)

### Routing Structure

Follow the routing strategy defined in `docs/front-end-routing-strategy.md`:

- `/book/quote` - Quote Review step (Client Component)
- `/book/details` - Contact Details step (Client Component)
- `/book/payment` - Payment step (Client Component)
- `/confirmation` - Confirmation page (Server Component, accepts `?id={bookingId}`)

All booking routes are in the `(app)` route group for dynamic behavior (no ISR caching).

### State Management

The Zustand store (`src/features/booking/hooks/useBookingStore.ts`) is already set up with the necessary structure:

```typescript
interface BookingState {
  // Step 1: Search (from Story 1.1)
  origin: Location | null;
  destination: Location | null;
  date: Date | null;
  passengers: number;
  flightNumber: string | null;

  // Step 2: Quote
  selectedVehicleId: string | null;
  quoteAmount: number | null;
  estimatedDuration: number | null;
  distance: number | null;

  // Step 3: Details
  customer: { name: string; email: string; phone: string } | null;

  // Actions
  selectVehicle: (vehicleId: string, amount: number) => void;
  setCustomerDetails: (customer: BookingState['customer']) => void;
  // ... other actions
}
```

**Key Actions to Use:**
- `selectVehicle(vehicleId, amount)` - Called when user selects a vehicle on Quote page
- `setCustomerDetails(customer)` - Called when Contact Details form is submitted
- Store is accessed via `useBookingStore()` hook in Client Components

Example schema structure:
```typescript
import { z } from 'zod';

export const contactDetailsSchema = z.object({
  name: z.string().min(2, 'Name must be at least 2 characters'),
  email: z.string().email('Invalid email address'),
  phone: z.string().regex(/^(\+27|0)[0-9]{9}$/, 'Invalid South African phone number'),
  flightNumber: z.string().optional(),
});
```

### Route Protection Implementation

Implement route guards to ensure users can't skip steps. Reference `docs/front-end-routing-strategy.md`:

- Check Zustand store state before rendering page content
- Redirect to appropriate step if required data is missing
- Use Next.js `useRouter()` and `redirect()` for navigation
- Consider using middleware for route protection (optional, can be client-side checks for MVP)

Example pattern:
```typescript
'use client';

import { useEffect } from 'react';
import { useRouter } from 'next/navigation';
import { useBookingStore } from '@/features/booking/hooks/useBookingStore';

export default function QuotePage() {
  const router = useRouter();
  const { origin, destination } = useBookingStore();

  useEffect(() => {
    if (!origin || !destination) {
      router.push('/book/search');
    }
  }, [origin, destination, router]);

  // ... rest of component
}
```

### Animation & Transitions

Use **framer-motion** for smooth step transitions as specified in `docs/frontend-architecture.md`:

- Install framer-motion: `npm install framer-motion`
- Create a `StepTransition` wrapper component with slide/fade animations
- Apply to all checkout step pages for consistent UX

Example:
```typescript
import { motion } from 'framer-motion';

export function StepTransition({ children }: { children: React.ReactNode }) {
  return (
    <motion.div
      initial={{ opacity: 0, x: 20 }}
      animate={{ opacity: 1, x: 0 }}
      exit={{ opacity: 0, x: -20 }}
      transition={{ duration: 0.3 }}
    >
      {children}
    </motion.div>
  );
}
```
