## Story

- As **finance / ops**, I need a **“Ready to invoice”** view on **`/ops/invoicing`** that lists **`ready_to_invoice`** account bookings with **reference**, **customer account** name, **totals**, **trip completed** time, **PO**, **credit terms** from the booking’s **`account_snapshot`**, and a computed **due date**, **sorted soonest first by default**, with **CSV export**, so that I can **prioritise billing** without leaving the ops console (**US-D1** **ACs 3–5**, **Q10** queue contract — PDF still deferred).
- As **finance**, I need **Mark invoiced** and **Mark paid** on each row so that the booking moves **`ready_to_invoice` → `invoiced` → `paid_invoice`**, with optional **external invoice reference**, **payment fields** updated on pay, and an **audit trail**, so that the **queue stays accurate** and disputes are traceable (**US-D2** **ACs 2–5**).

### US-D1 — Invoicing queue (Theme D) — **13.10 slice (Epic US-D1 ACs 3–5)**

_(Epic **[`docs/epic-13.md`](../epic-13.md)** **§4 US-D1** — **AC3** tab/columns, **AC4** sort default, **AC5** CSV.)_

1. **“Ready to invoice” tab/view:** *(Epic **US-D1 AC3**.)* The existing **`/ops/invoicing`** area gains a dedicated **tab or view** (naming per UX consistency with the app) that lists bookings in **`bookings.status = 'ready_to_invoice'`** (and scoped appropriately to **account** / staff visibility). Columns **visible** in the grid include:
   - **`booking_reference`**
   - **`customer_account`** display **name** (from linked account / snapshot per project data model)
   - **`total_amount`**
   - **`trip_completed_at`** (from completed trip linked to the booking — use the project’s authoritative source, e.g. **`trips`** completion timestamp)

2. **Sortable columns; default sort:** *(Epic **US-D1 AC4**.)* Columns are **sortable** in the UI; **default** sort order is **`due_date` ascending** (soonest due first).

3. **CSV export:** *(Epic **US-D1 AC5**.)* A **“Copy as CSV”** and/or **“Export visible rows”** control exports the **currently visible** (filtered/sorted) rows to a **stable** column set suitable for handoff to bookkeeping (headers and field order **documented** or obvious from export).

### Completion Notes List

- **Queues & tabs:** `/ops/invoicing` uses query tabs: default **Ready to invoice** (`bookings.status = ready_to_invoice`, `client_type = account_client`), **Invoiced (awaiting payment)** (`invoiced`) for **Mark paid**, and **Corporate hooks** (existing `OpsInvoicingHooksPanel`). Staff-scoped reads via `createUserServerClient()` (same RLS pattern as `/ops/bookings`).
- **`booking_reference`:** Display and CSV column map to `bookings.payment_reference` when non-empty, otherwise the booking UUID (no `booking_reference` column in DB).
- **`trip_completed_at`:** From linked **`booking_trips` → `trips`**: latest `status_history` entry with `to === 'completed'` (by parse order / last match), else `trips.updated_at` when `trips.status === 'completed'`; max across links if multiple completed trips.
- **`due_date` rule:** **UTC calendar-day arithmetic:** take the UTC calendar date of `trip_completed_at`, add **`credit_terms_days`** as whole days in UTC, emit **`YYYY-MM-DD`**. **`credit_terms_days`** read from **`account_snapshot`** first, then fallback to **`customer_accounts.credit_terms_days`**.
- **Sorting / CSV:** Client-side sort on visible columns; server default fetch sorted by **due_date ascending** (nulls last). CSV stable header order: `booking_reference`, `customer_account`, `total_amount`, `trip_completed_at`, `purchase_order_ref`, `credit_terms_days`, `due_date`, `external_invoice_ref`, `booking_id`; trip timestamps ISO-like in export.
- **Actions:** `markInvoicedAction` / `markPaidAction` in `opsInvoicingHooks.ts` with **`getOpsStaffForAction`**, **`createUserServerClient`**, **`appendBookingStatusHistoryEntry`** (`ops_mark_invoiced` / `ops_mark_paid_invoice`), **`appendOpsAuditLog`**: **`mark_invoiced`** (payload `booking_id`, `from`, `to`, `external_invoice_ref`) and **`mark_paid`** (payload `booking_id`, `from`, `to`, `payment_timestamp`). Wrong status → **`BAD_STATUS`** structured ops error. **Idempotency:** already **`invoiced`** on mark-invoiced / already **`paid_invoice`** on mark-paid returns success without mutation; concurrent race after optimistic read returns idempotent success if DB shows target status, else **`BAD_STATUS`** refresh message.
- **Payment columns:** **`payment_status`** / **`payment_timestamp`** already on `bookings` (existing migration); **no new migration** in 13.10.
- **Commands run:** `npm test -- --run src/lib/__tests__/ops-invoicing-queue.test.ts` (pass); `npm run build` (pass; pre-existing ESLint warnings in other files only).
