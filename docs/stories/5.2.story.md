# Story 5.2: Ops design system — Tailwind + Radix (+ shadcn-style parity)

## Status: Done

**Dependencies:** **[Story 5.1](5.1.story.md)** — **Done.** The **`/ops/*` dashboard shell** (sidebar, top bar, breadcrumbs, **`ops-nav-config`**, **`OpsShellClient`**, **`OpsSidebar`**, **`OpsTopBar`**) is in place per **`docs/ops-console.md`**. This story **does not** redesign IA or navigation; it **formalises** the **UI stack decision**, **parity vs capstone *interactions***, **ops tokens** aligned with that shell, and **shared primitives** so future ops pages stay consistent. **FE.5.3** (CRUD/list/edit **patterns** and convergence) is **out of scope** here—avoid duplicating full table/form state-machine guidance; FE.5.2 is **documentation + token foundation + initial primitive set** (implementations may be **minimal** with a **documented first consumer**).

## Story

- As a **developer or designer** building **`/ops/*`** (and aligned **authenticated `/field/*`** internal surfaces)
- I want a **documented ops design system** on **Tailwind + Radix** (optional **shadcn-style** composition), with **parity guidance** vs capstone **behaviour**, **CSS variables / Tailwind extensions** for ops chrome, and **reusable primitives** (page header, filters, table shell, actions)
- so that **new ops pages reuse one stack** (**no Ant Design**), stay **visually and behaviourally predictable** (**NFR.5.1**), and stay **lean on the client** where possible (**NFR.5.2**)

## Epic traceability (source)

**From `docs/epic-5.md` — FE.5.2 (abridged):** **`/ops/*` MUST use Tailwind CSS** with **Radix UI** primitives (extend **`@radix-ui/*`** as needed) and **optional shadcn/ui**-style components in **`src/features/ops`** or **shared UI** per **[Repository conventions](../repo-conventions.md)** — **Ant Design MUST NOT** be introduced for **`/ops/*`** or **authenticated `/field/*`** unless a **future ADR** revises this. The team MUST **document** a short **ADR** in **`docs/`** and **link** from **[Documentation Index](../index.md)** (rationale, scope, **non-goals**). The team MUST publish a **parity spec** vs **frontend-admin** / **frontend-manager** **interaction** patterns (not their Ant visual theme): **data tables**; **forms**; **feedback** (modal, drawer/sheet, toast — reference manager uses **Sonner**); **density/spacing** tokens; **dashboard widgets** (KPI cards, chart containers — reference uses **Recharts**, **DevExtreme**); **scheduling/calendar** surfaces (reference: **react-big-calendar**, **react-calendar**, **EventCalendar**). Optional: **global route loading** (**nextjs-toploader**) if **product** wants it. The spec MUST define **CSS variables or Tailwind theme extensions** (colours, radii, typography, **sidebar width**) for ops. Implementation MUST favour **shared ops primitives** (page header, filter row, table wrapper, primary/secondary actions)—**new ops pages MUST reuse them**.

**Constraining NFRs (Epic 5):**

- **NFR.5.1 (Maintainability):** Minimise **duplicate** table/form implementations; shared Tailwind-based **wrappers or tokens** MUST be **defined** and **used** as primitives land.
- **NFR.5.2 (Performance):** Keep **client JS lean**: prefer **Server Components**, **lazy-load** heavy client-only widgets (maps, large tables), avoid **duplicate component libraries**; Tailwind MUST stay **purged** to used classes in production.

**Explicit non-goals (epic + story):**

- **Pixel- or theme-match** to capstone **Ant Design** — parity is **interaction and density expectations**, not visual clone.
- **Full FE.5.3 CRUD pattern catalogue** — tables/forms **lifecycle** details (loading/empty/error/confirm flows **as a standard**) belong in **Story 5.3**; here, **name** those concerns in the parity spec and **stub** primitives only as far as needed for **one** reference consumer.

**Field shell:** **Authenticated `/field/*`** MUST follow the **same locked stack** (Tailwind + Radix; no Ant) per FE.5.2; this story’s **ADR** MUST state **scope: ops + field internal shells**. **Field-specific layout work** may remain minimal if unchanged, but **tokens and primitive import paths** MUST be **documented** so field pages can adopt without a second design language.

## Acceptance Criteria (ACs)

1. **ADR — ops/field UI stack:** Add a **short ADR** under **`docs/`** (see **Dev Technical Guidance** for naming) that records: **decision** (Tailwind + Radix + optional shadcn-style in-repo components; **no Ant** for **`/ops/*`** and **authenticated `/field/*`**); **rationale** (single stack with marketing/booking, brand fit, bundle size, maintainability); **scope** and **non-goals** (**no pixel-match** to capstone Ant; **auth/transport** differences vs capstone remain as in Epic 5 intro); **consequences** (where new primitives live, expectation to extend **`@radix-ui/*`** deliberately). 2. **Parity spec — interaction patterns:** Publish a **parity spec** (**same file as ADR or companion `docs/*.md`**) that maps **expected interaction patterns** for ops-style screens to **capstone reference *behaviour*** (cite paths under **`docs/capstone-reference/frontend-admin`** and **`frontend-manager`** as **examples only**). The spec MUST cover at least: **data tables** (sort, filter, pagination, loading/empty/error states); **forms** (labels, validation, async submit, disabled states); **feedback** (modal, drawer/sheet, toast vs inline alert — note **Sonner** in reference manager as **comparison**); **density and spacing tokens** for list-heavy views; **dashboard widgets** (stat/KPI cards, chart container shape, legend/empty-state consistency — reference **Recharts** / **DevExtreme** as **interaction** context only); **scheduling/calendar surfaces** (reference **react-big-calendar** / **react-calendar** / **EventCalendar** patterns as **interaction** only). Each subsection MUST state **Vestroo implementation posture** (e.g. “use shared **`OpsTableShell`** + TanStack Table in a later story” / “toast: align on **sonner** vs **inline alert** — decision recorded”) without **mandating** new heavy dependencies unless the story **explicitly** adds them with **bundle justification**.

3. **Theme tokens — ops alignment with Story 5.1:** Define **CSS custom properties** and/or **`tailwind.config.ts` `theme.extend`** entries for **`/ops/*`** (and document how **`/field/*`** may consume the same tokens) covering at least: **semantic ops colours** (sidebar/top bar/surface/border/text muted — today largely **zinc**-style in **`OpsSidebar` / `OpsTopBar`**); **radii** (consistent with global **`--radius`** where sensible); **typography scale** for ops dense UI (at minimum: documented **text sizes** for table header, body, page title); **sidebar width** tokens **matching** current shell: expanded **~14rem (`w-56`)**, collapsed **~4.5rem (`md:w-[4.5rem]`)** per **`src/features/ops/components/OpsSidebar.tsx`**, so **layout math** does not drift. **`src/app/globals.css`** and/or **scoped wrapper** approach MUST be **documented** (e.g. `data-ops-theme` vs global `:root` overrides) so **marketing/booking** defaults are not accidentally regressed.

4. **Shared ops primitives — documented + minimal path:** Introduce **documented** shared primitives under **`src/features/ops/`** (and re-export or wrap **`src/components/ui/*`** where appropriate per **[repo-conventions](../repo-conventions.md)**) for at least: **page header** (title, optional description/actions slot); **filter row** (horizontal slot for controls + consistent spacing); **table wrapper** (scroll container, optional caption/aria guidance, consistent borders/padding); **primary/secondary actions** (button group pattern or thin wrapper over **`Button`** variants). **At least one** primitive MUST be **used on a real ops page** as **first consumer** **or** ship as **stub components** with **clear “first consumer”** named in **`docs/ops-console.md`** or the parity doc. **New** ops-facing work in this story MUST **not** introduce **parallel** one-off chrome for the same concerns without **documented** exception.

5. **Package / dependency posture:** In the **parity spec** or **ADR appendix**, add a **short inventory**: current repo **`@radix-ui/*`** (**`react-label`**, **`react-slot`** only today), **absence** of **sonner**, **recharts**, **nextjs-toploader**, etc., vs epic mentions — and **recommendations** (add vs defer) tied to **NFR.5.2**. No **required** new runtime dependencies unless **justified** in the doc and **minimal** (e.g. **sonner** for toast parity); **prefer** existing **`src/components/ui/*`** + Radix extensions.

6. **Optional `nextjs-toploader`:** The **parity spec** MUST include a **product decision line**: **adopt** global route loading (**nextjs-toploader** or equivalent) **vs defer**, with **rationale** and **bundle note**. **Implementation** of top loader is **optional** in this story and **only** if product approves in the spec or PR discussion.

7. **NFR.5.1 — deduplication rule:** The **parity spec** or **ADR** MUST state explicitly that **ops list/table and form layouts** SHOULD use **these primitives** (and shared **`src/components/ui/*`**) rather than **copy-paste** Tailwind blocks — and that **FE.5.3** will **tighten** CRUD specifics.

8. **NFR.5.2 — lean client / RSC:** The **same** docs MUST state: prefer **Server Components** for ops pages; **lazy-load** (`next/dynamic` or equivalent) for **maps**, **large client tables**, and **charts** when introduced; **avoid** importing **duplicate** UI kits; confirm **`tailwind.config.ts` `content`** already includes **`src/features/**/*`** so **purge** remains correct when primitives are added.

9. **Documentation cross-links:** Update **`docs/ops-console.md`** with a **subsection** linking to the **ADR** and **parity spec**, and summarising **where primitives live** (`src/features/ops/...`). Optionally cross-link **`docs/frontend-architecture.md`** / **`docs/front-end-style-guide.md`** if a **single sentence** reduces drift.

10. **Testing / verification:** Add **light** verification: e.g. **Vitest** for any **pure** token map / nav label helper if introduced, or **documented manual checklist** (ops home or **first consumer** page: **contrast**, **focus**, **sidebar width** unchanged vs Story 5.1). **No** requirement for full visual regression tooling in this story.

## Dev Technical Guidance

### Baseline after Story 5.1

- **Shell:** `src/app/(ops)/ops/layout.tsx` → **`OpsShellClient`**; **`OpsSidebar`** (`md:w-56` / collapsed `md:w-[4.5rem]`, drawer on small viewports); **`OpsTopBar`** (breadcrumbs, search affordance, notifications stub); nav **`src/features/ops/ops-nav-config.ts`**.
- **Styling today:** Heavy use of **Tailwind zinc** classes in ops chrome; **global** tokens in **`src/app/globals.css`** (`:root` **shadcn-style** HSL vars) and **`tailwind.config.ts`** **vest** + semantic colours.
- **Shared UI:** `src/components/ui/*` — **Button**, **Card**, **Input**, **Form**, **Select**, **Tabs**, **Alert**, **Calendar**, etc. — prefer **composition** over new parallel atoms.

### Where to put new code

- **Ops-specific primitives:** `src/features/ops/components/` (e.g. `OpsPageHeader.tsx`) or `src/features/ops/ui/` if you split **chrome** vs **domain** — **follow `docs/project-structure.md`** and **`docs/repo-conventions.md`**.
- **Cross-cutting design tokens:** `src/app/globals.css` + `tailwind.config.ts`; avoid scattering **magic numbers** after tokenisation.
- **Radix:** `package.json` currently **`@radix-ui/react-label`**, **`@radix-ui/react-slot`** only — extend with **`@radix-ui/react-dialog`**, **`dropdown-menu`**, **`toast`**, etc., **only** when a primitive needs them; **document** each addition in parity spec (**bundle**).

### Capstone references (interaction only)

- **Manager menu / density:** `docs/capstone-reference/frontend-manager/src/components/Menu.tsx` (role visibility already mirrored in 5.1 — **do not** re-copy).
- **Tables/forms/modals:** grep **`frontend-admin`** / **`frontend-manager`** `src/app` for patterns; **do not** import reference code into production **`src/app`**.

### ADR / doc naming (no existing `docs/adr/`)

- **Preferred:** `docs/adr/0001-ops-field-ui-stack-tailwind-radix.md` for the **ADR**; companion **`docs/ops-design-system-parity.md`** for the **parity spec** (keeps ADR short).
- **Alternative:** single **`docs/ops-design-system.md`** with **§Decision** + **§Parity** + **§Tokens** — still **link once** from **`docs/index.md`**.

### FE.5.3 boundary

- This story **documents** table/form **expectations** and ships **wrappers**; it **does not** require **refactoring every ops page** to identical CRUD UX — that is **FE.5.3 / Story 5.3**.
