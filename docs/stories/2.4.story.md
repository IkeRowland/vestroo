# Story 2.4: Content Editing

## Status: Done

## Story

- As an **administrator**
- I want to **update all static marketing content (e.g., About Us, Contact, Landing Page text) via the PayloadCMS interface**
- so that **I can manage marketing content, update company information, and maintain the website without requiring technical knowledge or code changes**

## Acceptance Criteria (ACs)

1. **AC1:** The system MUST provide PayloadCMS Globals for static marketing content that allows administrators to:
   - Edit content for the Homepage/Landing Page (hero text, value propositions, trust indicators)
   - Edit content for the About Us page (company history, mission, team information)
   - Edit content for the Contact page (contact information, office hours, location details)
   - Preview changes before publishing (via PayloadCMS preview functionality)

2. **AC2:** Each Global MUST support RichText editing using PayloadCMS Lexical Editor for:
   - Formatted text (headings, paragraphs, lists, links)
   - Embedded media (images, videos) where appropriate
   - Custom HTML blocks if needed for advanced formatting

3. **AC3:** The Homepage Global MUST include the following editable fields:
   - `hero_title` (text): Main headline for the homepage hero section
   - `hero_subtitle` (text): Supporting text below the headline
   - `hero_cta_text` (text): Call-to-action button text (e.g., "Book Now")
   - `value_propositions` (array): List of key value propositions/benefits (title, description, icon)
   - `trust_indicators` (richText): Trust badges, certifications, or social proof content
   - `meta_title` (text, optional): SEO meta title
   - `meta_description` (text, optional): SEO meta description

4. **AC4:** The About Us Global MUST include the following editable fields:
   - `page_title` (text): Main page heading
   - `content` (richText): Main content area (company history, mission, values)
   - `team_section` (richText, optional): Team member information
   - `stats` (array, optional): Key statistics (label, value) to display
   - `meta_title` (text, optional): SEO meta title
   - `meta_description` (text, optional): SEO meta description

5. **AC5:** The Contact Global MUST include the following editable fields:
   - `page_title` (text): Main page heading
   - `content` (richText): Introduction text or instructions
   - `contact_info` (group): Contact details
     - `phone` (text): Primary phone number
     - `email` (text): Contact email address
     - `address` (textarea): Physical address
     - `office_hours` (textarea): Business hours information
   - `contact_form_enabled` (checkbox): Toggle to show/hide contact form
   - `meta_title` (text, optional): SEO meta title
   - `meta_description` (text, optional): SEO meta description

6. **AC6:** All Globals MUST be restricted to Admin-only access using PayloadCMS Access Control functions.

7. **AC7:** The frontend MUST render content from Globals on the following pages:
   - `/` (Homepage) - Renders Homepage Global content
   - `/about` (About Us page) - Renders About Us Global content
   - `/contact` (Contact page) - Renders Contact Global content

8. **AC8:** All marketing pages MUST use Incremental Static Regeneration (ISR) for:
   - High performance (sub-100ms load times where possible)
   - SEO optimization (static HTML generation)
   - Automatic content updates when Globals are modified (revalidation on content change)

9. **AC9:** The PayloadCMS admin interface MUST provide a stable, low-latency editing experience (NFR.2.1).

10. **AC10:** All Global data MUST be persisted in Supabase (PostgreSQL) database via PayloadCMS.

11. **AC11:** The system MUST validate that:
    - Required text fields are not empty
    - Email addresses are in valid format (if email fields are added)
    - URLs are in valid format (if URL fields are added)

## Dev Technical Guidance

### PayloadCMS Globals Overview

PayloadCMS Globals are singleton collections used for content that exists in a single instance (like site settings or page content). Unlike Collections which can have multiple documents, Globals have one document that can be edited.

**Key Differences from Collections:**
- Globals are accessed via `payload.findGlobal()` instead of `payload.find()`
- Globals don't have list views in admin (only edit view)
- Globals are perfect for singleton content like homepage, about page, site settings

**Reference:** See PayloadCMS 3.x documentation for Globals: https://payloadcms.com/docs/configuration/globals

### PayloadCMS Local API Usage

Since PayloadCMS is embedded in Next.js (Next.js Native), you can use the Local API directly in Server Components without HTTP requests:

```typescript
import { getPayload } from 'payload'
import config from '@payload-config'

// In a Server Component or Server Action
const payload = await getPayload({ config })
const homepage = await payload.findGlobal({
  slug: 'homepage',
})
```

**Reference:** See `docs/architecture.md#Pattern-1-Next.js-Native-CMS` for architecture details.

### ISR Implementation Strategy

For marketing pages, use Next.js ISR to achieve high performance and SEO:

**Option 1: Using `revalidate` export:**
```typescript
export const revalidate = 3600 // Revalidate every hour
```

**Option 2: Using `unstable_cache`:**
```typescript
import { unstable_cache } from 'next/cache'

const getCachedHomepage = unstable_cache(
  async () => {
    const payload = await getPayload({ config })
    return await payload.findGlobal({ slug: 'homepage' })
  },
  ['homepage'],
  { revalidate: 3600, tags: ['homepage'] }
)
```

**Option 3: On-demand Revalidation:**
Trigger revalidation when Globals are updated using PayloadCMS hooks:
```typescript
import { revalidatePath } from 'next/cache'

export const Homepage: GlobalConfig = {
  // ... fields
  hooks: {
    afterChange: [
      async ({ doc }) => {
        revalidatePath('/')
        revalidatePath('/about')
        revalidatePath('/contact')
      },
    ],
  },
}
```

**Reference:** See `docs/architecture.md#Pattern-2-Incremental-Static-Regeneration` and Next.js 15 ISR documentation.

### RichText Rendering

PayloadCMS Lexical Editor stores content in a JSON format. To render it on the frontend:

**Option 1: Use PayloadCMS React Renderer (Recommended):**
```typescript
import { serializeLexical } from '@payloadcms/richtext-lexical'
import { PayloadLexicalReactRenderer } from '@payloadcms/richtext-lexical/react'

// In Server Component
const serialized = await serializeLexical({
  nodes: homepage.content,
  config,
})

// In Client Component (if needed)
<PayloadLexicalReactRenderer nodes={serialized} />
```

**Option 2: Convert to HTML (if simpler formatting is sufficient):**
For basic content, you might extract plain text or convert to HTML using a custom serializer.

**Reference:** See PayloadCMS Lexical documentation: https://payloadcms.com/docs/richtext-lexical

### Access Control Pattern

Follow the same pattern used in Stories 2.1, 2.2, and 2.3:

```typescript
import type { GlobalConfig } from 'payload'

export const Homepage: GlobalConfig = {
  slug: 'homepage',
  access: {
    read: ({ req: { user } }) => {
      // Public read access (for frontend rendering)
      return true
    },
    update: ({ req: { user } }) => {
      // Admin-only update access
      return user?.role === 'admin'
    },
  },
  // ... fields
}
```

**Reference:** See existing collections (`src/collections/Routes.ts`, `src/collections/VehicleTypes.ts`) for access control examples.

### SEO Metadata Implementation

Use Next.js `generateMetadata` function for each page:

```typescript
export async function generateMetadata(): Promise<Metadata> {
  const payload = await getPayload({ config })
  const homepage = await payload.findGlobal({ slug: 'homepage' })
  
  return {
    title: homepage.meta_title || homepage.hero_title,
    description: homepage.meta_description || homepage.hero_subtitle,
  }
}
```

**Reference:** See Next.js 15 metadata documentation and `docs/architecture.md#NFR.3.2-SEO-Compliance`.
