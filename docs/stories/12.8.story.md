## Story

- As **security**, I need **`bookings` RLS** to enforce **Q3** on **account-linked** inserts, so that only **staff** or **`customer_account_members`** with **`role IN ('admin','booker')`** for the target **`customer_account_id`** can create rows where **`customer_account_id IS NOT NULL`** — **riders** and **non-members** are blocked at the database layer.
- As **product**, I need alignment with **MVP**: riders do not self-book on corporate accounts; **admin** and **booker** paths remain available for legitimate booking creation (**12.5** confirm flow must still succeed for allowed roles).

## Acceptance Criteria (ACs)

### US-E2 — Member INSERT / account-linked booking INSERT RLS (Theme E, **Q3**)

1. **`bookings` INSERT when `customer_account_id IS NOT NULL`:** Add (or extend) **`bookings`** RLS so that when **`customer_account_id IS NOT NULL`**, the insert is allowed only if the actor is **`public.is_staff(auth.uid())`** (or project-equivalent staff predicate — **discover** from current **`bookings` INSERT** policy chain) **or** is a **`customer_account_members`** row for **`auth.uid()`** and the **same** **`customer_account_id`** with **`role IN ('admin','booker')`**. (**`customer_account_members_staff_insert`** already covers staff-only **membership** creation per epic; this AC is the **`bookings`** side.)

2. **Rider blocked:** An authenticated user who is a **`role='rider'`** member on the target account **cannot** insert a **`bookings`** row that is account-linked (**`customer_account_id IS NOT NULL`** / **`client_type='account_client'`** per **`bookings_account_linkage_check`**) — RLS **denies** the insert.

3. **`smoke_rls` coverage:** Extend **`supabase/smoke_rls.sql`** (or the agreed SQL harness) with cases asserting: **staff** insert OK, **admin** member insert OK, **booker** member insert OK, **rider** member insert blocked, **non-member** insert blocked — for **account-linked** **`bookings` INSERT** (mirror the role matrix in **US-E2** epic text lines **164–166**).
