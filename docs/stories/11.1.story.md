**Constraining principles (from epic):**

- **One security model:** policies **compose** without circular `USING` / `WITH CHECK` dependencies between `bookings`, `booking_trips`, and related ops-critical tables.
- **No client bypass:** staff role(s) must have **explicit** policies; fixes belong in **Postgres RLS + server context**, not ad-hoc “skip RLS” in client code.
- **Regression gate:** **`supabase/smoke_rls.sql`** stays **merge-quality** for policies this story touches.

## Story

- As **ops staff** using the console (including **Experiences**-related views that join booking data)
- I need **consistent, non-recursive read access** to **`bookings`**, **`booking_trips`**, and related joins **under the same staff/ops policy model** as other ops modules
- so that **ops pages load without PostgreSQL infinite-recursion or policy errors**, and behaviour matches **RLS**, not accidental client workarounds

- As a **maintainer** running local or CI checks
- I need **`supabase/smoke_rls.sql`** to **document** which **roles** and **tables** are exercised, and to emit **actionable** output on failure
- so that **RLS regressions are caught early** and failures point to **policy / table / role**, not opaque errors

## Acceptance Criteria (ACs)

### US-A1 — Ops read access and policy model (Theme A)

1. **No infinite recursion:** Selecting from **`bookings`** and **`booking_trips`** (and **join patterns used by ops**, including **Experiences**-related queries) **MUST NOT** produce PostgreSQL **infinite recursion** errors — **[`docs/epic-11.md`](../epic-11.md)** Theme A (**US-A1** AC).

2. **Explicit composable policies:** Staff role(s) used by the app **MUST** have **explicit** RLS policies that **compose** without circular dependencies; **MUST NOT** rely on ad-hoc RLS bypass in client code as the fix — **US-A1** AC.

3. **Unified ops + Experiences:** **Experience-related tables / joins** that ops uses **MUST** fall under the **same unified staff/ops security approach** as other ops modules (no divergent “special case” policy graph that reintroduces recursion or hidden access) — **Phase 1** table in **[`docs/epic-11.md`](../epic-11.md)** (“unify staff/ops policies incl. Experiences”).

4. **`smoke_rls` passes:** **`supabase/smoke_rls.sql`** **MUST** **pass** against the **migrated** schema, **OR** the script **MUST** be **updated** to reflect **intentional** policy names/behaviour (with **PR rationale** — no silent drift) — **US-A1** AC.

### US-A2 — Maintainer regression coverage (Theme A)

5. **Documented roles and tables:** The smoke script (or adjacent comments/README section the team agrees to treat as normative for this repo) **MUST** document **which roles** are exercised and **which tables** are **critical paths for ops** — **US-A2** AC.

6. **Actionable failure output:** On failure, smoke output **MUST** be **actionable**: identify **which** policy / table / role (or equivalent structured detail) failed — **US-A2** AC.

### Cross-cutting

7. **Migrations are source of truth:** RLS fixes **MUST** ship via **`supabase/migrations/`** (and align with **`smoke_rls`**) — **[`docs/epic-11.md`](../epic-11.md)** §7.

8. **Ops routes are consumers:** Under **`src/app/(ops)/ops/`**, changes **if any** are **only** to align with correct server/session role usage or to remove **workarounds** made obsolete by RLS fixes — **not** new feature work scoped to later phases.

### Completion Notes List

- **Root cause:** `bookings_select_chauffeur_linked` (VST-8) subqueried `booking_trips` under `bookings` RLS; `booking_trips_select` subqueried `bookings` for customer rows. Either direction re-evaluated the other table’s policies → PostgreSQL infinite recursion on SELECT.
- **Fix:** New migration adds `public.booking_is_visible_to_chauffeur_via_trips(uuid)` — `STABLE` `SECURITY DEFINER`, `search_path = public`, documents recursion break. Policy `bookings_select_chauffeur_linked` now uses only this helper (no inline join to `booking_trips` in policy text). Staff continue to use existing `bookings_select` / `booking_trips_select` with `public.is_staff(auth.uid())`; `experience_packages_staff_all` unchanged and composes with same `is_staff()` model.
- **Ops:** `src/app/(ops)/ops/experiences/page.tsx` used `createServerClient()` (service role, RLS bypass). Replaced with `createUserServerClient()` so ops staff use JWT + explicit policies (**AC2**). `fulfil/page.tsx` already used user client; no change.
- **Smoke:** `supabase/smoke_rls.sql` — header documents roles/tables; includes `booking_trips` + `experience_packages` in RLS table list; `DO` blocks assert E1 helper exists and critical policies (`bookings_select_chauffeur_linked`, `booking_trips_select`, `booking_trips_select_chauffeur`, `experience_packages_staff_all`) exist; failures `RAISE EXCEPTION` with `[smoke_rls] FAIL` and `table=` / `policy=` / `role=` / `detail=`.
- **Verification:** **`npm run smoke:rls`** runs **`supabase/smoke_rls.sql`** against **`DATABASE_URL`** (or **`DIRECT_URL`**) in **`.env.local`** — no Docker. Alternatively paste the file in the Supabase SQL Editor or use **`psql -v ON_ERROR_STOP=1 -f supabase/smoke_rls.sql`**. See **`docs/local-development.md`** (RLS smoke tests).
