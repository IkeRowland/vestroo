## Story

- As a **customer** (account booking), I need a **trip confirmation** email that includes **driver, vehicle, route, totals, and line items**, plus **payment and support** copy, so that **I have an accurate paper trail** (**US-C1** — **Theme C** completion).
- As **ops/finance**, I need the **exact HTML sent** stored on **`booking_quotes.rendered_html`** when the quote is sent, so that **disputes reference what left the system**, not a re-rendered guess (**US-C1** fourth **AC**).
- As **engineering**, I need **`sendBookingQuote`** to invoke **`sendEmail`** with the real template and to **record send failures** for the retry story, without violating **Q9** non-rollback (**US-C2** logging slice).

## Acceptance Criteria (ACs)

### US-C1 — Resend trip confirmation email (Theme C) — **13.7 completes**

1. **Full template:** Replace the **13.6** placeholder with a production-ready **`account-trip-confirmation`** implementation (React-Email or equivalent under **`src/lib/email/templates/`**) that renders at minimum: **customer name**, **booking reference**, **pickup date/time**, **origin → destination**, **vehicle name + category**, **chauffeur full name**, **total amount**, **line items breakdown** (from **`BookingQuoteLineItem[]`** / quote row), payment terms **“Invoice to follow within X days”** where **X** = **`account_snapshot.credit_terms_days`** (resolve from booking/account context per schema), a **cancellation policy** snippet (repo-consistent copy or shared constant), and **support contact** — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-C1** second **AC**.

2. **From-address:** Sending uses **`RESEND_FROM_EMAIL`** from server env (same contract as **13.6** / **`docs/environment-vars.md`**); **never** expose secrets to the client bundle — **US-C1** third **AC**.

3. **`rendered_html` at send time:** Immediately before or as part of the successful send path, **render HTML** (or canonical string from the template pipeline), **persist** it on **`booking_quotes.rendered_html`** for that quote, and ensure **ops read paths** use the **stored** value for “what was sent”, **not** a fresh re-render solely for display — **US-C1** fourth **AC**. Coordinate with **`ops_send_booking_quote_v1`** / transaction boundaries so **`sent`** and **`rendered_html`** stay consistent (extend RPC or follow-up update in **one** logical operation — document chosen approach in Progress Notes).

4. **Test-mode / structured results:** When **`sendEmail`** returns **`ok: true, mode: 'skipped_test_mode'`** (or equivalent **13.6** discriminant), **do not** treat as hard failure; **still** persist **`rendered_html`** where product requires an audit artifact; **do not** write **`email_send_failed`** for test skip — **US-C1** fifth **AC** + **13.6** contract. When **`sendEmail`** returns **`ok: false`**, do **not** roll back **`sent`** (**Q9**); **surface** failure to caller per existing ops error patterns.

### Q8 / Q9 / US-C2 — Product locks & failure observability

5. **Q8 alignment:** Email content and trigger remain consistent with **one** account post-dispatch confirmation that embeds quote details — **no** second separate “quote-only” mail in this story; wording in template should match **trip confirmation + quote** intent — **[`docs/epic-13.md`](../epic-13.md)** **§1 Q8**.

6. **Q9 non-rollback + audit:** On Resend/API/network failure (**`sendEmail`** `ok: false` on live path), **quote row stays `sent`**; **append** **`ops_audit_log`** with **`action='email_send_failed'`**, **`entity`** / **`entityId`** tying to **`booking_quotes`** (and payload including **`quote_id`**, **`error_message`**, **`attempt_count`** if tracked) — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-C2** first **AC** and **§1 Q9**. If audit insert fails, log server-side and still return structured failure (**13.8** needs a trace).
