# Story 5.8: Accessibility baseline for ops and field shells

## Status: Done

**Dependencies:** **[Stories 5.1–5.7](5.7.story.md)** — **Done** (per user / project). **Story 5.1** delivers **`OpsShellClient`**, **`OpsSidebar`**, **`OpsTopBar`** and **`requireOpsStaffPage`**-gated **`src/app/(ops)/ops/layout.tsx`**. **Story 5.2** supplies **Tailwind ops tokens** and **[ADR 0001](../adr/0001-ops-field-ui-stack-tailwind-radix.md)** — semantic **`ops-*`** colours for dark chrome. **Story 5.7** added **tablet verification** subsections in **[`docs/ops-console.md`](../ops-console.md)** and **[`docs/field-tools.md`](../field-tools.md)**; this story **adds** an **accessibility baseline** for the same shells without re-auditing marketing or booking.

**Explicit out of scope:** **FE.5.9** (integration appendix); **marketing** and **`(app)` booking** full-site WCAG audit; **legal** accessibility certification or formal VPAT; **native** driver app parity (**FE.5.6** modality remains documentation-led).

**Constraining NFRs:**

- **NFR.5.3:** Landmark, skip-link, focus, and keyboard changes MUST **not** weaken **`requireOpsStaffPage()`** (**`src/lib/ops-auth.ts`**) or **`requireChauffeurPage()`** (**`src/lib/field-auth.ts`**); no client-only bypass of staff/chauffeur gates.
- **NFR.5.2:** Prefer **lean** changes: extend existing **Tailwind `focus-visible:ring-*`**, **`aria-*`**, and **layout ids**; avoid heavy new runtime (e.g. full-app axe in production). **SHOULD**-level testing guidance may use **dev-only** or **manual** paths per AC8.

## Story

- As a **staff member or chauffeur** who uses **keyboard**, **screen readers**, or **high-contrast** needs
- I want **`/ops/*` and authenticated `/field/*`** shells to expose **correct landmarks**, **skip navigation**, **visible focus**, **labeled controls**, and **usable contrast** on the **dark** ops chrome (and field slate shell)
- so that **internal consoles** meet an agreed **WCAG 2.x–oriented baseline** without scope creep into public marketing or booking surfaces

## Epic traceability (source)

**From [`docs/epic-5.md`](../epic-5.md) — FE.5.8:** The ops and field layouts MUST meet an agreed **WCAG-oriented baseline**: **landmarks** (`header`, `nav`, `main`), **skip link** where practical, **visible focus**, **`aria-label`** on icon-only controls, **color contrast** for dark ops chrome (or light theme variant if adopted), and **keyboard** access to sidebar collapse and primary nav. Automated checks (e.g. axe in CI or manual test script) **SHOULD** be referenced in project docs.

## Acceptance Criteria (ACs)

1. **Landmarks — `/ops/*`:** The authenticated ops shell exposes a coherent landmark map:
   - A single document **`header`** for the **top bar** (see **`OpsTopBar`**).
   - At least one **`nav`** for **primary section navigation** (sidebar — **`OpsSidebar`**), with a **distinct accessible name** (e.g. `aria-label="Operations sections"` — already present; keep or refine if duplicated).
   - A **`main`** landmark for page content, with stable **`id="ops-main"`** (already on **`OpsShellClient`**) and **skip target** alignment (**AC2**).
   - Where a **second `nav`** exists (e.g. **breadcrumb** `nav` in **`OpsTopBar`** with `aria-label="Breadcrumb"`), names MUST be **unique** and **hierarchy** sensible (sidebar = primary IA; breadcrumb = location — no ambiguous duplicate “Navigation” labels).

2. **Skip link — ops (verify) and field (implement):** **`src/app/(ops)/ops/layout.tsx`** already provides a **visually hidden until focus** skip control linking to **`#ops-main`**; **preserve** behaviour and ensure **`main`** remains the focus target (e.g. **`tabIndex={-1}`** on **`#ops-main`** if focus management expects it). **Authenticated field** (`**/field/*`** excluding public **`/field/login`** / **`/field/unauthorized`**) MUST add an equivalent **skip link** to a stable main id (**`#field-main`** unless team agrees another id — document choice in **Deviation Analysis** if renamed). **`main`** in **`src/app/(field)/field/layout.tsx`** MUST expose that **`id`**.

3. **Visible focus (`focus-visible`):** Interactive controls in **`OpsShellClient`**, **`OpsSidebar`**, **`OpsTopBar`**, and authenticated **field** header / **main** actions use **non-default-only** focus indication suitable for **zinc / ops dark** surfaces: prefer **`focus-visible:outline-none`** + **`focus-visible:ring-2`** **`ring-ops`** (or **`ring-slate-*`** on field) / token-aligned rings — **do not** rely on browser default alone where it is **low contrast** on **`bg-ops-*` / slate-950**. Extend consistently to **shell** buttons/links; **page-level** ops primitives may be follow-up if out of time — document **exceptions** with owner in **Deviation Analysis**.

4. **`aria-label` on icon-only controls:** Confirm and fix gaps for **icon-only** interactive elements in the shells, including at minimum: **sidebar collapse** (md+), **mobile menu open/close**, **notifications** stub, **compact search** (small breakpoint), and **any** field chrome control that is **icon-only**. **`FieldSignOutButton`** is currently **text** (“Sign out”); if refactored to icon-only, it MUST have an **`aria-label`** (or visible text). **`OpsSignOutButton`** same rule if design changes.

5. **Contrast — dark ops baseline:** Document a **baseline** in **`docs/`** (see **AC8** targets): **primary text** (`text-ops-foreground`), **muted** (`text-ops-muted`), **borders** (`border-ops-border`), and **primary buttons** / key interactive states against **WCAG 2.x AA** **intent** (normal text ≥ **4.5:1**, large text / UI components ≥ **3:1** where applicable). **Spot-check** against **`tailwind.config.ts`** / CSS variables used by **`data-ops-theme="dark"`**; **fix** worst offenders in **tokens** or **component classes**. Any **known exceptions** (e.g. decorative badges, “soon” placeholders) MUST list **rationale + owner + follow-up**.

6. **Keyboard — sidebar, drawer, nav order:** On **`md+`**, the **sidebar collapse** control in **`OpsSidebar`** MUST remain **reachable** via **Tab** and activatable with **Enter** / **Space**. **Primary nav** links in the sidebar MUST be **keyboard reachable** in **logical order** (DOM order matches visual priority). **Mobile drawer:** If implementation uses **Radix `Dialog` / `Sheet`** pattern, MUST meet **focus trap** and **Escape** to close. If the current pattern is **not** Radix (e.g. **CSS `translate`** only), **audit** and either (a) add **documented** focus management (**trap** + **Escape**) with minimal deps, or (b) document **gap**, **risk**, and **follow-up** ticket owner in **Deviation Analysis** — **prefer (a)** if low effort.

7. **Landmarks — authenticated `/field/*`:** Field shell MUST expose **`header`** (existing sticky chrome) and **`main`** with agreed **`id`** (**AC2**). If **secondary navigation** is added later, apply the same **unique `nav` names** rule as ops; for current layout, ensure **no** landmark confusion (e.g. do not wrap unrelated regions in **`nav`** without purpose).

8. **Testing / docs (SHOULD):** Pick **one** pragmatic automated or documented path and record it in **`docs/`** (see **Project Structure Notes** for suggested files):
   - **Option A — Dev:** `@axe-core/react` in **development** only (e.g. client provider gated by `NODE_ENV`), **or**
   - **Option B — Lint:** Extend **`eslint.config.mjs`** with **`eslint-plugin-jsx-a11y`** (verify compatibility with **flat config** / Next 15) for **`src/app/(ops)`**, **`src/app/(field)`**, **`src/features/ops`**, **`src/features/field`** — **warn** or **error** policy as team agrees, **or**
   - **Option C — E2E:** `@axe-core/playwright` in an existing or new **smoke** spec for **`/ops/*`** and **`/field/*`** (only if **low friction**), **or**
   - **Option D — Manual:** A short **numbered script** (keyboard + screen reader spot checks + contrast table) in **`docs/`**.

   **CI job** for axe is **optional** — add only if **low friction**; **do not** mandate heavy new infra. Cross-link from **[`docs/index.md`](../index.md)** only if the team adds a **dedicated** a11y doc (optional).
