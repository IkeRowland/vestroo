## Story

- As a **developer**, I need the **`service_runs` × `tickets` RLS infinite-recursion** defect removed using **`SECURITY DEFINER STABLE` helper functions** and **automated regression coverage**, so that **staff-critical ops pages load without SQLSTATE `42P17`**, downstream workflow stories (**A1**, **A2**, **M1**) and **N1** are unblocked, and the fix matches the **Epic 11 E1** pattern the codebase already established.

## Acceptance Criteria (ACs)

1. **Reproduce first (smoke):** Extend **`supabase/smoke_rls.sql`** with a block that authenticates as a **chauffeur** user and runs `select count(*) from public.service_runs;`. The assertion expects **no** SQLSTATE **`42P17`**. On the branch **before** the fix migration, this assertion **must fail**, confirming the bug; after the fix migration, it **passes**.

2. **New migration** (timestamp placeholder): add **`supabase/migrations/YYYYMMDDHHMMSS_ops16_service_runs_tickets_rls_helpers.sql`** (replace `YYYYMMDDHHMMSS` with the actual migration timestamp). The migration **must:**
   - **Drop** policy **`service_runs_select_party`** (originally from **`20260418150000_sh94_patterned_run_realtime.sql`**).
   - **Drop** policy **`tickets_chauffeur_run_select`** (originally from **`20260418140000_sh93_service_run_capacity_holds.sql`**).
   - **Create** **`public.service_run_is_visible_to_party(p_service_run_id uuid) returns boolean`** as **`SECURITY DEFINER STABLE`**. Body encapsulates the **original five-clause OR** semantics from the epic: chauffeur on linked trip via `trips.chauffeur_id`; customer on linked trip via `trips.customer_id`; customer via `booking_trips → bookings.customer_id`; ticket passenger via `tickets.passenger_id`; ticket-via-booking via `tickets → bookings.customer_id` (preserve behaviour; no policy drift beyond breaking the recursion).
   - **Create** **`public.ticket_is_visible_to_run_chauffeur(p_ticket_id uuid) returns boolean`** as **`SECURITY DEFINER STABLE`**. Body per epic:  
     `SELECT EXISTS (SELECT 1 FROM public.tickets t JOIN public.service_runs sr ON sr.id = t.service_run_id WHERE t.id = p_ticket_id AND sr.chauffeur_id = auth.uid())`  
     — **single-direction** lookup; must **not** re-enter **`service_runs` RLS** for the chauffeur visibility path because of **`SECURITY DEFINER`**.
   - **Recreate** the policies using **`USING (public.<helper>(id))`**-style expressions — **no** inline **`EXISTS`** cross-table checks in the policy bodies for this pair.
   - For **both** helpers: `REVOKE ALL ON FUNCTION … FROM PUBLIC;` `GRANT EXECUTE ON FUNCTION … TO authenticated;` `GRANT EXECUTE ON FUNCTION … TO service_role;` (per epic US-K1).
   - **Comment** on each helper cites **`docs/adr/0006-rls-cross-table-helpers.md` (Theme O)** per epic; align with **Dependencies** note if ADR file lands in O1 after K1.

3. **Post-fix smoke:** After the migration, the **smoke** regression block from **AC1** passes in CI/local smoke runs.

4. **Ops page:** **`/ops/fulfil`** (see **`src/app/(ops)/ops/fulfil/page.tsx`**) **or**, if **US-A4** has already shipped, its **redirect target** — loads **without** the red error block *"infinite recursion detected in policy for relation `service_runs`"* (manual or E2E smoke as available in repo).

5. **Migration test:** Add or extend **`tests/migrations/rls-no-recursion.spec.ts`** so it exercises **`SELECT count(*)`** (or equivalent safe read) on **`service_runs`**, **`tickets`**, **`bookings`**, **`booking_trips`** under **each** relevant role/fixture setup from the epic and asserts **no** recursion / **`42P17`** (match existing test harness patterns in `tests/migrations/`).

6. **Process:** **Paired migration review** by another engineer documented (PR description, review comment, or team checklist) **before merge** — per epic US-K1 and §6 risk mitigation for K1.
