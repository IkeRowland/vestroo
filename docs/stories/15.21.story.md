## Story

- As an **ops lead**, I need an **admin-only** page at **`/ops/comms`** that lists **`comms_templates`** and **`comms_dispatch_rules`** and lets me **toggle active state**, **change dispatch recipient role**, and **edit `recipient_filter` JSON**, with **every change audited**, so that **I can respond to policy changes without a deploy** while **template wording stays PR-governed** (**Q23**) and **full rendered preview** waits for **`15C.4`**.

## Acceptance Criteria (ACs)

1. **Route + staff gate:** **`src/app/(ops)/ops/comms/`** (align with existing **`(ops)`** layout, nav, and patterns from other ops pages per **[`docs/epic-15.md`](../epic-15.md)** §8). **`/ops/comms`** is reachable only for **staff** users (**`is_staff`** / same gating as sibling ops routes — **survey** existing **`(ops)`** layouts and middleware). Non-staff receive **403** or redirect consistent with the app.

2. **List `comms_dispatch_rules`:** The page (or subviews) lists **all** rows from **`public.comms_dispatch_rules`** with key fields visible (**`event_key`**, **`channel`**, **`recipient_role`**, **`active`**, **`recipient_filter`** summary or collapsed JSON indicator, **`id`**, timestamps as useful for triage).

3. **List `comms_templates`:** The page lists **all** rows from **`public.comms_templates`** with **metadata** visible (**`event_key`**, **`channel`**, **`subject`**, **`active`**, **`version`**, **`id`**, timestamps). **Per AC reconciliation:** include the **placeholder panel** copy that **seeded-variable rendered preview** is **`15C.4`**; **do not** ship HTML/text/SMS **render** with substitution in **`15.21`**.

4. **Per-rule mutations:** For each **rule**, staff can: **toggle** **`active`** (persisted to DB); **change** **`recipient_role`** to allowed values aligned with **`CommsDispatchRecipientRole`** in **`src/types/comms.ts`** (UI control matches type — select/dropdown); **edit** **`recipient_filter` jsonb** with **visual editor preferred** (e.g. key-value / structured form if product agrees) and **raw JSON editor acceptable** as fallback; invalid JSON **must** be rejected server-side with a clear error (no silent `{}` overwrite unless explicitly saved as empty object).

5. **Per-template mutations:** For each **template**, staff can **toggle** **`active`** only. **Body fields** (`body_html`, `body_text`, `sms_body`) and **subject** edits are **disabled** or omitted from mutation payloads; UI provides a **link** to the **GitHub PR template** (or single documented URL in env/config) for **body/subject copy changes** per **Q23**.

6. **`ops_audit_log` on every registry change:** **Every** successful **insert/update** of **`comms_dispatch_rules`** or **`comms_templates`** from this UI writes **`ops_audit_log`** with **`actor_id`** = staff user, a stable **`action`** name (const-exported or documented next to **`appendOpsAuditLog`** usage), **`entity`** / **`entity_id`** identifying the row (table + id or agreed convention), and **`payload`** (or dedicated columns if the project pattern uses them) containing **prior** and **new** value for the fields that changed (at minimum the mutated columns; **prefer** full row snapshot before/after for small rows if consistent with other ops audit payloads).

7. **RLS / client correctness:** Mutations use **staff** Supabase session (server actions / route handlers under **`(ops)`**), **not** portal **`createUserServerClient`** used for account JWT for **`comms_*`** writes. **Do not** weaken **15C.1** RLS; **no** new policy granting **non-staff** **`authenticated`** **write** to **`comms_*`**.

8. **Types and validation:** UI and server actions use **`CommsEventKey`**, **`CommsChannel`**, **`CommsDispatchRecipientRole`**, and DB row types from **`src/types/comms.ts`** / **`database.types.ts`**. **`recipient_filter`** persisted shape matches **15C.1** migration comments (empty **`{}`** = default semantics).

9. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-B2**, **Q23**, **Theme E `15C.3`**; prerequisite **[`15.19.story.md`](15.19.story.md)**; **defer** seeded preview to **`15C.4`**.

10. **(Optional stretch)** **Rule coverage summary:** If low-effort, add a compact summary (e.g. sidebar or section) where each **`CommsEventKey`** (or grouped by theme) shows whether **≥1** **`active`** rule exists **per channel** (**email** / **sms**), with a visible warning when an event/channel pair has **zero** active rules — mitigates epic §6 “misconfigured matrix” risk. **If** this risks scope creep, **defer** to **`15C.4`** or a later ops polish story and note deferral in **Progress Notes**.
