**Constraining principles (from epic Theme C):**

- **Segmentation:** **paid**, **pending**, and **trip_request** work are **addressable** via **tabs or filters**; **bucket definitions** are **documented** and **map 1:1** to **non-overlapping** query predicates (or a documented **priority order** if the product **must** allow overlap — default is **no ambiguous overlap**).
- **Empty states:** When a bucket has **no rows**, staff see **why** (e.g. “No bookings match **pending payment** in this queue” — exact copy per UX), not a generic “No results”.
- **Actions:** **Record payment** and **acceptance** paths are **optional** and **business-gated**; controls appear **only** when **booking/trip state** and **staff role** permit — otherwise **disabled with reason** **or** **hidden** per an agreed ops UX pattern **consistent** with other ops surfaces.
- **Freshness:** After mutations, lists **update** without a **full page reload** **where** [`docs/ops-data-freshness.md`](../ops-data-freshness.md) marks **`/ops/fulfil`** as **RSC per navigation** — use **`router.refresh()`**, **`revalidatePath`**, or **server action return + client state** per **11.2** patterns; any **exception** (e.g. hard navigation) **must** be **documented** in that matrix or in the bucket doc **with rationale**.

## Story

- As **fulfilment staff**
- I need **tabs or filters** for **paid**, **pending**, and **trip_request** work
- so that I can **prioritize** queues without mixing incompatible workloads — **US-C1**

- As **fulfilment staff**
- I need **optional paths** to **record payment** or **acceptance** where the business allows
- so that I can **complete** fulfilment steps **in context** without leaving the console — **US-C2**

## Acceptance Criteria (ACs)

### US-C1 — Tabs/filters and documented buckets (Theme C)

1. **Tabs or filters:** The primary fulfil surface (**`src/app/(ops)/ops/fulfil/page.tsx`**) **MUST** expose **tabs or filters** (or an equivalent segmented control) that let staff switch between **paid**, **pending**, and **trip_request** queue views — **[`docs/epic-11.md`](../epic-11.md)** Theme C (**US-C1**).

2. **Documented predicates:** **Each** bucket (**paid**, **pending**, **`trip_request`**) **MUST** have a **written definition** (field names, operators, and any joins) that **matches** the **actual** Supabase/Postgres query predicates used in code — **US-C1** AC. Definitions **MUST** be **non-ambiguous**: no row should **simultaneously** satisfy two bucket definitions unless the story **explicitly** documents a **tie-break** rule (default: **mutually exclusive** predicates).

3. **Empty states:** When the active bucket returns **zero** rows, the UI **MUST** show an **`OpsEmptyState`** (or equivalent from **`src/features/ops/components/OpsEmptyState.tsx`**) with copy that **explains why** that tab/filter is empty (e.g. criteria not met vs data lag), not a generic empty list — **US-C1** AC.

### US-C2 — Optional payment & acceptance; permissions; persistence (Theme C)

4. **Business-optional actions:** Where **product rules** allow, the fulfil surface **MUST** offer **optional** affordances to **record payment** and/or **acceptance** (exact verbs and flows **as agreed** — may delegate to existing booking/payment routes or **new** thin server actions under **`src/actions/ops*.ts`** if needed) — **US-C2** AC. If the business **defers** one path, **document** “not in v1” in the bucket doc (**AC2**) and **hide** or **omit** controls (not dead buttons).

5. **State + role gating:** **Record payment** / **acceptance** controls **MUST** appear **only** when **`booking`/`trip` state** and **staff role** permit the action; otherwise controls are **disabled with an accessible reason** **or** **omitted** per the same **show vs hide** pattern used elsewhere in ops — **US-C2** AC.

6. **Persist and reflect:** Successful mutations **MUST** **persist** to the database and **reflect** in the active queue list **without** requiring a **full browser reload**, **or** the team **MUST** document an **exception** aligned with **11.2** (e.g. **`/ops/fulfil`** remains **RSC per navigation** — then **`router.refresh()`** / **`revalidatePath`** after action success is the **normative** refresh path) in [`docs/ops-data-freshness.md`](../ops-data-freshness.md) and/or the bucket doc — **US-C2** AC.

### Cross-cutting

7. **Reuse E2 primitives:** Loading, fetch errors, and action failures on this page **MUST** use **`OpsDataFreshnessBar`**, **`OpsFetchErrorIsland`**, and **`OpsErrorState`** (or current successors) from **`src/features/ops/components/`** consistently with **[`docs/stories/11.2.story.md`](11.2.story.md)** — **Theme B** consumption, not re-implementation.

8. **Structured logging:** New or extended **`src/actions/ops*.ts`** entrypoints **MUST** use the **same** structured logging approach as **11.2** ([`docs/ops-server-action-logging.md`](../ops-server-action-logging.md)) — correlation, outcome, PII minimization.

9. **Assign flow alignment:** Existing **assignment** UX (**`AssignBookingPanel`**, dispatch/close-protection patterns) **MUST** remain **coherent** with new queues (correct props per bucket; no duplicate conflicting lists).
