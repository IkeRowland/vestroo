## Story

- As **Vestroo engineering**, we need **`comms_templates`** and **`comms_dispatch_rules`** in **Postgres** with **RLS** that matches **Epic 11** staff access patterns, plus shared **`CommsEventKey`** and **`CommsChannel`** types, so that **15C.2+** can drive **comms** from data **without** granting **portal users** the ability to **mutate** ops comms registries **via** the customer JWT.

## Acceptance Criteria (ACs)

1. **Migration(s) — `comms_templates`:** New table (name **`public.comms_templates`**) with columns at minimum: **`event_key`** (`text` — values constrained in app by **`CommsEventKey`**), **`channel`** ( **`text` or enum** — must support **`email`** and **`sms`** at minimum), **`subject`** (`text`, nullable where not applicable, e.g. some SMS), **`body_html`**, **`body_text`**, **`sms_body`** (appropriate nullability for channel — **document** in migration comments), **`version`** (integer or smallint, **≥ 1**), **`active`** (`boolean`, default **false** or per team convention — **document**), plus **standard** registry columns: **`id`** (**uuid**, PK, default `gen_random_uuid()` or project convention), **`created_at`**, **`updated_at`** (**timestamptz**, **`updated_at`** maintained via **trigger** or **consistent** with similar tables — **survey** `experience_packages` / other registries in **`supabase/migrations/`**). **Indexes:** at minimum usable paths for **( `event_key`, `channel` )** lookups for active rows; **unique** constraint strategy **TBD in migration** (e.g. **unique ( `event_key`, `channel`, `version` )** if multiple versions per pair — **must** be justified in migration comment).

2. **Migration(s) — `comms_dispatch_rules`:** New table **`public.comms_dispatch_rules`** with: **`event_key`**, **`channel`**, **`recipient_role`** (align values with product vocabulary used in **15C.3** — e.g. booker / rider / ops; store as `text` with check constraint or enum — **survey** **`profiles` / `customer_account_members` role** strings), **`recipient_filter`** (`jsonb`, not null default `'{}'`), **`active`**, plus **`id`**, **`created_at`**, **`updated_at`**. **Indexes** for **( `event_key`, `channel` )** and **partial** / composite indexes as needed for “active rules for event” queries.

3. **RLS — staff read/write, portal not writer:** **Enable RLS** on both tables. **Authenticated** users who are **staff** (`public.is_staff(auth.uid())` — same helper as **Epic 11** / existing ops tables) may **select**, **insert**, **update** (and **delete** only if a sibling registry allows staff delete; otherwise **no delete** for non-service-role — **survey** `close_protection_engagements` / **`ops_audit_log`**-adjacent patterns). **Explicit AC:** **no policy** that allows **`customer_account_members`** / **account portal** roles to **insert**, **update**, or **delete** these tables **using** the normal **portal** session (i.e. **not** `is_staff`). **Chauffeur** / **field** JWT, if distinct, **must not** write comms registries either unless explicitly aligned with a future story — default **no** **write** except **staff**; **select** for non-staff is **not required** in **15C.1** (default **deny** for anon; **deny** or no broad **select** for non-staff `authenticated` unless a documented read use case exists — **prefer** staff-only **select** on these tables for **15C.1**). **`service_role`** / **postgres** for migrations and seeds: unchanged standard.

4. **Grants:** **`anon`** / **`authenticated`** grants consistent with RLS; **no** accidental **bypass** of RLS for **`authenticated`** (verify **no** `grant all` without RLS or security-definer footguns for portal paths).

5. **Shared types — `CommsEventKey` + channel:** Add **`CommsEventKey`** as a **string union** (or const object + derived type) in **`src/types/`** (e.g. **`src/types/comms.ts`**) or **`src/lib/comms/`** if the project prefers colocated comms lib — **one** canonical export surface documented in **Progress Notes**. **Minimum** keys (extensible with comment): `booking_submitted`, `quote_sent_account`, `quote_sent_walk_in`, `quote_accepted`, `quote_rejected`, `payment_received`, `trip_assigned`, `trip_en_route`, `trip_completed`, `trip_cancelled`, `invoice_due_reminder`, `member_invited`. Add **`CommsChannel`** = **`'email' | 'sms'`** (minimum; document extension for e.g. push in a **future** epic). **AC:** new code **should** import these types instead of raw strings for **event** and **channel** in comms-related modules **as they are added** in follow-on stories (this story **adds** types; **wiring** is **15C.2**).

6. **Hand-maintained `database.types`:** After migration, update **[`src/types/database.types.ts`](../../src/types/database.types.ts)** (or project-agreed hand-maintained location) with **row types** / table names / enum notes consistent with the repo’s pattern (see file header: **VST-5** and **`ExperiencePackageRowDb`-style**). **Grep** for `Database` interface updates if the project extends a central type.

7. **Smoke RLS (optional but recommended):** If **[`supabase/smoke_rls.sql`](../../supabase/smoke_rls.sql)** (or **`npm run smoke:rls`**) is the merge gate, add **minimal** assertions for **new** policies **or** document **why** deferred in **Progress Notes** (e.g. follow-up in **15C.2** with staff session fixtures) — **prefer** extending **smoke** in **15C.1** if low effort.

8. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **Theme B / US-B1** (schema slice only: two tables + enumeration), **Q23** (bodies = PR path; this story = **durable** storage, not UI), **Theme E `15C.1`**; references **[`docs/epic-13.md`](../epic-13.md)**, **[`docs/epic-11.md`](../epic-11.md)** E1; **channel** alignment with **[`15.14.story.md`](15.14.story.md)**.

9. **No product sends in scope:** **Do not** add or require changes to **`src/lib/email/send.ts`**, **`src/services/sms.ts`**, or server actions to **read** these tables in **15C.1** — a **trivial** re-export or **type-only** import in an existing file is allowed **only** if it avoids dead code; prefer **new** `src/types/comms.ts` / `src/lib/comms/index.ts` **types-only** module.
