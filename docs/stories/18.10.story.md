## Story

- As **an organisation member**, I want **`/account/help`** to show **common questions**, **how to contact ops**, and (when configured) a **status page** link, so I can self-serve basics and know how to reach support.

- As **Vestroo**, we need the help surface to **degrade gracefully** when FAQ entries are not yet authored, reuse **existing support email / contact line** helpers, and stay visually consistent with the **account portal** (**Stories 18.1–18.9**).

## Acceptance Criteria (ACs)

1. **Route:** **`/account/help`** renders inside **`AccountShell`** on **`bg-account-canvas`** with page title and description consistent with other **18.4–18.8** account portal pages (**tokenised** chrome).
2. **FAQ section:** When **≥ 1** curated FAQ entry exists (static module or **Task 0**–approved source), render **3–5** items (cap at 5 if more are added later) as an accessible **Q/A list** (headings or definition list — **Task 0**); each entry has **question** + **answer** copy suitable for **B2B shuttle** customers (**no** rental / Wheelzie driver wording).
3. **Empty FAQ:** When **zero** curated entries, **do not** show an empty list shell that looks broken; show **friendly** copy (e.g. “No frequently asked questions yet”) via **`account-help-copy`** and, if aligned with **18.3**, reuse **`EmptyState`** with **`theme="account"`** or **`AccountEmptyState`** when that primitive exists — **Task 0** picks.
4. **Contact ops:** Prominent **mailto:** (or contact block) using **`resolveSupportEmailAddress()`**; visible **support address** matches env override behaviour (**`SUPPORT_EMAIL`**).
5. **SLA / expectations:** Display support / response copy derived from **`resolveSupportContactLine()`** and/or **Task 0**–approved **SLA strings** in **`account-help-copy`** (no invented “we reply in X hours” unless product-provided).
6. **Status link:** If **Task 0**–defined public status URL env is **set**, render an external link (new tab, **`rel="noopener noreferrer"`**); if **unset**, **omit** the link and any orphan label (**FE.18.9**).
7. **Stub cleanup:** Production **`src/app/(account)/account/(portal)/help/page.tsx`** **must not** use **`accountStubPagesCopy.helpTitle` / `helpBody`**; remove **`help*`** keys from **`account-stub-pages-copy.ts`** if nothing else references them (**Task 0** confirms).
8. **Copy discipline:** All user-visible strings for this page live in **`src/features/account/copy/account-help-copy.ts`** (single module export for future i18n — **no** new i18n framework in this epic).
9. **Server-first:** **`help/page.tsx`** remains **RSC**-oriented; **no** unnecessary client boundaries (**NFR.18.3**).
10. **Authorisation / scope:** Page shows **only** public help/contact content appropriate to any **signed-in** member (**NFR.18.1**); **no** org-private operational data.
11. **Feedback:** **No Sonner** (**NFR.18.2**); this page is informational (no mutating forms required for **MVP**).
12. **Accessibility:** Logical heading order, descriptive link text for mailto/status, keyboard focus order — **NFR.18.5**.
13. **Performance:** **No** heavy client bundles; static copy + optional small presentational client wrapper only if justified — **NFR.18.6**.
14. **Tests:** **`npm run test -- --run`** green; add **Vitest** only for **non-trivial** pure helpers (e.g. URL/env parsing) if introduced — otherwise rely on lint + manual + **Task 0** note.
15. **Lint:** **`npm run lint`** green.
16. **Parity doc:** **`docs/ops-design-system-parity.md` § 18.10** documents this route (**Story 18.10 / FE.18.9**).
17. **PR hygiene:** PR cites **FE.18.9** and **Story 18.10** — **does not** claim **FE.18.10** / **Story 18.11** (sign-in).
