## Story

- As a **developer or lead** working from **`docs/capstone-reference`**
- I want a **single canonical integration appendix** plus **UI dependency inventory** that contrasts reference **Nest + axios + JWT + Firebase + socket.io** patterns with Vestroo **Supabase + server gates + Server Actions + Storage + Realtime**
- so that teams **reuse IA and UX ideas** safely and **do not** blind-port **tokens, API clients, base URLs, or socket wiring** — and so **FE.5.10** can focus on **module-by-module** traceability without repeating integration fundamentals

## Epic traceability (source)

**From [`docs/epic-5.md`](../epic-5.md) — FE.5.9:** The traceability work MUST include a **short integration appendix** (same mapping artifact or linked doc) covering: **NestJS REST + axios + JWT in `localStorage`** (admin **`ClientLayout`** / manager **`AuthContext`**) vs Vestroo **Supabase + `requireOpsStaffPage` / server sessions**; **Firebase Storage** (admin vehicle images) vs **Supabase Storage** (or other); **socket.io** driver namespaces/events vs **Supabase Realtime** channels and policies. Purpose: teams may reuse **UI/IA ideas** from **`docs/capstone-reference`** but MUST **not** copy **auth tokens, API clients, or socket URLs** without a designed Vestroo equivalent. Reference **dependencies** worth awareness for parity discussions: admin **Leaflet / leaflet-routing-machine / leaflet-editable**; manager **TanStack Query**, **Redux**, **Zustand**, **MUI** date pickers, **Leaflet** on some flows — Vestroo chooses **Tailwind-era** equivalents per **FE.5.2** rather than importing this stack wholesale.
