## Story

- As an **admin**, I need to **override** a **`credit_limit_exceeded`** or **`overdue_invoices`** dispatch block with a **written reason**, so that **judgement calls** for trusted accounts are possible without weakening other guardrails — (**US-A3**, **Q12**, **[`docs/epic-13.md`](../epic-13.md)** **§4**).
- As **ops**, I need **dispatchers** to **see why** dispatch failed but **not** see an override control, so that **only admins** can bypass those two codes — (**US-A3**).

## Acceptance Criteria (ACs)

### US-A3 — Admin override (Theme A) & Q12

1. **Role gate — UI:** Override is **gated** to users whose **`profiles.role`** is **`admin`**. Users who are **not** admin (e.g. **`dispatcher`**) see the **13.2** block panel for **`credit_limit_exceeded`** / **`overdue_invoices`** but **no** override **button** or entry point — **[`docs/epic-13.md`](../epic-13.md)** **§4 US-A3** (first **AC**).

2. **Override form — `reason`:** When override is available, the UI collects a **`reason`** via a **textarea** with **minimum 10** and **maximum 2000** characters. Submit remains **disabled** until the minimum length is met — **US-A3** (second **AC**).

3. **Success path — re-dispatch:** On **successful** override authorization, **`assignBookingToRun`** is **re-invoked** with an **`override_token`** (or project-equivalent parameter) that causes the server to **bypass** the **`credit_limit_exceeded`** / **`overdue_invoices`** check **for that attempt**, having **recorded** the override context — **US-A3** (third **AC**). Client/server contract must **not** weaken bypass for **non-overridable** codes (see **AC5**).

4. **Server — admin re-verification:** The server **re-verifies** that the **calling user** is an **admin** before honouring **`override_token`** / bypass — **US-A3** (third **AC**). Client-side gating alone is insufficient.

5. **Non-overridable codes — UI + server:** For **`contract_expired`**, **`contract_not_yet_active`**, **`account_suspended`**, **`account_on_hold`**, and **`po_required_and_missing`**, the UI **does not** show an override affordance. The server **rejects** any override attempt targeting these reasons — **US-A3** (fifth **AC**).

6. **Audit log — `ops_audit_log`:** On a **successful** override (dispatch proceeds after admin bypass for an allowed code), insert **`ops_audit_log`** with:
   - **`action='dispatch_override'`**
   - **`entity='booking'`**
   - **`payload`** including **`original_reason_code`**, **`override_reason`**, **`overridden_by_profile_id`**, **`booking_id`** (JSON object with those keys; naming may match existing JSON conventions in the codebase) — **US-A3** (fourth **AC**), **Q12**.

### Completion Notes List

- **`override_token` design:** Server-issued **HMAC-SHA256** token (`src/lib/dispatch-override-token.ts`). Payload **v1**: `booking_id`, `reason_code` (`credit_limit_exceeded` \| `overdue_invoices` only at signing), `override_reason` (10–2000 chars), `profile_id` (admin who signs), `exp` (**15 min** TTL). Encoding: `base64url(body || hmac-32)`. Secret: **`DISPATCH_OVERRIDE_SECRET`** (min 32 chars, server-only) — documented in **`.env.example`**. Signing action: **`signDispatchOverrideToken`** (`src/actions/opsDispatch.ts`) uses **`getOpsAdminForAction()`**.
- **`assignBookingToRun`**: Optional **`overrideToken`** in schema. When RPC guard fails with an account reason: if token present, **`getOpsAdminForAction()`** + **`verifyDispatchOverrideToken`** + match **`reasonCode`**, **`bookingId`**, **`profile_id`** to session; bypass **only** if reason is **`credit_limit_exceeded`** or **`overdue_invoices`**. Otherwise **FORBIDDEN** / **VALIDATION**. Walk-in / RPC errors reject stray tokens. **Audit:** before standard trip audit, **`appendOpsAuditLog`** with **`action: 'dispatch_override'`**, **`entity: 'booking'`**, **`entityId: booking_id`**, payload **`booking_id`**, **`original_reason_code`**, **`override_reason`**, **`overridden_by_profile_id`**. If audit insert fails, assignment is rolled back (trip / links / chauffeur row).
- **UI:** **`viewerIsAdmin`** from **`getStaffSession()`** on **`/ops/fulfil`** (`page.tsx`). **`AssignBookingPanel`** shows **Admin override…** only for overridable reasons + admin. **`CreditLimitOverrideDialog`** — textarea 10–2000, **Authorize & assign** → **`signDispatchOverrideToken`** then **`assignBookingToRun`** with token.
- **Tests:** `src/lib/__tests__/dispatch-override-token.test.ts` (roundtrip, tamper, expiry, `isOverridableAccountDispatchReason`).
