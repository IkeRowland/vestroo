## Story

- As **the system**, I need a **daily scheduled job** that expires **sent** quotes whose **`expires_at`** is in the past, so that **stale quotes do not mislead ops** (**US-E1**, **[`docs/epic-13.md`](../epic-13.md)** **§3 Phase 5**).
- As **ops staff**, I need a **visible "Quote expired"** state on booking detail when **`current_quote_id`** still references an **expired** quote, so that I know to **re-send** a new version via the existing **13.5** action (**US-E1** last bullet; **[`docs/stories/13.5.story.md`](../stories/13.5.story.md)**).

## Acceptance Criteria (ACs)

### US-E1 — Daily expiry job (Theme E) — **13.11 slice (full US-E1)**

_(Epic **[`docs/epic-13.md`](../epic-13.md)** **§4 Theme E — US-E1** — lines ~157–162.)_

1. **Scheduler + UTC time:** *(Epic **US-E1** first **AC**.)* Implement **one** documented approach among: **`pg_cron`** invoking a **SQL function** / RPC, **Supabase Edge Function** on **Dashboard schedule**, or **`supabase/functions/`**-hosted cron (or other **equivalent** single choice). Document in **Story Progress Notes**: product name, **exact UTC schedule** (e.g. `0 2 * * *` = 02:00 UTC daily), and how ops/engineering verifies last run (Supabase dashboard, SQL query, or audit rows).

2. **Transition predicate:** *(Epic **US-E1** second **AC**.)* Job updates **`booking_quotes`** from **`status = 'sent'`** to **`status = 'expired'`** for every row where **`expires_at IS NOT NULL` AND `expires_at < now()`** (server **`now()`** — document timezone semantics: **UTC** in Postgres). Prefer a **single `UPDATE … WHERE …`** (or equivalent RPC) so the predicate is obvious and auditable.

3. **Idempotency:** *(Epic **US-E1** third **AC**.)* Re-running the job the same day does **not** error and does **not** corrupt non-`sent` rows; rows already **`expired`** are untouched. Second run transitions **only** rows that became eligible since the prior run or were missed due to clock skew (document behaviour).

4. **Ops-visible logging:** *(Epic **US-E1** fourth **AC**.)* Each successful job execution records **at least**: **(a)** a **run** identifier or timestamp, **(b)** **count of rows transitioned** in that execution (`GET DIAGNOSTICS … ROW_COUNT` or `UPDATE` return), and **(c)** optionally **rows examined** if cheap to compute — to an **ops-visible** store agreed in implementation (**`ops_audit_log`** recommended for consistency with **[`docs/ops-server-action-logging.md`](../ops-server-action-logging.md)** / **`appendOpsAuditLog`** patterns where applicable, or a dedicated table **if** cron cannot call app code — **document** payload **`action` / `entity`** naming).

5. **UI — "Quote expired" badge:** *(Epic **US-E1** fifth **AC**.)* On **ops booking detail**, when the **resolved** current quote (via **`bookings.current_quote_id`** with fallback per **13.5** / **`v_booking_current_quote`**) has **`status = 'expired'`**, show a clear **"Quote expired"** badge (or equivalent label). If **13.5** already shipped this badge, **13.11** **verifies** behaviour end-to-end after the job runs; if not, **implement** the badge in **`QuoteDetailPanel`** (or successor). **Re-send** remains the **13.5** path — no duplicate re-send implementation required in **13.11**.
