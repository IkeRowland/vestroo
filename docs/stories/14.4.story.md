## Story

- As a **customer**, I need a **“This isn’t right”** rejection page with an **optional** reason, so that **ops knows to send a corrected quote** — **US-C2**, **Q15** (**[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C**).
- As **ops**, I need the **rejected quote** and **triaged** booking to be **visible on `/ops/bookings`** with a **minimal** indicator, so that **I can re-quote without hunting** — **US-C2** last AC; full E2E reject coverage is **14.11**.

## Acceptance Criteria (ACs)

### US-C2 — Reject route + triaged booking (Theme C) + Q15

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme C — US-C2** lines ~120–127; **Q15**; **§7** rejection-path DoD; **§8** paths.)_

1. **Route (path + group):** Implement a **server** route whose path is **`/q/[token]/reject`**, **`[token]`** opaque per **14.2**. Place it under the **same** route group as **14.3** **`/q/[token]/accept`** (**`(public-ops)`** or **`(quote)`** — match **14.3**; document in **Dev Technical Guidance** / **Progress Notes**).

2. **GET — verify + load + `sent`:** Call **`verifyQuoteToken`** with **`expectedPurpose: 'reject'`**. On **`{ valid: false, reason }`**, render **user-safe** server-rendered error handling (**`expired`** | **`invalid_signature`** | **`malformed`** | wrong purpose) **analogous to 14.3** where sensible; **invalid/expired** must include **Q17** “Request a new quote” CTA when the epic’s pre-fill rules apply (same trip-input-only constraints as **14.3** — **no PII** in query string). After **`valid: true`**, load **`booking_quotes`** by **`quoteId`**; assert row matches **`bookingId`** from payload. **Only** if **`booking_quotes.status === 'sent'`** render the reject **form**; otherwise render appropriate messaging for **already rejected**, **superseded**, **accepted**, **expired** (DB), etc. (align with **14.3** patterns / **§6**).

3. **UI — minimal server-rendered form:** Label **“Why is this quote not right for you?”** — **textarea**, **optional**, **max 2000** characters (enforce server-side + client hint if using a thin client wrapper). **Primary:** **Submit**. **Secondary:** **“Actually, I’ll accept”** linking to **`/q/[token]/accept`** with the **same** raw token (encode for URL safety if the token contains characters that require it). **No** required heavy client JS beyond project-standard analytics (**US-C2** implies minimal page; match **14.3** SSR posture).

4. **POST / server action — transitions (Q15):** On submit, atomically (or with **documented ordering** / single transaction per project patterns): set quote **`sent → rejected`**; persist **`rejection_reason`** (trimmed string or **`null`** if optional left empty — **implementer must confirm** exact column name on **`booking_quotes`** from Epic **12–13** schema; if column missing, **one** migration allowed with justification). Set booking **`quote_sent → triaged`**. **Must not** set booking to **`cancelled`** (**Q15**).

5. **Confirmation:** After **successful** submit, show a **confirmation** view with copy equivalent to **“Thanks, we’ll be in touch”** (exact wording TBD; server-rendered).

6. **`ops_audit_log`:** Insert **`action='customer_rejected_quote'`** with payload including **`rejection_reason`** (**`null`** if none), **`booking_id`**, **`quote_id`** (and any fields required for consistency with existing audit entries — follow **`ops_audit_log`** usage elsewhere).

7. **Ops visibility — minimal:** On **`/ops/bookings`**, the updated booking row shows a **`rejected quote`** visual indicator (**badge** and/or **last action** / row metadata) so ops can see the customer rejected without opening the detail view first. **Scope:** **minimal** affordance per **US-C2** last AC — reuse **Epic 12** list row / chip patterns and existing ops components where possible; **do not** scope full **14.11** E2E here.

8. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 2** (**14.4**), **§4 Theme C (US-C2)**, **Q15**, **§4 Theme G 14.4**, **§7** rejection-path DoD, **§8** paths.

### Implementation notes

- **Opaque `[token]`:** Same handling as **14.3** (trim/decode only if required).
- **Idempotency:** Second POST after reject should not corrupt state — surface friendly “already handled” or rely on non-`sent` quote branch (**TBD**).
- **Q15 guard:** Code review / tests assert booking **never** becomes **`cancelled`** from this flow.
- **“Same token” vs `purpose`:** **US-C2** asks for **`/q/[token]/accept`** using the **same opaque URL segment** as the reject page. If **`verifyQuoteToken`** (per **Q16** / **14.2**) signs **`purpose`** into the payload, a **reject**-purpose token will not verify as **`accept`** — implementer documents the chosen approach in **Progress Notes** (e.g. **14.6** email carries **both** signed URLs and the reject page receives the **accept** token for the secondary link only, or an agreed exception) while preserving the **customer-visible** behaviour: secondary control still lands on **accept**.
