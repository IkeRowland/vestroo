## Story

- As a **dispatcher**, I need a **“Suggested vehicles”** section in the **Fulfil assign** flow, so that I can **see up to three ranked options** with **scores and rationales**, **click to prefill** the **existing** vehicle picker, and **still consciously press Assign** — with the panel **hidden** when dispatch suggestions are **disabled by config**, **without** breaking the current **free-pick** layout.

## Acceptance Criteria (ACs)

1. **New UI module:** Add **`src/features/ops/components/VehicleSuggestionsPanel.tsx`** and **embed** it in the existing **`AssignBookingPanel`** (repo survey: **`src/features/ops/components/AssignBookingPanel.tsx`**, used from **`src/app/(ops)/ops/fulfil/page.tsx`**). Panel title/copy reflects **“Suggested vehicles”** (or equivalent consistent with ops copy patterns).

2. **Data contract:** When a **booking is selected** for assign and the feature flag is **on**, the UI loads suggestions by calling **`suggestVehiclesForBooking(bookingId)`** through a **thin** Next.js **server action** and/or **route / RSC loader** (implementer choice) that wires **real** Supabase-backed deps **as already provided** by **`15D.1`** (or minimal glue **only** if **`15D.1`** left injectors for tests but production wiring is incomplete — **document** in **Progress Notes**).

3. **Display cap and order:** The panel shows **at most 3** suggestions, **sorted by score descending** (must match **`Suggestion`** order returned by the server path, or **re-sort** client-side if the API ever returns unsorted data — **prefer** server-ordered for parity with **`dispatch-suggestions`**).

4. **Row content:** Each row shows **vehicle display name** (same human-readable convention as the assign flow / vehicle picker), **score** in **0–100** (integer or clearly documented decimal rule **matching** **`15D.1`** UI expectations), and **one-line rationale** from **`Suggestion.rationale`**.

5. **Interaction — prefill only (Q25):** Clicking a suggestion **sets the existing vehicle picker** (or equivalent controlled state) to that **vehicle id**; **no** auto-assign, **no** implicit submit. The dispatcher **must** still trigger the current **Assign** control. Changing picker manually after a click is allowed (**free-pick**).

6. **Interaction — ignore / dismiss:** Dispatchers may **ignore** suggestions entirely and assign via **free-pick** only; **no** modal forcing review of suggestions. If explicit “dismiss” UI is added, it must be **optional** and must **not** remove access to the picker (epic **US-D1** “dismissing all suggestions is always possible”).

7. **Empty and error states:** When there are **zero** suggestions, **loading**, or **recoverable error**, the assign flow remains usable: show a compact empty or inline error state **inside** or **adjacent** to the panel region **without** blocking assign. **Survey** existing ops empty/error patterns (**E2**) for consistency.

8. **Feature flag (epic §7 / Q27):** Sub-epic **15D** is behind a dedicated flag — add **`NEXT_PUBLIC_DISPATCH_SUGGESTIONS_ENABLED`** **or** **`DISPATCH_SUGGESTIONS_ENABLED`** (choose **one** primary; **document** whether evaluation is **client** vs **server** so secrets / hydration are correct). Update **`.env.example`** with the variable, default **off** for safe rollout.

9. **Flag off — no layout shift:** When the flag is **false** / unset, the **suggestions panel is not rendered** (or occupies **no** reserved space that collapses awkwardly). The assign form **must not** regress **layout** vs current production (no large blank gap, no jumping controls). **Survey** current **`AssignBookingPanel`** structure before adding wrapper spacing.

10. **Traceability:** Story file, **DoD**, and **Progress Notes** reference **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15D.2`**, **Theme D US-D1**, **Q25**, **§5** (**15D** row), **§8** (**15D** paths). **`15D.3`** cross-link in **Progress Notes** when handoff needs audit.
