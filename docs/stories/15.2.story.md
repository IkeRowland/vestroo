## Story

- As an **account user** (admin, booker, or rider on a customer account), I need the **`/account` home** to show **who I am acting for**, **my role**, and **obvious next actions**, so that I can reach bookings, billing, member management (when allowed), or start a new trip **without calling ops**.

## Acceptance Criteria (ACs)

1. **Replaces 15A.1 placeholder:** The **`/account`** page (under the existing **`(portal)`** layout) is no longer the "dashboard arrives in 15A.2" stub. It renders a **dashboard** with the elements in AC2–AC6.

2. **Account name:** The dashboard shows the **active organisation label** derived from **`customer_accounts`** for **`activeAccountId`**, using fields that exist in VST-14 — **survey** at implementation: primary headline **`name`**; if product needs a secondary line (e.g. billing entity), **`default_billing_entity_ref`** may be used where non-null. Server-side only; **no** trusting client-supplied account ids.

3. **Role badge:** The dashboard shows the signed-in member’s **role** for the **active** account: **`admin`**, **`booker`**, or **`rider`**, from **`customer_account_members.role`** (row matching active account + current user / accepted membership — align with **`accepted_at IS NOT NULL`** gate already used in 15.1). Badge copy is human-readable (e.g. "Admin", "Booker", "Rider").

4. **Quick-link: Bookings:** A prominent control (card or CTA) **"Bookings"** links to **`/account/bookings`**. **This story MUST ship a resolvable route** for that path: either it already exists after a prior change, or **add** a **thin placeholder** page (e.g. one short paragraph + **"Full list in Story 15A.3"** in copy or Progress Notes). **No 404** from the dashboard for this href.

5. **Quick-link: Members (admin-only):** A **"Members"** control exists **only** when the active membership role is **`admin`**. For **`booker`** and **`rider`**, the card is **omitted** (not merely disabled — **hidden**), per **US-A1**. It links to **`/account/members`**. Same **thin placeholder** rule as AC4 if the real **15A.5** UI is not built yet — stub must cite **15A.5** in on-page or Progress Notes.

6. **Quick-link: Invoices (admin + booker only):** An **"Invoices"** control exists when role is **`admin`** or **`booker`**; **hidden** for **`rider`**, per **US-A1**. It links to **`/account/invoices`**. Thin placeholder rule if **15A.7** is not built — stub cites **15A.7**. *(Note: US-A4 in the epic refines **archive** behaviour as admin-focused; portal **home** visibility follows **US-A1** admin+booker. If **15A.7** tightens page-level access, align in that story.)*

7. **Quick-link: New Booking:** A **"New booking"** (or equivalent) control links into the **existing public booking funnel** — **survey** `src/app/(app)/book/` (e.g. **`/book/search`** as entry). **Do not** require PO/email/account **deep prefill** or new query-param contract in **15A.2**; document chosen URL in Progress Notes. If the codebase already supports harmless account-context query params, they may be added **only** when already present or trivial; otherwise defer to **US-A2 / 15A.3**.

8. **Layout cohesion:** Dashboard uses the **existing account portal shell** (header, switcher slot from 15A.1). Spacing/typography align with current portal/marketing tokens — no redesign of global chrome.

9. **RLS / data loading:** Any new queries for account name / role reuse **server** Supabase client patterns from 15.1. Loads are scoped to **active account** + **verified membership**. Document in **Progress Notes** how this continues to align with **`account_ids_for_current_user()`** / VST-14 RLS.

10. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **US-A1** home bullets **not** deferred to 15A.1 placeholder; catalogue **15A.2**.
