## Story

- As **Vestroo** (and as an **account** with **`live_rider_tracking=true`** when the product allows it), I need the **public rider track page** to show a **read-only Google Maps** view of the **latest chauffeur position** from **`vehicle_trackings`** **only** when **both** the deploy **`RIDER_LIVE_LOCATION_ENABLED`** flag and the **account** **`customer_accounts.live_rider_tracking`** flag are **true** (**Q22** double opt-in), with **safe refresh and staleness UX**, so that **riders** get **GPS-level** transparency **without** exposing live location when either gate is off, **without** granting anonymous clients **direct** read access to **`vehicle_trackings`**, and so the map **disappears as soon as** the trip is **`completed`** (milestone view stays **static**).

## Acceptance Criteria (ACs)

1. **Schema — per-account opt-in:** Add **`customer_accounts.live_rider_tracking boolean not null default false`** (and comment) via a new migration **if** the column does not already exist. Align with **[`20260426120000_epic15_15b1_bookings_rider_columns.sql`](../../supabase/migrations/20260426120000_epic15_15b1_bookings_rider_columns.sql)** comment that deferred this to **15B.5**. Regenerate or hand-update **[`src/types/database.types.ts`](../../src/types/database.types.ts)** as per project convention.

2. **Env — global opt-in:** Introduce **`RIDER_LIVE_LOCATION_ENABLED`** (server-readable; document parsing rules in **`.env.example`** alongside existing Maps keys). The live map feature is **off** unless this evaluates to enabled (same spirit as **`SMS_ENABLED`** in **15.14**).

3. **Double opt-in (Q22):** Render **`LiveLocationMap`** (or equivalent under **`src/features/rider-tracking/components/`**) **only if** **both** **AC2** (env) **and** **`live_rider_tracking === true`** for the **booking’s** **`customer_account_id`** (join path from **`trips`** → **`booking_trips`** → **`bookings`** → **`customer_accounts`** — survey current loaders). If either gate is **false**, the page remains **milestone-first** only (**15B.3**); **no** map placeholder that leaks “live was almost on.”

4. **`vehicle_trackings` data — defence in depth:** The **public** **`/track/[token]`** session **must not** rely on **anon** Supabase JWT **or** broad **RLS** on **`vehicle_trackings`** for position reads. **AC:** Latest position for the trip’s active vehicle/assignment is fetched **server-side** after **`verifyRiderTrackToken`** (same token gate as **15B.3**), using **service role** (or a **`SECURITY DEFINER`** RPC that re-validates trip access) **only** on the **valid-token** path, returning a **narrow DTO** (e.g. lat/lng, **`updated_at`**) to the client. Document why **`subscribeVehicleTrackings`** in **[`src/lib/supabase/realtime.ts`](../../src/lib/supabase/realtime.ts)** is **RLS + JWT**-oriented and **unsuitable** for anonymous **`/track`** unless a future hardened pattern exists.

5. **Google Maps embed — read-only:** Use a **Google Maps** embed suitable for a **marker** at latest coords (iframe Static/Embed or JS map per team choice). **Survey** **[`src/lib/maps.ts`](../../src/lib/maps.ts)** — browser key **`NEXT_PUBLIC_GOOGLE_MAPS_KEY`** (see **`.env.example`**); respect existing key restrictions (HTTP referrers). **Do not** ship **route polyline** or **ETA** line on the rider map in this story.

6. **Refresh — 30s; staleness — >90s:** Position refresh interval **30 seconds** (align with **15B.3** poll cadence). If the latest **`updated_at`** (or equivalent) is older than **90 seconds**, show copy **“Last updated X ago”** (relative, accessible). **Survey** **[`src/lib/vehicle-tracking-throttle.ts`](../../src/lib/vehicle-tracking-throttle.ts)** for upstream write cadence (**12**/min cap) so UX expectations match server throttle.

7. **Trip status gating — `en_route` / `completed`:** Show the live map **only** while **`trips.status === 'en_route'`**. On **`completed`**, **hide the map immediately** (no delay until token **Q21** expiry); milestone view is **static** (no further position fetches for display, or fetches ignored for map). **`assigned`**, **`arrived`** (if mapped), **cancelled**: **no** live map (milestone-only).

8. **POPIA / minimisation:** Do not log raw coordinates at **info** in shared logs; avoid widening the public DTO beyond what the map needs.

9. **Account admin surface (minimal):** If the portal already edits **`customer_accounts`**, add a controlled way to set **`live_rider_tracking`** (e.g. admin-only setting) **or** document “DB / ops only for pilot” in **Tasks** and **Progress Notes** — **pick one**; default **false** must remain safe.

10. **Tests:** Vitest for pure helpers (e.g. “should show map”, staleness copy, status gating). Mock server path that returns DTO; **no** live Google calls in CI.

11. **Traceability:** Maps to **[`docs/epic-15.md`](../epic-15.md)** **Theme E `15B.5`**, **US-C3**, **Q22**; **§8** **`LiveLocationMap`**, **`vehicle_trackings`**.
