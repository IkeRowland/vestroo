## Story

- As **ops staff**, I need a **consistent split layout** (list + detail) that becomes a **drawer on small screens** and a **sticky rail on large**, so I can **review records** without losing list context (**Wheelzie 1 / 3 / 4 / 5 / 8** cues).

- As **the codebase**, we need **`OpsSplitView`** and **`OpsDetailRail`** so **17.10+** routes can **adopt one pattern** for list/detail instead of one-off layouts.

## Acceptance Criteria (ACs)

1. **`OpsSplitView` — layout:** **List** region uses **`min-w-0 flex-1`**; **detail** rail has fixed width in the **360–420px** range (exact default chosen in **Task 0**). On **`xl+`**, detail is **sticky** within the split; on **`< lg`**, detail is a **drawer** (not inline split).
2. **`OpsSplitView` — props:** **`list: ReactNode`** (required), **`detail: ReactNode`** (required), **`onCloseDetail?: () => void`** (back / **Esc** on mobile), **`detailVisible: boolean`** (controls drawer open state on **`< lg`**).
3. **`OpsDetailRail`:** Inner **card chrome** for the rail: **header** (title slot + **close** control on mobile / drawer contexts), **scrollable body**, **optional footer** with primary action slot — **token-only** styling (**NFR.17.4**, **17.1** tokens).
4. **Breakpoints:** Behaviour aligns with epic: drawer **`lg`** breakpoint vs sticky **`xl`** — document **`lg`** / **`xl`** split in parity **§ 17.9** (**NFR.17.1**).
5. **Deep linking (epic):** Story documents and implements the **Task 0** contract: opening detail **must** allow URL updates (**`?id=…`** or sub-route) at the **parent** or via agreed wrapper — parity **§ 17.9** states whether primitives expose **only slots/callbacks** vs a thin **router-aware** helper (**no** silent divergence from epic).
6. **Keyboard / mobile:** When drawer is open (**`< lg`**), **Esc** invokes **`onCloseDetail`** (when provided and drawer visible); **close** control in rail header invokes **`onCloseDetail`** — covered by tests (**AC11**).
7. **Focus management:** When detail closes from drawer, **focus returns** to the **originating row** or **last focused list control** per **Task 0** DOM contract (**NFR.17.5**, epic acceptance).
8. **Focus trap:** When drawer is open, use focus-trapping behaviour consistent with chosen **Sheet**/**Dialog** primitive (**NFR.17.5**); document any exceptions in parity.
9. **RSC / client boundary (NFR.17.3):** Prefer **RSC** shell; **`'use client'`** limited to **`OpsSplitView`** or a **thin wrapper** that owns drawer open state — smallest island; document in parity.
10. **Copy module (NFR.17.8):** Add **`src/features/ops/copy/ops-split-view-copy.ts`** (or epic-aligned path) for **aria-labels** and stable strings: e.g. **“Close detail”**, **“Open detail”** (if exposed), section labels if any — single module per surface rule.
11. **Tests — RTL:** **Esc** fires **`onCloseDetail`** when drawer open (appropriate setup); **close** button calls **`onCloseDetail`**.
12. **Tests — focus:** Assert **focus return** target when **RTL** + **`userEvent`** / **`jest-dom`** support exists; otherwise document **manual QA** steps in **Progress Notes** (**Task 0** gates feasibility).
13. **Adoption scope:** **`/ops/clients`**, **`/ops/vehicles`**, **`/ops/trips`**, **`/ops/bookings`**, **`/ops/roster`** — **out of scope** for **17.9** unless **optional pilot** is explicitly approved — **default: primitives + tests + docs only** (same pattern as **17.8**).
14. **Tablet verification:** Run the **FE.5.7** / ops-console tablet checklist (**`docs/ops-console.md`** per epic, or **Task 0** substitute); record outcomes in **Progress Notes**.
15. **Documentation (NFR.17.1):** Extend **`docs/ops-design-system-parity.md`** with **§ 17.9** — props, breakpoints, **a11y**, **focus** + **Esc**, deep-link contract, rail width decision.
16. **Quality:** **`npm run lint`** and **`npm run test`** green; no new heavy UI dependencies unless **Task 0** documents exception (**NFR.17.2**).
