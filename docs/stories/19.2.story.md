## Story

- As **a traveler starting a trip request**, I want **sensible, visible defaults** for **date**, **time**, and **passenger count** on **slide 1**, and a **reasonable phone country** on **slide 3**, so I can **submit faster** with fewer empty fields, while still **editing** any default (**FE.19.2**).

- As **ops / data integrity**, I need **timezone-correct** defaults in **`Africa/Johannesburg`** and **unchanged** **`validateRideDetailsStep`** / **`tripRequestSubmitPayloadSchema`** / **`submitTripRequest`** behaviour for valid paths (**NFR.19.6**).

- As **an a11y-conscious user**, I need **visible labels** for fields (including date/time/passengers/phone country) and **no placeholder substituting for a label** (**NFR.19.2** / epic **Design Goals**).

## Acceptance Criteria (ACs)

1. **Slide 1 date default:** On first load **without** marketing prefill (standalone bootstrap path), **ride date** is **today** in **`Africa/Johannesburg`**, **unless** **now + 90 minutes** (same TZ) is **after 22:00**, in which case the default date is **tomorrow** (per **[`docs/epic-19.md`](../epic-19.md)** **FE.19.2** lines **61–62**).
2. **Slide 1 time default:** Default **ride time** is **now + 90 minutes**, rounded **up** to the **next 15-minute** boundary, expressed on the chosen default **ride date** (handles **cross-midnight** when rounding pushes into the next calendar day).
3. **Passengers default:** Default **passenger count** is **1** (not **2**) for **`defaultRideDetailsFormValues()`** (or its successor) and any **BookingSearchForm** mirror logic that must stay aligned (**[`BookingSearchForm.tsx`](../../src/features/booking/components/BookingSearchForm.tsx)** comment today references **`defaultRideDetailsFormValues()`** — lines **144–150**).
4. **Empty addresses & notes:** **Pickup**, **drop-off** string inputs, and resolved **locations** start **empty**; **special instructions** empty; **flight number** empty and **flight UI** hidden until **airport pickup** per **`effectiveAirportPickup`** (**[`TripRequestRideDetailsSlide.tsx`](../../src/features/booking/components/trip-request/TripRequestRideDetailsSlide.tsx)**).
5. **Phone country default:** On slide **3**, the **country** combobox initial value is **`ZA`** unless a **server-derived** hint from **`Accept-Language`** and/or **IP country** (e.g. deployment headers) resolves to a supported **`iso2`** in **`loadTripRequestCountryOptions`**; user can change before submit. If inference fails, **`ZA`** (**epic** lines **63–64**).
6. **Timezone-aware parsing:** **`combineRideDateAndTime`**, **`rideDateTimeFutureCheck`**, and **`validateRideDetailsStep`** treat **`rideDate` + `rideTime`** as **wall-clock in `Africa/Johannesburg`** (update module docs; fix **`TripRequestRideDetailsSlide`** **`minDate`** if it still uses **local `Date`** only — lines **85–91**).
7. **Submit path:** With defaults left as-is **except** user fills **addresses**, **vehicle** on slide **2**, and **name / email / phone** on slide **3**, **submit** succeeds when **schema-valid** (**epic** lines **73–74**).
8. **Labels / placeholders:** Required fields use **visible `<Label>`** (or equivalent) **associated** with inputs; **placeholder** text is **not** the sole indicator of field purpose (**epic** line **74** + **NFR.19.2**). Audit **slide 1** address placeholders remain **hints**, not labels (**[`TripRequestRideDetailsSlide.tsx`](../../src/features/booking/components/trip-request/TripRequestRideDetailsSlide.tsx)**).
9. **Tests:** Add or extend **Vitest** coverage for default date/time math (TZ-fixed fixtures), passenger default **1**, and optional **country hint** mapping; keep **`trip-request-submit-schema.test.ts`** and **`ride-details-validate.test.ts`** green.
