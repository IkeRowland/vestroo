# Story 5.6: Field (chauffeur) web experience vs reference driver app modality

## Status: Done

**Dependencies:** **[Stories 5.1–5.5](5.1.story.md)** — **Done** (per project). **Story 5.2** locks **Tailwind + Radix** for **`/ops/*`** and **authenticated `/field/*`** — **Ant Design MUST NOT** be introduced for field shells unless a future ADR revises this. **Runbooks:** **[`docs/field-tools.md`](../field-tools.md)** for **`src/app/(field)/`** flows, transitions, and customer-contact policy; **[`docs/realtime-and-notifications.md`](../realtime-and-notifications.md)** (**VST-9**) for **Supabase Realtime** vs reference **socket.io** gap mapping.

**Explicit out of scope:** **FE.5.7** (dedicated tablet polish for internal routes) — **cross-reference only** in the modality doc. **FE.5.8** (full a11y baseline for ops/field shells) — **note alignment**; this story **does not** replace FE.5.8. **Building a new Expo / React Native driver app** — **out of scope**; deliver **assessment and mapping** only for native phase 2.

## Story

- As a **product or engineering lead**
- I want a **documented modality strategy** and **screen/socket mapping** from capstone **`frontend-driver`** (**`docs/capstone-reference/frontend-driver`**) to Vestroo **mobile-web** **`/field/*`**, plus **targeted web MVP UX improvements** (responsive layout, touch targets, task clarity)
- so that **chauffeur execution** stays **secure and server-gated** (**NFR.5.3**), **domain language** stays aligned with Epic 4 / VST (**NFR.5.4**), and the team knows **what the reference native app does**, **what web covers today**, **where Realtime gaps are** (**VST-9**), and **what a phase-2 native build would imply** — without weakening **`requireChauffeurPage`**

## Epic traceability (source)

**From `docs/epic-5.md` — FE.5.6:** The system MUST document **modality strategy**: reference **frontend-driver** is **Expo / React Native** (**NativeWind**), with **expo-location**, **expo-notifications**, **react-native-maps** + directions, and **socket.io-client** across multiple concerns; current **field** is **mobile-web**. The mapping MUST enumerate reference **screens and real-time domains**: **Home**; **Schedule** (with **ScheduleContext** / pause-confirm patterns); **Notifications** tab (**badge** unread count, **NotificationContext**); **Conversations** list + **ConversationDetail** (**useConversationSocket** and related hooks); **Trip tracking** (**TripTrackingScreen**, **useTripSocket**, **useTrackingSocket**); **Trip history** (implemented in codebase though one tab is commented in `AppNavigator`); **Profile**; **shared itinerary** (**useSharedItinerarySocket**). Cross-link **Vestroo** [Realtime and notifications](realtime-and-notifications.md) (**VST-9**) when mapping sockets to **Supabase Realtime** or recording gaps. The team MUST deliver a **short assessment** (pros/cons, MVP vs phase 2 native) and, for the **web MVP**, MUST improve **responsive** layout (breakpoints, sticky actions, safe-area awareness where applicable), **large touch targets**, and **obvious task flows** (today’s trips, accept/decline if applicable, check-in/out). If **in-app chat** or **push notifications** are out of scope for web, that MUST be explicit in the mapping doc and replaced with an **interim** pattern (e.g. deep link to approved channel, SMS policy per field tools doc) where product requires it.

**Constraining NFRs (mapping narrative + implementation):**

- **NFR.5.3:** Shell, layout, and UX refactors MUST **not** weaken **`requireChauffeurPage`** or **`getChauffeurForAction()`** — **server-first** chauffeur gating remains authoritative; no client-only “field” access paths.
- **NFR.5.4:** User-visible copy and route naming on **`/field/*`** MUST prefer **Epic 4 / VST** vocabulary (trips, assignments, chauffeur, corporate shuttle context) over capstone **demo** or legacy transit labels when documenting or adjusting UI.

   - **Home** → **`src/screens/HomeScreen.tsx`** (+ **ScheduleContext** usage as noted in file).
   - **Schedule** → **`src/screens/ScheduleScreen.tsx`**, **`src/context/ScheduleContext.tsx`**, pause confirm → **`src/components/DriverSchedule/ConfirmPause.tsx`**.
   - **Notifications** → **`src/screens/NotificationScreen.tsx`**, **`src/context/NotificationContext.tsx`**, badge/unread patterns; reference **`src/hook/useNotificationSocket.ts`** if wired.
   - **Conversations** → **`src/screens/ConversationScreen.tsx`**, **`src/screens/ConversationDetailScreen.tsx`**, **`src/hook/useConversationSocket.ts`**.

   - **Profile** → **`src/screens/ProfileScreen.tsx`**.
   - **Shared itinerary** → **`src/hook/useSharedItinerarySocket.ts`** + how trip tracking consumes shared itinerary (cite usage sites in reference tree).

   Each row MUST name **Vestroo target** route(s) (**`/field`**, **`/field/trips/[tripId]`**, **`/field/login`**, **`/field/unauthorized`**) or **not in web MVP** / **ops-only** / **deferred**, **status** (**implemented / partial / not started / not applicable** with footnotes), and **Realtime/socket gap** summary (**VST-9**).

3. **Assessment subsection:** Short **pros/cons** of **web MVP** vs **phase 2 native** (Expo) for chauffeurs: e.g. deployability, background location/push, maps SDK depth, socket.io parity cost vs Supabase Realtime — **no** commitment to build native in this story.

4. **Web MVP implementation (code):** Improve **`src/app/(field)/`** UX without new frameworks:
   - **Responsive layout:** sensible **breakpoints** (align with existing **`sm:` / `md:`** usage in **`field/layout.tsx`**); avoid horizontal clipping of **primary actions** on common phone widths; **sticky** primary action area on trip detail where it aids confirm / status flow (**per [`docs/field-tools.md`](../field-tools.md)**).
   - **Safe-area:** use **`env(safe-area-inset-*)`** (or equivalent documented pattern) on fixed/sticky chrome where notched devices need padding — **CSS-only**, no weakening auth.
   - **Touch targets:** establish or reuse a **~44px minimum** interactive target pattern (e.g. **`min-h-11 min-w-11`** / **44px** utilities) for primary buttons and list taps on field pages — consistent with header link already using **`min-h-11`** in **`field/layout.tsx`**.
   - **Task flows:** make **today’s assignments** and **confirm → en route → complete** obvious on list + detail pages per **field-tools** transition table; **do not** add chauffeur-only transitions that bypass **`fieldChauffeur.ts`** validation.

5. **Chat / push / interim comms:** In the mapping doc, **explicitly state** whether **in-app chat** (reference Conversations + sockets) and **native push** are **in** or **out** of **web MVP** (default expectation: **out** unless already implemented). Document **interim** patterns aligned with **[`docs/field-tools.md`](../field-tools.md)**: **maps deep links** (`src/lib/maps.ts`, **`field-navigation-target.ts`**); **customer contact** — masked display, **`tel:`** dialer, **`chauffeur_contact_intent`** audit when **`assigned` / `en_route`**; **note:** current field-tools runbook **does not** define **SMS** — if product requires SMS, state **gap** and point to future policy; otherwise interim = **tel:** + maps + operational **`notifications`** table (**VST-9**) as documented.

6. **Documentation wiring:** Add **`docs/capstone-driver-to-field-mapping.md`** to **[`docs/index.md`](../index.md)** with one-line description (**FE.5.6**). In **`docs/epic-5.md`**, under **FE.5.6**, add **one** bullet/sentence pointing to this file as the **living artifact** (do not duplicate the full table in the epic). Cross-link **`docs/field-tools.md`** and **`docs/realtime-and-notifications.md`** from the new doc’s intro or Related section. **Cross-reference FE.5.7** (tablet pass) and **FE.5.8** (a11y baseline) as **follow-on** work.

7. **Verification:** Author MUST verify **Vestroo** route and action claims against **`src/app/(field)/`**, **`src/actions/fieldChauffeur.ts`**, **`src/lib/field-auth.ts`**, and **`src/lib/supabase/realtime.ts`** (or current Realtime entrypoints); update **Status** cells to match repo reality.
