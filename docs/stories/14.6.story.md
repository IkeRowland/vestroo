## Story

- As **ops staff**, I need a **“Send quote”** action on **walk-in** bookings that emails the customer **accept / reject / pay** links, so that **quote-first walk-ins are actionable from the ops console** — **US-D1**, **Q13** (ops side only) (**[`docs/epic-14.md`](../epic-14.md)** **§4 Theme D**).
- As a **customer**, I need a **clear, branded walk-in quote email** with **expiry**, **line items**, and **one-click CTAs**, so that **I understand the offer and can commit safely** — **US-D2**.

## Acceptance Criteria (ACs)

### US-D1 — `sendWalkInQuote(bookingId)` (Theme D) + Q13 (ops) + Q9

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme D — US-D1** lines ~144–151; **§5** matrix **`sendWalkInQuote`**; **§6** Resend outage risk; **§8**.)_

1. **New server action:** Add **`sendWalkInQuote(bookingId)`** (e.g. **`src/actions/sendWalkInQuote.ts`**) — **staff-only**, same auth / logging conventions as **`bookingQuoteOps`** (or call into shared helpers — **TBD**).

2. **Booking guards:** Reject unless **`bookings.client_type = 'walk_in'`** and **`bookings.status IN ('submitted','triaged','quote_sent')`** (re-send allowed when already **`quote_sent`**).

3. **Versioned quote:** Create a new **`booking_quotes`** row via Epic **13** **`createBookingQuote`** (from **`bookingQuoteOps`** or extracted shared entry — **TBD**) with correct **line items** / **total** / default **`expires_at`** (**72h** walk-in default per existing **`defaultExpiresAtIso`** behaviour for walk-ins). Prior version is **superseded** per existing RPC/rules.

4. **Tokenised links:** For the **new** quote row, build **three absolute URLs** using **`signQuoteToken`** with **`purpose`**: **`'accept'`**, **`'reject'`**, **`'pay'`**; paths **`/q/<token>/accept`**, **`/q/<token>/reject`**, **`/q/<token>/pay`** — **consistent with 14.3–14.5** (same path shape; **no** purpose in query string). **`exp`** in payload must match **`booking_quotes.expires_at`** (second-rounded) per **14.2**.

5. **Render + send:** Render the new **`walk-in-quote`** template to HTML; send via **Resend** through the same **`sendEmail`** / infrastructure as other ops quote emails; capture **`rendered_html`** on the quote row per Epic **13** conventions.

6. **Success state:** On send success: set quote **`status = 'sent'`**, set **`bookings.current_quote_id`** to this quote, transition booking to **`quote_sent`** (if not already).

7. **Q9 failure handling:** On Resend/render failure: **do not** falsely mark quote **`sent`** or booking **`quote_sent`** if that would contradict “email not delivered”; follow Epic **13** **Q9** — **no destructive rollback** of unrelated rows; **retry queue / ops panel** records failure and allows retry (**reuse** **`sendBookingQuote`** / **`computeNextEmailFailureAttemptCountForQuote`** patterns — **TBD** exact code path).

8. **Ops UI:** Booking **detail** view shows **“Send quote”** (or equivalent) for **walk-ins** only; **hidden** for **`account_client`**.

9. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§3 Phase 3** (**14.6**), **§4 Theme D (US-D1)**, **§5**, **§6**, **§7** partial, **§8**.

### US-D2 — Template `walk-in-quote` (Theme D)

_(Epic **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme D — US-D2** lines ~152–158.)_

1. **New template module:** Add **`walk-in-quote`** under **`src/lib/email/templates/`** — epic suggests **`.tsx`**; if the repo standard is **`.ts`** (like **`account-trip-confirmation.ts`**), use that **or** introduce **`.tsx`** only if required by the email renderer — document in **Progress Notes**.

2. **Rendered content:** Template includes: **customer name**, **booking reference**, **pickup date/time**, **origin → destination**, **vehicle category** if selected / available on booking, **passenger count**, **total**, **line items**, **friendly expiry** copy (epic example: *“This quote expires on Fri 22 April at 18:00 SAST”* — use project timezone/date helpers), primary CTA **“Accept & pay”** (accept URL), secondary **“This isn’t right for me”** (reject URL), **company contact** info (reuse footer / contact blocks from existing templates if present).

3. **CTA URLs:** CTAs use **only** the three **HMAC-signed** URLs — **no** query-string PII; **pay** link uses **`/q/.../pay`** for parity with **14.5**.

4. **Subject line:** **`Your Vestroo quote — {booking_reference} — valid until {expires_at}`** — date format per project helpers (consistent with other transactional email).

5. **US-D2 AC3 (mail clients) — deferred:** Proving rendering in **Gmail, Outlook web, Apple Mail, iOS Mail** (“team checks **3 of 4** manually”) is **out of scope for 14.6 proof** — tracked under **Story 14.11**. **14.6** may add **snapshot** or **render unit test** **if** the repo already does for **`account-trip-confirmation`** or similar.

6. **Traceability:** Maps to **[`docs/epic-14.md`](../epic-14.md)** **§4 Theme D (US-D2)**, **§8**.
