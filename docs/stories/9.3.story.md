## Story

- As a **product, ops, and engineering** stakeholder with **go** at **[`#sh-9-1`](../epic-9.md#sh-9-1)** and **SH.9.2** domain + **ADR 0002** in place
- I want **inventory-safe** **capacity** and **reservation** behaviour for **patterned / capacity-managed** departures — **transactional holds**, **no oversell**, and **clear cancellation / expiry rules** — informed by reference **`ticketingSystem` / `seatTracking`** **logic** only, not transit **product** labels
- so that concurrent bookings cannot exceed **declared per-run / per-segment** capacity, **holds** have predictable lifetimes, and **occupancy** remains **authoritative** in **Postgres** for audit and compliance

## Acceptance Criteria (ACs)

### Gate and prerequisites

1. **Gate compliance:** No implementation merging **SH.9.3** behaviour (migrations, Server Actions / RPCs, or **RLS** changes for capacity) unless **[`docs/epic-9.md#sh-9-1`](../epic-9.md#sh-9-1)** records **go**. If **no-go** or unset for implementation, outcome is **N/A — not executed** (same spirit as **SH.9.2** **AC1**).

2. **Prerequisite traceability:** PR description and story footnotes **MUST** cite **[`docs/stories/9.1.story.md`](9.1.story.md)**, **[`docs/stories/9.2.story.md`](9.2.story.md)**, and **[`docs/adr/0002-patterned-shuttle-domain-sh9-2.md`](../adr/0002-patterned-shuttle-domain-sh9-2.md)** when claiming **SH.9.3** scope.

### Capacity, holds, and occupancy (when **go**)

3. **Transactional holds:** Creating or extending a **reservation** / **hold** that consumes **run** capacity **MUST** run in a **transaction** (or **RPC** / **single** database round-trip) such that **check + reserve** cannot commit **oversell** under concurrent sessions — **NFR.1.2**.

4. **No oversell:** For each **capacity dimension** agreed in implementation (e.g. **per `service_run_id`**, and/or **segment** via **`trip_seats`**-style keys per **[`docs/data-models.md`](../data-models.md)** § gap analysis), **committed** holds + **confirmed** occupancy **MUST NOT** exceed **declared** capacity (vehicle / pattern / product rule — **documented** in **ADR** or **data-models** update in same delivery).

5. **Cancellation / expiry:** **Documented** rules for **hold expiry**, **customer / staff cancellation**, and **transition** to **released** or **confirmed** state (aligned with **`bookings`** / payment lifecycle only as needed — **SH.9.5** remains out of scope for full payment rules). Invalid transitions **rejected** at DB or **trusted server** layer.

6. **Idempotency:** **Repeat** client requests (same **idempotency key** or natural **unique** business key, e.g. **`booking_id` + `service_run_id` + segment**) **MUST NOT** double-consume capacity — **dedupe** or **upsert** behaviour **verified** by test.

7. **DB-backed contention:** Load or concurrency test (or **documented** SQL simulation) proving **two** concurrent reservers cannot both pass capacity — **not** “last writer wins” without **Postgres** enforcement.

8. **RLS:** New or touched **`public.*`** tables/columns for holds / occupancy **MUST** have **RLS** enabled and **role-appropriate** policies (**customer**, **chauffeur**, **dispatcher** / **`is_staff()`** per existing conventions — see **[`docs/data-models.md`](../data-models.md)**). **Service role** remains **server-only**.

9. **Documentation:** **[`docs/data-models.md`](../data-models.md)** (and **`src/types/database.types.ts`** if schema changes) **MUST** reflect **tickets** / **trip_seats** / hold semantics **without** contradicting **ADR 0002** § **`tickets` / manifest** split.

10. **Tests:** Automated tests (integration against **local** / **CI** DB, or **Supabase** test project) covering **hold create**, **expiry**, **cancel**, **concurrent** reservation, and **idempotency** — **minimum** set agreed in PR; **no** merge without tests for **AC3–AC7** paths.
