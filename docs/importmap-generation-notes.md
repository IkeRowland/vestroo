# ImportMap Generation Notes

## Issue

The `payload generate:importmap` command fails with a module resolution error:
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../src/collections/Routes'
```

This happens because the command runs in ESM mode and can't resolve TypeScript imports without file extensions.

## Solution

### Option 1: Manual Update (Current Approach)
Manually add missing components to `src/app/(payload)/admin/importMap.js` when new storage adapters or plugins are added.

For S3 storage, add:
```javascript
import { S3ClientUploadHandler as S3ClientUploadHandler_[hash] } from '@payloadcms/storage-s3/client'

export const importMap = {
  // ... existing entries
  "@payloadcms/storage-s3/client#S3ClientUploadHandler": S3ClientUploadHandler_[hash]
}
```

**Note:** PayloadCMS generates hash-based aliases like `f97aa6c64367fa259c5bc0567239ef24`. These can be auto-generated by PayloadCMS or manually added.

### Option 2: Fix Module Resolution (Future)

To fix the `payload generate:importmap` command, we could:
1. Add `.js` extensions to imports in `payload.config.ts` (but this breaks TypeScript)
2. Use a different module resolution strategy
3. Wait for PayloadCMS to fix the importMap generation for Windows/ESM

Currently, manual updates work fine and the importMap is automatically updated by PayloadCMS in most cases.

## When to Update ImportMap

The importMap needs manual updates when:
- Adding new storage adapters (like S3)
- Adding new PayloadCMS plugins that have client components
- Getting "PayloadComponent not found in importMap" errors

## Verification

After adding to importMap, verify:
1. The import statement matches the package export
2. The key in the importMap matches exactly (including `#ComponentName`)
3. The component alias is unique (use hash if needed)
4. No syntax errors in the importMap file
