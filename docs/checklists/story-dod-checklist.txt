# Story Definition of Done (DoD) Checklist

## Code Quality
- [ ] All code is written in TypeScript with strict mode
- [ ] No use of 'any', 'unknown', 'as', or '!' operators
- [ ] All new functions have JSDoc comments
- [ ] Code follows project naming conventions (.cursorrules)
- [ ] No hardcoded values; use environment variables or configuration

## Testing
- [ ] Unit tests written for all new business logic
- [ ] All tests pass locally
- [ ] Test coverage meets project requirements (100% for pricing logic)
- [ ] Edge cases are tested

## Documentation
- [ ] README updated if needed
- [ ] API documentation updated if new endpoints added
- [ ] Data models documentation updated for schema changes
- [ ] Comments added for complex logic

## Security
- [ ] Input validation implemented using Zod
- [ ] Access control implemented correctly
- [ ] No sensitive data exposed to client
- [ ] RLS policies implemented for Supabase tables (if applicable)

## Integration
- [ ] New code integrates properly with existing codebase
- [ ] No breaking changes to existing functionality
- [ ] Backward compatibility maintained
- [ ] Dependencies properly declared in package.json

## User Experience
- [ ] UI is responsive (mobile-first)
- [ ] Loading states implemented
- [ ] Error states handled gracefully
- [ ] Success feedback provided to user

## Performance
- [ ] No unnecessary re-renders
- [ ] Database queries optimized
- [ ] Images optimized (if applicable)
- [ ] Lazy loading implemented where appropriate

## Compliance
- [ ] Follows architectural patterns defined in project
- [ ] Follows Next.js 15 best practices (async params/searchParams)
- [ ] Follows Payload CMS 3.x patterns
- [ ] Follows .cursorrules standards

## Delivery
- [ ] All tasks and subtasks in story file are marked complete
- [ ] Code builds successfully
- [ ] No TypeScript errors
- [ ] No linting errors
- [ ] Story status updated to "Review"
